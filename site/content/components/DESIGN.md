# Home design language: quiet precision

The homepage explains a precise tool, so it should look precise and stay quiet: neutral grays, near-flat surfaces, a thin line of light on raised edges, short contact shadows, and cards that stand directly on the ground. Every rule below has a token or primitive in `../design.css`; components use those names instead of palette steps.

## Principles

1. **Type carries the hierarchy.** Size, weight and gray level order the page. Color is a signal, not decoration.
2. **One neutral: zinc.** Every gray is a step of the preset's `zinc` family, a near-neutral with a faint cool, metallic cast. Home tokens alias the preset roles and the site roles in `styles/docs-shell/theme.css`, so the homepage, header, footer and docs share one system.
3. **One light, one accent.** One lamp hangs above the page and a pointer carries it, in the hero and below it. What the hero cuts from stone (obsidian in light mode, moonstone in dark mode), the rest of the page cuts from the same stone: section titles, the primary controls and the objects a figure is about. Secondary hero controls use clear liquid glass; the gold signal (`--home-signal`, the preset's amber at the logo's hue) marks only live states, the path a change takes and the Master CSS figure in a chart. The hero field and the closing field are the same gold, so the page carries one brand color; preset yellow appears only where a sample class names it.
4. **Figures explain mechanisms.** Every illustration shows something Master CSS actually does: classes becoming rules, layers ordering them, rules flowing to a delivery target. No ornamental art.
5. **Motion shows cause and effect.** Things move because data moves or state changes. Ambient motion is slow; everything stops for reduced motion.
6. **Truthful samples.** Code, diagnostics, completions and numbers come from the engine, linter, language service or committed benchmarks, and tests keep them that way.
7. **One left rail, two centered moments.** Every section header and figure hangs on the content edge. The hero and the closing invitation center, so the page opens and closes on one axis.
8. **One idea per figure.** A section shows one demo, or a few cards that each show one thing. When several samples make the same point, put them behind tabs in one figure instead of repeating the frame.
9. **Frame only what is a tool.** A frame (a card or a window) says "this is a UI you would use": editor windows, the lint bench, the agent session, bento cards that hold several capabilities. Diagrams, charts and drawings sit open on the ground at the content width, held by whitespace and at most one rule. The page alternates framed and open sections, a figure never nests more than two surfaces, and a logo or shape is never captioned with what it already says.

## Rhythm

- Sections are `--home-section-space` apart (96 → 168px) and every figure starts `--home-header-space` (48 → 80px) below its header. The page should feel unhurried: when in doubt, add air, not ornament.
- A section header is a single stack on the left rail, never two columns: eyebrow, title (`max-width: 22ch`, balanced), lead (`max-width: 38rem`), then a text link to the guide that goes deeper. Every numbered section has one, so the reader always knows where to read next.
- Drafting rails run 20px outside the content edges from `md`, so text and frames sit inside a ruled column instead of touching the line. In the hero they start below the fixed header and fade in.
- On the homepage the header's content sits on the same column (`.home-header`), so the logo and the last icon share the sections' edges; the docs keep their full-width header.
- Every change of the homepage header runs as a view transition of the header alone: reaching the top re-forms the bar, and scrolling away or back slides it as one piece without a cross-fade. The root is marked with `data-header-transition`, never a class, because canvases read the root's class as a theme change; no CSS transition doubles the view transition. Reduced motion, or a browser without view transitions, applies the change at once.
- Rulers run down the outside of each rail from `md`: a short tick every 16px and a longer one every 128px, the way a design tool measures its canvas. They are the page's drafting texture; a hatch band in the margins would read as someone else's.
- Inside cards: 28px padding on phones, 36px from `sm`, 40–44px from `lg`; the title sits 12px above its body; the figure starts a padding-width below the body and is pushed to the card's bottom so figures in a row share a baseline. A figure that cannot fill its card (a list, a marquee) grows to fill it instead of leaving a gap.

## Surfaces

From the page outward. Each home token aliases a role; light step first, dark second.

| Token | Role | Zinc steps | Use | Treatment |
| --- | --- | --- | --- | --- |
| `--home-ground` | `surface-canvas` (site) | 0–5 mix / 95 | The page and the canvas | Flat |
| `--home-tray` | `surface-shell` (site) | 5–10 mix / 95–100 mix | Reserved; no homepage surface uses it now | Flat: one soft step below the ground, no ring and no shadow |
| `--home-sheet` | `surface-raised` | white / 90 | Cards, windows, selected segments | Hairline ring, 1px top light, contact shadow (`--home-elevation-1`) |
| `--home-well` | `surface-canvas` (site) | 0–5 mix / 95 | Figures and code inside a sheet: a recess back down to the canvas | Groove (`--home-groove`) |
| `--home-float` | `surface-floating` | white / 80 | Popovers and menus | `--home-elevation-2` |
| `--home-ink` | `surface-ink` (site) | 90 / 5 | Focus rings and the selected icon | Flat, 1px inner light |
| `.home-stone` | `--stone-*` | obsidian / moonstone | Tour controls, the theme handle, the engine and server, the source files in Workflow | Bevelled face, lamp sheen, lit rim, cast shadow (see below) |

Light mode stays clean and white: the ground is about `#f7f7f7` and sheets white, so structure comes from contours, not dark grounds. Text aliases `text-strong`, `text-body` and `text-muted`; `--home-text-faint` mixes 72% `text-muted` into the site's `text-subtle`, so annotations stay quiet but still read at 4.5:1 on the ground and on sheets in both schemes. Lines alias the site's `line-contour` (an 8.5% dark contour), `line-divider` and a 55% mix of `line-control`.

## Cards, inset and radii

- Cards stand directly on the page ground with their own 1px contour; there is no shell around a set of cards or the call to action, so no edge ever reads as a thick border. Cards in a grid sit 12px apart, 16px from `md`.
- Inside a card the figure may sit in a well 12px in (`--home-gap`), and nothing deeper: at most two surfaces.
- Radii nest concentrically, outer = inner + inset: well 8px, sheet 20px.
- Never put a sheet directly on a sheet; put a well between them.
- A card narrower than 28rem cannot spare the illustration's 7rem column: its title shares a row with a 4rem illustration (3rem below 16rem) and the description takes the card's full measure, so no line holds only a word or two.

## Light and shadow

- An edge is built from parts: a 1px dark contour holds the shape, a 1px inner light finishes the top edge (fainter on the left, the light comes from above and slightly left), and the shadow fades out in layers.
- `--home-edge`: the inner lights (`shadow-edge`).
- `--home-contact`: three contact layers, `.5px`, `2px` and `5px` deep at 4.5%, 2.5% and 1.6%, so the edge never looks cut out (`shadow-contact`). Depth starts at the sheets; nothing behind them carries a shadow.
- `--home-pressed`: two soft inner layers and a contour (`shadow-pressed`). Tracks are pressed into the ground; pressing a button swaps its outer shadow for this and nothing moves.
- Seams inside a bar are single 1px lines inset from both ends with a 1px light beside them, never full-height borders.
- The rest of the site uses the same light through `shadow-raised`, `shadow-floating` and `shadow-pressed` in `styles/docs-shell/theme.css`, with radii `r-lg` (wells), `r-xl` (controls and code), `r-2xl` (sheets) and `r-3xl` (shells). The docs' `--color-accent` and `--color-focus` are ink too, so active and focused states read the same on every page.

## Controls

- **Segmented control**: a soft pill track drawn with one 1px line, and a raised pill thumb (hairline, two soft shadows, a top highlight) that slides to the chosen option and takes its width. Until it is measured, the chosen option paints the raised look itself, so nothing jumps on hydration.
- **Buttons outside the hero**: primary is ink, secondary is a sheet with a rule ring. Both use the 10px control radius and are 44px tall, like the install command, whose copy target has a 6px concentric corner. Phone actions share one width.
- **Links into the guide** (`.home-section-link`: a section's link, "See details", "How it works") are quiet: 14px, the faint text color, a 14px arrow that moves on hover. They follow the copy and never compete with the figure. On touch, the 20px line reaches a 44px target into the air around it without moving.
- **Focus**: a 2px ink outline, offset 2px; inside a clipped well or pane the ring sits on the inner edge instead. Elsewhere on the site `:focus-visible` falls back to the same ring.
- **Reduced motion** keeps color, opacity and visibility cues but removes travel: hover arrows, logo lifts, tooltip rises and photo zoom stay put. A theme switch commits with transitions off, so the page recolors at once.
- **Forced colors**: framed tools keep a `CanvasText` outline, the size chart keeps its measured bars, the agent's current step keeps a `Highlight` outline, and the footer's engraved mark is removed.

## Glass

The base `.home-glass` combines a translucent fill, 10px backdrop blur, top and left inner light, a faint dark contour and soft falloff. The hero overrides it with the clear liquid glass below. Main content stays solid.

## Lines, guides and text

- `--home-hairline` separates, `--home-rule` divides, `--home-rule-strong` marks the selected item.
- Drafting guides: from `md`, each section draws rails 20px outside the content edges (`--home-rail`), a rule across its top and a cross where they meet (`--home-guide`). They sit behind content.
- `--home-text` is for display type, titles and data; `--home-text-body` for code; `--home-text-quiet` for prose; `--home-text-faint` for annotations.
- Code samples share the site's syntax palette in `styles/docs-shell/syntax-theme.css`: rose keywords, blue tags and functions, cyan properties, parchment strings and lavender numbers. Dark mode pairs soft colors with warm-white text on zinc-95; light mode deepens the same hues. Highlighted lines use a subdued amber wash. The hand-rendered editor figures alias those same roles through `--home-code-*`; code surfaces use `--color-code-surface`. Keep syntax colors intact on highlighted and diff lines, and maintain at least 4.5:1 text contrast in both modes. Success, warning and error retain green, amber and red independently of syntax colors; status tones (`.home-tone-*`) remain separate.

## Markers

The page labels itself with a few markers, and only these:

- **Section eyebrow** (`.home-eyebrow`): index, a short rule that draws in, and the section name. Every numbered section starts with one; the hero and the closing invitation have none.
- **Status marker** (`.home-status`): a dot and a word. `-live` uses the signal and is the only pulsing element in its figure.
- **Annotation marker** (`.home-annotation`): mono caps at `--home-label` that name parts of a figure. Cards carry no kicker above their title.
- **Tag** (`.home-tag`): mono caps in a hairline box for a state such as Default.
- **Units** in figures drop to mono at caption size, like a dimension on a drawing.

## Type scale

One scale, set in `../design.css`. Two sizes are fluid; everything else is fixed.

Titles also use `word-break: keep-all`, so they break only at spaces and punctuation; a long Chinese title marks its phrase boundaries with `\u200b` in `public/dictionaries/tw.json` so it can still wrap between phrases on a phone.

## Copy

Plain and specific, the way the docs would say it. Say what the thing is or does, then stop: "A markup-driven CSS orchestration language for developers and AI agents", "Lint classes against your project". Headings are regular weight: soft and even, never bold. No superlatives, no slogans, no claims the samples cannot back up. Section leads run one or two sentences (about 20 words) and card descriptions one full sentence: long enough to say what the figure shows and why it matters, short enough that the figure leads. Details beyond that go to the guide behind a quiet link. Eyebrows are plain nouns (Interface styling, Editor, Rendering, CSS size, Lint, AI agents, Workflow).

## Data

- The CSS size chart uses each brand's colors for its gradient bars, with the Master CSS row in gold. Gridlines, ticks and text stay neutral. Bars share a square left edge; only a bar's own count ever changes its length, and the chart has no ambient motion at rest.
- Third-party logos and brand icons keep their own colors; the gray system governs surfaces, lines and text, not other people's marks.
- Every figure that shows a number names its source and date, such as the benchmark snapshot, and the tests read the same file.

## Drafting material

The page borrows the quiet marks of a design tool, used sparingly so they read as structure, not decoration:

- **Guides and crosses**: rails outside the content, a rule between sections and a cross where they meet (`--home-guide`, `--home-rule-strong`).
- **Rulers**: ticks down the outside of each rail, restarting at each section's top so the first long tick meets the section's cross.
- **Hatch** (`.home-hatch`, `--home-hatch`: the site's 6% stripe tile): reserved, inactive or empty space inside a figure, and the footer's wordmark. Never a page texture.
- **Artboard marks** (`.home-marks`): four corner ticks about 6px outside an open figure or a window, in `--home-mark`. A box that already has its own border does not take them.
- **Light**: `--home-highlight` is the top-edge light on a sheet or glass, `--home-highlight-ink` the same on an ink surface; components use these instead of raw white.

## Windows and wells

- A **well** (`.home-bento-visual`) draws its contour in a layer above the figure, so a pane that fills it never hides the line and a pane's own edge never doubles it. Panes inside a well never carry their own outer border.
- An **editor window** (the editor stage, the lint bench, the agent session) has a bar: three dots, a file tab and a status on the right. It is the only place window chrome appears, and inside it every divider is a single 1px line: no bar border, well groove and ring stacking on one edge.
- A **code well** inside a card is just code in the well, with no bar. Docs code-block borders and fills are reset inside home figures.
- The **dot grid** marks a rendered preview, a canvas where markup becomes UI: the theme split, the gallery. Diagrams, palettes and code never sit on it.
- Problems are marked in the code with the word-mark directives the docs use (`@ERROR`, `@WARN`, `@MARK`), so the underline points at exactly what the rule reports; tests check the mark starts at the reported column.

## The hero's gold, stone and glass

The hero has an announcement, heading and actions; no description. Two slowly warped gold folds, lying a little deeper than the type so they lag behind it while the page scrolls, form broad valleys and continuous crests, with crisp creases between them, a thin bright line on each crest, a broad reflection that gives way to the satin streak wherever the sheet domes (so lit areas read as streaks along the folds rather than round, out-of-focus spots; on dark silk broad, nearly flat lit areas also settle slightly toward shadow, so they never read as pillows) and a soft lip highlight that never peaks into a needle where folds meet, a satin highlight that stretches along each fold and stays narrow across it, and fine grain drawn out along the folds' diagonal like threads. A held lamp brightens the crests turned toward it and deepens those turned away, so it shows on pale silk as contrast, and the crests nearest it mirror it as a narrow satin glint that slides along the folds with the hand. Independent phases evolve over 20–30 seconds. Light mode is pale champagne gold whose valleys stay light, so the obsidian title is the darkest thing on the page; with little room between its body and sheen, its broad reflection tightens and the satin carries the folds, so it reads as cloth rather than haze; dark mode is deep amber with warm, saturated crests, and a soft open reading band dims bright crests behind pale type with a warm factor, so they stay amber instead of turning khaki; under the header the silk recedes, so a crest never passes behind its icons or the gold logo mark. The fade toward the ground passes through warm ivory in light mode and dark amber in dark mode rather than gray, and lets go of that warmth first near the section's foot so no seam shows. The action row opens into a partial lower-left fade that still leaves silk, at about half strength, under the glass. On tall screens the top fade narrows and starts higher, so the silk reaches up toward the header instead of leaving the top empty.

One lamp lights everything. It lowers into place as the silk forms, so shadows grow from short and faint to their resting length. It rests over the title's first line, left of center, and drifts slowly, so its reflection now and then slides across the letters, and stays with the viewer as the page scrolls, so light slides across the stone even on phones; the lamp's resting height and the silk's lag follow the page's own scroll from the top, so a re-measure taken mid-page (re-entering view, a resize) never shifts either; where a phone reports orientation without a permission prompt, tilting it swings the lamp. A mouse picks it up and carries it lower, and lower still over the title, as if to examine the stone, so its light rakes across nearby folds, its highlights travel over the letters and every shadow turns away from it. Pressing sends one ring through the silk from where it was pressed, spreading and fading over about two and a half seconds: a mouse anywhere in the hero, touch or an activating key only from a control. Keyboard focus hangs it over the focused control, and a tap sets it down under the finger for a moment without holding it, so scrolling stays free. Let go, it drifts back to rest rather than jumping. Reduced motion keeps the resting lamp.

The title is cut stone. In light mode it is polished obsidian, a near-neutral black that matches Get started:

- The hand-polished face is almost but not perfectly flat. It mirrors a trace of the silk, mostly desaturated and with its contrast kept, with a slight waver, under a barely-there softbox. The face stays as black as its edges, so no rim reads as an inner outline; only the lamp and its reflection lift it.
- A quarter-round bevel about 4% of the type's size reflects the gold silk beside it on edges turned toward the lamp and flares close to it, so where the lamp hangs reads at a glance; edges turned away fall into the stone's black, so no even ring outlines a letter. The lit line reaches the outermost pixel, so the rounded edge itself catches the light.
- The lamp is a strip light: the faces beneath it mirror it as one crisp, slightly tilted streak below full white, and the bevels mirror it through their own tilt, so only the side turned toward the lamp catches it; a streak reads as a reflection where a broad panel would read as a lighter fill inside dark outlines. It glides over the first line at half strength while the lamp rests.
- One small, crisp highlight below full white sits where a mirror would show the lamp, its size independent of the lamp's height, so no single letter turns to chrome and the point never spreads into a gray smudge on the black; around it a faint, diffuse warm glow lights face and bevel alike, so the face never washes gray and no dark ring forms inside a lit letter.
- A soft warm shadow falls on the silk, away from the lamp and leaning slightly down, since the room's light comes from above as well. A letter straight under the lamp hides its shadow beneath itself, so no penumbra rings it like a glow. Held close, the stone seems to lift toward the lamp: the letters float higher and their shadows stretch further and darken a little, so the lamp's height reads too.

In dark mode it is moonstone, lit from within by the lamp: its warm ivory body is brightest and coolest near the lamp and settles to a deeper ivory away from it, never toward gray, so where the lamp hangs reads across the whole line, a touch denser in its lower edges, whose contour lets only a trace of the bright gold behind it through, warming slightly on the lamp side, so its edge never reads as an orange outline, while light that enters on the lamp's side leaves through the far edges near it as a warm amber band, as through translucent stone held up to a light; it casts only a faint shadow for separation. Its adularescence, a cool billowing sheen with a faint blue fringe, drifts across the whole line in broad continuous clouds, never as patches inside single letters, wherever the lamp's angle catches it, as a soft hint at rest so the line reads as one stone with Get started; where a held lamp hangs, it gathers across a few letters into a clearly whiter, neutral-cool glow, never violet against the gold, so the lamp reads on the pale stone at once. A single glint crosses the line once as the stone forms (on moonstone, a broad wave of that cool sheen), and a slow studio light sweeps it afterwards. Contour pixels never take reflections, and the bevel's highlight is placed by distance and weighted by the edge's direction rather than its exact slope, so a lit diagonal reads as one line instead of a row of beads at 1× and on 5K screens alike. Native text owns layout and accessibility; its mask changes only with fonts, text or layout, and replaces native ink only after a successful frame. The hero is a scene, so nothing in it can be selected except the install command.

Get started is cut from the same stone: obsidian with light ink in light mode, moonstone with dark ink in dark mode, its cool sheen a broad, soft cloud low in the pill, across from the lamp, never a spot on a wide phone button. In light mode its shadow takes the title's warm tone, so the two read as one lighting. Its rim catches the lamp on the near side and a neutral reflection of the gold on the far side, its curved top carries the lamp's sheen and a small, crisp hot spot near its top when the pointer arrives, a glint crosses it on hover (in moonstone the cool sheen also brightens, since a white glare would vanish on the pale stone), its arrow leads a step ahead like the announcement's and the closing invitation's, and its shadow follows the lamp.

Announcement and install are clear liquid glass: a nearly transparent white fill (8% in light mode) with only a faint top light and no added brightness, so the command never outshines Get started, two lit rims, a short bright streak on the curved top that slides along it as the lamp passes, an inner pool of light at the bottom and a lamp-following shadow. Dark glass is lightly smoked rather than white, clear enough to show the silk yet keeping its text above 4.5:1 over any fold. The canvas refracts the silk beneath them: each rim pulls in what lies just outside it, split slightly by wavelength and deepened in color, and the middle magnifies a little; hovered or focused glass is drawn a little closer, magnifying and bending more. Light the glass gathers through its curved rim lands as a soft warm caustic on the silk just past the far edge, where an opaque control's shadow would fall. Once that refraction draws, their backdrop blur drops to 1px so the bending stays visible; without the canvas they keep a 6px frosted blur. Copying the install command answers with one gold light that crosses its glass. The announcement's live dot is a polished bead of the same signal gold, whose glow brightens as the lamp comes near. With reduced transparency or more contrast requested, the glass becomes a solid sheet and the canvas stops refracting beneath it.

Main controls are at least 52px tall, with a 44px copy target. Mobile actions share a width and fit at 320px, where the title steps down so its no-break "developers and" never splits inside a word. Enlarged text splits the announcement into rows and places copy below the complete command, preserving its reading width.

- `--hero-gold-shadow`, `--hero-gold-body` and `--hero-gold-sheen` own the palette; `--stone-*` and `--glass-*` own the control materials. The canvas hands the lamp to controls as `--lit-x`, `--lit-y`, `--lit-angle`, `--cast-x`, `--cast-y` and `--lit-near`; their CSS defaults hang it above the title when the canvas is unavailable.
- Gold forms over 2.2 seconds and the stone over 800ms, followed by the glint. Switching themes re-cuts the title: the native ink returns, then the other stone forms and glints. The canvas fades in as a whole over the static CSS gold, which leaves only after the silk has mostly arrived, so arrival never dips through the bare ground. Controls render independently of canvas.
- Gold renders at 60% density, capped at 1.5 million pixels; final output reaches the display's density up to nine million pixels and steps down at runtime when frames fall under about 40fps, with glyph masks up to 3×, so the stone stays as crisp as native type on phones. Grain resolves at CSS-pixel scale and disappears at the page ground. The title's distance field reaches 30% of its font size, and the mask's padding covers that range, so shadows end inside it.
- The canvas hands the lamp to controls every frame while it is held, and ten times a second while it drifts; Get started transitions only its fill, since easing lamp-driven shadows would restyle every frame.
- Canvas pauses off screen, in hidden tabs, in print and forced colors. Reduced motion freezes the current phase and the lamp, drops the hover glint and makes control feedback immediate. Context loss restores native ink and the CSS gold at once before rebuilding; failures release GPU resources and the lamp properties. CSS gold and text survive unavailable WebGL or fonts. Print and forced colors use solid ink and boundaries.
- Class samples belong to the MCP figure, not the hero.

## Stone, lamp and silk below the hero

The hero's materials continue down the page, so the reader meets one world rather than a hero and a document. They mark what matters, never fill space: everything else stays zinc, hairline and sheet.

- **The lamp** (`HomeLamp`, `home-lamp.ts`) hangs above the viewport a little left of center and stays with the viewer, so light slides across the stone as the page scrolls. A mouse carries it lower over what it points at; keyboard focus hangs it above a focused stone control, or above the stone a focused control moves (the theme slider's handle); on phones that report orientation without a prompt, tilting swings it, as in the hero. Every `.home-lit` element in view receives it relative to itself as `--lit-x`, `--lit-y`, `--lit-angle`, `--cast-x`, `--cast-y` and `--lit-near`, the hero's own properties; CSS defaults hang it above-left without script, and reduced motion keeps it at rest. It closes on its target with the same 120ms time constant as the hero's and the close's lamps, at any refresh rate. Lit elements are either the material itself or an empty child of a frame, so moving the lamp restyles nothing inside a figure.
- **Stone** (`.home-stone`, tokens `--stone-*` in `../design.css`): a face that darkens toward its base, a broad sheen and a hot spot from the lamp, a rim lit on the near side and warmed by a faint gold floor on the far side, and a shadow cast away from the lamp. On moonstone a cool sheen floats low across from the lamp. Outside the hero there is no silk to mirror, so the warm lower bevel stays faint until a figure marks the stone live; then it mirrors the gold. Small stones (tour controls, the theme handle, Workflow's source chips) use a quieter moonstone (`.home-stone-quiet`), so in a dark figure only the primary action and the engine stay the brightest things. On moonstone the engine's dormant mark darkens to graphite rather than fading into the pale stone, and turns gold while it generates. Stone is used for the closing Get started and the tour controls (`.home-stone-button` adds the hero's hover glint and pressed state), the theme preview's handle, the Compiler engine in Rendering, the MCP server in AI agents, and in Workflow the source `index.css`, the changed token and, in the monorepo, only the entry the selected project resolves through, so each drawing holds one stone path; Canvas figures paint the same stone from the same tokens.
- **Cut type** (`.home-stone-type`): section titles and the closing destination are set in the same stone, darkening down each line with a faint reflection across the upper part of each line, a small neutral highlight with a solid core where the lamp falls on obsidian and a broader warm one on moonstone, a cool sheen on moonstone and a soft contact shadow that phones and 1× screens omit. Canvases redraw for a theme change only, never for the header's transitions.
- Under `prefers-reduced-motion: reduce`, loops stop and figures show their finished state.
- Write animations with longhand properties when a value uses a route variable; a variable inside the `animation` shorthand makes the build keep every preset keyframe.

## Depth

3D is used to separate meaning into planes, never as a gimmick:

- The hero gold is lit as a matte surface: sculpted folds catch a broad sheen from one light. The stone title floats a short height above it, so its shadow lengthens and softens as the lamp comes lower.
- The cascade layer figure explodes `@layer theme, base, defaults, components, utilities` into orthographic planes, so flat callouts beside it rise with their planes and stay level.
- The palette card's well holds extruded bars on a hatched floor plate, as tall as each swatch's oklch chroma; they rise in a diagonal wave on scroll and flatten into a table under the pointer or keyboard.
- The MCP figure stands liquid-glass client marks and the server on a wide, low, dial-rimmed floor of real classes; narrow widths tilt less.

Perspective is `--home-perspective`. A plane that carries content to read tilts less than 20° and settles flat. Diagram planes may tilt further when they only carry short labels, and anything longer turns to face the reader.

## Matrix

Rows of real classes from `ctaClassRows` (`glyphFieldLines`), which the tests lint, are the one place the page shows classes as texture: the floor of the MCP figure, the project the server reads. Nothing else uses classes as decoration.

## Homepage style ownership

Shared materials and layout remain in `@master/internal-site/home/design.css` and
`home.css`. Feature rules are explicit dependencies: bento owners import
`home/bento.css`, segmented-control owners import `home/segmented-control.css`.
A consumer of `home.css` alone does not receive either feature. The section owns
any feature class it passes to a child as a prop.

Product file windows share `HomeEditorWindow`, `HomeEditorBar`, `HomeEditorTab`
and `HomeEditorLights`. The window imports `home-window-surface.css`, the bar
and lights import `home-editor-chrome.css`, and the tab imports
`home-editor-tab.css`. The three wrapper components
accept `children` snippets, `class` and native HTML attributes; lights are purely
decorative. `--home-editor-tab-fill`, `--home-editor-tab-line` and
`--home-editor-tab-radius` describe tab material without importing scene rules.
The Agent uses `.home-window-surface` for its outer material and `HomeEditorTab`
for its desktop file tab. Lint tabs retain the well fill while using the Editor contour.

`HomeCodeWindow` owns `home-code-window.css`; its unused `fixPreviewCode` prop
and overlay layers are removed. Product diagnostics still use
`HomeCodeWindowProblem`: that shared data type remains in use by Lint and Agent.
CopyCommand owns its control stylesheet. Agent owns spinner and step forced-color
rules. The tiny `home-code-colors.css` leaf is imported by Agent and CascadeLayers.

Each scene keeps its playback state machine. Lint has one reactive `phase`, not
a second imperative mirror. Elapsed time, token geometry and paused-time snapshots
remain separate because they represent different information.

`site/tests/home-window-fixtures.mjs` verifies these boundaries in a disposable
packed consumer. It must never create production example routes.
