## 개요 [sr-only] \{#overview\}
앱이 모든 페이지에 필요한 스타일을 한곳에서 불러오게 하세요. 진입점은 여러 소스 파일을 가져올 수 있습니다. 공유 값, 문서 기본값, 컴포넌트 규칙을 각 소유 소스에 유지하고 같은 앱 스타일시트로 조합합니다.

먼저 [프레임워크 설치](/guide/installation#integrations)를 완료하세요. 아래 예제는 기존 CSS 진입점을 확장하며 Master CSS를 두 번째로 설치할 필요는 없습니다.

## 하나의 앱 진입점에서 시작하기 \{#entry-stylesheet\}

앱이 이미 불러오는 스타일시트 시작 부분에 기본 가져오기를 유지하세요:

```css name=styles/app.css
@import '@master/css';
```

이 가져오기는 `theme, base, defaults, components, utilities` 순서를 포함한 프리셋 정의와 기본 스타일을 불러옵니다. 통합은 이 진입점으로 프로젝트의 생성 CSS를 전달합니다. 프레임워크 설치 가이드에 따라 앱 루트, 루트 레이아웃 또는 빌드 진입점에서 가져오세요.

소스 파일을 나누어도 또 다른 전체 진입점은 필요하지 않습니다. 자신의 파일을 `app.css`에서 가져오세요:

```css name=styles/app.css
@import '@master/css';
@import './theme.css';
@import './defaults.css';
@import './components.css';
```

<GlobalIllustration />

이 파일들은 하나의 진입점 그래프를 구성합니다. 공유 정의는 `app.css`에 직접 작성하든 가져온 파일에 작성하든 사용할 수 있습니다. 각 라우트 스타일시트에서 전체 Master CSS 진입점을 다시 가져오지 마세요. 각 파일이 진입점이 되어 전역 네이티브 CSS가 중복될 수 있습니다.

## 문서 기본 스타일 설정하기 \{#base-layer\}

프리셋 초기화 스타일은 `base`에 유지하세요. 제품의 문서 기본값은 일반 컴포넌트와 유틸리티 선언이 덮어쓸 수 있도록 `defaults`에 둡니다:

```css name=styles/defaults.css
@layer defaults {
  body {
    background-color: var(--color-surface-base);
    color: var(--color-text-body);
  }
}
```

추가 클래스 없이 기본값을 받아야 하는 요소에는 네이티브 선택자를 사용하세요. 선택자의 범위를 의도적으로 정해야 합니다. 전역 `button` 규칙은 모든 기능 내부의 버튼에도 적용됩니다. 규칙이 특정 제품 역할에 속한다면 컴포넌트 클래스를 사용하세요.

프리셋 기본 스타일은 이미 문서에 글꼴 토큰을 적용합니다. 글꼴을 선택하려면 [타이포그래피](/guide/typography#site-typeface)에 따라 토큰을 바꾸세요. 선언이 경쟁하면 [캐스케이드 레이어](/guide/cascade-layers)를 참고하세요. 규칙을 나중에 불러온다고 더 강한 레이어로 이동하지는 않습니다.

## 공유 그래프에 포함할 내용 결정하기 \{#shared-vocabulary\}

| 공유 결정 | 정의 위치 | 이어서 읽기 |
| --- | --- | --- |
| 사용 측이 함께 바뀌어야 하는 값 | `theme.css`의 `@theme` | [테마 토큰](/guide/theme) |
| 모든 페이지에 필요한 기본값 | `@layer defaults`의 네이티브 선택자 | 위 예제 |
| 반복되는 제품 요소 | `@layer components`의 네이티브 클래스 | [스타일 재사용](/guide/reusing-styles#keep-a-components-shared-appearance-together) |
| 사용할 때 생성되는 클래스 기능 | 가져온 스타일시트의 `@utility` | 아래 헬퍼 예제 |
| 반복되는 CSS 선언이나 중첩 스타일 | `@mixin`을 `@apply`로 확장 | [CSS 재사용](/guide/reusing-styles) |
| 이름이 있는 뷰포트 또는 컨테이너 조건 | `@custom-media` 또는 `@custom-container` | [반응형 디자인](/guide/responsive-design) |

가져오는 `theme.css`에서는 프로젝트에 필요한 값부터 시작하세요:

```css name=styles/theme.css
@theme {
  --spacing-card: 1.5rem;
}
```

이 토큰은 `p-card`, `gap-card`와 해당 키를 받는 다른 간격 계열을 등록합니다. 선언은 프로젝트에서 필요할 때 출력됩니다. 진입점 그래프에 둔다고 일반 토큰이 정적으로 바뀌지는 않습니다.

의미가 공유되기 때문에 정의를 공유하세요. 두 기능이 지금 같은 수치를 사용해도 별도 토큰이 필요할 수 있습니다. 한 요소가 여러 클래스를 사용한다는 사실만으로 컴포넌트 추상화가 필요한 것은 아닙니다.

### 컴포넌트 소유 관계 명확히 하기 \{#component-classes\}

예를 들어 공유 알림은 `components.css`에 둘 수 있습니다:

```css name=styles/components.css
@layer components {
  .notice {
    padding: var(--spacing-md);
    border: 1px solid var(--color-line-divider);
    border-radius: var(--radius-md);
    background-color: var(--color-surface-raised);
    color: var(--color-text-body);
  }
}
```

```html
<aside class="notice">Your changes are saved locally.</aside>
```

이 네이티브 선택자는 `.notice`에 스타일을 적용하며 `notice`라는 유틸리티를 등록하지는 않습니다. 공유 상태와 조건을 컴포넌트 규칙 안에 작성하세요. Master CSS 수정자를 받는 클래스 레시피가 필요하면 `@utility`를 사용합니다. [스타일 재사용](/guide/reusing-styles)에서 작동하는 예제로 비교합니다.

진입점 그래프의 네이티브 CSS는 사용하지 않는 컴포넌트 규칙을 포함해 기본적으로 출력됩니다. 네이티브 가지치기는 명시적으로 선택해야 합니다. [네이티브 가지치기](/guide/optimizing-css-delivery#native-pruning)를 참고하세요. 정의를 보이게 하려는 이유만으로 큰 라우트 전용 스타일시트를 전역 그래프로 옮기지 마세요.

## 공유 헬퍼 추가하기 \{#custom-utilities\}

전역 정의는 가능한 모든 클래스의 규칙을 생성하지 않고 여러 기능에 필요한 동작을 표현할 수 있습니다. 다음 헬퍼는 관련 링크를 배치하고 화면 밖 내용의 렌더링 작업을 생략하며 인쇄에서 그룹을 제외합니다:

<DemoConfiguredExample name="global-related-guides" title="공유 헬퍼로 구성한 링크 그룹" source={`@utility flow {
  display: grid;
  gap: var(--spacing-md);
}

@utility content-auto {
  content-visibility: auto;
  contain-intrinsic-size: auto 32rem;
}

@utility print-hidden {
  @media print {
    display: none;
  }
}`} html={`<section class="content-auto flow print-hidden p-md b-solid b(1) b-line-divider r-md bg-surface-raised">
  <h2 class="m(0) text-lg font-regular">Related guides</h2>
  <a class="text-sm fg-text-body underline" href="/guide/theme" target="_top">Choose shared theme values</a>
  <a class="text-sm fg-text-body underline" href="/guide/responsive-design" target="_top">Adapt a layout to its available space</a>
</section>`} caption="flow는 그리드와 간격을 제공합니다. print-hidden은 인쇄 매체에서 그룹을 제거합니다. content-auto는 화면 밖 렌더링을 생략할 수 있습니다. 32rem 고유 크기는 폴백 추정치이며 고정 섹션 높이가 아닙니다." />

기존 Master CSS 가져오기 뒤에 정의를 두거나 앱 진입점에서 `utilities.css`를 가져오세요. 클래스는 마크업에서 발견될 때 CSS를 생성합니다. 앱에서 인쇄 미리보기를 열어 `print-hidden`을 확인하고 인쇄에도 링크가 필요하면 해당 클래스를 제거하세요. 자신의 레이아웃 내용에 맞는 [고유 크기 추정치](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size)를 선택합니다.

## 로컬 전달은 로컬에 유지하기 \{#organize-global-files\}

앱 진입점은 페이지 간 공유 스타일에 집중하게 하세요. 통합이 라우트 스타일시트에 프로젝트 정의를 제공하므로 전체 Master CSS를 다시 가져올 필요가 없습니다. 그래프 밖의 추가 정의에는 `@reference`를 사용하지만 참조한 네이티브 CSS를 전달하지는 않습니다. 로컬 규칙 전달은 여전히 라우트 로더가 담당합니다.

설정 방법은 [라우트 수준 스타일](/guide/route-level-styles)을, 독립 앱에 별도 진입점 그래프가 필요하다면 [모노레포](/guide/monorepo)를 참고하세요. 전역 파일을 나눈 뒤 정의를 사용하는 페이지와 사용하지 않는 페이지를 확인합니다. 공유 스타일은 여전히 앱 진입점으로 전달되어야 하며 라우트 전용 규칙은 로컬 소유 관계를 유지해야 합니다.
