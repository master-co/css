## 概覽 [sr-only] \{#overview\}
讓應用程式集中從一個位置載入每個頁面需要的樣式。這個進入點可以匯入多個原始檔：將共用值、文件預設樣式與元件規則保留在各自所屬來源，再透過同一份應用程式樣式表組合。

請先完成[框架安裝](/guide/installation#integrations)。下方範例擴充既有 CSS 進入點，不需要再次安裝 Master CSS。

## 從一個應用程式進入點開始 \{#entry-stylesheet\}

在應用程式已載入的樣式表開頭，保留預設匯入：

```css name=styles/app.css
@import '@master/css';
```

此匯入會帶入預設集定義與基礎樣式，包含 `theme, base, defaults, components, utilities` 的順序。整合以這個進入點傳遞專案產生的 CSS。請依框架安裝指南，從應用程式根元件、根版面配置或建置進入點匯入。

拆分原始檔不需要另一個完整進入點。從 `app.css` 匯入你自己的檔案：

```css name=styles/app.css
@import '@master/css';
@import './theme.css';
@import './defaults.css';
@import './components.css';
```

<GlobalIllustration />

這些檔案組成同一個進入點圖。無論直接寫在 `app.css` 或某個匯入檔，共用定義都可使用。避免在每個路由樣式表重複匯入完整 Master CSS 進入點：那會讓每個檔案都成為進入點，並可能重複全域原生 CSS。

## 設定文件預設樣式 \{#base-layer\}

將預設集重設樣式保留在 `base`。產品的文件預設樣式則放進 `defaults`，讓一般元件與 utility 宣告能覆寫它們：

```css name=styles/defaults.css
@layer defaults {
  body {
    background-color: var(--color-surface-base);
    color: var(--color-text-body);
  }
}
```

不加額外類別就應取得預設樣式的元素，請使用原生選擇器。有意識地控制選取範圍：全域 `button` 規則也會作用於每個功能內的按鈕。若規則屬於某個產品角色，請使用元件類別。

預設集基礎樣式已將字型 token 套用到文件。選擇字型時，依[文字排版](/guide/typography#site-typeface)調整這些 token。宣告互相競爭時，請參閱[串接層](/guide/cascade-layers)；較晚載入規則，不會使它進入更高優先的串接層。

## 決定哪些內容屬於共用圖 \{#shared-vocabulary\}

| 共用決策 | 定義位置 | 延伸閱讀 |
| --- | --- | --- |
| 使用端應一起改變的值 | `theme.css` 中的 `@theme` | [主題 token](/guide/theme) |
| 每頁都需要的預設樣式 | `@layer defaults` 中的原生選擇器 | 上方範例 |
| 反覆出現的產品元素 | `@layer components` 中的原生類別 | [重用樣式](/guide/reusing-styles#keep-a-components-shared-appearance-together) |
| 使用時才產生的類別能力 | 匯入樣式表中的 `@utility` | 下方輔助類別範例 |
| 重複的 CSS 宣告或巢狀樣式 | `@mixin`，以 `@apply` 展開 | [CSS 重用](/guide/reusing-styles) |
| 具名檢視區或容器條件 | `@custom-media` 或 `@custom-container` | [響應式設計](/guide/responsive-design) |

匯入的 `theme.css`，可從專案需要的值開始：

```css name=styles/theme.css
@theme {
  --spacing-card: 1.5rem;
}
```

此 token 會註冊 `p-card`、`gap-card` 與其他接受該鍵名的間距家族。專案需要時才會輸出宣告；放進進入點圖，不會使一般 token 變成靜態。

因為語意共用，才共用定義。兩個功能今天使用相同數字，仍可能需要不同 token；一個元素用了多個類別，本身也不代表需要元件抽象。

### 明確保留元件歸屬 \{#component-classes\}

例如，共用通知元件可放在 `components.css`：

```css name=styles/components.css
@layer components {
  .notice {
    padding: var(--spacing-md);
    border: 1px solid var(--color-line-divider);
    border-radius: var(--radius-md);
    background-color: var(--color-surface-raised);
    color: var(--color-text-body);
  }
}
```

```html
<aside class="notice">Your changes are saved locally.</aside>
```

此原生選擇器為 `.notice` 套用樣式，不會註冊名為 `notice` 的 utility。將共用狀態與條件寫在元件規則內。若需要接受 Master CSS 修飾詞的類別組合樣式，請改用 `@utility`。[重用樣式](/guide/reusing-styles)以可操作範例比較這些選擇。

進入點圖中的原生 CSS 預設會輸出，包括未使用的元件規則。原生修剪需要明確啟用；請參閱[原生修剪](/guide/optimizing-css-delivery#native-pruning)。不要只為讓定義可見，就把大型路由專用樣式表移進全域圖。

## 加入共用輔助類別 \{#custom-utilities\}

全域定義能描述多個功能需要的行為，而不必為每種可能類別都產生規則。這些輔助類別排列相關連結、允許畫面外內容略過渲染工作，並在列印時隱藏整組內容：

  content-visibility: auto;

}

@utility print-hidden {
  @media print {
    display: none;

}`} html={`<section class="content-auto flow print-hidden p-md b-solid b(1) b-line-divider r-md bg-surface-raised">

  <a class="text-sm fg-text-body underline" href="/guide/theme" target="_top">Choose shared theme values</a>
  <a class="text-sm fg-text-body underline" href="/guide/responsive-design" target="_top">Adapt a layout to its available space</a>
</section>`} caption="flow 提供網格與間隔。print-hidden 在列印媒體隱藏整組內容。content-auto 可略過畫面外渲染；32rem 固有尺寸是備援估計值，並非固定區塊高度。" />

將定義放在既有 Master CSS 匯入之後，或從應用程式進入點匯入 `utilities.css`。類別在標記中被發現時才產生 CSS。請在應用程式開啟列印預覽，檢查 `print-hidden`；若連結也應出現在列印中，移除該類別。依自己的版面配置內容，選擇[固有尺寸估計值](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size)。

## 區域樣式維持區域傳遞 \{#organize-global-files\}

讓應用程式進入點專注於跨頁共用樣式。整合會為路由樣式表提供專案定義，無須再次完整匯入 Master CSS。圖之外的其他定義請使用 `@reference`；它不會傳遞被參照的原生 CSS。路由載入器仍負責傳遞區域規則。

此設定請參閱[路由層級樣式](/guide/route-level-styles)；獨立應用程式需要各自的進入點圖時，請參閱 [Monorepo](/guide/monorepo)。拆分全域檔案後，檢查一個使用其定義的頁面與一個未使用的頁面：共用樣式仍應由應用程式進入點傳入，路由專用規則則應保留原本的區域歸屬。
