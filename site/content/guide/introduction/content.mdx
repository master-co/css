## Overview [sr-only]
<Overview />
Master CSS is a CSS framework for styling interfaces in markup and defining shared styles in CSS. The card combines shared colors, spacing and type with local layout choices: its classes describe the styling where you use it, and the theme supplies the shared values.

The class language combines native declarations such as `grid`, named values such as `p-lg`, and conditions such as `bg-blue-70:hover`. Master generates CSS for recognized classes and retains the resources they need. Start with the supplied theme and write local styles without designing a complete system first; as values and patterns become shared, name them in your project CSS with theme tokens, native component classes and custom utilities. Complex selectors and longer reusable styles can stay in native stylesheets alongside your classes.

## Define values that should change together \{#write-your-first-class\}
In the card, `p-lg` reads a spacing token and `bg-surface-raised` reads a surface color. These names come from the supplied theme. Add your own token when several elements should share a project decision, such as the brand color used by primary actions.

After [Installation](/guide/installation), your application loads a CSS entry containing:

```css name=app.css
@import '@master/css';
```

Add the following definitions after that import. The two links show alternative ways to give the card's action a brand background: `bg-brand` uses the theme token through a Master class, while `card-action` uses the same token in native CSS.

  --color-brand: #2563eb;
}

Both backgrounds reference `--color-brand`. Changing that definition updates both consumers wherever the value applies. Local layout classes can still differ, and a reusable component can collect more declarations as its role becomes clear.

Share a token because its consumers should change together. An informational color may initially have the same value as the brand color and still deserve a separate token. [Theme Tokens](/guide/theme) explains shared values; [Global Styles](/guide/global-styles) covers reusable components and utilities.

## Understand the next change
Before editing a shared token such as `--color-brand`, the CLI, MCP server, [Language Service](/guide/language-service) and [Code Linting](/guide/code-linting) read the same project definitions to locate its consumers and compare snapshots of the affected classes and outputs. [AI Coding](/guide/ai-coding#review-the-second-change) walks through that review with a coding agent.

## Choose how CSS is delivered
Use the recommended static setup for your framework. It scans complete class names at build time and delivers ordinary CSS, without a Master browser runtime or engine. Changing state does not require compiling CSS in the browser: toggle known classes, use native selectors, or update custom properties for coordinates, progress and other dynamic values. Choose runtime only when a playground, visual editor or deployed content introduces previously unknown class names; [Rendering Modes](/guide/rendering-modes) compares static, runtime and progressive delivery.

Start with [Installation](/guide/installation), then follow the [Syntax Tutorial](/guide/syntax-tutorial) to build a card with interaction states, responsive conditions and a project token.
