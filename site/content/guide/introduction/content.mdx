Master CSS is a CSS framework for styling interfaces in markup and defining shared styles in CSS. Write classes where you build an element; use your stylesheet for the values and patterns that belong to the wider project. Master generates the CSS those classes need.

You can start with the supplied colors, spacing and typography. You do not need to design a complete theme before building your first component.

## Build an interface with CSS and utilities \{#overview\}

This card combines a native component class with utilities. `.action` defines the button's base styles in CSS; `w-full`, `mt-md` and `bg-blue-60` choose its width, margin and color for this card. The rest of the markup uses preset utilities for layout, spacing and typography.

After [Installation](/guide/installation), add the example's CSS after the preset import in your app stylesheet, and put its HTML in a source file your integration scans:

```css name=app.css
@import '@master/css';
```

<Overview />

The preview uses the displayed CSS and HTML together. `.action` is defined by this example in `@layer components`; Master generates the utility rules from the classes in markup. Keep the button's common geometry and focus treatment in `.action`, while this instance keeps its blue colors and full width.

Try changing `p-lg` to `p-md`: the card's content padding becomes smaller without changing the button's base styles.

## Follow a class into CSS \{#write-your-first-class\}

Take `p-lg` from the card. The preset connects `p-` to padding and `lg` to the spacing token `--spacing-lg`. Master generates a class selector whose declaration references that CSS variable.

<IntroductionIllustration />

<Class2CSS classes={['p-lg']} />

The browser applies `padding: var(--spacing-lg)` to the matching element. With the preset's value, that is `1.5rem` on all four sides. The class stays the same if you change the shared value in your theme.

Other classes express different kinds of decisions: `w-full` is a fixed utility for `width: 100%`, while `bg-blue-70:hover` adds a hover state. The [Syntax tutorial](/guide/syntax-tutorial) walks through values, selectors and conditions in a working example.

## Define what should change together

Add a theme token when several elements should share a project decision. For a primary action color, define `--color-brand` after the import in your app stylesheet, then use `bg-brand` in markup:

<ConfiguredExample source={`@theme {
  --color-brand: #2563eb;
}`} html={`<a class="inline-flex px-md py-xs r-md bg-brand fg-white" href="/guide/installation">
  Start building
</a>`} />

Changing `--color-brand` updates elements that use it. Share that token because the elements should change together; two unrelated colors can have the same value without needing the same name. [Theme tokens](/guide/theme) explains how to define and override shared values.

Use a component class such as `.action` when several elements should share a styling contract, and a UI component when they should share markup. A long class list alone does not require a new CSS name. [Reusing styles](/guide/reusing-styles) helps you choose between a shared token, a component class and a custom utility.

## Start with static CSS

Use the recommended static integration for your framework. It finds complete class names in your source at build time and delivers ordinary CSS, without a Master browser runtime or engine.

Interactive interfaces still work: switch between known classes, use selectors such as `:hover`, or update CSS custom properties for values such as progress and coordinates. A runtime is useful when a playground, visual editor or deployed content introduces previously unknown class names. [Rendering modes](/guide/rendering-modes) explains the delivery choices.

Follow [Installation](/guide/installation) to connect Master CSS to your app, then build a card with interaction states and responsive conditions in the [Syntax tutorial](/guide/syntax-tutorial). For completion and diagnostics while you write, set up the [Language service](/guide/language-service).
