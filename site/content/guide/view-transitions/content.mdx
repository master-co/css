## Overview [sr-only]
The [View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API) animates between two visual states of a page; MDN's [Using the View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API/Using) explains `startViewTransition()`, snapshot naming, cross-document navigation and fallbacks. Master CSS covers the CSS side: name and group snapshots with classes, and style the transition pseudo-elements with selector suffixes on `html`.

| Class syntax | Use |
| --- | --- |
| `(view-transition-name:…)` | Names an element snapshot so it can animate apart from the root. |
| `(view-transition-class:…)` | Groups named snapshots for shared pseudo-element styling. |
| `…::view-transition` | Targets the root view-transition pseudo-element tree. |
| `…::view-transition-group()` | Styles the group box for a named snapshot or `.class`. |
| `…::view-transition-image-pair()` | Styles the wrapper around the old and new snapshot images. |
| `…::view-transition-old()` | Styles the outgoing snapshot image. |
| `…::view-transition-new()` | Styles the incoming snapshot image. |

## Article list to detail
A common use case is moving from an article feed to an article detail page. The selected article's image, title, and date can keep the same `view-transition-name` in both layouts, while the surrounding card grid and detail content change normally. This demo also uses `view-transition-class` so the transition timing applies only to article snapshots.

(click) Open an article, then return to the collection. Keyboard focus follows the selected article and returns to its button.
<DemoViewTransition example="articles" />

In the list view, every article gets unique names for its shared elements. Use an image from your own project at the example path:

```html name=article-list.html
<section data-articles>
  <article>
    <img
      alt="A mountain ridge under soft light"
      class="(view-transition-class:article) (view-transition-name:article-aurora-image)"
      src="/images/article-aurora.jpg"
    />
    <time class="(view-transition-class:article) (view-transition-name:article-aurora-date)">May 12, 2026</time>
    <h3 class="(view-transition-class:article) (view-transition-name:article-aurora-title)">
      Designing transitions that preserve context
    </h3>
    <p>Keep the selected image and heading connected to their destination.</p>
    <button type="button" data-read-more>Read article</button>
  </article>
</section>
```

Keep the detail markup in a template. Its matching image, date and heading use the same names; the template stays outside the rendered list until it is selected:

```html name=article-detail.html
<template id="article-detail">
  <article>
    <img
      alt="A mountain ridge under soft light"
      class="(view-transition-class:article) (view-transition-name:article-aurora-image)"
      src="/images/article-aurora.jpg"
    />
    <time class="(view-transition-class:article) (view-transition-name:article-aurora-date)">May 12, 2026</time>
    <h1 tabindex="-1" class="(view-transition-class:article) (view-transition-name:article-aurora-title)">
      Designing transitions that preserve context
    </h1>
    <p>The image, date and heading keep their snapshot names.</p>
    <button type="button" data-back>Back to collection</button>
  </article>
</template>
```

Place the list and template in the same document, then replace the list contents inside `startViewTransition()`. Restore focus after each update so keyboard readers can continue from the new view:

```js name=article-transition.js
const root = document.querySelector('[data-articles]')
const detail = document.querySelector('#article-detail')
const list = root.cloneNode(true)

function changeView(update) {
  const reduceMotion = matchMedia('(prefers-reduced-motion: reduce)').matches
  if (!document.startViewTransition || reduceMotion) {
    update()
  } else {
    const transition = document.startViewTransition(update)
    // Rapid input may skip the animation; the DOM update still completes.
    transition.ready.catch(() => {})
  }
}

root.addEventListener('click', (event) => {
  if (event.target.closest('[data-read-more]')) {
    changeView(() => {
      root.replaceChildren(detail.content.cloneNode(true))
      root.querySelector('h1').focus()
    })
  } else if (event.target.closest('[data-back]')) {
    changeView(() => {
      root.replaceChildren(...list.cloneNode(true).childNodes)
      root.querySelector('[data-read-more]').focus()
    })
  }
})
```

Apply the shared timing to the document root:

```html
<html class="(animation-duration:.52s)::view-transition-group(.article)">
```

<Class2CSS>
  {[
      '(view-transition-name:article-aurora-image)',
      '(view-transition-name:article-aurora-date)',
      '(view-transition-name:article-aurora-title)',
      '(view-transition-class:article)',
      '(animation-duration:.52s)::view-transition-group(.article)'
    ]}
</Class2CSS>

(i) The same `view-transition-name` must be unique in the rendered document, or the browser skips the transition. The list uses article-specific names such as `article-aurora-image` and `article-studio-image` so the selected card can match the detail page without colliding with other cards.

## Styling transition pseudo-elements
Write the pseudo-element after the declaration, and put these classes on the `html` element: the pseudo-element tree is generated from the document root, so a class on an ordinary descendant generates CSS that never matches.

```html
<html class="
  (animation-name:fade)::view-transition-new(hero) (animation-fill-mode:both)::view-transition-new(hero)
  (animation-name:fade)::view-transition-old(hero) (animation-direction:reverse)::view-transition-old(hero) (animation-fill-mode:both)::view-transition-old(hero)
  animation-slow::view-transition-group(hero)
">
```

<Class2CSS>
  {[
      'animation-slow::view-transition-group(hero)',
      '(animation-name:fade)::view-transition-old(hero) (animation-direction:reverse)::view-transition-old(hero) (animation-fill-mode:both)::view-transition-old(hero)',
      '(animation-name:fade)::view-transition-new(hero) (animation-fill-mode:both)::view-transition-new(hero)'
    ]}
</Class2CSS>

The group supplies one duration for its movement and both image animations. The outgoing `fade` runs in reverse; the incoming `fade` runs forward.

## Reduced motion
Scope custom transition timing with `@motion-safe`, which maps to `@media (prefers-reduced-motion: no-preference)`:

```html
<html class="(animation-duration:.42s)::view-transition-group(root)@motion-safe">
```

<Class2CSS>
  {['(animation-duration:.42s)::view-transition-group(root)@motion-safe']}
</Class2CSS>

This condition controls only your duration override; it does not disable the browser's default transition. The article example also skips `startViewTransition()` when reduced motion is requested.
