## Overview [sr-only] \{#overview\}
Master CSS classes select named styles or express CSS declarations directly in markup. Read each class from left to right: start with the style you want, then add optional [state selectors](/reference/rules/selectors) and optional [conditional queries](/reference/rules/conditions).

```html
<!-- @MARK fg-white --><!-- @MARK :hover --><!-- @MARK @md -->
<button type="button" class="fg-white:hover@md">Save</button>
```

Use a hyphenated name for named styles (`font-mono`, `p-md`), a fixed utility for a common native value (`block`, `items-center`), and parentheses for any other declaration (`(font-size:16px)`, `(padding:1rem)`). Direct declarations use full CSS property names; named token families may use shorter prefixes. Values never infer a subproperty or implicitly resolve theme tokens. Use `var(--name)` for explicit variable references.


## Native properties
Write a native declaration as `(property:value)` with the full property name. A common fixed value has a short utility instead: `block` generates `display: block`, and `(opacity:.5)` generates `opacity: .5`. The browser decides layout and paint behavior. Use [MDN’s CSS reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference) for native property semantics and [Layout System](/guide/layout-system) for composing a page.

```html
<div class="block (opacity:.5) (opacity:1):hover">Hover to reveal</div>
```

<Class2CSS>{['block', '(opacity:.5)', '(opacity:1):hover']}</Class2CSS>

Opacity changes paint, including descendants. It does not disable a control or remove it from keyboard navigation. Native CSS property coverage does not depend on whether a dedicated documentation page exists.

### Declaration heads \{#declaration-heads\}
A native declaration is one parenthesized head. Master CSS finds its closing parenthesis with CSS rules before it looks up any property, utility or selector name, then reads the optional selector, condition and `!` suffix after it:

```html
<!-- @MARK (display:block)[aria-expanded=true]:hover@sm -->
<button class="(display:block)[aria-expanded=true]:hover@sm">Menu</button>
```

<Class2CSS>{['(display:block)[aria-expanded=true]:hover@sm']}</Class2CSS>

- Strings, comments, escapes, nested parentheses and brackets, and unquoted `url()` tokens stay inside the value: `(content:')')::before`, `(grid-template-columns:[start]|1fr|[end])`, `(background-image:url(/a{b.svg))` and `(--payload:a:b@c_foo)` each end at their own closing parenthesis.
- A head contains exactly one declaration. A top-level `;`, a second head such as `(color:red)(display:block)`, a missing closing parenthesis or an unbalanced bracket makes the class invalid; it generates no CSS and does not fall back to another class form.
- Braces belong only in custom property values, such as `(--state:{open})`.
- A custom property may be empty: `(--slot:)` generates `--slot:`. Every other property needs a value, so `(width:)` is invalid.
- `|` writes a space inside the value. `_` inside the parentheses is ordinary value text, as in `(animation-name:slide_in)`; after the closing parenthesis it starts a descendant selector.
- Any syntactically valid property name generates its declaration, including properties that tooling does not list. Tooling uses its property data only for completion and diagnostics.
- A bare `property:value` is not a declaration. `flex:hover` applies the `flex` utility while hovered, and `display:block` generates nothing.

### Fixed utilities \{#fixed-utilities\}
The preset names 94 common fixed values. Each class emits exactly the one declaration in this table, with no implied `display` or reset of related properties:

| Property | Classes |
| --- | --- |
| `display` | `block`, `inline`, `inline-block`, `flow-root`, `flex`, `inline-flex`, `grid`, `inline-grid`, `contents`, `list-item`, `table`, `inline-table`, `table-caption`, `table-cell`, `table-column`, `table-column-group`, `table-header-group`, `table-footer-group`, `table-row`, `table-row-group` (value equals the name); `hidden` (`none`) |
| `position` | `static`, `relative`, `absolute`, `fixed`, `sticky` |
| `visibility` | `visible`, `invisible` (`hidden`) |
| `isolation` | `isolate` |
| `box-sizing` | `box-border` (`border-box`), `box-content` (`content-box`) |
| `font-style` | `italic`, `oblique` |
| `text-transform` | `uppercase`, `lowercase`, `capitalize` |
| `text-decoration-line` | `underline`, `overline`, `line-through` |
| `flex-direction` | `flex-row`, `flex-row-reverse`, `flex-col` (`column`), `flex-col-reverse` (`column-reverse`) |
| `flex-wrap` | `flex-wrap`, `flex-nowrap`, `flex-wrap-reverse` |
| `align-items` | `items-normal`, `items-start`, `items-end`, `items-flex-start`, `items-flex-end`, `items-center`, `items-baseline`, `items-stretch` |
| `align-content` | `content-normal`, `content-start`, `content-end`, `content-flex-start`, `content-flex-end`, `content-center`, `content-baseline`, `content-stretch`, `content-between`, `content-around`, `content-evenly` (`space-*`) |
| `align-self` | `self-auto`, `self-normal`, `self-start`, `self-end`, `self-flex-start`, `self-flex-end`, `self-center`, `self-baseline`, `self-stretch` |
| `justify-content` | `justify-normal`, `justify-start`, `justify-end`, `justify-flex-start`, `justify-flex-end`, `justify-center`, `justify-between`, `justify-around`, `justify-evenly` (`space-*`), `justify-stretch` |
| `object-fit` | `object-cover`, `object-contain`, `object-fill`, `object-none`, `object-scale-down` |
| `object-position` | `object-center`, `object-top`, `object-bottom`, `object-left`, `object-right` |

`start` and `end` keep their native meaning, distinct from `flex-start` and `flex-end`. `flex-col` only sets the direction; combine it with `flex` on the container. `underline` sets `text-decoration-line` alone; use `(text-decoration:underline)` when you need the shorthand to reset color, style and thickness as well. Fixed utilities are ordinary static utilities: they accept selectors, conditions and `!`, and generate CSS only when used.


### Independent properties \{#independent-properties\}

Each class expresses one styling decision. Use named color tokens and full CSS properties for explicit values:

```html
<div class="(border-width:1px) b-line-control (border-style:solid)">Content</div>
```

A single value may express one decision, as with `p-sm`, `gap-md`, `(overflow:hidden)`, and `(animation:none)@media(print)`. Give different edges or axes their own declarations. Native stylesheets and inline styles retain ordinary CSS syntax.

### Motion properties \{#motion-properties\}

Use `(animation-name:*)`, `(animation-duration:*)`, `(transition-property:*)` and `(transition-duration:*)` to express independent settings. Named `animate-*` tokens contain complete animation shorthands. To override one field, combine them with a full-property declaration such as `(animation-duration:var(--duration-fast))`. See [animation tokens](/reference/tokens/animate) for ordering and defaults.

### Combining declarations \{#combining-declarations\}
Write each declaration as a separate class, repeating any shared selector or query suffix. To register a reusable class recipe for markup, define an [`@utility`](/reference/directives/definitions#utilities). For reuse within CSS, define an [`@mixin` and expand it with `@apply`](/reference/directives/definitions#reusing-a-matched-value); a mixin does not register a markup class.

```html
<ul class="block>li:hover@md (font-size:14px)>li:hover@md (text-align:center)>li:hover@md">…</ul>
```

Within the same layer and conditions, fixed utilities and other recipes sort before native declarations, so a `(property:value)` class can override one setting of a utility independently of markup order. Fixed utilities among themselves sort by class name; give conflicting states mutually exclusive classes instead of relying on that order.

## Combine with states and queries \{#combine-with-states-and-queries\}
After the declaration itself is clear, you can attach selectors and conditions without changing the declaration syntax.

```html
<!-- @MARK bg-blue-60 --><!-- @MARK bg-blue-70:hover@md --><!-- @MARK (transition-property:background-color) (transition-duration:0.2s) -->
<button type="button" class="bg-blue-60 (transition-property:background-color) (transition-duration:0.2s) bg-blue-70:hover@md">
  Save
</button>
```

This means:

- `bg-blue-60` applies by default.
- `bg-blue-70:hover@md` applies only when the button is hovered and the viewport matches `@md`.
- `(transition-property:background-color) (transition-duration:0.2s)` adds a `background-color` transition.

Continue with [selectors](/reference/rules/selectors) for element states and relationships, or [conditions](/reference/rules/conditions) for viewport, media, container, and layer suffixes. The [syntax tutorial](/guide/syntax-tutorial) introduces the authoring workflow.
