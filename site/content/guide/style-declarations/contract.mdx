<a id="overview"></a>

A class starts with a registered utility or a native declaration, followed by optional selectors, conditions and importance. This page defines those declaration forms, value parsing and rejection rules. For a worked introduction, use the [Syntax tutorial](/guide/syntax-tutorial); for native property meanings, use the [CSS reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference).

The named forms below assume the default preset is loaded through `@import '@master/css'`. Project definitions can add or replace utilities. Native declarations do not require a registered utility.

## Accepted forms \{#basic-syntax\}

<a id="utilities"></a>

| Form | Example | Meaning |
| --- | --- | --- |
| Static utility | `flex` | A registered name; here, `display: flex` |
| Token utility | `p-md` | A registered prefix and token key; here, `padding: var(--spacing-md)` |
| Functional utility | `p(12)` | A registered function with arguments; here, `padding: calc(12 * 1px)` |
| Native declaration | `(padding:1rem)` | One full CSS property and value |

These are syntax shapes, not interchangeable spellings. Static, token and functional utilities can each contain several declarations: `truncate`, `text-sm` and `grid-cols(2)` are recipes. A native head contains exactly one declaration, which may use a CSS shorthand.

<Class2CSS classes={['flex', 'p-md', 'p(12)', '(padding:1rem)']} />

<a id="combine-with-states-and-queries"></a>

Every form accepts suffixes. In `p(12):hover@sm!`, the head is `p(12)`, `:hover` is the selector, `@sm` is the condition and `!` marks importance. A suffix affects its own class only. [Selectors](/reference/rules/selectors) and [Conditions](/reference/rules/conditions) own their complete contracts.

## Native declarations \{#declaration-heads\}

<a id="native-properties"></a>
<a id="native-declaration-fallback"></a>

Write `(property:value)` using the full property name. Master CSS reads the balanced head before parsing suffixes. A colon after a bare name starts a selector: `flex:hover` selects the registered `flex` utility; `display:block` is not an alternative to `(display:block)`.

### The closing boundary \{#the-closing-boundary\}

Strings, comments, escapes, nested parentheses and brackets, and unquoted `url()` tokens follow CSS component-value boundaries. A `)` inside a quoted string does not close the head:

```html
<span class="(content:')')::before"></span>
```

<ReferenceIllustration id="native-value-boundary" />

Other CSS constructs keep their own boundaries inside the head:

| Class | Value boundary |
| --- | --- |
| `(width:calc(1px+(2px*3)))` | Nested parentheses belong to the calculation |
| `(grid-template-columns:[start]_1fr_[end])` | Brackets enclose grid line names |
| `(background-image:url(/a{b.svg))` | The brace belongs to the unquoted URL token |

<Class2CSS classes={["(content:')')::before", '(width:calc(1px+(2px*3)))', '(grid-template-columns:[start]_1fr_[end])', '(background-image:url(/a{b.svg))']} />

CSS escaping still applies inside a value. For an unquoted URL containing parentheses, use a quoted URL or CSS escapes so the token remains valid.

### Invalid heads \{#invalid-heads\}

A malformed head generates no rule; it is not retried as a utility or a different class form.

| Rejected class | Reason |
| --- | --- |
| `(display:block` | Missing closing parenthesis |
| `(color:red)(display:block)` | Two heads in one class |
| `(color:red;display:block)` | More than one declaration |
| `(display:block;)` | A top-level semicolon, even at the end |
| `(width:calc(1px])` | Mismatched delimiters |
| `(width:)` | Empty value for an ordinary property |
| `(color:{red})` | A brace block as an ordinary property value |
| `(width:calc(((…1px…))))` nested 65 levels | Brackets nested more than 64 levels deep |

A custom property may have an empty value or a balanced brace block: `(--slot:)` and `(--state:{open})` are accepted. `(--slot:!important)` is an empty important custom property, while `(width:!important)` is invalid.

### Emission and browser validity \{#vendor-prefixes\}

A syntactically valid property name can emit a declaration even when tooling does not list it. Native values are not limited to the preset, but they must still be valid for the property in the target browser. For example, `(font-size:48)` emits `font-size: 48`; it does not acquire `px`, and that nonzero unitless length is invalid CSS. Use `(font-size:48px)` for that length. A native property such as `(field-sizing:content)` needs no utility registration.

<Class2CSS classes={['(font-size:48px)', '(field-sizing:content)']} />

Master CSS emits selected compatibility declarations, such as `-webkit-backdrop-filter` beside `backdrop-filter`. It does not add vendor-specific selectors or polyfill browser features. Inspect the generated CSS and use [Compatibility](/guide/compatibility) for browser requirements and fallback design.

<Class2CSS classes={['(backdrop-filter:blur(16px))', '(background-color:#000)::-webkit-scrollbar']} />

## Value encoding \{#values\}

### Spaces, strings and underscores \{#value-encoding\}

HTML whitespace separates classes, even when the value contains CSS quotes. Within a class value, an unquoted `_` encodes a space, as it does between selectors. Inside a quoted string or a `url()`, the underscore remains literal. Keep CSS punctuation such as commas and slashes in place.

```html
<div class="(color:rgb(30_60_90/80%)) (content:'a_b')::before"></div>
```

<Class2CSS classes={['(color:rgb(30_60_90/80%))', "(content:'a_b')::before", '(animation-name:slide\\_in)', '(color:red)_a']} />

The color value becomes `rgb(30 60 90 / 80%)`; the content string stays `'a_b'`. For an actual space in a CSS string, use a CSS escape such as `\000020`: `(content:'New\000020collection')::before` produces “New collection”. The six-digit escape avoids a terminating space in the HTML class.

Escape an underscore that belongs to a name: `(animation-name:slide\_in)` emits `slide\_in`, the CSS escape of `slide_in`. Two adjacent underscores stay literal, as in `card__title`, and the custom property that opens a `var()` keeps its name, as in `var(--brand_primary)`. After the head closes, `_` starts a descendant selector: `(color:red)_a` targets descendant links. Registered utility names cannot contain `_`; a token key containing it can still be referenced through `var(--name)`.

Master CSS 2.0 wrote these spaces as `|`. That spelling still works but is deprecated; the [`prefer-canonical-classes`](/guide/code-linting) rule rewrites it to `_`.

### Functions and explicit variables \{#functions\}

CSS functions remain values of the native property. Master CSS normalizes arithmetic spacing in `calc(100%-2rem)`, through at most 64 levels of nested parentheses and chained subtractions such as `1px-2px-3px`, and leaves anything deeper as written; the browser evaluates the calculation. It does not infer a token from a bare word or evaluate a CSS function as a utility call.

<Class2CSS classes={['(width:calc(100%-2rem))', '(width:calc(100%-var(--spacing-md)))', '(color:var(--color-red))']} />

<a id="rgb-hsl-oklch-"></a>
<a id="hexadecimal-color"></a>

Native color values retain their meaning: `(color:red)`, `(color:#175fe9)` and `(color:rgb(23,95,233))` all supply CSS values. `fg-red` instead selects a theme token. A `var()` reference is explicit; `(font-family:mono)` names the CSS family `mono`, not `--font-mono`. See [Variables and modes](/reference/rules/modes) for token resolution, modes and derived values.

### Numbers and units \{#units\}

<a id="decimal"></a>
<a id="unit-conversion"></a>
<a id="unit-sensing"></a>
<a id="multiplier-units"></a>

Native declarations preserve units. They do not convert `rem` to pixels or infer a unit from the property. Leading zeros on decimals are optional: `(opacity:.5)` and `(opacity:0.5)` supply the same numeric value.

| Native value | Interpretation |
| --- | --- |
| `(margin:1rem)` | Length relative to the root font size |
| `(width:50%)` | Percentage resolved in the property's context |
| `(rotate:30deg)` | Explicit angle |
| `(animation-duration:200ms)` | Explicit time; `.2s` expresses the same duration |
| `(opacity:.5)` | Unitless number |
| `(background-image:image-set(url(a.png)_1x,url(b.png)_2x))` | Native image resolution in dots per CSS pixel |

Whether a property accepts a number, length, percentage or other type is a [CSS values and units](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Values_and_units) rule. `p(12)` is different: the preset function explicitly multiplies its argument by `1px`.

### Negative values \{#negative\}

Native negatives stay inside the value: `(margin-top:-2rem)`. Direct numeric arguments use `mt(-8)`. Negative token classes put `-` before the complete class: `-mt-sm`. The negative-token form requires a numeric token and a supporting utility; `-p-sm` is rejected because padding does not support it.

<Class2CSS classes={['(margin-top:-2rem)', 'mt(-8)', '-mt-sm']} />

Argument validation does not redefine the CSS property’s value constraints.

## Registered utilities \{#registered-utilities\}

### Token names \{#variable-alias\}

<a id="property-abbreviations"></a>

Token prefixes are registered by utility definitions, not inferred from property abbreviations. `p-md` reads `--spacing-md`; `fg-red` and `bg-red` both read `--color-red` but set different properties. There is no automatic full-property equivalent such as `padding-md`, and no implicit numeric scale such as `p-4`: that key must exist in the selected namespace.

A static name wins over a same-spelled token class. For example, `w-full` remains `width: 100%` even if the project defines `--container-full`; `pill` remains a fully rounded radius even if `--radius-pill` exists. A static utility and a function with the same name register independently.

Use the [token family index](/reference/tokens/families) for complete prefix-to-namespace mappings, and [utility definitions](/reference/directives/definitions#utilities) for registration and replacement rules. [Theme tokens](/guide/theme) owns the workflow for defining and scoping project values.

<ReferenceIllustration id="fixed-name-reservation" />

### Direct numeric values \{#direct-values\}

Preset functions such as `m(4)`, `b(1)` and `grow(1)` take one static number. Length functions emit a multiplication by `1px`; `grow()`, `shrink()` and `order()` pass the number through, with `order()` requiring an integer. Zero, decimals and negative arguments follow each parameter's declared type.

Units and dynamic expressions are not numeric arguments: `m(1px)` and `b(var(--x))` generate no rule. Use `(margin:1rem)` or `(border-width:var(--x))` for those values. [Direct values](/reference/direct-values) owns the complete function list, parameter types and generated declarations.

<a id="motion-properties"></a>

Recipes can coordinate properties or companions: `text-sm` includes size, line height and tracking, while `animate-fade` supplies an animation shorthand. Their lookup and override rules belong to [text tokens](/reference/tokens/text#primary-and-companions) and [motion tokens](/reference/tokens/motion#duration-overrides).

## Custom properties \{#variable-properties\}

A `(--name:value)` head declares a CSS custom property on the matched element. It can carry the same selectors and conditions as any other declaration. It does not register a utility or a theme token.

```html
<div class="(--progress:40%) (--progress:60%):hover (width:var(--progress))">
  Progress
</div>
```

<Class2CSS classes={['(--progress:40%)', '(--progress:60%):hover', '(width:var(--progress))']} />

`var(--progress)` uses normal CSS resolution and inheritance. An unresolved variable or an incompatible substituted value can make the consuming declaration invalid; use a [CSS variable fallback](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/var) where appropriate. The [Syntax tutorial](/guide/syntax-tutorial#complete-card) covers keeping a fixed class while supplying a dynamic value.

## Composition and importance \{#combining-declarations\}

<a id="group"></a>
<a id="independent-properties"></a>

Separate classes express independent decisions, such as `b(1) b-solid b-line-control`. Native shorthands remain supported: this authoring preference does not change CSS grammar. Repeat selectors and conditions on each class that needs them.

```html
<ul class="block>li:hover@md (font-size:14px)>li:hover@md text-center>li:hover@md">…</ul>
```

Within the same layer, conditions and selector, recipes sort before single-declaration utilities, then native declarations. Single-declaration utilities sort by property family and coverage before value source; a token precedes a fixed or direct value for the same property. HTML class order does not determine the result:

<Class2CSS classes={['p-md', 'p(12)', '(padding:1rem)', 'm-md', 'mt(0)', 'mx-auto']} />

Here the native padding follows both utilities, while `mt(0)` and `mx-auto` override the relevant parts of `m-md`. [Cascade layers](/reference/rules/layers) owns the complete ordering contract. Use [Reusing styles](/guide/reusing-styles) to choose a component class, `@utility` recipe or CSS mixin.

### Importance \{#important\}

A final `!` marks the class's declarations important. A trailing native `!important` inside a parenthesized value has the same effect; writing both emits it once. The text `'!important'` inside a string remains content.

<Class2CSS classes={['text-center!', '(color:red!important)', '(color:red!important)!', "(content:'!important')::before"]} />

## Fixed utility lookup \{#fixed-utilities\}

The preset provides 292 fixed, single-declaration utilities. Each sets only its listed property: `flex-col` does not enable flex layout, `b-none` does not reset border width, and `pill` does not set a size. The multi-declaration `truncate` recipe is listed separately in [Truncation](/reference/truncation).

<FixedUtilities />

`start` and `end` retain their native meaning, distinct from `flex-start` and `flex-end`. For logical axes, `x` means inline and `y` means block; `t`, `r`, `b` and `l` are physical sides. Fixed utilities accept selectors, conditions and `!`, and emit CSS when used.
