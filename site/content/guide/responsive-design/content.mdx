## Overview [sr-only]
Append a condition to any class with `@`. Viewport conditions such as `@md` adapt a page; container queries adapt a component to the space it receives.

(resize) Resize the gallery with the slider or its arrow keys. Its column count follows the preview viewport.

<DemoPageViewport src="/examples/responsive-gallery" title="Responsive asset gallery" height={420} />

```html
<!-- @MARK @2xs @sm @md -->
<div class="grid-cols(2) gap-md grid-cols(3)@2xs grid-cols(4)@sm grid-cols(5)@md">
  <img class="grid-col-span(2) grid-row-span(2) w-full h-full min-h(0) object-cover"
    src="mountain1.jpg" alt="Snowy peaks above the clouds" />
  <img class="w-full (aspect-ratio:2/1) object-cover" src="mountain2.jpg" alt="A pyramid-shaped summit" />
  <img class="w-full (aspect-ratio:2/1) object-cover" src="mountain3.jpg" alt="Snowy ridges beneath stars" />
</div>
```

<Class2CSS>{['grid-cols(2)', 'grid-cols(3)@2xs', 'grid-cols(4)@sm', 'grid-cols(5)@md']}</Class2CSS>

The unconditioned `grid-cols(2)` is the base layout; each wider condition replaces the column count.

## Choose a viewport or a container \{#choose-a-boundary\}

Choose the condition by what owns the change:

- The page, such as navigation, the app shell or page columns, uses a viewport condition: `grid-cols(12)@md`.
- A reusable component uses a container query: `grid-cols(2)@container(--md)`.

A card with `grid-cols(2)@md` splits at the page's `md` width even inside a narrow sidebar. Give it a container query so it follows its own space.

## Viewport breakpoints \{#based-on-viewport-breakpoints\}

`@md` reads the preset's `@custom-media --md` definition. Breakpoints are custom media, not theme variables: the preset has no `--breakpoint-*` custom properties.

<FoundationBreakpoint />

```html
<!-- @MARK font-2xl --><!-- @MARK font-3xl@md -->
<h1 class="font-2xl font-3xl@md">Build for the current viewport</h1>
```

<Class2CSS>{['font-2xl', 'font-3xl@md']}</Class2CSS>

To change a threshold, redeclare its custom media in your project CSS entry. This replaces the preset `md` for every class that uses it:

```css name=index.css
@custom-media --md (width >= 48rem);
```

Below a breakpoint, use its `max-` complement: `hidden@max-md` applies under `@md` and never overlaps it. Redeclaring `--md` moves both.

For a one-off range, write the complete native query, such as `hidden@media(52.125rem<=width<=64rem)`. See [Breakpoints](/reference/tokens/breakpoints) for the preset names and [conditions](/reference/rules/conditions#mediafeature) for the query syntax.

## Container queries \{#based-on-container-sizes\}

`container-inline` makes an ancestor an inline-size query container. Its descendants then take a container condition such as `@container(--md)`, the preset's 28rem width; an element cannot query itself.

<FoundationContainerGrid />

```html
<!-- @MARK container-inline --><!-- @MARK grid-cols(2)@container(--md) -->
<section class="container-inline">
  <article class="grid-cols(1) gap-lg grid-cols(2)@container(--md)">
    <img src="mountain.jpg" alt="" />
    <div>…</div>
  </article>
</section>
```

<Class2CSS>{['container-inline', 'grid-cols(2)@container(--md)']}</Class2CSS>

Container widths are their own scale, from `--3xs` (16rem) to `--7xl` (80rem), each with a `--max-` complement such as `@container(--max-md)`. They do not follow the viewport breakpoints: `@md` stays a 64rem viewport query. Define project widths with `@custom-container`, or write a one-off query such as `@container(width>=40rem)`. Changing `--container-md` changes `max-w-md`, not `@container(--md)`. See [conditions](/reference/rules/conditions#named-container-conditions) for the scale and the complete query contract.

### Named containers \{#creating-named-containers\}

A query measures the nearest container. To measure an outer one, name it with `(container-name:<name>)` and put the name before the condition: `@container(card|--md)`.

## Condition only the style that changes \{#syntax-first\}

A condition can sit on any class, so a style that belongs to one range needs no reset outside it. Write the base state without a condition, then attach a condition only where a style differs:

```html
<!-- @MARK bg-surface-raised@max-md -->
<aside class="p-md bg-surface-raised@max-md">…</aside>
```

<Class2CSS>{['bg-surface-raised@max-md']}</Class2CSS>

Minimum, maximum and bounded conditions all use the same syntax, and a page breakpoint and a component query can apply to the same element.
