## Overview [sr-only]
A page layout and a reusable card can need different responsive rules. Let the page follow the viewport; let the card follow the space its parent gives it. In Master CSS, append a condition to the class whose style should change.

Complete [Installation](/guide/installation) first. These examples use the default preset and an app stylesheet that loads `@import '@master/css';`. Each preview includes the controls needed to observe its boundary; **Generated CSS** shows what the accompanying classes produce.

## Choose what should control the change \{#choose-a-boundary\}

Use a viewport condition for page-wide decisions, such as the number of columns in a workspace. Use a container query when the same component can appear in a main column, a sidebar or another constrained region.

| What should decide? | Write | What is measured? |
| --- | --- | --- |
| The page viewport | `grid-cols(3)@md` | The viewport's width |
| The component's available space | `grid-cols(2)@container(--md)` | The nearest eligible ancestor container's width |

<ResponsiveIllustration />

Both cards in the figure share one viewport, but their parents have different widths. A viewport condition would match for both at once. A container query lets the narrow instance stay stacked while the wide instance splits into columns.

## Adapt a page to its viewport \{#based-on-viewport-breakpoints\}

Start with one column, then add columns where the content has room. This workflow uses the preset's `2xs` threshold at 37.5rem and `md` at 64rem. At the standard 16px initial font size, those boundaries are 600px and 1024px.

`grid-cols(1)` is the base layout. The conditions replace only the column count; content order, spacing and surface styles remain the same. Three columns are useful only while their content fits—try longer labels before adopting a threshold in your app.

`@md` reads the preset's `@custom-media --md` definition. It does not read a `--breakpoint-md` theme variable. To change the threshold for every class using `@md`, redeclare the custom media in the app CSS entry:

```css name=app.css
@import '@master/css';

@custom-media --md (width >= 48rem);
```

Use a project-specific name when the new boundary belongs to one layout rather than the whole preset:

```css name=app.css
@custom-media --workspace-wide (width >= 72rem);
```

```html
<section class="grid-cols(1) grid-cols(3)@workspace-wide">…</section>
```

The [breakpoint reference](/reference/rules/named-conditions#viewport-widths) lists the preset names and values. Choose a threshold from the content's needs; a name such as `md` does not identify a particular device.

## Adapt a component to its container \{#based-on-container-sizes\}

Put `container-inline` on an ancestor, then give its descendant a container condition. Here the summary and its status stack in a narrow region and become two columns when that ancestor reaches the preset's 28rem `--md` container threshold.

<FoundationContainerGrid />

```html
<section class="container-inline">
  <article class="grid-cols(1) gap-lg p-md b-solid b(1) b-line-divider r-lg bg-surface-raised grid-cols(2)@container(--md)">
    <div class="min-w(0)">
      <h3 class="m(0) text-md font-regular fg-text-strong">Release notes</h3>
      <p class="mb(0) mt-xs text-sm fg-text-muted">Review the changes before publishing.</p>
    </div>
    <dl class="grid gap-xs m(0) text-sm">
      <div>
        <dt class="fg-text-muted">Status</dt>
        <dd class="m(0) fg-text-strong">Draft ready</dd>
      </div>
      <div>
        <dt class="fg-text-muted">Next step</dt>
        <dd class="m(0) fg-text-strong">Editorial review</dd>
      </div>
    </dl>
  </article>
</section>
```

<Class2CSS classes={['container-inline', 'grid-cols(1)', 'grid-cols(2)@container(--md)']} />

Move the **Container** slider while keeping your browser window unchanged. It resizes the ancestor, not the viewport. At a 16px font size, compare 447px and 448px: the second column should appear at 448px. The control stays within the article's available width; widen the browser if the article itself is narrower than that threshold.

The ancestor establishes the query boundary; the descendant changes layout. An element cannot use its own size as the ancestor for its container query. Keep the card's height content-driven so wrapping text can grow naturally.

### Keep the two scales separate

`@md` and `@container(--md)` use different definitions:

| Class or value | Meaning in the preset |
| --- | --- |
| `@md` | A 64rem viewport threshold from custom media |
| `@container(--md)` | A 28rem container threshold from a custom container condition |
| `max-w-md` | A maximum width using the `--container-md` sizing token |

Changing `--container-md` changes the width cap, not either query threshold. Define a reusable container condition with `@custom-container`, or write a local query such as `grid-cols(2)@container(width>=30rem)`. See [named container conditions](/reference/rules/conditions#named-container-conditions) for their definition syntax and complete scale.

### Name an outer container \{#creating-named-containers\}

An unnamed size query measures the nearest eligible ancestor. If a nested layout introduces another container, that inner boundary takes over. Name the outer container with `(container-name:outer)` and use `@container(outer|--md)` when the outer width is the one you intend to measure.

The two status readouts sit inside the same narrow inner container. Widening the outer boundary changes only the named query's result. Naming a container chooses an ancestor; it does not make the element query itself.

## Condition only the style that changes \{#syntax-first\}

Keep shared styles unconditional. Add a condition only for the property and range that need a different value. For example, an aside can have a raised surface below `md` without carrying that background into larger layouts:

```html
<aside class="p-md bg-surface-raised@max-md">…</aside>
```

<Class2CSS classes={['bg-surface-raised@max-md']} />

`@max-md` is the complement of the preset `@md`; they do not overlap. Redeclaring `--md` moves both. A local bounded condition, such as `hidden@media(52.125rem<=width<=64rem)`, can target a specific interval without changing the project's named thresholds. The [conditions reference](/reference/rules/conditions#mediafeature) covers that query syntax.

## Verify the boundary, not just the screenshot

Test immediately below and at each threshold. In the page example, check the actual iframe viewport at 599/600px and 1023/1024px. In the component example, hold the page viewport steady and check its ancestor at 447/448px with a 16px font size.

Inspect the descendant's computed `grid-template-columns` when the result is unexpected. Check that the condition matches, that a container query has the intended eligible ancestor, and that another rule has not won in the [cascade](/guide/cascade-layers).

Finally, try long text, enlarged text and narrow layouts. Keep the reading order useful at every width, allow content to wrap, and avoid fixed card heights. [Layout](/guide/layout-system) develops the grid and spacing decisions independently of these query boundaries.
