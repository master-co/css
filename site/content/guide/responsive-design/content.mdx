## Overview [sr-only]
Choose the boundary that owns the change: viewport queries adapt a page; container queries adapt a component to the space it receives. Start with a layout that fits, then add a condition where the content needs it.

(resize) Resize the gallery with the slider or its arrow keys. Its column count follows the preview viewport.

<DemoPageViewport src="/examples/responsive-gallery" title="Responsive asset gallery" height={420} />
```html
<!-- @MARK @xs @sm @md -->
<div class="grid-cols(2) grid-cols(3)@2xs grid-cols(4)@sm grid-cols(5)@md …">…</div>
```
Viewport queries use [named custom media](/guide/breakpoints). [Container queries](/guide/containers) measure an eligible ancestor at an explicit threshold.

## Based on viewport breakpoints
Use viewport breakpoints when navigation, page columns, outer spacing or another page-level decision changes. Append `@<name>` to the declaration or token class.

### Using responsive breakpoints
The syntax is `@<breakpoint>`, where `<breakpoint>` can be any [custom media name](/guide/breakpoints), such as `xs`, `sm`, `md`, `lg`, etc.
```html
<!-- @MARK @xs @sm @md -->
<div class="grid-cols(2) grid-cols(3)@2xs grid-cols(4)@sm grid-cols(5)@md …">…</div>
```

### Querying viewport ranges
Use a complete [native media query](/reference/rules/conditions#mediafeature) to create more complex viewport range queries.
```html
<!-- @MARK @media((52.125rem<=width<=64rem)) -->
<div class="display:none@media((52.125rem<=width<=64rem))">…</div>
```
<Class2CSS>
  {['display:none@media((52.125rem<=width<=64rem))']}
</Class2CSS>

### Creating responsive wrappers
Set fixed maximum widths from the container scale when a wrapper should step through product layout widths.
```html
<!-- @MARK max-w-4xl@sm max-w-5xl@md max-w-7xl@lg -->
<div class="max-w-4xl@sm max-w-5xl@md max-w-7xl@lg …">…</div>
```

## Based on container sizes
Use [container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries) for reusable cards, media objects and controls. The component can stack inside a sidebar while staying horizontal in a wider region of the same page.

### Using container queries
The `container-type:inline-size` declaration establishes an inline-size query container, making it a query container for `@container((width>=18rem))` and other native container queries.

(resize) Try making the container smaller.

```html
<div class="container-type:inline-size …">
  <!-- @MARK @container((width<=18rem)) -->
  <div class="display:flex flex-direction:column@container((width<=18rem))">…</div>
</div>
```
<Class2CSS>
  {['container-type:inline-size', 'flex-direction:column@container((width<=18rem))']}
</Class2CSS>
Choose component thresholds from the space the content needs. Changing a [container size token](/reference/tokens/container) does not update a literal query. Reuse a condition with a CSS mixin wrapper when needed; see [Container queries](/guide/containers).

### Querying container ranges
Use a complete [native container query](/reference/rules/conditions#containersize) for a bounded container range.
```html
<!-- @MARK @container((24rem<=width<=28rem)) -->
<div class="display:none@container((24rem<=width<=28rem))">…</div>
```
<Class2CSS>
  {['display:none@container((24rem<=width<=28rem))']}
</Class2CSS>

### Creating named containers
Set `container-name` and `container-type` on the ancestor. Include its name and a size condition in the descendant’s query.
```html
<!-- @MARK container-name:card container-type:inline-size -->
<div class="container-name:card container-type:inline-size">
  <!-- @MARK @container(card|(width>=16rem)) -->
  <div class="display:none@container(card|(width>=16rem))"></div>
</div>
```
<Class2CSS>
  {['container-name:card container-type:inline-size', 'display:none@container(card|(width>=16rem))']}
</Class2CSS>

## Strategies
Start with the default state that best describes the interface. Add minimum-width conditions to grow it, maximum-width conditions to simplify it, or a bounded condition for a style that only belongs in one range. All three use the same syntax.

### Mobile-first
Use unqualified classes for the compact layout, then add changes at larger widths:

```html
<p class="font-2xl font-3xl@md">A heading with room to grow</p>
```

<Class2CSS>{['font-2xl', 'font-3xl@md']}</Class2CSS>

The heading uses `font-2xl` by default and `font-3xl` when `@md` matches. The actual threshold comes from the project's custom media definition.

### Desktop-first
Use the wider treatment as the default, then apply a change below an explicit threshold:

```html
<p class="font-3xl font-2xl@media((width<64rem))">A compact heading below 64rem</p>
```

<Class2CSS>{['font-3xl', 'font-2xl@media((width<64rem))']}</Class2CSS>

Use this when the wide layout is the natural starting point for the product. Keep the small-screen state complete enough to read and operate.

### Syntax-first
A style that only belongs in one range does not need a reset outside it. Attach the condition to that style directly:

```html
<!-- Only below 64rem -->
<div class="bg-surface-raised@media((width<64rem))">...</div>

<!-- Only when the named md query matches -->
<div class="bg-surface-raised@md">...</div>
```

<Class2CSS>{['bg-surface-raised@media((width<64rem))', 'bg-surface-raised@md']}</Class2CSS>

Test just below and above each threshold, including with longer text. A page breakpoint and a component container query can work together; choose each one for the region it controls.
