## 概覽 [sr-only] \{#overview\}
頁面版面與可重用卡片可能需要不同的響應式規則。頁面跟隨檢視區，卡片則跟隨父元素提供的空間。在 Master CSS 中，將條件附加到需要改變樣式的 class 後方。

請先完成[安裝](/guide/installation)。這些範例使用預設集，以及載入 `@import '@master/css';` 的應用程式樣式表。每個預覽都提供觀察邊界所需的控制項；**產生的 CSS** 顯示隨附 class 的輸出。

## 選擇變化的依據 \{#choose-a-boundary\}

工作區欄數這類頁面整體決策，使用檢視區條件。同一元件可能出現在主欄、側欄或其他受限區域時，則使用容器查詢。

| 由什麼決定？ | 寫法 | 量測對象 |
| --- | --- | --- |
| 頁面檢視區 | `grid-cols(3)@md` | 檢視區寬度 |
| 元件可用空間 | `grid-cols(2)@container(--md)` | 最近且符合資格的祖先容器寬度 |

<ResponsiveIllustration />

圖中兩張卡片共用同一個檢視區，但父元素寬度不同。檢視區條件會同時套用到兩者；容器查詢則讓窄版維持堆疊，寬版分為多欄。

## 讓頁面隨檢視區調整 \{#based-on-viewport-breakpoints\}

從單欄開始，在內容有足夠空間時再增加欄數。此工作流程使用預設集的 `2xs` 門檻 37.5rem 與 `md` 門檻 64rem。以標準初始字級 16px 計算，兩者分別為 600px 與 1024px。

`grid-cols(1)` 是基礎版面。條件只替換欄數；內容順序、間距與表面樣式維持不變。三欄只有在內容放得下時才有幫助——採用門檻前，先在應用程式中試用較長標籤。

`@md` 讀取預設集的 `@custom-media --md` 定義，不會讀取 `--breakpoint-md` 主題變數。若要調整所有使用 `@md` 的 class 門檻，在應用程式 CSS 進入點重新宣告自訂媒體查詢：

```css name=app.css
@import '@master/css';

@custom-media --md (width >= 48rem);
```

若新邊界只屬於某個版面，而非整個預設集，請使用專案專屬名稱：

```css name=app.css
@custom-media --workspace-wide (width >= 72rem);
```

```html
<section class="grid-cols(1) grid-cols(3)@workspace-wide">…</section>
```

[斷點參考](/reference/rules/named-conditions#viewport-widths)列出預設集名稱與值。依內容需求選擇門檻；`md` 這類名稱不代表特定裝置。

## 讓元件隨容器調整 \{#based-on-container-sizes\}

在祖先元素加上 `container-inline`，再為後代元素設定容器條件。此處摘要與狀態在窄區域中上下堆疊；祖先達到預設集 `--md` 容器門檻 28rem 時，改為兩欄。

<FoundationContainerGrid />

```html
<section class="container-inline">
  <article class="grid-cols(1) gap-lg p-md b-solid b(1) b-line-divider r-lg bg-surface-raised grid-cols(2)@container(--md)">
    <div class="min-w(0)">
      <h3 class="m(0) text-md font-regular fg-text-strong">Release notes</h3>
      <p class="mb(0) mt-xs text-sm fg-text-muted">Review the changes before publishing.</p>
    </div>
    <dl class="grid gap-xs m(0) text-sm">
      <div>
        <dt class="fg-text-muted">Status</dt>
        <dd class="m(0) fg-text-strong">Draft ready</dd>
      </div>
      <div>
        <dt class="fg-text-muted">Next step</dt>
        <dd class="m(0) fg-text-strong">Editorial review</dd>
      </div>
    </dl>
  </article>
</section>
```

<Class2CSS classes={['container-inline', 'grid-cols(1)', 'grid-cols(2)@container(--md)']} />

保持瀏覽器視窗不變，移動 **容器** 滑桿。它調整的是祖先元素，而不是檢視區。以 16px 字級比較 447px 與 448px：第二欄應在 448px 出現。控制項受限於文章可用寬度；若文章本身比門檻窄，請加寬瀏覽器。

祖先建立查詢邊界，後代改變版面。元素不能把自己的尺寸當作容器查詢的祖先。讓卡片高度由內容決定，文字換行時才能自然成長。

### 區分兩套尺度 \{#keep-the-two-scales-separate\}

`@md` 與 `@container(--md)` 使用不同定義：

<DocumentComparison>

| Class 或值 | 在預設集中的意義 |
| --- | --- |
| `@md` | 自訂媒體查詢的 64rem 檢視區門檻 |
| `@container(--md)` | 自訂容器條件的 28rem 容器門檻 |
| `max-w-md` | 使用 `--container-md` 尺寸 token 的最大寬度 |

</DocumentComparison>

調整 `--container-md` 會改變寬度上限，不會改變任一查詢門檻。使用 `@custom-container` 定義可重用容器條件，或直接撰寫 `grid-cols(2)@container(width>=30rem)` 這類區域查詢。定義語法與完整尺度請見[具名容器條件](/reference/rules/conditions#named-container-conditions)。

### 為外層容器命名 \{#creating-named-containers\}

未具名的尺寸查詢會量測最近且符合資格的祖先。若巢狀版面再建立另一個容器，就會改以內層邊界為準。當你要量測的是外層寬度，請以 `(container-name:outer)` 為外層命名，再使用 `@container(outer_--md)`。

兩個狀態讀值位於同一個窄內層容器中。加寬外層邊界只會改變具名查詢的結果。容器命名是選擇祖先，不是讓元素查詢自身。

## 只對改變的樣式加條件 \{#syntax-first\}

共用樣式維持無條件。只有需要不同值的屬性與範圍才加上條件。例如，側欄在低於 `md` 時使用凸起表面，而較大版面不保留這個背景：

```html
<aside class="p-md bg-surface-raised@max-md">…</aside>
```

<Class2CSS classes={['bg-surface-raised@max-md']} />

`@max-md` 是預設集 `@md` 的補集，兩者不重疊。重新宣告 `--md` 會一起移動兩個邊界。`hidden@media(52.125rem<=width<=64rem)` 這類區域範圍條件，可鎖定特定區間而不改變專案的具名門檻。[條件參考](/reference/rules/conditions#mediafeature)說明此查詢語法。

## 驗證邊界，不只看截圖 \{#verify-the-boundary-not-just-the-screenshot\}

測試每個門檻前一刻與剛好達到門檻的情況。頁面範例請檢查實際 iframe 檢視區的 599/600px 與 1023/1024px。元件範例則固定頁面檢視區，以 16px 字級檢查祖先元素的 447/448px。

結果不如預期時，檢查後代元素計算後的 `grid-template-columns`。確認條件相符、容器查詢使用預期且符合資格的祖先，並且沒有其他規則在[階層串接](/guide/cascade-layers)中勝出。

最後測試長文字、放大文字與窄版面。每種寬度都應保持合理的閱讀順序、允許內容換行，並避免固定卡片高度。[版面](/guide/layout-system)會另外說明格線與間距的決策，不與查詢邊界混為一談。
