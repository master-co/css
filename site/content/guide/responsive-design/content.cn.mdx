## 概览 [sr-only] \{#overview\}
页面布局与可复用卡片可能需要不同的响应式规则。页面跟随视口，卡片则跟随父元素提供的空间。在 Master CSS 中，将条件附加到需要改变样式的 class 后方。

请先完成[安装](/guide/installation)。这些示例使用默认预设，以及加载 `@import '@master/css';` 的应用样式表。每个预览都提供观察边界所需的控件；**生成的 CSS** 显示随附 class 的输出。

## 选择变化的依据 \{#choose-a-boundary\}

工作区列数这类页面整体决策，使用视口条件。同一组件可能出现在主列、侧栏或其他受限区域时，则使用容器查询。

| 由什么决定？ | 写法 | 测量对象 |
| --- | --- | --- |
| 页面视口 | `grid-cols(3)@md` | 视口宽度 |
| 组件可用空间 | `grid-cols(2)@container(--md)` | 最近且符合条件的祖先容器宽度 |

<ResponsiveIllustration />

图中两张卡片共用同一个视口，但父元素宽度不同。视口条件会同时应用到两者；容器查询则让窄版保持堆叠，宽版分为多列。

## 让页面随视口调整 \{#based-on-viewport-breakpoints\}

从单列开始，在内容有足够空间时再增加列数。此工作流程使用预设的 `2xs` 阈值 37.5rem 与 `md` 阈值 64rem。以标准初始字号 16px 计算，两者分别为 600px 与 1024px。

`grid-cols(1)` 是基础布局。条件只替换列数；内容顺序、间距与表面样式保持不变。三列只有在内容放得下时才有帮助——采用阈值前，先在应用中试用较长标签。

`@md` 读取预设的 `@custom-media --md` 定义，不会读取 `--breakpoint-md` 主题变量。若要调整所有使用 `@md` 的 class 阈值，在应用 CSS 入口重新声明自定义媒体查询：

```css name=app.css
@import '@master/css';

@custom-media --md (width >= 48rem);
```

若新边界只属于某个布局，而非整个预设，请使用项目专属名称：

```css name=app.css
@custom-media --workspace-wide (width >= 72rem);
```

```html
<section class="grid-cols(1) grid-cols(3)@workspace-wide">…</section>
```

[断点参考](/reference/rules/named-conditions#viewport-widths)列出预设名称与值。按内容需求选择阈值；`md` 这类名称不代表特定设备。

## 让组件随容器调整 \{#based-on-container-sizes\}

在祖先元素加上 `container-inline`，再为后代元素设置容器条件。此处摘要与状态在窄区域中上下堆叠；祖先达到预设 `--md` 容器阈值 28rem 时，改为两列。

<FoundationContainerGrid />

<DocumentExample>

```html
<section class="container-inline">
  <article class="grid-cols(1) gap-lg p-md b-solid b(1) b-line-divider r-lg bg-surface-raised grid-cols(2)@container(--md)">
    <div class="min-w(0)">
      <h3 class="m(0) text-md font-regular fg-text-strong">Release notes</h3>
      <p class="mb(0) mt-xs text-sm fg-text-muted">Review the changes before publishing.</p>
    </div>
    <dl class="grid gap-xs m(0) text-sm">
      <div>
        <dt class="fg-text-muted">Status</dt>
        <dd class="m(0) fg-text-strong">Draft ready</dd>
      </div>
      <div>
        <dt class="fg-text-muted">Next step</dt>
        <dd class="m(0) fg-text-strong">Editorial review</dd>
      </div>
    </dl>
  </article>
</section>
```

<Class2CSS classes={['container-inline', 'grid-cols(1)', 'grid-cols(2)@container(--md)']} />

</DocumentExample>

保持浏览器窗口不变，移动 **容器** 滑块。它调整的是祖先元素，而不是视口。以 16px 字号比较 447px 与 448px：第二列应在 448px 出现。控件受限于文章可用宽度；若文章本身比阈值窄，请加宽浏览器。

祖先建立查询边界，后代改变布局。元素不能把自己的尺寸当作容器查询的祖先。让卡片高度由内容决定，文本换行时才能自然增长。

### 区分两套尺度 \{#keep-the-two-scales-separate\}

`@md` 与 `@container(--md)` 使用不同定义：

<DocumentComparison>

| Class 或值 | 在预设中的含义 |
| --- | --- |
| `@md` | 自定义媒体查询的 64rem 视口阈值 |
| `@container(--md)` | 自定义容器条件的 28rem 容器阈值 |
| `max-w-md` | 使用 `--container-md` 尺寸 token 的最大宽度 |

</DocumentComparison>

调整 `--container-md` 会改变宽度上限，不会改变任一查询阈值。使用 `@custom-container` 定义可复用容器条件，或直接编写 `grid-cols(2)@container(width>=30rem)` 这类局部查询。定义语法与完整尺度请见[具名容器条件](/reference/rules/conditions#named-container-conditions)。

### 为外层容器命名 \{#creating-named-containers\}

未具名的尺寸查询会测量最近且符合条件的祖先。若嵌套布局再建立另一个容器，就会改以内层边界为准。当你要测量的是外层宽度，请用 `(container-name:outer)` 为外层命名，再使用 `@container(outer_--md)`。

两个状态读数位于同一个窄内层容器中。加宽外层边界只会改变具名查询的结果。容器命名是选择祖先，不是让元素查询自身。

## 只对改变的样式加条件 \{#syntax-first\}

共用样式保持无条件。只有需要不同值的属性与范围才加上条件。例如，侧栏在低于 `md` 时使用凸起表面，而较大布局不保留这个背景：

<DocumentExample>

```html
<aside class="p-md bg-surface-raised@max-md">…</aside>
```

<Class2CSS classes={['bg-surface-raised@max-md']} />

</DocumentExample>

`@max-md` 是预设 `@md` 的补集，两者不重叠。重新声明 `--md` 会一起移动两个边界。`hidden@media(52.125rem<=width<=64rem)` 这类局部范围条件，可锁定特定区间而不改变项目的具名阈值。[条件参考](/reference/rules/conditions#mediafeature)说明此查询语法。

## 验证边界，不只看截图 \{#verify-the-boundary-not-just-the-screenshot\}

测试每个阈值前一刻与刚好达到阈值的情况。页面示例请检查实际 iframe 视口的 599/600px 与 1023/1024px。组件示例则固定页面视口，以 16px 字号检查祖先元素的 447/448px。

结果不如预期时，检查后代元素计算后的 `grid-template-columns`。确认条件匹配、容器查询使用预期且符合条件的祖先，并且没有其他规则在[层叠](/guide/cascade-layers)中胜出。

最后测试长文本、放大文本与窄布局。每种宽度都应保持合理的阅读顺序、允许内容换行，并避免固定卡片高度。[布局](/guide/layout-system)会另外说明网格与间距的决策，不与查询边界混为一谈。
