## 개요 [sr-only] \{#overview\}
페이지 레이아웃과 재사용 카드에는 서로 다른 반응형 규칙이 필요할 수 있습니다. 페이지는 뷰포트를 따르고 카드는 부모가 제공하는 공간을 따르게 하세요. Master CSS에서는 스타일을 바꿀 클래스 뒤에 조건을 붙입니다.

먼저 [설치](/guide/installation)를 완료하세요. 예제는 기본 프리셋과 `@import '@master/css';`를 불러오는 앱 스타일시트를 사용합니다. 각 미리보기에는 경계를 관찰하는 데 필요한 컨트롤이 있으며, **생성된 CSS**에서 함께 제시된 클래스의 출력을 볼 수 있습니다.

## 변화의 기준 선택 \{#choose-a-boundary\}

작업 공간의 열 수처럼 페이지 전체에 관한 결정에는 뷰포트 조건을 사용하세요. 같은 컴포넌트가 주 열, 사이드바 또는 다른 제한된 영역에 배치될 수 있다면 컨테이너 쿼리를 사용하세요.

| 결정 기준 | 작성 방법 | 측정 대상 |
| --- | --- | --- |
| 페이지 뷰포트 | `grid-cols(3)@md` | 뷰포트 너비 |
| 컴포넌트의 가용 공간 | `grid-cols(2)@container(--md)` | 가장 가까운 적격 상위 컨테이너의 너비 |

<ResponsiveIllustration />

그림의 두 카드는 같은 뷰포트를 공유하지만 부모 너비는 다릅니다. 뷰포트 조건은 둘에 동시에 일치합니다. 컨테이너 쿼리는 좁은 인스턴스는 세로 배치를 유지하고 넓은 인스턴스만 열로 나누게 합니다.

## 페이지를 뷰포트에 맞추기 \{#based-on-viewport-breakpoints\}

한 열로 시작하고 콘텐츠 공간이 충분해지는 곳에서 열을 추가하세요. 이 워크플로는 프리셋의 `2xs` 임계값 37.5rem과 `md` 임계값 64rem을 사용합니다. 표준 초기 글자 크기 16px에서는 각각 600px와 1024px입니다.

`grid-cols(1)`이 기본 레이아웃입니다. 조건은 열 수만 바꾸며 콘텐츠 순서, 간격, 표면 스타일은 유지됩니다. 3열은 내용이 들어갈 때만 유용합니다. 앱에서 임계값을 채택하기 전에 긴 라벨로 시험해 보세요.

`@md`는 프리셋의 `@custom-media --md` 정의를 읽으며 `--breakpoint-md` 테마 변수는 읽지 않습니다. `@md`를 사용하는 모든 클래스의 임계값을 바꾸려면 앱 CSS 진입점에서 사용자 지정 미디어를 다시 선언하세요.

```css name=app.css
@import '@master/css';

@custom-media --md (width >= 48rem);
```

새 경계가 전체 프리셋이 아닌 한 레이아웃에만 해당하면 프로젝트 고유 이름을 사용하세요.

```css name=app.css
@custom-media --workspace-wide (width >= 72rem);
```

```html
<section class="grid-cols(1) grid-cols(3)@workspace-wide">…</section>
```

[중단점 레퍼런스](/reference/rules/named-conditions#viewport-widths)에 프리셋 이름과 값이 나열되어 있습니다. 콘텐츠의 필요에 따라 임계값을 선택하세요. `md` 같은 이름이 특정 기기를 뜻하지는 않습니다.

## 컴포넌트를 컨테이너에 맞추기 \{#based-on-container-sizes\}

상위 요소에 `container-inline`을 추가한 뒤 하위 요소에 컨테이너 조건을 지정하세요. 여기서는 좁은 영역에서 요약과 상태가 세로로 쌓이며 상위 요소가 프리셋의 `--md` 컨테이너 임계값 28rem에 도달하면 2열이 됩니다.

<FoundationContainerGrid />

```html
<section class="container-inline">
  <article class="grid-cols(1) gap-lg p-md b-solid b(1) b-line-divider r-lg bg-surface-raised grid-cols(2)@container(--md)">
    <div class="min-w(0)">
      <h3 class="m(0) text-md font-regular fg-text-strong">Release notes</h3>
      <p class="mb(0) mt-xs text-sm fg-text-muted">Review the changes before publishing.</p>
    </div>
    <dl class="grid gap-xs m(0) text-sm">
      <div>
        <dt class="fg-text-muted">Status</dt>
        <dd class="m(0) fg-text-strong">Draft ready</dd>
      </div>
      <div>
        <dt class="fg-text-muted">Next step</dt>
        <dd class="m(0) fg-text-strong">Editorial review</dd>
      </div>
    </dl>
  </article>
</section>
```

<Class2CSS classes={['container-inline', 'grid-cols(1)', 'grid-cols(2)@container(--md)']} />

브라우저 창을 그대로 둔 채 **컨테이너** 슬라이더를 움직이세요. 뷰포트가 아닌 상위 요소의 크기를 바꿉니다. 글자 크기 16px에서 447px와 448px를 비교하면 448px에서 두 번째 열이 나타나야 합니다. 컨트롤은 기사의 가용 너비 안에 머무르므로 기사 자체가 임계값보다 좁다면 브라우저를 넓히세요.

상위 요소가 쿼리 경계를 만들고 하위 요소가 레이아웃을 바꿉니다. 요소는 자신의 컨테이너 쿼리에서 자기 크기를 상위 요소로 사용할 수 없습니다. 카드 높이를 콘텐츠에 맡겨 줄바꿈에 따라 자연스럽게 늘어나게 하세요.

### 두 크기 체계 구분 \{#keep-the-two-scales-separate\}

`@md`와 `@container(--md)`는 서로 다른 정의를 사용합니다.

<DocumentComparison>

| 클래스 또는 값 | 프리셋에서의 의미 |
| --- | --- |
| `@md` | 사용자 지정 미디어의 64rem 뷰포트 임계값 |
| `@container(--md)` | 사용자 지정 컨테이너 조건의 28rem 컨테이너 임계값 |
| `max-w-md` | `--container-md` 크기 토큰을 사용하는 최대 너비 |

</DocumentComparison>

`--container-md`를 바꾸면 너비 상한만 바뀌며 두 쿼리 임계값은 변하지 않습니다. `@custom-container`로 재사용 가능한 컨테이너 조건을 정의하거나 `grid-cols(2)@container(width>=30rem)` 같은 로컬 쿼리를 작성하세요. 정의 구문과 전체 크기 체계는 [이름이 있는 컨테이너 조건](/reference/rules/conditions#named-container-conditions)을 참고하세요.

### 바깥 컨테이너에 이름 지정 \{#creating-named-containers\}

이름이 없는 크기 쿼리는 가장 가까운 적격 상위 요소를 측정합니다. 중첩 레이아웃에 다른 컨테이너가 생기면 안쪽 경계가 기준이 됩니다. 바깥 너비를 측정하려면 `(container-name:outer)`로 바깥 컨테이너에 이름을 붙이고 `@container(outer|--md)`를 사용하세요.

두 상태 표시는 같은 좁은 내부 컨테이너 안에 있습니다. 바깥 경계를 넓히면 이름이 있는 쿼리의 결과만 바뀝니다. 컨테이너 이름은 상위 요소를 선택할 뿐 요소가 자기 자신을 조회하게 만들지는 않습니다.

## 바뀌는 스타일에만 조건 추가 \{#syntax-first\}

공유 스타일은 조건 없이 유지하세요. 다른 값이 필요한 속성과 범위에만 조건을 추가하세요. 예를 들어 aside는 `md` 미만에서 돌출 표면을 사용하고 더 큰 레이아웃에는 해당 배경을 적용하지 않을 수 있습니다.

```html
<aside class="p-md bg-surface-raised@max-md">…</aside>
```

<Class2CSS classes={['bg-surface-raised@max-md']} />

`@max-md`는 프리셋 `@md`의 여집합으로 두 조건은 겹치지 않습니다. `--md`를 다시 선언하면 두 경계가 함께 바뀝니다. `hidden@media(52.125rem<=width<=64rem)` 같은 로컬 범위 조건은 프로젝트의 명명된 임계값을 바꾸지 않고 특정 구간을 지정할 수 있습니다. 쿼리 구문은 [조건 레퍼런스](/reference/rules/conditions#mediafeature)를 참고하세요.

## 스크린샷뿐 아니라 경계 검증 \{#verify-the-boundary-not-just-the-screenshot\}

각 임계값 바로 아래와 정확히 도달한 지점을 테스트하세요. 페이지 예제에서는 실제 iframe 뷰포트를 599/600px와 1023/1024px에서 확인하세요. 컴포넌트 예제에서는 페이지 뷰포트를 고정하고 글자 크기 16px에서 상위 요소를 447/448px로 확인하세요.

결과가 예상과 다르면 하위 요소의 계산된 `grid-template-columns`를 검사하세요. 조건이 일치하는지, 컨테이너 쿼리가 의도한 적격 상위 요소를 사용하는지, [캐스케이드](/guide/cascade-layers)에서 다른 규칙이 우선하지는 않는지 확인하세요.

마지막으로 긴 텍스트, 확대된 텍스트, 좁은 레이아웃을 시험하세요. 모든 너비에서 읽기 순서를 유지하고 줄바꿈을 허용하며 카드 높이를 고정하지 마세요. [레이아웃](/guide/layout-system)은 쿼리 경계와 별개로 그리드와 간격 결정을 설명합니다.
