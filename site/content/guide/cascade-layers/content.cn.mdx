## 概述 [sr-only] \{#overview\}
局部调整无需提高选择器优先级。将共用组件规则放在 `components` 层，再由各个实例的工具类覆盖需要改变的属性。

<CascadeIllustration />

## 局部覆盖组件样式 \{#override-a-component-locally\}

CSS 层叠层会先确定各组声明的顺序，再比较选择器优先级。将可复用的组件样式放在 components 层；当某个实例需要不同的值时，再添加工具类：

<DemoConfiguredExample name="layer-local-override" title="共用组件，局部调整" source={`@layer components {
  .collection-card {
    padding: 1.5rem;
    border: 1px solid var(--color-line-divider);
    border-radius: var(--radius-lg);
    background-color: var(--color-surface-raised);
  }
}`} html={'<div class="grid-cols(1) gap-lg wrap-anywhere"><article class="collection-card"><h2 class="m(0) text-lg font-regular">Release notes</h2><p class="mt-xs mb(0) text-sm fg-text-muted">Updates for your workspace.</p></article><article class="collection-card p-sm"><h2 class="m(0) text-lg font-regular">Release notes</h2><p class="mt-xs mb(0) text-sm fg-text-muted">Updates for your workspace.</p></article></div>'} caption="两张卡片的内容与组件 class 相同。第一张的内边距为 24px；第二张添加了 p-sm，在预览的根字号为 16px 时，内边距变为 12px。圆角、边框与表面样式保持不变。" />

预设为普通声明建立以下顺序：

```css
@layer theme, base, defaults, components, utilities;
```

`p-sm` 工具类的优先级高于组件的内边距声明，与这个 class 在 HTML 属性中的位置无关。[层叠规则](/reference/rules/layers#how-layers-control-the-cascade)说明了这一顺序及其适用范围。

这个工具类只改变内边距，不会替换组件或移除其他声明。因此，小幅的局部调整不需要新增组件变体，也不需要使用 `!important`。

## 将原生规则放在正确的层中 \{#keep-native-rules-in-the-intended-layer\}

不属于任何层的普通规则，优先级高于命名层中的普通规则。如果工具类已经编译却没有效果，请检查是否存在未分层的组件规则：

```css
/* This normal rule wins over a layered padding utility. */
.collection-card {
  padding: 1.5rem;
}
```

如果这个共用规则应当允许工具类覆盖，就将它移到 `@layer components` 中。不要仅仅为了弥补非预期的分层方式而添加 `!important`。

<GuideStudy id="unlayered-obstacle" />

分层不会取代层叠的其他规则。重要性会先于普通层的优先级进行比较，而 `!important` 会反转层与层之间的顺序。行内声明、动画与过渡也各有其优先级。这些规则请参阅 [CSS 层叠规范](https://www.w3.org/TR/css-cascade-5/#layer-order)；预设的层顺序则见 [Master CSS 分层规则](/reference/rules/layers#how-layers-control-the-cascade)。

## 排查相互竞争的声明 \{#diagnose-a-competing-declaration\}

1. 在浏览器开发者工具中选中元素，在计算样式中找到该属性，再追查最终生效的声明。
2. 确认两个规则都选中该元素，而且各自的条件均成立。
3. 检查每个声明所属的层，也要留意层外的原生 CSS。
4. 添加局部覆盖之前，先将广泛适用的默认样式放回原本规划的层。
5. 如果仅凭层顺序仍无法解释结果，就继续检查重要性与原生层叠规则。

通过正常的 Master CSS 入口加载基础样式表。生成的规则会包含所属的 layer 块，但不会自行添加基础层顺序声明。

将 `collection-card p-sm` 对调为 `p-sm collection-card` 无法解决问题：HTML 中的 class 顺序不会控制层叠结果。如果同一条件下的两个工具类相互重叠，可用[代码检查](/guide/code-linting#no-conflicting-classes)找出冲突，再决定要保留哪个声明。
