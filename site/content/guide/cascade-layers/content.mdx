## Override a component locally

CSS cascade layers give groups of declarations an order before selector specificity is compared. Keep reusable component styling in the components layer, then apply a utility when one instance needs a different value:

<DemoConfiguredExample name="layer-local-override" title="A shared component, a local adjustment" source={`@layer components {
  .collection-card {
    padding: 1.5rem;
    border-radius: var(--radius-lg);
    background-color: var(--color-surface-raised);
  }
}`} html={'<div class="display:grid gap-lg"><article class="collection-card"><h2 class="margin:0 text-lg font-semibold">Component padding</h2><p class="mt-xs margin-bottom:0 text-sm fg-text-muted">The component supplies 1.5rem.</p></article><article class="collection-card p-sm"><h2 class="margin:0 text-lg font-semibold">Local utility padding</h2><p class="mt-xs margin-bottom:0 text-sm fg-text-muted">p-sm overrides the padding on this instance.</p></article></div>'} theme previewFirst caption="Both cards share the same component class. Only the second adds p-sm; its utility declaration wins over normal component-layer padding." />

The preset establishes this order for normal declarations:

```css
@layer theme, base, defaults, components, utilities;
```

The `padding` utility takes precedence over the component declaration, regardless of where the class appears in the HTML attribute. The [cascade contract](/reference/rules/layers#how-layers-control-the-cascade) describes the order and its scope.

## Diagnose a competing declaration

1. Confirm both rules target the element and their conditions match.
2. Check which layer owns each declaration, including native CSS outside layers.
3. Keep broad defaults in their intended layer before adding local overrides.
4. Inspect importance and the native cascade when layer order alone does not explain the result.

Load the base stylesheet through the normal Master CSS entry. Generated rules contain their layer blocks; they do not add the base layer statement themselves.
