A guide card needs spacing, readable text and a link that responds to interaction. Master CSS lets you make those decisions in HTML: choose a style, then add a selector or condition where that style should apply.

Complete [Installation](/guide/installation) first. These examples use the default preset, with no custom utility definitions. Keep the markup in a source file your integration scans and load your app stylesheet:

```css name=app.css
@import '@master/css';
```

Each **Generated CSS** disclosure shows output compiled from the accompanying classes. Open one to check what reaches the browser; you do not need to copy that output into your stylesheet.

## Read a class \{#declarations\}

Start with a link that turns blue on hover, but only when the viewport matches the preset's `sm` query:

<DocumentExample>

```html
<a href="/guide/reusing-styles" class="fg-blue-60:hover@sm">
  Read the guide
</a>
```

<Class2CSS classes={['fg-blue-60:hover@sm']} />

</DocumentExample>

The class has three parts. `fg-blue-60` selects the style, `:hover` selects a state, and `@sm` adds a condition. The style applies only when both the selector and the condition match. Without those suffixes, `fg-blue-60` applies regardless of hover or viewport width.

<SyntaxIllustration />

The generated rule sets `color` through a CSS variable and sits inside a media query. Its selector escapes punctuation to match the literal HTML class name. Write the readable form in HTML; escaped CSS selectors belong in the generated output.

## Choose how to supply a value \{#values\}

Use the preset's names for common decisions. When you need an exact local value, pass a number to a supported function or write a native declaration:

<DocumentComparison>

| Write | Decision |
| --- | --- |
| `flex` | A fixed utility for `display: flex` |
| `p-md` | A token class for named spacing |
| `p(12)` | A direct value: 12 pixels of padding |
| `(max-width:32rem)` | A native declaration with a full CSS property and value |
| `text-sm` | A recipe coordinating text size, line height and tracking |

</DocumentComparison>

<Class2CSS classes={['flex', 'p-md', 'p(12)', '(max-width:32rem)', 'text-sm']} />

Fixed utilities such as `items-center` and `text-center` cover common declarations. Direct-value functions such as `m(4)`, `b(1)` and `grow(1)` take a number; length functions use pixels, while `grow(1)` supplies a unitless flex factor. Native declarations keep the full property name inside parentheses. A recipe such as `text-sm` or `grid-cols(2)` can coordinate several declarations. All these forms accept selector and condition suffixes.

### Keep spaces inside one class \{#keep-spaces-inside-one-class\}

HTML separates classes at whitespace. Outside quoted strings, write `_` where a CSS value needs a space, the same character a selector uses for a descendant space. Keep commas, slashes and parentheses in place:

<DocumentExample>

```html
<div class="(transform:translate(0,1rem)) (color:rgb(30_60_90/80%))">
  <span class="(content:'New_collection')::before"></span>
</div>
```

<Class2CSS classes={['(transform:translate(0,1rem))', '(color:rgb(30_60_90/80%))', "(content:'New_collection')::before"]} />

</DocumentExample>

The color becomes `rgb(30 60 90 / 80%)`. Inside the quoted content string, the underscore stays literal: the text is `New_collection`. Elsewhere in a value, escape an underscore that belongs to a name, as in `slide\_in`. Master CSS also normalizes operator spacing in expressions such as `calc(100%-2rem)`; the browser evaluates the expression. See [Declarations and values](/reference/rules/declarations) for native declaration boundaries, quoted values and escaping.

## Use tokens for shared values \{#token-families\}

A token class connects a prefix to a named value. `p-md` and `gap-md` both read the spacing token `--spacing-md`, but set different properties:

<DocumentComparison>

| Class | Declaration |
| --- | --- |
| `p-md` | `padding: var(--spacing-md)` |
| `gap-md` | `gap: var(--spacing-md)` |
| `fg-text-muted` | `color: var(--color-text-muted)` |

</DocumentComparison>

<Class2CSS classes={['p-md', 'gap-md', 'fg-text-muted']} />

These selected spacing values come directly from the preset:

<TokenValues namespace="spacing" keys={['sm', 'md', 'lg']} />

`p-md` and `(padding:1rem)` can look identical, but they express different decisions. Changing `--spacing-md` changes the token-based padding; the literal stays at `1rem`. Use tokens when styles should follow a shared value. [Theme tokens](/guide/theme) explains how to define and scope your own values; the [family index](/reference/tokens/families) lists prefixes and namespaces.

## Compose independent decisions \{#composition\}

Build a small surface by giving each decision its own class:

<DocumentExample>

```html
<article class="p-md r-lg b(1) b-solid b-line-divider bg-surface-raised">
  <h2 class="m(0) text-lg fg-text-strong">Field notes</h2>
  <p class="mt-sm mb(0) text-sm fg-text-muted">Keep useful ideas close.</p>
</article>
```

<Class2CSS classes={['p-md', 'r-lg', 'b(1)', 'b-solid', 'b-line-divider', 'bg-surface-raised', 'm(0)', 'text-lg', 'fg-text-strong', 'mt-sm', 'mb(0)', 'text-sm', 'fg-text-muted']} />

</DocumentExample>

Here `b(1)` sets the border width, `b-solid` its style, and `b-line-divider` its color. Change one without restating the others. The padding, corner radius and text treatment stay independent too. This makes a later variation small: a wider layout can change padding while keeping the same surface and text.

### Class order does not set priority \{#cascade\}

If you write `p-md p(12)`, the direct value wins over the token for this property. Reversing the HTML class order produces the same CSS:

<Class2CSS classes={['p-md', 'p(12)']} />

Choose one base padding unless an override is intentional. When combining native component CSS and utilities, layer order matters as well: the preset places normal `utilities` declarations after `components`. [Cascade layers](/guide/cascade-layers) covers competing rules; [Reusing styles](/guide/reusing-styles) shows how to keep a component's shared appearance while changing one instance.

## Add states and selector relationships \{#states\}

Attach a selector to the class whose behavior changes. This button changes its surface on hover and gains an outline when reached with the keyboard:

<DemoConfiguredExample
  name="syntax-button"
  title="A surface change and a focus outline"
  source=""
  html={`<button type="button" class="px-md py-xs text-sm r-md b(1) b-solid b-line-divider bg-surface-raised fg-text-strong shadow-sm bg-surface-inset:hover outline-offset(3) outline(2):focus-visible outline-solid:focus-visible">
  Save changes
</button>`}
  caption="Hover the button, then reach it with Tab. Hover changes the surface; keyboard focus adds an outline. This button demonstrates styling and does not save data."
/>

The hover suffix belongs only to `bg-surface-inset:hover`; it does not make neighboring classes conditional. Native pseudo-classes and pseudo-elements work here, including `:disabled`, `:nth-child(2)` and `::before`. Selector functions work too: `fg-blue-60:is(:hover,:focus-visible)` uses either state.

A selector can target another element. In this example the article owns the class, but its direct child link receives the color while the article is hovered:

<DocumentExample>

```html
<article class="fg-blue-60:hover>a">
  <h3>Field notes</h3>
  <a href="/guide/reusing-styles">Read the guide</a>
</article>
```

<Class2CSS classes={['fg-blue-60:hover>a']} />

</DocumentExample>

Use `>` for a direct child and `_` for a descendant: `fg-blue-60_a` reaches descendant links. The class-bearing element remains the anchor for the suffix. [Selectors](/reference/rules/selectors) covers sibling combinators, attributes, selector lists and specificity.

## Add conditions \{#conditions\}

A condition controls when a class applies. Add `@sm` to change a style only while the viewport matches that named query. This preview makes the opening example observable:

<DemoConfiguredExample
  name="syntax-viewport"
  title="Hover color depends on viewport width"
  source=""
  html={`<div class="p-sm p-lg@sm">
  <a href="/guide/responsive-design" target="_top" class="inline-flex py-xs text-sm fg-text-body underline fg-blue-60:hover@sm">
    Explore responsive design
  </a>
</div>`}
  responsive
  widthPresets={[{ label: 'Below sm', width: 640 }, { label: 'Above sm', width: 900 }]}
  caption="Choose Above sm and hover the link: it turns blue. Below sm, hovering keeps the base text color. The padding also increases at sm. These controls resize the preview's viewport, independently of the surrounding page."
/>

`@sm` refers to the preset's custom media query. For a one-off viewport threshold, write a native query such as `p-lg@media(width>=48rem)`. Other condition forms follow the same pattern:

<DocumentComparison>

| Class | Condition |
| --- | --- |
| `hidden@media(print)` | Printing |
| `grid@supports(display:grid)` | Support for the declaration |
| `grid@sm@supports(display:grid)` | Both the named viewport query and declaration support |

</DocumentComparison>

<Class2CSS classes={['p-lg@media(width>=48rem)', 'hidden@media(print)', 'grid@supports(display:grid)', 'grid@sm@supports(display:grid)']} />

Several conditions nest from left to right, so every wrapper must match. See [Conditions](/reference/rules/conditions) for custom media and the other wrappers.

### Follow a component's available space \{#follow-a-components-available-space\}

A card in a sidebar has less room than a card in the main content area, even at the same viewport width. Give its parent `container-inline`, then put a container condition on the card's layout class. The final example uses `(container-name:card)` to name that parent and `@container(card_width>=28rem)` to query it.

The parent establishes the container; the child changes layout. The `28rem` threshold is an explicit query value, separate from sizing tokens such as `--container-md`. [Responsive design](/guide/responsive-design#based-on-container-sizes) develops this distinction with named and nested containers.

## Put it together \{#complete-card\}

This card combines the decisions above. It starts in one column; when its named parent reaches `28rem`, the link moves beside the text and the padding grows. The link's hover and focus styles remain independent of the layout.

<DemoConfiguredExample
  name="syntax-complete"
  title="A guide card that fits its space"
  source=""
  html={`<section class="container-inline (container-name:card)">
  <article class="grid gap-lg p-md r-lg b(1) b-solid b-line-divider bg-surface-raised shadow-sm (grid-template-columns:1fr_auto)@container(card_width>=28rem) p-lg@container(card_width>=28rem)">
    <div>
      <h3 class="m(0) text-lg font-regular fg-text-strong">Reusable styles</h3>
      <p class="mt-sm mb(0) text-sm fg-text-muted (max-width:38ch)">Keep shared appearance together and local choices in markup.</p>
    </div>
    <a href="/guide/reusing-styles" target="_top" class="inline-flex items-center justify-center self-start self-center@container(card_width>=28rem) gap-xs px-md py-xs text-sm (text-decoration-line:none) r-md b(1) b-solid b-line-divider bg-surface-raised fg-text-strong shadow-sm bg-surface-inset:hover outline-offset(3) outline(2):focus-visible outline-solid:focus-visible">
      Read the guide <span aria-hidden="true">→</span>
    </a>
  </article>
</section>`}
  responsive
  container
  widthPresets={[{ label: 'Narrow', width: 320 }, { label: 'Wide', width: 640 }]}
  caption="Switch between Narrow and Wide. The named container controls the card's columns and padding. Hover or Tab to Read the guide to check its states; activating it opens Reusing styles."
/>

Keep complete class names in your source when choosing variants, such as `'p-md'` and `'p-lg'`. Building a class from fragments such as `'p-' + size` does not give a source scanner the complete name. For continuous values, use a native custom property with a fixed class such as `(width:var(--progress))`. [Scanning class names](/guide/scanning-and-pruning) explains source discovery; [Rendering modes](/guide/rendering-modes) covers when CSS is generated.

If an expected style is missing, open **Generated CSS** and check the class first. Then check which element its selector targets, whether its conditions match, the resolved custom properties, and competing rules in the browser. Reordering classes in HTML is not a fix for the cascade.

Continue with [Theme tokens](/guide/theme) to define shared values or [Reusing styles](/guide/reusing-styles) to choose between component classes, utilities and mixins. Their complete contracts remain in Reference.
