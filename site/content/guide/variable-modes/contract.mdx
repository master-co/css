<a id="overview"></a>

A theme token has two roles: its name makes a value available to registered utility families, and its emitted custom property participates in native CSS. Master CSS resolves the class and retains its dependencies. The browser resolves the custom property's value through the cascade and inheritance.

This page defines token lookup, dependency delivery, substitution and mode activation. [Theme](/guide/theme) explains when to share a token and how to build a project theme; the [token index](/reference#tokens) lists preset values.

## Registration and lookup \{#namespace-resolution\}

Declare tokens in a top-level `@theme` block. A native custom property declared outside `@theme` can be used in CSS, but does not register token-backed classes by itself. Native selectors and queries belong outside the block. See [`@theme`](/reference/directives/theme#theme) for its stylesheet grammar.

<a id="contextual-token-lookup"></a>

A token family determines which namespace to search. The key is the remaining part of the token name; hyphens within the key are preserved.

| Token | Class | Generated declaration |
| --- | --- | --- |
| `--spacing-card` | `p-card` | `padding: var(--spacing-card)` |
| `--radius-card` | `r-card` | `border-radius: var(--radius-card)` |
| `--color-brand` | `bg-brand` | `background-color: var(--color-brand)` |
| `--color-text-action` | `fg-text-action` | `color: var(--color-text-action)` |
| `--color-line-divider` | `b-line-divider` | `border-color: var(--color-line-divider)` |

`text-action` and `line-divider` are keys in the `color` namespace. `outline-line-divider` can consume `--color-line-divider`; `outline-divider` does not implicitly insert `line-`. The same key in two namespaces can supply different values: `p-card` and `r-card` resolve independently.

<ConfiguredExample source={'@theme {\n  --spacing-card: 1.5rem;\n  --radius-card: .5rem;\n  --color-brand: #1d4ed8;\n  --color-text-action: var(--color-brand);\n  --color-line-divider: rgb(0 0 0 / 12%);\n}'} html={'<article class="p-card r-card b(1) b-solid b-line-divider">\n  <a class="fg-text-action" href="/settings">Settings</a>\n</article>'} />

<a id="default-namespace-sources"></a>

The [family index](/reference/tokens/families) owns the complete prefix-to-namespace mapping. Full CSS property names do not create token families automatically. Register a custom pattern with [`@utility`](/reference/directives/definitions#utilities) when a project needs a new mapping. Fixed spellings such as `w-full` retain their fixed definition even if a token with the same key exists; see [class resolution](/reference/rules/declarations).

## Dependency delivery \{#variable-lifecycle\}

A generated declaration normally retains its `var()` reference. Used managed tokens emit under `:root, :host` in the `theme` layer, together with their transitive managed dependencies.

<a id="custom-spacing-example"></a>

<ConfiguredExample source={'@theme { --spacing-card: 1.5rem; }'} classes={['p-card']} />

When a token is live, its duplicate declarations remain in source order. Dependencies referenced by those values remain live too. Native stylesheet references can retain managed tokens; native custom-property declarations and scoped overrides remain part of their owning stylesheet and follow that file's preservation policy.

Master CSS does not choose a light, dark or viewport-specific value while generating a class. Inspection can report the authored declarations and dependencies; it cannot establish a computed value without the element, its ancestors and the browser environment.

### Missing names and invalid values

An unknown token key cannot produce a matching token-family class. This differs from a valid class whose emitted `var()` later resolves to an invalid value in the browser. Inheritance, cycles, fallbacks and property-value validity follow [native custom-property rules](https://www.w3.org/TR/css-variables-1/); retaining a declaration does not prove that its eventual computed value is valid.

## Inheritance and scoped aliases \{#mode-buckets\}

Declare local overrides with native selectors. The same class can then receive different values in different scopes:

```css
@theme { --color-panel: white; }
[data-theme="ocean"] { --color-panel: #082f49; }
```

```html
<section data-theme="ocean">
  <div class="bg-panel">Ocean panel</div>
</section>
```

### Derived values \{#derived-mode-aware-values\}

An alias such as `--color-link: var(--color-brand)` resolves on the element where that alias is declared, before its computed value is inherited. Overriding only `--color-brand` in a descendant does not rebind the inherited alias. Redeclare the alias in the descendant scope when it should derive from the local brand.

The same scope rule applies to derived expressions such as `color-mix()`:

```css
@theme {
  --color-brand: #1d4ed8;
  --color-link: var(--color-brand);
  --color-link-hover: color-mix(in oklab, var(--color-brand), black 15%);
}
[data-theme="plum"] {
  --color-brand: #86198f;
  --color-link: var(--color-brand);
  --color-link-hover: color-mix(in oklab, var(--color-brand), black 15%);
}
```

These functions remain CSS expressions. Master CSS does not calculate a separate color for every authored scope. See the [interactive alias example](/guide/theme#alias-and-override-tokens) for the inherited and rebound results side by side.

## Inline substitution and static delivery \{#inline-and-static-variables\}

`inline` changes what a generated declaration references. `static` changes whether the token's custom-property declaration needs a discovered consumer. These are independent behaviors.

| Definition | Generated class declaration | Custom-property delivery |
| --- | --- | --- |
| `@theme` | Keeps the token reference | Retained when needed |
| `@theme inline` | Substitutes the token value once | The substituted class does not itself require that token declaration |
| `@theme static` | Keeps the token reference | Retained without a discovered consumer |
| `@theme static inline` | Substitutes the token value once | Retained without a discovered consumer |

Inline substitution removes one level of indirection. References inside the substituted value still resolve in the browser; `inline` does not recursively replace them with constants. It applies to Master-generated declarations, including `@apply` expansion. Handwritten native CSS keeps its original `var()` references.

### Where the remaining variable resolves

Both configurations below define `--color-brand: var(--app-brand)` and use `bg-brand`. Only the `inline` modifier changes. In each case the document root is blue and a nested section overrides `--app-brand` to plum.

<ReferenceIllustration id="inline-resolution" />

With ordinary `@theme`, the generated declaration reads `--color-brand`. That token's `var(--app-brand)` resolves at the root; the nested element inherits the resulting blue value.

<ConfiguredExample source={'@theme { --color-brand: var(--app-brand); }\n:root { --app-brand: #1d4ed8; }\n[data-theme="plum"] { --app-brand: #86198f; }'} html={'<section data-theme="plum">\n  <div class="bg-brand">Inherited blue</div>\n</section>'} />

With `@theme inline`, the generated declaration reads `--app-brand` directly on the styled element. It receives the plum value from its section.

<ConfiguredExample source={'@theme inline { --color-brand: var(--app-brand); }\n:root { --app-brand: #1d4ed8; }\n[data-theme="plum"] { --app-brand: #86198f; }'} html={'<section data-theme="plum">\n  <div class="bg-brand">Local plum</div>\n</section>'} />

Use `static` independently when an external consumer needs a token that discovery cannot see. See the [theme modifiers](/reference/directives/theme#theme-static) for accepted forms and definition scope.

## Mode activation \{#mode-triggers\}

A mode is an authored CSS scope or condition, not a second token namespace. Changing token values and restricting a rule to a mode are separate operations.

| Mechanism | What changes | What activates it |
| --- | --- | --- |
| Native custom-property override | Values inherited in that scope | The authored selector or native query |
| `light-dark()` token | Selected color value | The element's used color scheme |
| Preset `@dark` or `@light` suffix | Whether a rule can apply | System `prefers-color-scheme` media query |
| Selector mixin via `@apply(--name)` | Where the generated rule matches | Exactly the selector written in the mixin |

### Manual scopes and rule wrappers

A token class such as `bg-surface` follows the variable it inherits. To apply a different declaration only in an ocean scope, explicitly author that scope in a mixin. `&` stands for the generated selector; the descendant branch below is written deliberately, not inserted by Master CSS.

<ConfiguredExample source={'@theme { --color-surface: white; }\n[data-theme="ocean"] { --color-surface: #082f49; }\n@mixin --ocean {\n  &:where([data-theme="ocean"], [data-theme="ocean"] *) { @contents; }\n}'} html={'<section data-theme="ocean">\n  <div class="bg-surface p(16)@apply(--ocean)">Ocean panel</div>\n</section>'} />

The token override changes the background value. The mixin changes where padding applies. Neither mechanism defines the other. For wrapper arguments and placement, see [Utilities and mixins](/reference/directives/definitions#reusing-a-matched-value).

### System preference and manual color schemes

The full preset supplies native `color-scheme` rules: the root allows `light dark`, while `data-theme="light"` or `data-theme="dark"` fixes the scheme on a region. A token can use `light-dark(white, #111827)` to follow that scheme. The browser selects the value; no second class is needed. See [`light-dark()`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark) for native behavior.

The preset's `@dark` and `@light` suffixes remain system media queries even inside a manually themed region. Changing `data-theme` does not activate them. [Color](/guide/colors#native-color-scheme-and-manual-themes) demonstrates manual activation and nested regions.

### Local overlap and Shadow DOM

Overlapping scopes follow the ordinary cascade, including layer order and specificity. A local value is not automatically stronger merely because its selector describes a theme. See [Cascade layers](/reference/rules/layers).

Default theme declarations include `:host`. Write scoped host overrides explicitly and load the needed stylesheets in the shadow tree:

```css
@theme { --color-panel: white; }
:host([data-theme="dark"]) { --color-panel: #111827; }
```

Tokens do not replace resource delivery. Native keyframes and their dependency retention are covered by [the keyframe contract](/reference/directives/pruning#native-keyframes), and stylesheet preservation by [Native CSS pruning](/reference/directives/pruning).
