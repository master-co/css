## Prevent premature rendering

Runtime-only pages generate their initial rules in the browser. If you use that mode, add `hidden` to the root element so the page waits for runtime initialization:

```html
<html lang="en" hidden>
  <!-- Load the stylesheet and runtime using your integration's setup. -->
</html>
```

The runtime removes `hidden` after startup; its handled startup error path also unhides the root. If JavaScript is disabled, or the runtime script is blocked or fails to download, that code never runs and the page stays hidden. Use static or pre-rendered CSS for content that should remain readable in those conditions.

Progressive pages already contain the first screen's CSS and should stay visible. Follow the [installation guide](/guide/installation) for the framework's default setup, and use [Rendering modes](/guide/rendering-modes) when choosing runtime delivery.

For a runtime-only page, [preloading its critical resources](/guide/preload-critical-resources) can start the required requests earlier.

## Check the first paint \{#benefits\}

Test a cold page load with network and CPU throttling. Confirm that styles are available when content first appears, then check startup failure and disabled-JavaScript behavior for the chosen rendering mode.

Preventing an unstyled flash improves visual continuity. Measure loading and interaction performance separately; hiding the page does not by itself make it load faster.
