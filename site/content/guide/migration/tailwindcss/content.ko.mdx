Tailwind CSS v4와 Master CSS는 모두 클래스 이름과 CSS 지시문으로 CSS를 생성하지만 그대로 교체할 수는 없습니다. 스타일 구현을 바꾸는 작업으로 다루세요. Tailwind와 함께 Master CSS를 설치하고 라우트나 컴포넌트 그룹을 하나씩 변환합니다. 해당 영역이 빌드되고 의도한 디자인과 일치한 뒤 Tailwind를 제거합니다.

이 가이드는 Tailwind CSS v4의 CSS 우선 워크플로인 `@import "tailwindcss"`, `@theme`, `@utility`, `@variant`, `@custom-variant`, `@source`, `@apply`를 다룹니다. Tailwind 동작은 공식 [함수와 지시문](https://tailwindcss.com/docs/functions-and-directives), [테마 변수](https://tailwindcss.com/docs/theme), [소스에서 클래스 감지](https://tailwindcss.com/docs/detecting-classes-in-source-files), [상태와 변형](https://tailwindcss.com/docs/hover-focus-and-other-states)을 확인하세요.

## 마이그레이션 전략 \{#migration-strategy\}
에이전트와 작업할 때는 정적 HTML 또는 JSX 컴포넌트 하나, 스타일시트 진입점, 원래 Tailwind 버전을 공식 `master-css` 스킬에 제공합니다. 모양과 상호작용을 보존하고 남긴 CSS와 Tailwind 의존성을 보고하도록 요청하세요. 스킬은 검토된 절차이며 프로젝트 전체 자동 변환기는 아닙니다.

클래스 이름을 바꾸기 전에 원본에 설치된 Tailwind 도구 체인으로 빌드합니다. 컴파일한 CSS가 실제 값, 변형, 변수 의존성을 제공합니다. 테마나 플러그인 설정이 없는 조각은 해당 문맥을 먼저 파악한 뒤 충실한 변환인지 판단하세요. `mastercss_suggest_classes`는 독립 선언 블록에만 쓰고 복잡한 선택자와 미해결 동적 표현식은 네이티브 CSS에 둡니다. Master 클래스를 넘기기 전에 `tailwind-merge` 등 Tailwind 전용 클래스 처리를 확인합니다.

같은 리셋, 글꼴, 테마, 브라우저 상태에서 두 버전을 비교하세요. Tailwind v4의 `hover:`에는 `(hover: hover)` 미디어 조건도 필요하므로 의사 클래스만 복사하면 동작이 달라집니다. `mastercss_css_compare`는 Master 출력끼리 비교합니다. 원본 컴포넌트와 변환 결과의 비교에는 브라우저를 사용하세요.

공존, 기준 캡처, 제거 검사는 [공통 마이그레이션 절차](/guide/migration#migration-strategy)를 사용합니다. 첫 작업에서 다음 Tailwind 전용 계약을 확인하세요.

<DocumentComparison>

| 계약 | 보존 또는 교체 대상 |
| --- | --- |
| 컴파일러 입력 | Tailwind 지시문은 Tailwind 컴파일러에 두고 생성한 일반 CSS를 Master 진입점 다음에 로드합니다. |
| 테마와 변형 | Master 클래스를 선택하기 전에 실제 토큰 값과 조건을 해석합니다. |
| Preflight, 플러그인, 전역 CSS | 아직 바꾸지 않은 화면에 필요한 규칙을 유지합니다. |
| 클래스 처리 | Tailwind 전용 병합과 조각 조립을 명시적인 클래스 맵으로 바꿉니다. |
| 컴포넌트 내부 | 컴포넌트 자체를 옮길 때까지 외부 CSS와 복잡한 선택자를 유지합니다. |

전역 검색·치환은 피하세요. 두 시스템은 리셋, 스케일, ring 모델, 지시문 계약이 다릅니다. 같은 키워드도 다른 작업을 의미할 수 있습니다.

## Tailwind와 함께 Master CSS 설치 \{#install-master-css-beside-tailwind\}
Tailwind 진입점은 계속 Tailwind 컴파일러가 처리합니다. 일반 CSS로 컴파일한 뒤 그 결과를 Master CSS 진입점 다음에 로드합니다. 두 시스템은 `@theme`, `@utility`, `@apply`라는 이름을 서로 다른 계약으로 사용하므로 처리되지 않은 Tailwind 정의를 Master CSS 컴파일러로 넘기지 마세요.

```css name=app.css
@layer properties, theme, base, defaults, components, utilities;
@import "@master/css";
```

```ts name=main.ts
import './app.css'
import './legacy-tailwind.generated.css'
```

기존 Tailwind 빌드가 `legacy-tailwind.generated.css`를 생성하도록 유지합니다. 레이어 순서를 먼저 선언하세요. Tailwind 출력은 `defaults` 없이 `properties`와 자체 레이어를 선언하며, 뒤쪽 문에서 처음 등장한 레이어는 순서의 맨 끝으로 갑니다. 이 문이 없으면 `defaults`가 `utilities`보다 우선합니다.

두 시스템은 `text-sm`처럼 같은 클래스 이름에 대한 규칙을 `utilities` 레이어에 각각 생성할 수 있고, 일부 같은 테마 변수도 정의합니다. Tailwind 출력을 나중에 로드하면 변환하지 않은 마크업에서 Tailwind의 규칙과 값이 계속 적용됩니다. 공존 중에는 리셋과 중복 이름을 비교하세요. [shadcn/ui에서 마이그레이션](/guide/migration/shadcn-ui#load-master-css-beside-the-shadcn-ui-build)에서 중복 이름을 나열하고 문서 타이포그래피를 그대로 유지하는 방법을 설명합니다.

대부분의 통합에는 여기서 Master CSS 소스 지시문이 필요하지 않습니다. 통합이나 CLI 스캐너가 일반 앱 파일을 찾으므로 기본 범위 밖에 있는 변환 마크업에만 `@source`를 추가합니다.

그런 다음 프로젝트 프레임워크나 빌드 도구의 [설치](/guide/installation)를 따릅니다. React는 번들러 가이드를, Laravel과 Blazor는 [서버 렌더링 앱](/guide/installation/server-rendered)의 호스트별 절을 사용합니다.

아직 Tailwind를 제거하지 마세요. 첫 목표는 앱의 모양을 유지하면서 Master CSS가 새 마크업이나 변환한 마크업의 규칙을 생성하는 상태입니다.

## 렌더링 모드 선택 \{#choose-a-rendering-mode\}
[정적 렌더링](/guide/rendering-modes)부터 시작하세요. 대부분의 Tailwind 프로젝트는 소스에 완전한 클래스 문자열을 이미 보유합니다. 클래스를 전환하거나 요소별 CSS 변수를 바꾸는 데 브라우저 런타임은 필요하지 않습니다.

빌드 후 앱이 실제로 새 클래스 이름을 만들 때만 런타임이나 점진적 렌더링을 사용합니다. 모드를 고르기 전에 조각 조립을 완전한 클래스 맵으로 바꾸고 기존 빌드가 의존하는 소스 경계를 확인하세요.

## CSS 우선 테마 값 변환 \{#translate-css-first-theme-values\}
Tailwind v4 `@theme` 변수는 유틸리티 클래스와 변형을 만들고, Master CSS `@theme` 변수는 네임스페이스의 디자인 토큰을 정의합니다. 형태는 비슷하지만 생성 클래스 구문은 다릅니다.

```css name=tailwind.css
@import "tailwindcss";

@theme {
  --color-brand: oklch(0.62 0.2 265);
  --spacing-card: 1.5rem;
  --radius-card: 1rem;
  --breakpoint-dashboard: 72rem;
}
```

```css name=app.css
@import "@master/css";

@theme {
  --color-brand: oklch(0.62 0.2 265);
  --spacing-card: 1.5rem;
  --radius-card: 1rem;
}

@custom-media --dashboard (width >= 72rem);
```

```html
<article class="grid r-card grid-cols(3)@dashboard bg-brand p-card">
  ...
</article>
```

Master CSS는 네임스페이스에 따라 토큰 이름을 해석합니다. `--color-brand`는 `bg-brand`, `fg-brand`, 테두리 색 유틸리티에, `--spacing-card`는 `p-card`, `gap-card`, `m-card` 같은 간격 유틸리티에 사용할 수 있습니다.

| Tailwind v4 테마 개념 | Master CSS 대응 | 설명 |
| --- | --- | --- |
| `--color-*` | `--color-*` | 색 토큰은 `bg-*`, `fg-*`, 테두리·윤곽선 색 유틸리티에 사용합니다. `text-*`는 색 별칭이 아닌 타이포그래피 레시피입니다. |
| `--spacing-*` 또는 기본 간격 | `--spacing-*` | 제품 간격에는 명명된 토큰, 직접 값에는 명시적인 네이티브 단위를 사용합니다. |
| `--radius-*` | `--radius-*` | `r-card` 같은 명명된 반경 유틸리티나 전체 `border-radius` 선언 클래스를 씁니다. |
| `--shadow-*` | `--shadow-*` | `shadow-card` 같은 명명된 그림자 유틸리티나 전체 `box-shadow` 선언 클래스를 씁니다. |
| `--font-*`, `--text-*`, `--leading-*`, `--tracking-*` | 글꼴, 텍스트, 행간, 자간 네임스페이스 | 전체 텍스트 처리를 공유하려면 `text-*`를 우선합니다. |
| `--breakpoint-*` | `@custom-media --md (width >= 48rem);` | `@md` 같은 뷰포트 접미사를 정의합니다. 사용자 정의 속성은 조건을 등록하지 않습니다. |

`@theme inline`은 생성 선언에서 토큰 값을 한 번 대입하고, `@theme static`은 사용처가 없어도 토큰과 의존성을 유지합니다. 두 수정자를 함께 쓸 수 있습니다. 테마 블록에는 사용자 정의 속성 선언만 둡니다. 키프레임은 네이티브 CSS에 두고 사용 기반 출력을 원하면 해당 파일에 `@prune native;`를 넣습니다.

수동 테마 전환용 `.light`, `.dark` 선택자는 `@theme` 밖에 둡니다. 마크업이 `@apply(--manual-light)`나 `@apply(--manual-dark)` 접미사를 사용한다면 선택자 믹스인을 별도로 정의합니다.

```css name=app.css
@import "@master/css";

@mixin --manual-light { &:where(.light, .light *) { @contents; } }
@mixin --manual-dark { &:where(.dark, .dark *) { @contents; } }

@theme {
  --color-panel:#fff;
  --color-text-body:#111827;
}

.light {
  --color-panel: #fff;
  --color-text-body: #111827;
}

.dark {
  --color-panel: #111827;
  --color-text-body: #f9fafb;
}

```

```html
<section class="fg-text-body bg-panel">
  ...
</section>
```

Tailwind와 Master CSS의 기본 테마는 다릅니다. 사용자 정의 제품 토큰을 먼저 변환한 뒤 기본 팔레트와 스케일 대체를 의도적으로 검토하세요.

Master CSS 프리셋에는 `--duration-fast`처럼 Tailwind 기본 테마에 없는 토큰도 있습니다. 네이티브 CSS가 이런 이름을 자체 변수로 읽으면 Master CSS가 프리셋 값을 `:root, :host`에 전달하므로, 프로젝트 범위 밖의 요소에 원래 없던 값이 생깁니다. 그 이름이 프로젝트의 것이라면 프리셋 토큰을 제거하세요.

```css name=app.css
@import "@master/css";
@theme { --duration-fast: initial; }

.panel { --duration-fast: 120ms; transition-duration: var(--duration-fast); }
```

[토큰 제거](/reference/directives/theme#theme-removal)를 참고하세요.

## 유틸리티 변환 \{#translate-utilities\}
명시적인 Master CSS 선언으로 시작한 뒤 로컬 어휘가 분명한 곳을 줄입니다.

| Tailwind v4 패턴 | Master CSS 패턴 | 설명 |
| --- | --- | --- |
| `p-6`, `px-4`, `mt-8` | `(padding:1.5rem)`, `(padding-inline:1rem)`, `(margin-top:2rem)` | Tailwind 기본 .25rem 스케일을 가정합니다. 원래 설정을 확인하고 제품 간격에는 `p-card` 같은 정의된 토큰을 사용합니다. |
| `-mt-4` | `(margin-top:-1rem)` | 음수 원시 값이나 정의된 숫자 토큰용 `-mt-card`를 사용합니다. |
| `w-full`, `h-screen`, `min-w-0` | `w-full`, `(height:100vh)`, `min-w(0)` | 픽셀과 0은 직접 값 함수, 다른 단위는 네이티브 구문을 사용합니다. |
| `rounded-lg` | `r-lg` | 기본값은 둘 다 .5rem입니다. 이름 재사용 전에 프로젝트 재정의를 확인합니다. |
| `bg-blue-600`, `text-white` | `bg-blue-60`, `fg-white` | Master CSS 프리셋 색 단계는 Tailwind 기본 팔레트와 다릅니다. |
| `bg-zinc-50`, `text-zinc-500` | `bg-zinc-5`, `fg-zinc-60` | 스케일이 다릅니다. 더 어두운 텍스트 단계가 고정 밝은 표면의 가독성을 유지합니다. 10으로 나누지 말고 실제 값을 비교하세요. |
| `text-lg`, `font-semibold`, `leading-7` | `font-lg`, `font-semibold`, `(line-height:1.75rem)` | 전체 텍스트 처리를 의도할 때만 `text-*`를 사용합니다. |
| `flex`, `items-center`, `justify-between` | `flex`, `items-center`, `justify-between` | 이 고정 유틸리티는 이름과 선언이 같습니다. `(property:value)`로 가기 전에 [고정 유틸리티 목록](/reference/rules/declarations#fixed-utilities)을 확인합니다. |
| `grid-cols-3`, `gap-4` | `grid-cols(3)`, `(gap:1rem)` | 명시적인 그리드 레시피와 네이티브 `gap` 속성을 사용합니다. |
| 임의 값 예: `w-[min(100%,72rem)]` | `(width:min(100%,72rem))` | 네이티브 CSS 함수 값을 직접 씁니다. |
| 임의 속성 예: `[scroll-margin-top:4rem]` | `(scroll-margin-top:4rem)` | Master CSS는 모든 네이티브 선언을 소괄호로 감쌉니다. |
| important 수정자 예: `mt-0!` | `mt(0)!` | 현재 Tailwind v4와 Master CSS는 important 표시를 클래스 끝에 둡니다. |

다음은 프리셋 값을 쓰는 Master CSS 레이아웃입니다. 지정되지 않은 Tailwind 레이아웃을 픽셀 단위로 재현한 변환은 아닙니다.

```html
<section class="grid gap-lg w-full max-w-5xl mx-auto px-md py-2xl grid-cols(3)@md">
  <article class="p-lg r-lg bg-surface-base shadow-sm">
    <h2 class="m(0) font-2xl font-regular fg-text-neutral">Account</h2>
    <p class="mt-xs fg-text-muted">Review profile settings.</p>
  </article>
</section>
```

짧은 Master CSS 별칭이 없는 Tailwind 클래스는 CSS 속성을 직접 사용합니다.

## 변형과 상태 변환 \{#translate-variants-and-states\}
Tailwind는 유틸리티 앞에 변형을 쓰고 Master CSS는 선언 뒤에 선택자와 조건을 붙입니다.

| Tailwind v4 패턴 | Master CSS 패턴 | 설명 |
| --- | --- | --- |
| `hover:bg-blue-700` | `bg-blue-70:hover@media(hover:hover)` | Tailwind v4의 호버 가능 조건을 유지합니다. 색은 새 프리셋 선택이므로 정확한 재현에는 원래 토큰을 복사합니다. |
| `focus-visible:outline-2` | `outline(2):focus-visible` | 너비만 대응합니다. 윤곽선 스타일과 색도 유지하세요. 너비만으로 같은 포커스 표현이 되지는 않습니다. |
| `disabled:opacity-50` | `(opacity:.5):disabled` | 속성과 의사 클래스 선택자를 지원합니다. |
| `md:grid-cols-3` | `grid-cols(3)@tailwind-md` | 명시적 조건으로 원래 임계값을 유지합니다. 두 프리셋의 `md` 값은 다릅니다. |
| `dark:bg-slate-950` | `bg-slate-95@apply(--manual-dark)` | 명시적인 `--manual-dark` 선택자 믹스인을 따릅니다. |
| `motion-safe:animate-spin` | `animate-rotate@motion-safe` | 프리셋 회전은 1s, 선형, 무한 반복이며 `@motion-safe`는 모션 감소 설정을 존중합니다. |
| `supports-[display:grid]:grid` | `grid@supports(display:grid)` | 로컬 조건에는 원시 `@supports()`를 사용합니다. |
| `data-[state=open]:...` | `bg-blue-5[data-state=open]` | 네이티브 속성 선택자를 직접 붙입니다. |
| `has-[:checked]:...` | `bg-blue-5:has(:checked)` | 네이티브 `:has()`를 지원합니다. |

```html
<button type="button" class="inline-flex items-center (min-height:2.5rem) px-md r-md bg-blue-60 fg-white bg-blue-70:hover@media(hover:hover) (opacity:.5):disabled">
  Save
</button>
```

Tailwind 기본 `md`는 48rem부터, Master CSS 프리셋 `md`는 64rem부터입니다. 위 반응형 행은 명명된 조건으로 Tailwind 임계값을 유지합니다.

```css name=app.css
@custom-media --tailwind-md (width >= 48rem);
```

Tailwind의 `max-md:`는 `@custom-media --max-tailwind-md not (--tailwind-md);`와 `@max-tailwind-md` 접미사로 유지합니다. Master 프리셋 `@max-md`는 자체 64rem 임계값의 여집합입니다. 재사용 미디어 쿼리는 `@custom-media`, 다른 래퍼는 `@contents`를 포함한 믹스인을 쓰며 선택자 상태는 접미사나 중첩 선택자로 유지합니다.

```css name=app.css
@import "@master/css";

@custom-media --compact (width < 48rem);

```

{ }
```html
<button type="button" class="bg-blue-70:hover@media(hover:hover) fg-white:hover@media(hover:hover) px-sm@compact">
  Save
</button>
```
{ }

Tailwind의 `group-*`, `peer-*` 패턴에는 가능하면 네이티브 선택자를 사용합니다. Master CSS는 자손, 자식, 형제, 속성, `:has()`를 대상으로 할 수 있지만 Tailwind의 group·peer 변형 이름을 구현하지 않습니다.

```html
<article class="bg-blue-5:hover_h2@media(hover:hover) fg-blue-60:hover_h2@media(hover:hover)">
  <h2 class="fg-text-neutral">Project</h2>
</article>
```

## 유틸리티 조합을 네이티브 CSS로 교체 \{#replace-utility-composition-with-native-css\}
Tailwind 조합을 네이티브 선언과 선택자로 다시 쓰고 토큰 참조와 상태를 보존합니다. Master 유틸리티는 마크업에서 직접 사용하세요. Master CSS `@apply`는 명명된 `@mixin` 하나를 펼치며 유틸리티 클래스 목록을 받지 않습니다. `@compose`는 지원하지 않습니다.

```css name=tailwind.css
.btn {
  @apply inline-flex items-center gap-2 rounded-md bg-blue-600 px-4 py-2 text-white shadow-sm;
}
```

```css name=app.css
@import "@master/css";

.btn {
  display: inline-flex;
  border-radius: var(--radius-md);
  gap: var(--spacing-xs);
  padding-block: var(--spacing-xs);
  padding-inline: var(--spacing-md);
  background-color: var(--color-blue-60);
  box-shadow: var(--shadow-sm);
  color: oklch(100% 0 none);
  align-items: center;
}
```

이 예는 Master 프리셋 팔레트와 그림자를 사용하므로 Tailwind 기본값과 정확히 같은 모양은 아닙니다. 충실한 변환을 원하면 프로젝트가 디자인을 명시적으로 변경할 때까지 원래 해석된 색과 그림자 값을 유지하세요.

CSS 안에서 선언 그룹을 재사용해야 한다면 믹스인 이름을 부여합니다. 이것이 Master CSS의 `@apply` 의미입니다.

```css name=app.css
@mixin --control {
  padding-inline: 1rem;
  padding-block: .5rem;
}

.btn {
  @apply --control;
}
```

컴포넌트 전용 스타일은 네이티브 선언으로 규칙 전체를 표현할 수 있습니다.

```css name=app.css
.form-panel {
  border-radius: var(--radius-lg);
  padding: var(--spacing-lg);
  background-color: oklch(100% 0 none);
  box-shadow: var(--shadow-sm);
  border: 1px solid color-mix(in oklab, currentColor 12%, transparent);
}
```

Vite, Next.js, Webpack 통합에서는 CSS Modules와 프레임워크 스타일 블록에 프로젝트 토큰, 믹스인, 사용자 정의 미디어를 자동으로 제공합니다. 추가 정의 파일이나 독립 컴파일에만 `@reference`를 사용하세요.

```css name=Button.module.css
.button {
  display: inline-flex;
  border-radius: var(--radius-md);
  padding-inline: var(--spacing-md);
  background-color: var(--color-blue-60);
  color: oklch(100% 0 none);
  align-items: center;
  height: 2.5rem;
}
```

따옴표 문자열, 복잡한 content 값, 특수 선택자는 일반 CSS 선언이나 중첩 CSS로 유지합니다.

## 사용자 정의 유틸리티와 컴포넌트 이동 \{#migrate-custom-utilities-and-components\}
Tailwind `@utility`는 변형과 함께 쓰는 사용자 정의 유틸리티를 만듭니다. Master CSS에서는 클래스 레시피에 `@utility`, 선언 재사용에 `@mixin`, 제품 역할에 `@layer components`를 사용합니다.

```css name=tailwind.css
@utility content-auto {
  content-visibility: auto;
  contain-intrinsic-size: auto 32rem;
}
```

```css name=app.css
@import "@master/css";

@utility content-auto {
  content-visibility: auto;
  contain-intrinsic-size: auto 32rem;
}
```

```html
<section class="content-auto">
  ...
</section>
```

이름이 저수준 기본 기능이 아니라 제품 UI 역할을 설명하면 `@layer components`를 사용합니다.

```css name=app.css
@layer components {
  .btn {
    display: inline-flex;
    border-radius: var(--radius-md);
    gap: var(--spacing-xs);
    padding-block: var(--spacing-xs);
    padding-inline: var(--spacing-md);
    font-size: var(--font-size-sm);
    font-weight: var(--font-weight-medium);
    align-items: center;
    justify-content: center;
    background-color: var(--color-blue-60);
    color: oklch(100% 0 none);

    &:disabled {
      opacity: .5;
      pointer-events: none;
    }

    @media (--md) {
      padding-inline: var(--spacing-lg);
    }
  }
}
```

```html
<button class="btn">
  Submit
</button>
```

유틸리티 조합으로 읽기 어려워지는 복잡한 외부 재정의는 네이티브 CSS에 유지합니다.

## 동적 클래스 처리 \{#handle-dynamic-classes\}
Tailwind와 Master CSS 정적 렌더링은 페이지 실행 전에 찾을 수 있는 클래스 이름에 의존합니다. 완전한 문자열이 가장 안전한 마이그레이션 대상입니다.

(x) 조각 조립을 피하세요.

```ts
const className = '(background:' + tone + ')'
```

(o) 완전한 클래스 맵을 사용하세요.

```ts
const toneClasses = {
  neutral: 'bg-surface-base fg-text-neutral',
  success: 'bg-green-80 fg-white',
  danger: 'bg-red-70 fg-white'
}
```

값만 동적이면 클래스는 고정하고 런타임 값은 CSS 변수로 전달합니다.

```tsx
function Progress({ value }: { value: number }) {
  const percent = Number.isFinite(value) ? Math.max(0, Math.min(100, value)) : 0
  return (
    <div role="progressbar" aria-label="Progress" aria-valuemin={0} aria-valuemax={100} aria-valuenow={percent}
      className="overflow-hidden (height:1rem) pill bg-surface-inset">
      <div
        className="h-full (width:var(--progress)) bg-text-muted (transition-property:width) (transition-duration:var(--duration-fast))@motion-safe (transition-timing-function:var(--easing-smooth))"
        style={{ '--progress': `${percent}%` } as React.CSSProperties}
      />
    </div>
  )
}
```

Master CSS로 전환하면 대부분의 Tailwind `@source` 경계를 삭제할 수 있습니다. 공유 워크스페이스 패키지나 외부 콘텐츠처럼 통합이나 CLI가 원래 스캔하지 않는 소스에만 Master CSS `@source`를 유지하거나 추가합니다.

```css name=app.css
@import "@master/css";

@source "../content/**/*.mdx";
@source "../packages/ui/**/*.{ts,tsx}";
@source not "../packages/ui/**/*.stories.tsx";
```

스캔 소스에 없는 유한한 클래스에는 `@safelist`를, 잘못 감지한 항목에는 `@blocklist`를 사용합니다.

```css name=app.css
@import "@master/css";

@safelist "bg-blue-60 bg-red-60@dark";
@blocklist "debug-*";
```

Tailwind `@source inline()`은 인라인 문자열과 중괄호 확장으로 클래스를 생성할 수 있습니다. Master CSS의 `@safelist`에는 프로젝트에 필요한 클래스를 명시적으로 나열합니다.

## 마이그레이션 검증 \{#validate-the-migration\}
각 작업을 코드와 UI 양쪽에서 검토합니다.

- 프로젝트 포매터, 린터, 타입 검사, 테스트, 프로덕션 빌드를 실행합니다.
- [코드 린트](/guide/code-linting)로 Master CSS 클래스 문자열을 검증하고 충돌을 찾습니다.
- 라이트·다크 테마, 반응형 중단점, 호버·포커스, 필요하다면 인쇄 상태에서 이전 Tailwind 버전과 비교합니다.
- Tailwind Preflight, 기본 테마 값, ring 유틸리티, `container`, 공식 플러그인, group·peer 변형에 의존한 라우트를 확인합니다.
- 변환된 페이지가 Tailwind 클래스나 플러그인 출력에 의존하지 않을 때까지 Tailwind를 읽습니다.

작업별 검사가 통과하면 더 이상 사용하지 않는 Tailwind 유틸리티만 제거합니다. 제품에 필요한 동안 두 시스템을 계속 함께 사용할 수 있습니다.

## Tailwind 제거 \{#remove-tailwind\}
변환한 경로가 빌드되고 의도한 디자인과 시각적으로 일치한 뒤에만 Tailwind를 제거합니다.

1. 앱 루트에서 생성 Tailwind CSS import를 제거하고 별도의 Tailwind 빌드 입력을 폐기합니다.
2. 대체된 Tailwind 전용 `@theme`, `@utility`, `@custom-variant`, `@variant`, `@apply`, `@source inline()`, `@plugin` 사용을 제거합니다.
3. 어떤 스타일시트도 Tailwind를 가져오지 않을 때 패키지와 PostCSS 또는 Vite 통합 코드를 제거합니다.
4. 프로젝트 전체 검증을 실행합니다.
5. 브라우저에서 주요 페이지를 다시 확인합니다.

서드파티 플러그인이나 외부 스타일시트가 유용한 CSS를 제공한다면 제품 전용 대안이 생길 때까지 일반 CSS로 유지합니다.

## Master CSS에 직접 대응하지 않는 Tailwind CSS 기능 \{#tailwind-css-capabilities-without-a-direct-master-css-equivalent\}
| Tailwind 기능 | Master CSS 상태 | 마이그레이션 경로 |
| --- | --- | --- |
| Tailwind 클래스 구문과 즉시 호환 | Tailwind 클래스 구문을 읽지 않습니다. | Master CSS 구문으로 다시 쓰거나 각 영역을 옮길 때까지 Tailwind를 유지합니다. |
| `@plugin`으로 Tailwind 플러그인 로드 | Tailwind 플러그인을 실행하지 않습니다. | 네이티브 CSS, `@theme`, `@mixin`, `@layer components`로 필요한 출력을 재현하고 필요하면 플러그인 CSS를 임시 유지합니다. |
| Tailwind CSS 우선 테마 해석 | 자체 토큰 네임스페이스와 유틸리티 매칭을 사용합니다. | 공유 값을 Master CSS `@theme`으로 옮기고 생성 클래스 이름을 검토합니다. |
| Tailwind `prefix(...)` | 클래스 접두사 모드가 없습니다. | Master CSS 구문을 직접 쓰고 앱 루트로 범위를 제한하려면 네이티브 선택자를 사용합니다. |
| `@source inline()` 중괄호 확장 safelist | 대응하는 중괄호 확장 지시문이 없습니다. | 명시적인 `@safelist` 항목과 완전한 클래스 문자열을 사용합니다. |
| 정확히 같은 Tailwind Preflight | 기본 스타일은 Tailwind Preflight가 아닙니다. | UI를 비교하고 리셋 세부 사항에 의존하는 곳에 네이티브 CSS를 추가합니다. |
| Tailwind `@property` 폴백 | Tailwind는 프로젝트가 직접 작성한 것을 포함해 최상위 `@property`마다 초기값을 `@supports`로 보호한 `@layer properties` 규칙에 추가해 `@property`를 지원하지 않는 브라우저에 대비합니다. Master CSS는 `@property`를 작성한 그대로 유지합니다. | 빌드 대상에 그런 브라우저가 포함되면 같은 초기값을 네이티브로 선언합니다. 상속되는 속성이라면 `@layer base { :root { --content-gutter: 24px; } }`처럼 작성합니다. |
| typography, forms 등 공식 플러그인 출력 | Tailwind 플러그인 CSS를 자동 재현하지 않습니다. | 플러그인 CSS를 임시 유지하거나 제품 전용 컴포넌트와 유틸리티를 작성합니다. |
| Tailwind `container` 유틸리티 의미 | 네이티브 `container-type`으로 쿼리 경계를 만듭니다. | 페이지 래퍼에는 `w-full (max-width:72rem) mx-auto (padding-inline:1rem)`, 조상 쿼리 컨테이너에는 `container-inline`을 사용합니다. |
| Tailwind ring 유틸리티 모델 | 같은 ring 유틸리티 계열이 없습니다. | `(outline:*)`, `(outline-offset:*)`, `(box-shadow:*)` 또는 사용자 정의 유틸리티를 사용합니다. |
| group·peer 변형 구문 | `group-*`, `peer-*` 변형을 구현하지 않습니다. | 네이티브 선택자, `:has()`, 결합자를 사용합니다. |
