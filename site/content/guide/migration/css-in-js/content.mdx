CSS-in-JS migrations are most successful when static visual styles move first and runtime behavior moves last. Styled Components and Emotion can stay in the project while Master CSS takes over class-based styling one component family at a time.

This guide covers `styled-components`, `@emotion/react`, and `@emotion/styled`. It does not require deleting CSS-in-JS from components that still need runtime-generated selectors or values.

---

## Migration strategy
Run both systems during migration.

1. Add Master CSS to the app CSS entry and choose a rendering mode.
2. Audit styled wrappers, `css` helpers, object styles, global styles, theme providers, and variant props.
3. Move project-owned theme values into Master CSS `@theme`.
4. Convert static styles to class strings or `@layer components`.
5. Convert variant props to complete class maps.
6. Pass truly dynamic values through CSS variables.
7. Remove CSS-in-JS packages only after no converted surface depends on their runtime.

Do not start with a global codemod. CSS-in-JS often mixes layout, visual styling, variants, element selection, animation, and runtime state in the same component.

---

## Audit checklist
Inspect the CSS-in-JS surface before changing files.

| Area | What to look for | Migration decision |
| --- | --- | --- |
| Styled wrappers | `styled.div`, `styled(Component)`, `as`, transient props, and polymorphic components | Convert pure visual wrappers first; keep wrappers that encode behavior or DOM choice. |
| Emotion `css` | `css` prop, `css()` helper, object styles, arrays, and conditional fragments | Replace static fragments with class strings or class maps. |
| Themes | `ThemeProvider`, `DefaultTheme`, palette, spacing, radius, typography, breakpoints, and modes | Move shared design values into `@theme`; keep non-CSS app config in the JS theme. |
| Global styles | `createGlobalStyle`, Emotion `Global`, resets, font faces, and base element rules | Move app-owned CSS to the CSS entry; keep third-party resets that still matter. |
| Variants | Props such as `tone`, `size`, `selected`, `dense`, and `disabled` | Use complete class maps so static rendering can see every class. |
| Runtime values | Measurements, user colors, drag positions, progress, and live layout values | Use CSS variables or keep the CSS-in-JS rule until there is a clearer replacement. |

## Convert static styled components
Start with wrappers that only apply stable visual styles.

```tsx name=Button.tsx
import styled from 'styled-components'

const Button = styled.button`
  display: inline-flex;
  align-items: center;
  gap: .5rem;
  min-height: 2.5rem;
  padding: 0 1rem;
  border-radius: .5rem;
  background: ${({ theme }) => theme.colors.primary};
  color: white;
`
```

Move the reusable value into `@theme`, then use a class string where the button is rendered.

```css name=app.css
@import "@master/css";

@theme {
  --color-primary: #2563eb;
}

```

```tsx name=Button.tsx
export function Button(props: React.ButtonHTMLAttributes<HTMLButtonElement>) {
  const { className, type = 'button', ...buttonProps } = props
  return (
    <button
      className={['display:inline-flex align-items:center gap-xs min-height:2.5rem padding-block:0 px-md r-lg bg-primary fg-white', className].filter(Boolean).join(' ')}
      type={type}
      {...buttonProps}
    />
  )
}
```

The original `.5rem` radius maps to the preset `r-lg`, not `r-md`. Compare computed values when replacing literals with named tokens. This wrapper defaults to `type="button"`; pass `type="submit"` when it submits a form. Check existing form call sites because a native button without a type defaults to submission.

This example replaces a visual wrapper. Preserve any existing ref forwarding, polymorphic `as` prop, or event behavior separately before replacing a component with a wider contract.

If the project needs a named component class, keep the `@theme` block above and add a component layer below it:

```css name=app.css
@import "@master/css";

@layer components {
  .btn {
    display: inline-flex;
    align-items: center;
    justify-content: center;
    border-radius: var(--radius-lg);
    gap: var(--spacing-xs);
    padding-block: 0;
    padding-inline: var(--spacing-md);
    background-color: var(--color-primary);
    color: oklch(100% 0 none);
    min-height: 2.5rem;
    &:hover {
      background-color: var(--color-blue-70);
    }
    &:disabled { opacity: 0.5; }
  }
}
```

```html
<button type="button" class="btn">Save</button>
```

## Convert variants to class maps
Avoid building Master CSS class names from string fragments. Static rendering and linting work best with complete class strings.

```tsx
const toneClasses = {
  neutral: 'bg-surface-base fg-text-body b-line-divider border-style:solid border-width:1px',
  primary: 'bg-blue-60 fg-white bg-blue-70:hover',
  danger: 'bg-red-70 fg-white bg-red-80:hover'
}

const sizeClasses = {
  sm: 'height:2rem px-sm font-sm',
  md: 'height:2.5rem px-md font-sm',
  lg: 'height:3rem px-lg font-md'
}

type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> & {
  tone?: keyof typeof toneClasses
  size?: keyof typeof sizeClasses
}

export function Button({ tone = 'primary', size = 'md', className, type = 'button', ...props }: ButtonProps) {
  return (
    <button
      className={['display:inline-flex align-items:center r-md', sizeClasses[size], toneClasses[tone], className].filter(Boolean).join(' ')}
      type={type}
      {...props}
    />
  )
}
```

When a variant controls more than visual styles, keep the prop and only migrate the visual declarations.

Appending `className` preserves the caller's classes; it does not make them win over conflicting utilities. HTML class order does not decide the [cascade](/guide/cascade-layers). Use the variant props to select one value, or put overridable defaults in `@layer components` so caller utilities can override them.

## Use CSS variables for dynamic values
Runtime values should not become generated class names. Keep the class static and pass the changing value through a CSS variable.

```tsx
export function Meter({ value }: { value: number }) {
  const percent = Number.isFinite(value) ? Math.max(0, Math.min(100, value)) : 0
  return (
    <div role="progressbar" aria-label="Progress" aria-valuemin={0} aria-valuemax={100} aria-valuenow={percent}
      className="overflow:hidden height:0.5rem border-radius:100% bg-gray-10">
      <div
        className="height:100% width:var(--value) bg-green-60 transition-property:width transition-duration:var(--duration-fast)@motion-safe transition-timing-function:var(--easing-smooth)"
        style={{ '--value': `${percent}%` } as React.CSSProperties}
      />
    </div>
  )
}
```

Keep CSS-in-JS for cases where the component must create selectors, keyframes, or style blocks from runtime data that cannot be represented clearly with CSS variables.

## Move global styles carefully
Global styles often contain real app infrastructure. Move them in small groups.

```tsx name=GlobalStyles.tsx
import { Global, css } from '@emotion/react'

export function GlobalStyles() {
  return <Global styles={css`
    body {
      margin: 0;
      background: var(--color-surface-base);
    }
  `} />
}
```

```css name=app.css
@import "@master/css";

@layer base {
  body {
    margin: 0;
  }
}

@layer defaults {
  body { background: var(--color-surface-base); }
}
```

Keep CSS-in-JS global styles until the replacement CSS entry is loaded in every route, shell, and server-rendered path that previously received them.

---

## Validate the migration
- Run formatter, lint, type check, tests, and production build after each batch.
- Compare server-rendered output if the CSS-in-JS setup had SSR extraction or hydration logic.
- Check dark mode, responsive breakpoints, hover, focus-visible, disabled, selected, and polymorphic `as` states.
- Remove Babel plugins, Emotion cache setup, styled-components SSR wiring, and package dependencies only after no remaining component needs them.
