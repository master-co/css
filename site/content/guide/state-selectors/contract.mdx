<a id="overview"></a>

A selector suffix determines which element or pseudo-element receives a class's declarations. The element carrying the complete class is the starting point: a suffix can test that element, select a related element, or do both.

This page defines selector attachment, encoding, grouping and specificity. The [Syntax tutorial](/guide/syntax-tutorial#states) teaches how to add hover and keyboard-focus styles to a component; [CSS selectors](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Selectors/Selectors_and_combinators) defines native matching behavior.

## Selector attachment \{#basic-selectors\}

Append the selector to a registered utility or to the closing parenthesis of a native declaration. Place any [condition](/reference/rules/conditions) after the selector, and importance at the end:

```txt
utility<selector><conditions>!
(property:value)<selector><conditions>!
```

The angle-bracket parts and `!` above are optional syntax placeholders. For example, `underline:hover@sm` applies the underline when the class-bearing element is hovered and the viewport matches `@sm`. The condition does not change which element the selector targets.

<Class2CSS classes={['underline:hover@sm', '(text-decoration-thickness:2px):hover@sm']} />

Master CSS escapes the complete class name in the generated CSS selector. The colon inside `.underline\:hover` is part of that literal class name; the appended `:hover` is the actual pseudo-class. Write the unescaped class in HTML, as shown in the examples.

## Matching the class-bearing element \{#matching-the-owner\}

Without a combinator, the suffix adds a requirement to the element carrying the class. `underline.active` matches only an element with both `underline.active` and `active` in its class list.

```html
<a class="underline.active active" href="/guide/installation">Installation</a>
```

<a id="class"></a>
<a id="id"></a>
<a id="attribute"></a>
<a id="pseudo-class"></a>
<a id="element"></a>
<a id="--universal"></a>

| Class | Requirement on the class-bearing element |
| --- | --- |
| `underline.active` | Also has the class `active` |
| `underline#current` | Has the ID `current` |
| `underline[data-current]` | Has the attribute `data-current` |
| `underline:hover` | Matches the browser's hover state |
| `underline:is(a)` | Is an `a` element |

<Class2CSS classes={['underline.active', 'underline#current', 'underline[data-current]', 'underline:hover', 'underline:is(a)']} />

For a type check on the same element, use `:is(a)` or `:where(a)`. To select its children, use `>a` or `>*`. A bare tag name immediately after a utility name is not a separate selector suffix.

### Combined requirements \{#combined-requirements\}

Adjacent simple selectors describe the same element. `underline:hover:not([aria-disabled=true])` requires hover and excludes an element whose `aria-disabled` attribute is `true`. It does not set or update that attribute.

<Class2CSS classes={['underline:hover:not([aria-disabled=true])']} />

Selectors respond to DOM and browser state; they do not create interaction behavior. Native attributes and ARIA retain their own semantics. In particular, `aria-disabled="true"` describes a disabled state but does not itself prevent activation.

## Related elements \{#combinators\}

A combinator moves from the class-bearing element to another element. The declaration is applied to the element at the end of the selector, rather than inherited from the class-bearing element.

<a id="_--descendant"></a>
<a id="--child"></a>
<a id="--adjacent-sibling"></a>
<a id="--general-sibling"></a>

| Class | Target |
| --- | --- |
| `underline_a` | Descendant links at any depth |
| `underline>a` | Direct child links |
| `underline+a` | The next element sibling, if it is a link |
| `underline~a` | All later sibling links with the same parent |
| `underline>*` | Every direct child element |

`_` encodes the descendant space between selectors. An actual space in HTML would start another class. `>`, `+` and `~` keep their native CSS meanings.

### State position \{#state-position\}

The position of a state determines which element must match it. These two classes share the same parent-to-child relationship but test hover at different points:

| Class on the article | Hover requirement | Underlined links |
| --- | --- | --- |
| `underline:hover>a` | The article is hovered | All direct child links |
| `underline>a:hover` | A direct child link is hovered | That link only |

<ReferenceIllustration id="selector-targets" />

<DocumentExample>

```html
<article class="underline:hover>a">
  <p>Documentation</p>
  <a class="(text-decoration-line:none)" href="/guide/installation">Installation and setup</a>
  <a class="(text-decoration-line:none)" href="/reference/packages">API reference</a>
</article>

<article class="underline>a:hover">
  <p>Documentation</p>
  <a class="(text-decoration-line:none)" href="/guide/installation">Installation and setup</a>
  <a class="(text-decoration-line:none)" href="/reference/packages">API reference</a>
</article>
```

<Class2CSS classes={['(text-decoration-line:none)', 'underline:hover>a', 'underline>a:hover']} />

</DocumentExample>

Hovering a link also hovers its ancestor article. In the first example, that makes both links eligible; in the second, the other link still fails its own `:hover` test. The article owns each class, but the declarations target its links. The link classes remove the default underline; the more specific parent-to-child selectors restore it when their hover tests match.

## Selector lists \{#selector-groups\}

A top-level comma starts another branch from the same class-bearing element. Repeat each branch's combinator: `block>div,>span` targets direct `div` children and direct `span` children. The second branch does not continue from the first branch's target.

<DocumentExample>

```html
<section class="block>div,>span">
  <div>First child</div>
  <span>Second child</span>
</section>
```

<Class2CSS classes={['block>div,>span', "(content:'“')::before,::after"]} />

</DocumentExample>

Commas inside functions or quoted attribute values stay inside those constructs. `underline:is(:hover,:focus-visible)` contains one selector suffix with two alternatives, rather than two top-level branches.

<Class2CSS classes={['underline:is(:hover,:focus-visible)', "underline[data-label='draft,review']"]} />

### Selector functions \{#selector-functions\}

<a id="not"></a>
<a id="has"></a>

| Function | Matching behavior |
| --- | --- |
| `:is(...)` | Matches at least one selector in the list |
| `:where(...)` | Matches like `:is()`, with zero specificity from the function and its arguments |
| `:not(...)` | Excludes elements matching any selector in the list |
| `:has(...)` | Tests for a relative match from the element being selected |

`:has()` tests a relationship without moving the declaration to the matched relative. `b-blue-60:has(>input:checked)` sets the label's border color when its direct child input is checked:

<DocumentExample>

```html
<label class="b(1) b-solid b-line-control b-blue-60:has(>input:checked)">
  <input type="checkbox" /> Include archived items
</label>
```

<Class2CSS classes={['b-blue-60:has(>input:checked)', 'underline:has(+input:checked)']} />

</DocumentExample>

A relative match can also be a sibling: `underline:has(+input:checked)` underlines the class-bearing element when the next element sibling is a checked input. Native [`:has()` restrictions](https://www.w3.org/TR/selectors-4/#relational) still apply; nesting `:has()` inside itself is invalid. For a working checkbox example and a usable fallback, see [Compatibility](/guide/compatibility#new-selectors).

## Native states \{#pseudo-classes\}

<a id="hover--active--focus"></a>
<a id="first--last--odd--even"></a>

<a id="disabled"></a>

<a id="rtl--ltr"></a>

Master CSS preserves native pseudo-class names. The following are common suffixes, not an exhaustive state registry:

| Suffix | Native matching context |
| --- | --- |
| `:hover`, `:active` | Pointer hover or activation |
| `:focus`, `:focus-visible`, `:focus-within` | Focus on the element, visible focus indication, or focus within it |
| `:first-child`, `:last-child`, `:nth-child(even)` | Position among element siblings |
| `:valid`, `:invalid`, `:required` | Native form constraints |
| `:disabled` | Disabled form controls |
| `:checked`, `:indeterminate` | Native control state |
| `:dir(rtl)`, `:dir(ltr)` | Resolved text direction |

Use complete names such as `:first-child` and `:nth-child(odd)`. A spelling that Master CSS emits can still be unsupported or invalid in the browser. The [native pseudo-class reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Pseudo-classes) owns each state's detailed behavior.

<DocumentExample>

```html
<ul>
  <li class="bg-surface-inset:nth-child(even)">Draft</li>
  <li class="bg-surface-inset:nth-child(even)">In review</li>
  <li class="bg-surface-inset:nth-child(even)">Published</li>
</ul>
```

## Attribute selectors \{#attribute-selectors\}

Attribute suffixes test the DOM value. A boolean-style attribute selector tests presence: `[open]` matches an expanded `details` element, and `[data-active]` matches whenever that attribute exists. To test a particular state value, include the value, as in `[aria-pressed=true]`.

<a id="open"></a>
<a id="aria-keyvalue"></a>
<a id="data-keyvalue"></a>
<a id="attrvalue"></a>
<a id="attrvalue-1"></a>
<a id="attrvalue-2"></a>
<a id="attrvalue-3"></a>
<a id="attrvalue-4"></a>
<a id="attrvalue-5"></a>

| Suffix | Match |
| --- | --- |
| `[data-active]` | Attribute is present, even with an empty value |
| `[aria-pressed=true]` | Exact value `true` |
| `[href^=https]` | Value starts with `https` |
| `[href$='.pdf']` | Value ends with `.pdf` |
| `[title*=master]` | Value contains `master` |
| `[lang\|=en]` | Value is `en` or begins `en-` |
| `[title~=css]` | Whitespace-separated value contains the word `css` |

<ReferenceIllustration id="attribute-word-match" />

Quoted attribute text remains literal: `underline[data-state=':first']:first-child` tests the value `:first` and separately tests the element's position. An underscore in `[data-id='a_b']` stays inside the value; an escaped underscore in `.is\_active` stays in the class identifier.

<DocumentExample>

```html
<a class="underline[data-state=':first']:first-child" data-state=":first" href="/guide">Guide</a>
<a class="underline.is\_active is_active" href="/reference">Reference</a>
```

<Class2CSS classes={["underline[data-state=':first']:first-child", "underline[data-id='a_b']", 'underline.is\\_active']} />

</DocumentExample>

CSS quotes do not prevent HTML whitespace from splitting a class. Use a CSS escape for a literal space in an attribute value, such as `[data-label='New\000020collection']`. A quoted value can be followed directly by a case flag, as in `[data-kind='draft'i]` for an ASCII case-insensitive match. See [attribute selectors](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Attribute_selectors) for native operators and case matching.

<Class2CSS classes={["underline[data-label='New\\000020collection']", "underline[data-kind='draft'i]"]} />

A pseudo-element suffix targets that pseudo-element rather than its originating element. For generated content, write the `content` declaration explicitly:

```html
<span class="(content:open-quote)::before (content:close-quote)::after">

</span>
```

Write vendor-specific selectors explicitly. Master CSS preserves their spelling; it does not expand a pseudo-element into vendor variants or supply browser support. For quoted values containing parentheses, see [native declaration boundaries](/reference/rules/declarations#declaration-heads).

## Specificity \{#specificity\}

The generated selector follows the browser's [specificity rules](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Specificity). Its escaped class name contributes one class selector, regardless of punctuation inside that name. The appended suffix contributes separately.

| Class | ID – class/attribute/state – type/pseudo-element |
| --- | --- |
| `underline` | `0-1-0` |
| `underline:hover` | `0-2-0` |
| `underline>a` | `0-1-1` |
| `underline:where(:hover,#selected)` | `0-1-0` |
| `underline:is(:hover,#selected)` | `1-1-0` |

`:is()`, `:not()` and `:has()` use the most specific argument in their selector list. `:where()` adds no specificity, including from its arguments. Combinators and the universal selector add none. These weights apply after the cascade has resolved origin, importance and layer precedence; a higher-specificity selector does not automatically defeat a rule in another layer.

<Class2CSS classes={['underline:where(:hover,#selected)', 'underline:is(:hover,#selected)']} />

<ReferenceIllustration id="where-specificity" />

Use [Cascade layers](/reference/rules/layers) for rule ordering and [the Guide's override workflow](/guide/cascade-layers#override-a-component-locally) for practical decisions. Reordering classes in HTML does not change specificity.

## External context \{#external-context\}

<a id="of"></a>

A suffix starts at the class-bearing element. When a target needs styles based on an ancestor or preceding sibling, a native CSS rule can state that relationship directly:

```css
@layer components {
  .active .contextual { display: none; }
  .active > .child-contextual { display: none; }
  .active + .adjacent-contextual { display: none; }
  .active ~ .sibling-contextual { display: none; }
}
```

To wrap several utility declarations in the same relationship, use a mixin with a native selector and `@contents`. The [mixin contents contract](/reference/directives/definitions#contents) owns expansion and forwarding; [Reusing styles](/guide/reusing-styles#share-a-wrapper-with-contents) explains when to choose this form.

Generated CSS is evidence of emission, not proof that the browser supports or matches the selector. Check the DOM relationship, actual state and native selector validity. In an ordinary CSS selector list, an invalid branch can invalidate the whole list; `:is()` and `:where()` use [forgiving lists](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Selector_list). [Compatibility](/guide/compatibility) owns browser checks and fallback design.
