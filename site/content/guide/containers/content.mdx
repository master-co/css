## Overview [sr-only]
A reusable card should adapt to the space its parent gives it. Create an ancestor query container, then change the card's layout when its content has room for a second column. Use [Breakpoints](/guide/breakpoints) for viewport-wide decisions.

## Create a query container
Add `(container-type:inline-size)` to an ancestor whose inline size comes from the surrounding layout. Then apply full `@container((width>=28rem))` queries to its descendants. A [size query](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries) cannot select the element itself as its query container.

```html
<section class="(container-type:inline-size)">
  <!-- @MARK grid-cols(2)@container((width>=28rem)) -->
  <article class="grid-cols(1) gap-lg grid-cols(2)@container((width>=28rem))">
    <div>
      <h2>Flexible workspace</h2>
      <p>A quiet desk with natural light.</p>
    </div>
    <div>
      <h3>Plan your visit</h3>
      <p>Available for a full day or an afternoon.</p>
    </div>
  </article>
</section>
```

<Class2CSS>
  {['(container-type:inline-size)', 'grid-cols(1)', 'grid-cols(2)@container((width>=28rem))', 'gap-lg']}
</Class2CSS>

Resize the preview across `28rem`: the two child regions form one column below that width and two columns at or above it.

Container queries make components portable. The same card can be stacked in a sidebar and split into columns in a wide content region without knowing the viewport width.

Container queries use explicit native thresholds. Changing `--container-md` does not change `(width>=28rem)`; container tokens only supply sizing declarations. See [Sizing](/guide/sizing#use-container-tokens) for width caps and [conditions](/reference/rules/conditions#containersize) for the complete query contract.

## Choose a component threshold \{#container-query-scale\}
Resize the component in both a sidebar and a wide content region. Add a second column only when the description and visit details each have enough space. Test with longer headings and enlarged text as well. The `28rem` example is a local design decision, not a lookup of `--container-md`.

## Query container ranges
Use native CSS range and logical operators when a component needs a bounded range.

```html
<!-- @MARK hidden@container((24rem<=width<=28rem)) -->
<div class="hidden@container((24rem<=width<=28rem))">...</div>
```

<Class2CSS>
  {['hidden@container((24rem<=width<=28rem))']}
</Class2CSS>

Keep a one-off threshold beside the class that uses it. Share a repeated condition with a [mixin wrapper](/reference/directives/definitions#contents). A container name belongs inside the full query; an unknown `@name` does not select a container.

---

## Use named containers
Use a name when a descendant should query an outer container instead of the nearest eligible one.

```html
<!-- @MARK (container-name:card) (container-type:inline-size) -->
<section class="(container-name:card) (container-type:inline-size)">
  <!-- @MARK @container(card|(width>=16rem)) -->
  <article class="grid-cols(2)@container(card|(width>=16rem))">...</article>
</section>
```

<Class2CSS>
  {['(container-name:card) (container-type:inline-size)', 'grid-cols(2)@container(card|(width>=16rem))']}
</Class2CSS>

In this nested example, both query results live inside a container capped at `14rem`. The first query selects that nearest container. The second selects the ancestor named `outer`, whose width changes with the preview.

The browser [selects an eligible ancestor before evaluating the query](https://drafts.csswg.org/css-conditional-5/#container-rule). A false size condition does not make an unnamed query keep searching wider ancestors. A name filters that ancestor selection; if several eligible ancestors share the name, the nearest one is selected. Use names for boundaries that need to be addressed from deeper components, and omit them when the nearest container already owns the decision.

## Choose caps or queries
Use [Sizing](/guide/sizing#use-container-tokens) to limit a wrapper's width. Use a query to change its descendants when that wrapper grows or shrinks.

(x) A reusable card depends on the viewport, so it changes at the wrong time inside narrow parents.

```html
<article class="grid-cols(2)@md">...</article>
```

(o) The card depends on the space it receives.

```html
<section class="(container-type:inline-size)">
  <article class="grid-cols(2)@container((width>=28rem))">...</article>
</section>
```

(i) If a layout rule describes the whole page, use [breakpoints](/guide/breakpoints). If it describes a reusable component use container queries.
