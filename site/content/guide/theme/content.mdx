## Overview [sr-only]
Define a token when several elements should share a design value. Put it in `@theme`, then use the matching class in markup. Changing the token updates its consumers together.

Master CSS resolves token names when generating class rules. Values stay as CSS custom properties; the browser computes the active value in each scope. A referenced token retains its declarations and transitive dependencies. Native overrides follow stylesheet delivery.

---

## Project CSS entry
A project needs a CSS entry that marks the Master CSS graph. Put shared tokens in the stylesheet that imports `@master/css`, or in CSS already imported by that entry.

```css name=index.css
@import '@master/css';

@theme {
  --color-brand: #4f46e5;
}

```

The important part is the graph, not a special file name. Theme tokens can live wherever the project CSS entry already reaches them.

## Define tokens
Write custom properties directly in `@theme` for on-demand tokens in the default `:root, :host` scope. Use native selectors outside the block for scoped overrides. Write the full token name with the leading `--`; the prefix places the value in a namespace that Master CSS utilities already understand. Only theme declarations register named utility tokens.

```css name=index.css
@theme {
  --color-brand: #4f46e5;
  --color-text-action: var(--color-brand);
  --spacing-card: 1.5rem;
  --font-family-sans: Geist, ui-sans-serif, system-ui, sans-serif;
  --radius-card: 1rem;
  --container-panel: 28rem;
}
```

Use token names that describe the shared decision, not the first component that needed the value. A `brand` color, `lg` spacing step, or `card` shadow can be reused. A token named after one button or one modal usually belongs closer to that component.

---

## Use tokens
Utilities resolve token values from the namespace they use. The same short key can mean spacing in `p-lg`, radius in `r-lg`, a container width in `max-w-md`, while `@md` names a separately declared custom media condition.

```html
<!-- @MARK p-card --><!-- @MARK r-card --><!-- @MARK font-sans -->
<article class="p-card r-card font-sans bg-surface-raised shadow-sm">
  <h2>Dashboard</h2>
  <a class="fg-text-blue" href="/settings">Settings</a>
</article>
```

For a deeper explanation of namespace resolution and contextual lookup, see [Variables and Modes](/guide/variables-and-modes#namespace-resolution).

## Alias and override tokens
Use native CSS `var()` when a token should reference another token. This keeps semantic roles tied to a smaller set of foundation values.

Aliases resolve where they are declared. If `--color-text-action` is declared at the root, overriding only `--color-brand` in a descendant does not rebind that inherited alias. Redeclare the alias in the descendant scope or override the semantic token directly.

```css name=index.css
@theme {
  --color-brand: #4f46e5;
  --color-text-action: var(--color-brand);
}

```

Define the same token key as a preset token when you want to override it. Declarations retain author order, including duplicate fallbacks. Normal CSS specificity, conditions, and cascade order determine the winning value.

```css name=index.css
@theme {
  --color-blue: #4589ff;
  --spacing-lg: 1.625rem;
}

```

Use overrides intentionally. If the whole product should use a different `blue` or `lg`, override the preset token. If only one product role changes, create a semantic token such as `color-text-action` or `shadow-card`.

## Add mode-aware values
Use `light-dark()` for a color that should follow the element's color scheme. The same classes then work with the system preference, a manual theme switch or a nested light/dark region.

```css name=index.css
@theme {
  --color-surface-card: light-dark(#ffffff, #18181b);
  --color-text-card: light-dark(#27272a, #f4f4f5);
  --shadow-card: 0 4px 16px light-dark(rgb(0 0 0 / .1), rgb(0 0 0 / .4));
}
```

```html
<!-- @MARK bg-surface-card --><!-- @MARK fg-text-card --><!-- @MARK shadow-card -->
<article class="bg-surface-card shadow-card fg-text-card">...</article>
```

Keep the token name mode-neutral. Markup should say `bg-surface-card` or `fg-text-card`, not `dark-card`.

The preset enables native `color-scheme: light dark`. Set `data-theme="light"` or `data-theme="dark"` to make an explicit choice. Use native selectors or media queries outside `@theme` for other scoped changes; media queries follow the system preference. See [Colors](/guide/colors#native-color-scheme-and-manual-themes) for manual and nested themes.

## Choose token delivery and value substitution
Ordinary tokens emit on demand and utilities reference their custom properties. Use `static` for values consumed by integrations independently of utility classes:

```css
@theme static { --color-integration-brand: #4f46e5; }
```

Use `inline` to bridge a native variable that should resolve on the element using the utility:

```css
@theme inline { --color-brand: var(--app-brand); }
:root { --app-brand: #4f46e5; }
[data-theme="ocean"] { --app-brand: #0369a1; }
```

`bg-brand` emits `background-color:var(--app-brand)`. Combine the independent behaviors with `@theme static inline`. Inline substitution also applies to utility classes and `@apply`; handwritten native CSS keeps its authored references.

## Define responsive tokens
Define viewport conditions with `@custom-media`. Container tokens supply width caps; container queries use explicit native thresholds. A `--breakpoint-*` custom property does not register a condition.

```css name=index.css
@theme {
  --container-sm: 24rem;
  --container-md: 28rem;
  --container-lg: 32rem;
}

@custom-media --sm (width >= 40rem);
@custom-media --md (width >= 48rem);
@custom-media --lg (width >= 64rem);
```

```html
<!-- @MARK grid-cols(2)@md --><!-- @MARK grid-cols(3)@lg --><!-- @MARK max-w-lg --><!-- @MARK grid-cols(2)@container((width>=28rem)) -->
<div class="grid-cols(1) gap-md grid-cols(2)@md grid-cols(3)@lg">
  ...
</div>

<aside class="container-type:inline-size max-w-lg">
  <article class="grid-cols(1) grid-cols(2)@container((width>=28rem))">
    ...
  </article>
</aside>
```

Keep named viewport conditions broad and product-wide. Use container queries when a reusable component should respond to the space it receives. Changing a container token does not change a literal query threshold. See [Breakpoints](/guide/breakpoints) and [Container queries](/guide/containers).

## Define motion tokens

<a id="animation-tokens-and-definitions"></a>
Motion values can be tokens too. Put complete animation shorthands, durations, and easing curves in `@theme`. Write keyframes as native top-level CSS and import their stylesheet wherever the animation is needed.

```css name=index.css
@theme {
  --duration-enter: 180ms;
  --easing-standard: cubic-bezier(.4, 0, .2, 1);
  --animate-dialog-in: dialog-in var(--duration-enter) var(--easing-standard) both;
}
@keyframes dialog-in {
  from { translate: 0 0.5rem; opacity: 0; }
  to { translate: 0; opacity: 1; }
}

```

```html
<!-- @MARK animate-dialog-in -->
<dialog class="animate-dialog-in"></dialog>
```

Keyframes stay in their imported stylesheet by default. Add `@prune native;` to their owning file for usage-based delivery; referenced animation tokens retain their definitions. `@reference` supplies compilation context without importing native rules. See [Motion](/guide/motion) for a working entrance and [Animation tokens](/reference/tokens/animate) for the full contract.
