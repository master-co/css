## 개요 [sr-only] \{#overview\}
카드 간격, 동작 색상, 본문 열 너비처럼 여러 요소가 함께 바뀌어야 할 때 토큰을 정의하세요. 앱 스타일시트의 기존 `@import '@master/css'` 뒤에 `@theme`으로 작성하고 마크업에서 대응하는 클래스를 사용합니다.

<DemoConfiguredExample name="theme-first-card" title="세 공유 값으로 만든 카드" source={`@theme {
  --color-brand: #4f46e5;
  --spacing-card: 1.5rem;
  --radius-card: 0.5rem;
}`} html={'<article class="max-w-sm mx-auto p-card r-card bg-surface-raised fg-text-body shadow-sm"><p class="flex items-center gap-xs m(0) text-xs fg-text-muted"><span aria-hidden="true" class="h(8) w(8) pill bg-brand"></span>Brand color</p><h2 class="mt-sm mb-xs text-lg font-regular">Field notes</h2><p class="m(0) text-sm fg-text-muted">Keep the details that matter.</p></article>'} caption="p-card와 r-card가 공유 안쪽 여백과 모서리 반경을 설정합니다. 작은 표시는 bg-brand로 카드의 중립색 표면을 바꾸지 않고 색상 토큰을 보여 줍니다." />

`p-card`는 `padding: var(--spacing-card)`를 생성하며 브라우저가 카드 요소에서 사용자 지정 속성을 해석합니다. 모든 사용 측을 함께 바꿔야 하면 토큰을 수정하고, 한 요소만의 변경이라면 로컬 값을 사용하세요.

## 하나의 값으로 모든 사용 측 변경하기 \{#change-one-value-across-its-consumers\}

`--spacing-card`는 카드 안쪽 여백과 목록 간격을 모두 제공할 수 있습니다. 값을 `1.5rem`에서 `2rem`으로 바꾸면 마크업을 편집하지 않고 두 곳이 함께 바뀝니다:

```html
<article class="p-card">Field notes</article>
<ul class="flex gap-card">
  <li>Draft</li>
  <li>Ready</li>
</ul>
```

<ThemeIllustration />

이 연동은 디자인 결정입니다. 카드는 여유롭게 하되 목록 간격은 유지해야 한다면 별도 토큰을 사용하세요. 지금 같은 수치를 쓴다는 이유만으로 두 인터페이스 부분이 항상 함께 바뀌어야 하는 것은 아닙니다.

## 네임스페이스에 따라 토큰 명명하기 \{#define-tokens\}

토큰 접두사가 네임스페이스를 선택하고 각 클래스 계열은 자신이 지원하는 네임스페이스를 읽습니다. `--spacing-card`는 `p-card`, `m-card`, `gap-card`에, `--radius-card`는 `r-card`에, `--container-panel`은 `max-w-panel`에 쓰입니다. 같은 키도 계열에 따라 다른 값이 될 수 있습니다. `p-lg`는 간격을, `r-lg`는 반경을 읽습니다.

```css name=index.css
@theme {
  --color-text-action: var(--color-brand);
  --font-family-sans: Geist, ui-sans-serif, system-ui, sans-serif;
  --container-panel: 28rem;
}
```

클래스 토큰을 등록하는 것은 `@theme` 선언뿐이며 다른 위치의 네이티브 사용자 지정 속성은 등록하지 않습니다. 처음 사용한 컴포넌트가 아닌 `brand`, `card` 같은 공유 결정에 따라 이름을 지으세요. `--spacing-lg` 같은 프리셋 키를 재정의하면 프로젝트 전체의 값을 바꿀 수 있습니다. 클래스별 네임스페이스는 [계열 색인](/reference/tokens/families), 해석 방식은 [변수와 모드](/reference/rules/modes#namespace-resolution)를 참고하세요.

## 토큰 별칭과 재정의 \{#alias-and-override-tokens\}

한 토큰이 다른 토큰을 따르게 하려면 `var()`를 사용하세요. [별칭은 상속 전에 해석됩니다](https://www.w3.org/TR/css-variables-1/#cycles). 루트에서 `--color-text-action`을 선언했다면 자손에서 `--color-brand`를 덮어써도 상속된 별칭은 다시 연결되지 않습니다. 해당 범위에서 별칭을 재선언하세요.

<DemoConfiguredExample name="theme-local-alias" title="로컬 브랜드 색상과 상속된 별칭" source={`@theme {
  --color-brand: light-dark(#1d4ed8, #93c5fd);
  --color-text-action: var(--color-brand);
}

@layer components {
  [data-brand="plum"] {
    --color-brand: light-dark(#86198f, #f0abfc);
  }
  [data-rebind-action] {
    --color-text-action: var(--color-brand);
  }
}`} html={'<section data-brand="plum" class="p-lg r-lg bg-surface-raised"><h2 class="m(0) text-lg font-regular fg-brand">Plum brand scope</h2><p class="mt-md mb(0) text-sm font-regular fg-text-action">Inherited action: blue</p><p data-rebind-action class="mt-sm mb(0) text-sm font-regular fg-text-action">Rebound action: plum</p></section>'} caption="두 동작 레이블 모두 fg-text-action을 사용합니다. 첫 번째는 루트에서 계산된 별칭을 상속하고, 두 번째는 --color-brand가 자두색인 범위에서 별칭을 재선언합니다." />

<GuideStudy id="inherited-alias" />

라이트 및 다크 모드를 따르는 색상에는 토큰 값으로 `light-dark()`를 사용하고 `--color-surface-card`처럼 모드와 무관한 이름을 유지하세요. 모드 활성화는 [색상](/guide/colors#native-color-scheme-and-manual-themes)을 참고하세요.

## 토큰 전달과 값 치환 선택하기 \{#choose-token-delivery-and-value-substitution\}
두 수정자는 서로 다른 질문에 답합니다:

| 요구 사항 | 선택 | 결과 |
| --- | --- | --- |
| 프로젝트에서 사용할 때 값 출력 | 일반 `@theme` | 필요할 때 선언하며 클래스는 토큰 참조를 유지합니다. |
| 사용 측이 발견되지 않아도 값 유지 | `@theme static` | 외부 통합 등에서 토큰 선언을 계속 사용할 수 있습니다. |
| 스타일이 적용된 각 요소에서 참조 변수 해석 | `@theme inline` | 생성 선언에서 토큰 값을 한 번 치환합니다. |

정적 탐색이 볼 수 없는 통합에서 읽는 값에는 `static`을 사용하세요:

```css
@theme static { --color-integration-brand: #4f46e5; }
```

클래스를 사용하는 요소에서 해석해야 하는 네이티브 변수를 연결하려면 `inline`을 사용하세요:

```css
@theme inline { --color-brand: var(--app-brand); }
:root { --app-brand: #4f46e5; }
[data-theme="ocean"] { --app-brand: #0369a1; }
```

```html
<section data-theme="ocean">
  <div class="bg-brand">Ocean background</div>
</section>
```

여기서 `bg-brand`는 `background-color: var(--app-brand)`를 출력하므로 내부 요소는 section에서 상속된 ocean 값을 읽습니다. 치환은 중간 `--color-brand` 참조를 제거하며 모든 요소에 고정 색상을 복사하는 것은 아닙니다.

두 동작이 모두 필요하다면 `@theme static inline`으로 수정자를 조합하세요. 인라인 치환은 클래스와 `@apply`에 적용되며 직접 작성한 네이티브 CSS는 기존 참조를 유지합니다. [테마 계약](/reference/directives/theme#theme-static)을 참고하세요.

## 모션 토큰 정의하기 \{#define-motion-tokens\}

<a id="animation-tokens-and-definitions"></a>

`--animate-*` 토큰은 완전한 `animation` 단축 속성이므로 키프레임 이름, 지속 시간, 이징 토큰을 조합할 수 있습니다. 키프레임은 그 옆에 네이티브 CSS로 작성하세요:

<DemoDialogEntrance />

```css name=index.css
@theme {
  --duration-enter: 180ms;
  --easing-emphasized: cubic-bezier(.16, 1, .3, 1);
  --animate-dialog-in: dialog-in var(--duration-enter) var(--easing-emphasized) both;
}

@keyframes dialog-in {
  from { translate: 0 0.5rem; opacity: 0; }
}
```

```html
<!-- @MARK animate-dialog-in@motion-safe -->
<dialog class="animate-dialog-in@motion-safe">…</dialog>
```

이 토큰에는 반복 횟수가 없으므로 진입 애니메이션이 한 번 실행됩니다. 프리셋의 `animate-*` 토큰은 반복됩니다. 동작 줄이기를 요청하면 `@motion-safe`가 대화 상자를 정지 상태로 유지합니다. 키프레임은 기본적으로 스타일시트에 남으며, `@prune native`에서는 참조된 애니메이션 토큰이 자신의 키프레임을 유지합니다. JavaScript만 적용하는 이름에는 `@safelist keyframes "dialog-in";`을 추가하세요. [모션](/reference/tokens/motion)과 [키프레임 계약](/reference/directives/pruning#native-keyframes)을 참고하세요.
