## Overview [sr-only]
The Master CSS Language Service brings the project manifest into the editor. It reads project tokens, utility recipes, mixins, custom media, selectors and conditions, then uses that context for completion, hover previews, highlighting, color tools, directive formatting and diagnostics in class strings and stylesheets.

---

## Set up VS Code \{#set-up-vs-code\}
Install the official [Master CSS extension](https://marketplace.visualstudio.com/items?itemName=masterco.master-css-vscode) for language-service features, and the [ESLint extension](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint) for class policy diagnostics and sort-on-save once the project has [Code linting](/guide/code-linting) set up. The extension finds project context through a CSS entry that imports `@master/css` or a `package.json` that declares a Master CSS package.

Enable suggestions inside strings, and restrict ESLint's save action to class sorting:

```json name=.vscode/settings.json
{
  "editor.quickSuggestions": {
    "strings": true
  },
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "eslint.codeActionsOnSave.rules": [
    "@master/css/sort-classes"
  ]
}
```

The rule list alone does not turn on fixes when saving, and the ESLint extension's `problems` mode ignores the filter; keep `eslint.codeActionsOnSave.mode` at its default `all`. See the [ESLint extension settings](https://github.com/microsoft/vscode-eslint#settings-options).

## Editor features
### Syntax suggestions
Completion works inside configured class sources: markup attributes, bound framework attributes, JavaScript helper calls, tagged templates and project-specific class declarations. Suggestions include utilities, property values, color tokens, selectors, queries and directive syntax, and project tokens appear once the workspace manifest loads.

### Hover inspection
Hovering a class such as `bg-blue-60:hover@sm` previews the CSS Master CSS emits for it, including its selector state and query.

```html
<button class="bg-blue-70 fg-white bg-blue-60:hover@sm">
  Save
</button>
```

### Syntax highlighting
The extension highlights directive syntax in CSS-family documents and uses semantic tokens for class-list spans: declaration, value, selector, query, unit, important marker, quoted segment and component boundaries. By default it highlights only the class string under the cursor, keeping long markup calm. If semantic colors do not appear, enable semantic highlighting in the active VS Code theme.

Shiki code examples use the same quiet default for markup class attributes, with pointer hover in place of the cursor. Import the public stylesheet alongside `transformerMasterCSS`:

```ts
import '@master/css-language-service/shiki.css'
import { transformerMasterCSS } from '@master/css-language-service/shiki'
```

### Color tools
Master CSS color utilities and manifest colors use VS Code color decorators and the color picker. Keep both `masterCSS.renderSyntaxColors` and VS Code's [`editor.colorDecorators`](https://code.visualstudio.com/docs/languages/css) enabled.

### Directive formatting
Document and range formatting repairs directive source in CSS, SCSS and LESS documents and in CSS-family `<style>` blocks in Vue, Svelte and Astro, without changing generated CSS. For class-list directives it keeps important markers attached to their class: `@safelist "(background-color:transparent) !";` becomes `@safelist "(background-color:transparent)!";`.

### Diagnostics
The language server reports directive errors in the same documents and project manifest loading errors. Class-string syntax, policy and sorting diagnostics belong to [Code linting](/guide/code-linting) and are not duplicated. Language-server clients can also opt into token-reference checks for open managed CSS files with the `designSystem` setting, which takes the same [design-system options](/reference/tools/cli#design-system-options) as `master-css inspect`.

## Settings and class sources \{#supported-class-sources\}
Set options in `.vscode/settings.json` or VS Code user settings. The defaults cover HTML, PHP, JavaScript, TypeScript, JSX, TSX, CSS, SCSS, LESS, Vue, Svelte, Rust, Astro, Markdown and MDX.

| Setting | Default | Use |
| --- | --- | --- |
| `masterCSS.includedLanguages` | Common web and template language IDs | Languages that receive language-service features. |
| `masterCSS.classAttributes` | `class`, `className` | Markup attributes whose values contain class strings. |
| `masterCSS.classAttributeBindings` | Framework binding defaults | Bound attributes such as `:class`, `v-bind:class`, `[ngClass]` and `class:list`. |
| `masterCSS.classFunctions` | `clsx`, `cva`, `ctl`, `cv`, `class`, `classnames`, `classVariant`, `styled`, `classList.add/remove/toggle/replace` | Callees whose string arguments contain class strings; `styled` also accepts member forms such as `styled.button`. |
| `masterCSS.classDeclarations` | `[]` | Variables or object properties whose strings are class declarations. |
| `masterCSS.exclude` | `.git`, `node_modules`, `.hg` | Files excluded from all features. |
| `masterCSS.suggestSyntax` | `true` | Completion items. |
| `masterCSS.inspectSyntax` | `true` | Hover inspection and generated CSS previews. |
| `masterCSS.renderSyntaxColors` | `true` | Color decorators for Master CSS color syntax. |
| `masterCSS.formatDirectives` | `true` | Directive formatting. |
| `masterCSS.embeddedSyntaxHighlighting` | `active` | `active` highlights the class under the cursor, `always` every embedded class, `off` none; directive syntax stays highlighted. |
| `masterCSS.workspaces` | `auto` | Workspace detection for project manifests. |

Language-service arrays extend the built-in class sources; ESLint settings replace them instead:

```json name=.vscode/settings.json
{
  "masterCSS.classAttributes": ["ui"],
  "masterCSS.classDeclarations": ["classes", "styles"],
  "masterCSS.classFunctions": ["cn"]
}
```

## Workspace-aware manifests
In `auto` mode the language server detects a workspace for each CSS file importing `@master/css` and each `package.json` declaring a Master CSS package, and gives each its own manifest. In a monorepo, completions, hover previews, colors and diagnostics follow the nearest Master CSS project. List workspace directories when detection does not match the repository layout, and see [Monorepo](/guide/monorepo) for project boundaries:

```json name=.vscode/settings.json
{
  "masterCSS.workspaces": ["apps/admin", "apps/shop", "packages/design-system"]
}
```

Run `Master CSS: Restart Language Server` after dependency changes, workspace-layout changes or manifest edits that VS Code has not picked up.

## Troubleshooting
| Symptom | Fix |
| --- | --- |
| Completions do not show inside strings. | Enable `editor.quickSuggestions.strings`. |
| Project tokens, components or utilities are missing. | Add a CSS entry that imports `@master/css`, or declare a Master CSS package dependency, then restart the language server. |
| The wrong monorepo package is used. | Set `masterCSS.workspaces` to explicit workspace directories. |
| Color decorators do not appear. | Enable `masterCSS.renderSyntaxColors` and `editor.colorDecorators`; check language-specific overrides. |
