## Overview [sr-only]
Use `shadow-<token>` to lift a surface from its background. Compare the six preset levels on the same surface; each shadow has room to spread beyond the card.

<FoundationTokens namespace="shadow" keys={["xs", "sm", "md", "lg", "xl", "2xl"]} />

```html
<article class="bg-surface-raised r-lg shadow-sm">Card</article>
<div class="bg-surface-floating r-lg shadow-lg">Floating panel</div>
```

The colors inside each shadow adapt to the element's color scheme. The preset keeps the same offsets and blur in light and dark modes. Use the preview's theme control to compare them.

---

## Choose an elevation token
Start with the surface relationship, then choose the lowest token that makes that relationship clear. More shadow does not create more hierarchy when every surface competes for depth.

Try `shadow-sm` for a card and `shadow-lg` for a floating surface, then compare them against the actual background. These are design suggestions, not fixed token semantics.

See the complete [values and consumers](/reference/tokens/shadow) in Reference.

The role of each token should stay stable across modes. Custom light and dark recipes can vary geometry as well as color, but `shadow-sm` should still mean a standard raised surface in both modes.

---

## Pair elevation with color roles
Elevation needs a visible ground. Pair shadows with `bg-surface-*`, `fg-text-*`, and radius tokens so depth reads correctly in light and dark themes.

<FoundationElevation />

```html
<!-- @MARK shadow-lg -->
<article class="r-lg bg-surface-raised shadow-lg">
  <h2 class="fg-text-strong">Raised surface</h2>
  <p class="fg-text-muted">Cards need a clear surface before they need a large shadow.</p>
</article>
```

Use surface roles for the ground and shadows for separation. A strong shadow on every panel makes the page noisy, even when the surfaces use different color roles.

---

## Use shadow tokens
Use `shadow-<token>` for common elevation levels. The utility resolves values from `shadow-*` tokens and emits a stable `box-shadow: var(--shadow-*)` declaration; native `light-dark()` colors follow the element's `color-scheme`.

```html
<!-- @MARK shadow-sm -->
<article class="r-lg bg-surface-raised shadow-sm">
  ...
</article>

<!-- @MARK shadow-lg -->
<div class="r-lg bg-surface-floating shadow-lg">
  ...
</div>
```

<Class2CSS>
  {['shadow-sm', 'shadow-lg']}
</Class2CSS>

Use `shadow-<token>` for named product tokens. Use the explicit `box-shadow:*` form when documenting native property mapping or when surrounding code benefits from the native property name.

---

## Namespace for elevation

`shadow-` reads the `shadow` namespace and sets `box-shadow`.

This lets elevation utilities use `sm`, `lg`, or project token names without repeating the `shadow-` prefix.

---

## Change elevation by state

<FoundationElevationState />
State elevation should communicate interaction, not decoration. A hover shadow can make a card feel liftable; a focus shadow should not replace an accessible focus indicator.

```html
<!-- @MARK shadow-sm --><!-- @MARK shadow-md:hover --><!-- @MARK box-shadow:none@media(print) -->
<article class="shadow-sm shadow-md:hover box-shadow:none@media(print)">
  ...
</article>
```

<Class2CSS>
  {['shadow-sm', 'shadow-md:hover', 'box-shadow:none@media(print)']}
</Class2CSS>

Keep state changes small. Moving from `shadow-sm` to `shadow-md` is usually enough for hover. Jumping from `shadow-sm` to `shadow-2xl` makes a normal card feel like a modal.

## Customize mode-aware shadows
Override a `shadow-*` token with your own recipe. Use `light-dark()` for each shadow color so manual themes and nested color schemes work too.

```css name=index.css
@theme {
  --shadow-card:
    0 0 0 1px light-dark(oklch(0% 0 none / .05), oklch(100% 0 none / .06)),
    0 4px 12px -2px light-dark(oklch(0% 0 none / .12), oklch(0% 0 none / .4));
}
```

```html
<article class="bg-surface-raised r-lg shadow-card">...</article>
```

Keep the name independent of the active mode. A custom recipe may change geometry as well as color, but its role should remain consistent. Keep one-off art direction in local CSS until it needs a reusable token.

## Avoid elevation noise
(x) Every panel competes for depth.

```html
<main class="shadow-lg">
  <section class="shadow-xl">
    <article class="shadow-2xl">...</article>
  </section>
</main>
```

(o) Only the surfaces that need separation are elevated.

```html
<main class="bg-surface-base">
  <section class="bg-surface-base">
    <article class="bg-surface-raised shadow-sm">...</article>
  </section>
</main>
```

Promote a repeated shadow into a named token rather than copying the raw value into every card. Keep the page canvas flat and elevate only the surfaces that need separation.

The preset shadows follow manual and nested schemes without recompilation; see [Colors](/guide/colors#native-color-scheme-and-manual-themes).
