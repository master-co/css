## Overview [sr-only]
Class scanning decides which classes are used. Native CSS is preserved by default. Explicit native CSS pruning uses that usage graph to remove unused class rules from selected stylesheets.

<DeliveryFlow name="pruning" />

Importing `@master/css` supplies the preset and generated CSS entry. Add `@prune native;` to opt this source file into pruning; the directive does not affect its imports. Passing class names to a compiler API alone never enables pruning.

```css name=src/style.css
@prune native;
@import "@master/css";

.card {
  border: 1px solid rgb(0 0 0 / 12%);
}

.unused {
  color: red;
}
```

If source files use `card` but never use `unused`, the output keeps `.card` and removes `.unused`. The output excerpt below shows only the native rule; the preset and any generated utilities still follow the normal entry pipeline.

```html name=src/index.html
<!-- @MARK card -->
<article class="card">Card</article>
```

```css name=generated.css
.card {
  border: 1px solid rgb(0 0 0 / 12%);
}
```

Use [Scanning latent classes](/guide/scanning-latent-classes) for the source scanning model. This page focuses on what happens after a stylesheet enters the Master CSS pipeline.

## Explicit pruning
Import `@master/css` from the CSS entry that should receive generated Master CSS. Native class selector rules remain intact unless this file declares `@prune native;` or the integration explicitly enables `pruneNativeCSS: true`. The integration option applies only to project-owned sources.

The integration replaces the Master import with generated CSS; the browser does not receive the package import.

Use `@preserve native;` when the stylesheet contains class names that are intentionally invisible to the scanner.

```css name=src/vendor-overrides.css
@import "@master/css";
@preserve native;

.cms-card {
  color: red;
}

.injected-by-payment-widget {
  color: blue;
}
```

This stylesheet is still Master-managed, but its native CSS is preserved as written.

For exact stylesheet directive syntax, see [CSS directives](/reference#directives).

## Import graph
Resolved CSS imports retain their own source boundaries. Each file opts in with `@prune native;`; an importing file cannot enable pruning in its dependencies. With the integration-wide `pruneNativeCSS: true` option, project-owned dependencies also participate unless they declare `@preserve native;`. Qualified native imports keep their media, supports and layer wrappers.

```css name=src/style.css
@prune native;
@import "@master/css";
@import "./styles/cards.css";
@import "./styles/buttons.css";

.page {
  display: grid;
}
```

```css name=src/styles/cards.css
@prune native;
.card {
  border: 1px solid rgb(0 0 0 / 12%);
}

.unused-card {
  color: red;
}
```

```css name=src/styles/buttons.css
@prune native;
.button {
  display: inline-flex;
}

.unused-button {
  color: blue;
}
```

```html name=src/index.html
<main class="page">
  <article class="card">
    <button class="button">Save</button>
  </article>
</main>
```

The compiled native CSS keeps `.page`, `.card`, and `.button`, then removes `.unused-card` and `.unused-button`.

```txt
src/style.css
  -> imports @master/css
  -> imports ./styles/cards.css
  -> imports ./styles/buttons.css
  -> each opted-in source pruned with root usage
```

Package and remote styles do not become project-owned merely because the project imports them. Preserve files with externally controlled classes, or opt in only where the complete class vocabulary is available.

## Root scope
Pruning activation belongs to each source file. Once enabled, filtering uses the importing root’s usage scope. The same opted-in shared source can therefore retain different classes under different roots.

<DeliveryFlow name="pruning-scope" />

```css name=app/a/a.css
@prune native;
@import "@master/css";
@source "./page.html";
@import "../shared.css";

.a-page {
  color: red;
}
```

```css name=app/b/b.css
@prune native;
@import "@master/css";
@source "./page.html";
@import "../shared.css";

.b-page {
  color: blue;
}
```

```css name=app/shared.css
@prune native;
.shared-card {
  border: 1px solid rgb(0 0 0 / 12%);
}

.only-used-in-b {
  color: blue;
}
```

Each root above selects its adjacent `page.html`:

```html name=app/a/page.html
<article class="a-page shared-card">A</article>
```

```html name=app/b/page.html
<article class="b-page shared-card only-used-in-b">B</article>
```

The `a.css` output keeps `.a-page` and `.shared-card`, but removes `.only-used-in-b` from the shared source. The `.b-page` rule belongs to the other root and is not imported here.

The `b.css` output keeps `.b-page`, `.shared-card`, and `.only-used-in-b`.

The same imported file can therefore be pruned differently under different roots. If `shared.css` is also imported directly by JavaScript or by a framework route, then `shared.css` becomes its own root only when that direct import enters the Master CSS pipeline.

## Scoped scanning
By default, a pruned stylesheet uses the global scanner scope. Add `@source`, `@source not`, `@safelist`, and `@blocklist` inside the stylesheet graph when that root needs a narrower or wider usage graph.

```txt
app/a/a.css
  -> scans app/a/page.html
  -> imports ../shared.css

app/b/b.css
  -> scans app/b/page.html
  -> imports ../shared.css
```

```css name=app/a/a.css
@prune native;
@import "@master/css";
@source "./page.html";
@import "../shared.css";

.a-card {
  color: red;
}

.b-card {
  color: blue;
}
```

```css name=app/b/b.css
@prune native;
@import "@master/css";
@source "./page.html";
@import "../shared.css";

.a-card {
  color: red;
}

.b-card {
  color: blue;
}
```

```css name=app/shared.css
@prune native;
@safelist "shared-card";
@blocklist "debug-*";

.shared-card {
  border: 1px solid rgb(0 0 0 / 12%);
}

.debug-outline {
  outline: 1px solid red;
}
```

`./page.html` is resolved relative to the CSS file that declared it. The directives in `shared.css` are merged into whichever root imports it, so `shared-card` is included for both roots and `debug-*` is blocked for both roots.

```html name=app/a/page.html
<article class="a-card shared-card">A</article>
```

```html name=app/b/page.html
<article class="b-card shared-card">B</article>
```

The `a.css` output keeps `.a-card` and `.shared-card`. The `b.css` output keeps `.b-card` and `.shared-card`. Both roots remove `.debug-outline` because the imported `@blocklist "debug-*";` directive belongs to each root scope.

If a root must scan a file, make sure no `@source not` pattern removes it.

```css name=app/a/a.css
@import "@master/css";
@source "./pages/*.html";
@source not "./pages/preview.html";
```

## Rule filtering
Native CSS pruning filters class selector rules by detected usage. A class rule is kept when its selector branch references a class that is used.

```css name=src/style.css
@prune native;
@import "@master/css";

body {
  margin: 0;
}

.card,
.unused:hover {
  border: 1px solid rgb(0 0 0 / 12%);
}

@media (width >= 48rem) {
  .card .title {
    font-weight: 700;
  }

  .debug-card {
    outline: 1px solid red;
  }
}
```

```html name=src/index.html
<!-- @MARK card title -->
<article class="card">
  <h2 class="title">Card</h2>
</article>
```

The output keeps `body`, `.card`, and `.card .title`. It removes `.unused:hover` and `.debug-card`.

```css name=output.css
body {
  margin: 0;
}

.card {
  border: 1px solid rgb(0 0 0 / 12%);
}

@media (width >= 48rem) {
  .card .title {
    font-weight: 700;
  }
}
```

This is a conservative class-name check. For `.card .title`, finding either `card` or `title` is enough to retain the selector branch; the compiler does not prove that the two elements form that descendant relationship in the live DOM. A retained rule can therefore still match no element.

Rules without class selectors, such as `body`, `html`, and `:root`, are not class-usage rules and are preserved. Keyframes follow their declaring file's preserve/prune policy; under pruning, animation usage determines which remain. Empty at-rule blocks are removed after their unused class rules are pruned.

## Manifest references
Pruned native CSS can reference variables and keyframes from the project CSS entry graph. When a kept native rule uses `var(--*)` or a manifest animation name, Master CSS includes the required manifest output.

```css name=index.css
@prune native;
@theme {
  --color-primary: #175cff;
}

@keyframes fade-in {
  from {
    opacity: 0;
  }

  to {
    opacity: 1;
  }
}
```

```css name=src/style.css
@prune native;
@import "@master/css";
@import "../index.css";

.notice {
  color: var(--color-primary);
  animation-name: fade-in;
}

.unused-notice {
  color: var(--color-primary);
}
```

```html name=src/index.html
<!-- @MARK notice -->
<p class="notice">Saved</p>
```

The kept `.notice` rule pulls in `--color-primary` and `@keyframes fade-in`. `.unused-notice` is removed, so it does not keep anything alive by itself.

## Included classes
If a native class is used by a bounded external source, include it explicitly so pruning keeps the rule.

```css name=src/dialog.css
@prune native;
@import "@master/css";
@safelist "dialog-open dialog-closing";

.dialog-open {
  overflow: hidden;
}

.dialog-closing {
  pointer-events: none;
}
```

Use this for known class contracts. Do not use it as a replacement for putting normal application classes in source.

## Prune animation definitions

Keyframes use the same file policy as native classes:

```css
@prune native;
@theme { --animate-reveal: reveal .2s ease-out both; }
@keyframes reveal { from { opacity: 0; } to { opacity: 1; } }
@safelist keyframes "external-enter";
@keyframes external-enter { from { opacity: 0; } to { opacity: 1; } }
```

Pruned keyframes become on-demand definitions, like tokens: they leave the native output, and the output that uses one emits it with the generated CSS. Using `animate-reveal` emits `reveal`. The safelist emits `external-enter` for a JavaScript consumer without generating an animation declaration. Definitions used only by a pruned class or unused mixin are not emitted. An emitted definition brings the tokens its frames read.

Without a pruning policy, native classes and keyframes remain in the output in place. `@preserve native;` takes precedence within its file. Neither directive changes imported files' policies; package styles preserve their existing default unless they opt in. `preserveNativeCSS: false` suppresses native delivery; on-demand definitions are still emitted where they are used.

Emitted definitions keep their conditions, named layers and declaration order. Declare on-demand keyframes in named layers and with absolute `url()` values; see the [keyframe contract](/reference/directives/theme#native-keyframes).

## Checklist
- Import `@master/css` from CSS entries that should receive generated Master CSS.
- Enable pruning separately with `@prune native;` or `pruneNativeCSS: true`.
- Add `@preserve native;` to Master-managed entries whose native CSS must be preserved.
- Check every source boundary: `@prune native;` does not propagate to imports.
- Use `@safelist` for native classes used by bounded external systems.
- Keep animation definitions with their owning stylesheet; on-demand keyframes need named layers and absolute URLs.
- Use `@preserve native;` for files with external class vocabularies when project-wide pruning is enabled.
