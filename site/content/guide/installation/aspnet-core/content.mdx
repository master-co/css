Use static rendering when ASP.NET Core Razor Pages or MVC views contain complete class strings and you want Vite to build a generated CSS asset before .NET serves the page.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Create a project
      If you do not have an ASP.NET Core project, create one first.
    </StepL>
    <StepR>
      ```bash name=Terminal
      dotnet new webapp -o my-app
      cd my-app
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build static CSS into `wwwroot/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'static' })
        ],
        build: {
          outDir: 'wwwroot/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'src/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import Master CSS and scan Razor Pages and MVC views where classes are authored.
    </StepL>
    <StepR>
      ```ts name=src/main.ts
      import './app.css'
      ```

      ```css name=src/app.css
      @import "@master/css";

      @source "../Pages/**/*.cshtml";
      @source "../Views/**/*.cshtml";
      @source not "../bin/**";
      @source not "../obj/**";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Load the stylesheet
      Reference the generated CSS from your shared layout.
    </StepL>
    <StepR>
      ```html name=Pages/Shared/_Layout.cshtml
      <link rel="stylesheet" href="~/assets/app.css" asp-append-version="true">
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Now style your first Razor page using Master CSS syntax.
  </Step>
  <HelloWorld url="localhost:5000" />
</StepSection>

```html name=Pages/Index.cshtml
@page
@model IndexModel

<h1 class="m-2xl font-style:italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Static rendering depends on complete class strings in scanned source files. If a Razor view assembles class names from fragments, map states to complete class strings or add bounded candidates with [`@safelist`](/reference/directives/candidates#safelist).

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy `app.css` and every CSS file it imports together, preserving their names and relative paths.

## Keep the page and layout connected
The `@page` directive makes this Razor file a routable page. Keep the generated PageModel and shared layout. For MVC, put the heading in the view rendered by your controller instead.

New .NET templates can include Bootstrap. Normal unlayered Bootstrap declarations can override layered Master CSS utilities, so check the loaded stylesheets and computed styles when a class appears ineffective. See [Cascade layers](/guide/cascade-layers) for precedence.

## Verify the result
Build Vite assets before `dotnet build` or `dotnet publish`, so .NET includes them in its static asset output. Run `dotnet run` and use the URL printed by the server. The heading should be large, heavy and italic.

For server-rendered HTML, styling should remain with JavaScript disabled. A WebAssembly-only Blazor app still needs its framework JavaScript to render the component.
