Use Vite runtime rendering when PHP renders pages directly from templates. PHP serves the page, while the Vite-built Master CSS runtime generates class rules in the browser as templates render.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Open your project
      Start from the PHP or CodeIgniter project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      cd my-php-app
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc @master/css-runtime@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build the runtime entry and base stylesheet into `public/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'runtime' })
        ],
        build: {
          outDir: 'public/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'resources/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import the Vite-managed runtime and the Master CSS stylesheet.
    </StepL>
    <StepR>
      ```ts name=resources/main.ts
      import { MasterCSSRuntime } from '@master/css-runtime'
      import program from 'virtual:master-css-program'
      import emittedGlobals from 'virtual:master-css-emitted-globals'
      import './app.css'

      const runtime = await MasterCSSRuntime.start({ program, emittedGlobals })
      runtime.observe()
      ```

      ```css name=resources/app.css
      @import "@master/css";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Add build scripts
      Merge these fields into the existing `package.json`, keeping the dependencies installed above. Build the frontend assets before deploying, or keep Vite watching in development.
    </StepL>
    <StepR>
      ```json name=package.json
      {
        "scripts": {
          "build:assets": "vite build",
          "watch:assets": "vite build --watch"
        }
      }
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Load the Vite output and style your first PHP template.
  </Step>
  <HelloWorld url="localhost" />
</StepSection>

```html name=public/index.php
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Master CSS with PHP</title>
  <link rel="stylesheet" href="/assets/app.css">
</head>
<body>
  <h1 class="m-2xl font-style:italic font-5xl font-heavy fg-text-neutral">
    Hello World
  </h1>
  <script type="module" src="/assets/app.js"></script>
</body>
</html>
```

For CodeIgniter, load `/assets/app.css` and `/assets/app.js` with your normal asset helper. Use [PHP static rendering](/guide/installation/php) when complete PHP template class strings should be compiled into a CSS asset.

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy every generated stylesheet, import and program asset together.

## Check the page
For a plain PHP project, run `php -S localhost:8000 -t public` after building the assets, then visit `http://localhost:8000`. Use your framework’s normal server for CodeIgniter. This example assumes `public` is the web root; adjust URLs if the app lives under a subpath.

Runtime styling starts after the browser loads JavaScript. The example keeps the document visible if scripts are unavailable; see [Flash of Unstyled Content](/guide/flash-of-unstyled-content) before adding page hiding.

After startup, run this in the browser console. The heading should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('text-decoration-line:underline')
```
