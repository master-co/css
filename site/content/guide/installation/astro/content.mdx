Generate a stylesheet for an Astro site from complete class names in its sources. The installer configures the integration and creates the CSS entry; the page below imports that entry.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Add Master CSS
      In an existing [Astro project](https://docs.astro.build/en/install-and-setup/), run the installer from the project root. Static is the default: it scans complete class strings and emits ordinary CSS.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm create @master/css@rc -- --framework astro --yes
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Start using Master CSS
    Start the dev server. Import `src/styles/global.css` from the page frontmatter, then add the heading. Use the same import in a shared layout when several pages need it.
  </Step>
  <HelloWorld url="localhost:4321" />
</StepSection>

```astro name=src/pages/index.astro
---
import '../styles/global.css'
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>Hello Master CSS</title>
  </head>
  <body>
    <h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">
      Hello World
    </h1>
  </body>
</html>
```

Keep the entry in a standalone CSS file. [Importing CSS from Astro frontmatter](https://docs.astro.build/en/guides/imports/#import-statements) attaches the processed stylesheet to the page. The installer creates:

```css name=src/styles/global.css
@import '@master/css';
```

## Check the setup
Run the project's build and preview scripts, then disable JavaScript and reload. Check that the heading retains its large, heavy italic styling. If no styles appear, confirm the page or its layout imports `global.css` and the Astro configuration includes the Master CSS integration. For custom definitions and scoped styles, see [Global styles](/guide/global-styles).

If a production build links the base styles but omits the utility rules, do not treat a successful build as a styled result. Check the output CSS for `italic`. Use the [CLI static workflow](/guide/installation/cli) when you need to generate and verify the stylesheet independently, or choose progressive rendering when a runtime handoff fits the application.

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default. The integration injects the runtime page script for the other modes, so they need no separate browser bootstrap:

| Mode | Installer option | Delivery |
| --- | --- | --- |
| Static | None | Generated stylesheet from source scanning |
| Runtime | `--mode runtime` | Browser runtime, without Astro middleware pre-rendering |
| Progressive | `--mode progressive` | Middleware-rendered CSS plus a runtime handoff |

<DocumentDisclosure title="Generate new classes in the browser">

```bash name=Terminal
npm create @master/css@rc -- --framework astro --mode runtime --yes
```

Run the build and preview scripts; the heading should be styled after the runtime starts. Runtime mode depends on JavaScript and its compiled program loading successfully, so check the console and network requests if it stays unstyled. To test a class introduced after the page was generated, run:

```js
document.querySelector('h1').classList.add('underline')
```

The heading should gain an underline without rebuilding.

</DocumentDisclosure>

<DocumentDisclosure title="Include server-rendered styles">

```bash name=Terminal
npm create @master/css@rc -- --framework astro --mode progressive --yes
```

Astro middleware renders the CSS into prerendered pages and server HTML responses, then the runtime handles later class changes. Disable JavaScript and reload: the heading should still be styled. Re-enable JavaScript, reload, and add `underline` from the console as above.

</DocumentDisclosure>
