Use Vite runtime rendering when Rails owns the page lifecycle. Rails renders ERB views, while the Vite-built Master CSS runtime generates class rules in the browser as pages and Turbo updates appear.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Create a project
      If you do not have a Rails project, create one first.
    </StepL>
    <StepR>
      ```bash name=Terminal
      rails new my-app
      cd my-app
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the Rails project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc @master/css-runtime@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build the runtime entry and base stylesheet into `public/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'runtime' })
        ],
        build: {
          outDir: 'public/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'app/frontend/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import the Vite-managed runtime and the Master CSS stylesheet.
    </StepL>
    <StepR>
      ```ts name=app/frontend/main.ts
      import { MasterCSSRuntime } from '@master/css-runtime'
      import program from 'virtual:master-css-program'
      import emittedGlobals from 'virtual:master-css-emitted-globals'
      import './app.css'

      const runtime = await MasterCSSRuntime.start({ program, emittedGlobals })
      runtime.observe()
      ```

      ```css name=app/frontend/app.css
      @import "@master/css";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Load the assets
      Add these asset tags to the existing application layout’s `<head>`. Preserve Rails’ CSRF/CSP tags, existing JavaScript imports, and `<%= yield %>`.
    </StepL>
    <StepR>
      ```erb name=app/views/layouts/application.html.erb
      <%= stylesheet_link_tag "/assets/app.css", "data-turbo-track": "reload" %>
      <%= javascript_include_tag "/assets/app.js", type: "module", "data-turbo-track": "reload" %>
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Add build scripts
      Merge these fields into the existing `package.json`, keeping the dependencies installed above. Build or watch the frontend assets beside the Rails server.
    </StepL>
    <StepR>
      ```json name=package.json
      {
        "scripts": {
          "build:assets": "vite build",
          "watch:assets": "vite build --watch"
        }
      }
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Now style your first ERB view using Master CSS syntax.
  </Step>
  <HelloWorld url="localhost:3000" />
</StepSection>

```html name=app/views/home/index.html.erb
<h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Use [Rails static rendering](/guide/installation/rails) when ERB class strings are complete at build time and you want a generated CSS asset.

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy every generated stylesheet, import and program asset together.

## Check the page
Create or use a route whose controller renders `app/views/home/index.html.erb`, then start Rails with `bin/rails server`. The view filename alone does not register a route. Verify that `/assets/app.css` returns the generated CSS.

These URLs serve files written under `public/assets` directly. Deploy that Vite output alongside the Rails application. For a new release, update the asset URLs with a version identifier, such as `/assets/app.css?v=2`, and configure caching for those URLs.

Turbo’s [asset tracking](https://turbo.hotwired.dev/handbook/drive#reloading-when-assets-change) compares the tracked tags. Overwriting files at the same URLs does not trigger `data-turbo-track="reload"`; update the tags and matching assets together.

Runtime styling starts after the browser loads JavaScript. The example keeps the document visible if scripts are unavailable; see [Flash of Unstyled Content](/guide/flash-of-unstyled-content) before adding page hiding.

After startup, run this in the browser console. The heading should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('underline')
```
