Use static rendering when Rails ERB views contain complete class strings and you want Vite to build a generated CSS asset before Rails serves the page.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Create a project
      If you do not have a Rails project, create one first.
    </StepL>
    <StepR>
      ```bash name=Terminal
      rails new my-app
      cd my-app
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the Rails project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build static CSS into `public/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'static' })
        ],
        build: {
          outDir: 'public/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'app/frontend/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import Master CSS and scan ERB views where classes are authored.
    </StepL>
    <StepR>
      ```ts name=app/frontend/main.ts
      import './app.css'
      ```

      ```css name=app/frontend/app.css
      @import "@master/css";

      @source "../views/**/*.erb";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Load the stylesheet
      Reference the generated stylesheet from the application layout.
    </StepL>
    <StepR>
      ```erb name=app/views/layouts/application.html.erb
      <%= stylesheet_link_tag "/assets/app.css", "data-turbo-track": "reload" %>
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Now style your first ERB view using Master CSS syntax.
  </Step>

```html name=app/views/home/index.html.erb
<h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Static rendering depends on complete class strings in scanned source files. If an ERB view assembles class names from fragments, map states to complete class strings or add bounded candidates with [`@safelist`](/reference/directives/scanning#safelist).

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy `app.css` and every CSS file it imports together, preserving their names and relative paths.

## Check the page
Create or use a route whose controller renders `app/views/home/index.html.erb`, then start Rails with `bin/rails server`. The view filename alone does not register a route. Verify that `/assets/app.css` returns the generated CSS.

These URLs serve files written under `public/assets` directly. Deploy that Vite output alongside the Rails application. For a new release, update the asset URLs with a version identifier, such as `/assets/app.css?v=2`, and configure caching for those URLs.

Turbo’s [asset tracking](https://turbo.hotwired.dev/handbook/drive#reloading-when-assets-change) compares the tracked tags. Overwriting files at the same URLs does not trigger `data-turbo-track="reload"`; update the tags and matching assets together.

The heading should remain large, heavy and italic with JavaScript disabled. If the stylesheet loads but the classes have no effect, check the `@source` paths and regenerate the CSS.
