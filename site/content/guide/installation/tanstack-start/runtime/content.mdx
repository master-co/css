The installer registers `@master/css-vite` in runtime mode, creates `src/styles/app.css`, and imports it from `src/routes/__root.tsx`.

```tsx name=src/routes/index.tsx
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/')({
  component: Home
})

function Home() {
  return (
    <h1 className="m-2xl italic font-5xl font-heavy fg-text-neutral">
      Hello World
    </h1>
  )
}
```

## Start the runtime in the browser

The framework produces its own HTML, which does not pass through Vite’s `index.html` runtime injection. Keep the existing root route and add the stylesheet import plus a browser-only runtime import:

```tsx name=src/routes/__root.tsx
import '../styles/app.css'

if (!import.meta.env.SSR) {
  void import('virtual:master-css-runtime')
}
```

Add these imports to the existing file; retain its route definitions and component exports. The guard keeps the virtual runtime out of server execution. Load it once per document.

```ts name=src/master-css.d.ts
/// <reference types="@master/css/client" />
```

After startup, introduce a class absent from the initial DOM and check its computed style. Framework SSR alone does not supply runtime-generated CSS before JavaScript runs.

---

## Check the setup
Build the application and serve it using the deployment adapter selected for the project. The heading should have a large, heavy italic face and generous margin. Keep `src/styles/app.css` imported by the root route so page navigation continues to load the same CSS entry.

Run this in the browser console after the page is ready:

```js
document.querySelector('h1').classList.add('underline')
```

The heading should gain an underline without rebuilding. If no runtime-generated classes appear, check that the guarded virtual import executes in the browser and that its program request succeeds.
