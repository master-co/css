Progressive rendering adds pre-rendered CSS and a hydration manifest to static or pre-rendered Next.js pages. The runtime initially tracks covered classes. A class outside the page manifest starts its engine, which validates and adopts matching rules before generating additional CSS. Request-time dynamic SSR responses are outside the build adapter's pre-rendered output. Their generated utility styles depend on the browser runtime. Choose [static CSS rendering](/guide/installation/nextjs) if those routes must have utility styles without JavaScript.

Local CSS and CSS Modules automatically receive project definitions in both Turbopack and Webpack. Use native declarations with project tokens directly, and native selectors for shared behavior. Their required theme resources are emitted globally, while local selectors retain the framework’s normal scope. Use `@reference` for additional definition files outside the project context.

## Verify the loaded configuration

The examples use a top-level `app` directory. Keep your global stylesheet imported by `app/layout.tsx`. When using a TypeScript configuration, return the integration from an async configuration function so an asynchronous build mode does not require top-level await in the config loader:

```ts name=next.config.ts
import type { NextConfig } from 'next'
import withMasterCSS from '@master/css-next'

const nextConfig: NextConfig = {}

export default async () => withMasterCSS(nextConfig, { mode: 'progressive' })
```

Keep your existing Next.js options in `nextConfig`.

```css name=app/globals.css
@import '@master/css';
```

```tsx name=app/layout.tsx
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="en"><body>{children}</body></html>
}
```

Run `npm run build` and `npm run start` to check production delivery. For a pre-rendered route, check the response source for `style#master-css` before JavaScript runs. Test a dynamic SSR route separately: this adapter does not add server-generated CSS to request-time HTML.

If a Turbopack production build reports that a generated `.master/stylesheets/...-entry.css` cannot be resolved, check the Webpack build with `npx next build --webpack`. Verify the resulting page with `npm run start` before deployment. A successful Webpack build does not verify the Turbopack path.

After the page is ready, add a class that was absent from its initial DOM:

```js
document.querySelector('h1').classList.add('underline')
```

The heading should gain an underline without a rebuild. Check the browser console and runtime program request if the update has no effect.
