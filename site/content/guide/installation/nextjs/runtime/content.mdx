Local CSS and CSS Modules automatically receive project definitions in both Turbopack and Webpack. Use native declarations with project tokens directly, and native selectors for shared behavior. Their required theme resources are emitted globally, while local selectors retain the framework’s normal scope. Use `@reference` for additional definition files outside the project context.

## Verify the loaded configuration

The examples use a top-level `app` directory. Keep your global stylesheet imported by `app/layout.tsx`. When using a TypeScript configuration, return the integration from an async configuration function so an asynchronous build mode does not require top-level await in the config loader:

```ts name=next.config.ts
import type { NextConfig } from 'next'
import withMasterCSS from '@master/css-next'

const nextConfig: NextConfig = {}

export default async () => withMasterCSS(nextConfig, { mode: 'runtime' })
```

Keep your existing Next.js options in `nextConfig`.

```css name=app/globals.css
@import '@master/css';
```

```tsx name=app/layout.tsx
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html lang="en"><body>{children}</body></html>
}
```

Run `npm run build` and `npm run start` to check production delivery. After startup, add a complete class absent from the initial DOM and inspect its generated rule. Runtime mode does not supply those generated rules before JavaScript starts.

If a Turbopack production build reports that a generated `.master/stylesheets/...-entry.css` cannot be resolved, check the Webpack build with `npx next build --webpack`. This generated-asset failure is reproducible in the current workspace integration; verify the resulting page with `npm run start` before deployment. A successful Webpack build does not verify the Turbopack path.
