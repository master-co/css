Runtime rendering generates rules in the browser when Angular adds class names that were not known at build time. Select it explicitly; the Angular installer otherwise sets up static CSS generation.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Create an Angular project
      Create a browser-rendered app using CSS. This example starts the runtime only from `src/main.ts`; an SSR server needs a separate initial-CSS strategy.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npx --package @angular/cli ng new my-app --style css --ssr=false
      cd my-app
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Add Master CSS in runtime mode
      The installer adds the runtime and preset packages, initializes `MasterCSSRuntime` in `src/main.ts`, and adds a stylesheet import to `src/styles.css`. For the browser-only setup below, replace that import with the native base stylesheet.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm create @master/css@rc -- --framework angular --mode runtime --yes
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Check the stylesheet entry
      Keep Angular's global stylesheet in its existing builder configuration. This setup loads the compiled default preset through `@master/css-runtime/default-program`; Angular’s CSS builder does not compile Master CSS directives. Keep only native CSS imports in the builder’s stylesheet.
    </StepL>
    <StepR>
      ```css name=src/styles.css
      @import '@master/css/base.css';
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Start the app
      Run the Angular development server.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm start
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Use a Master CSS class
    The browser runtime observes connected elements and generates rules for their class names.
  </Step>
  <HelloWorld url="localhost:4200" />
</StepSection>

```html name=src/app/app.html
<h1 class="m-2xl font-style:italic font-5xl font-heavy fg-text-neutral">Hello World</h1>
```

The generated runtime startup uses the default program. Adding `@theme` or `@utility` to Angular’s ordinary CSS input does not compile a custom runtime program. Use the static CLI path for project-defined vocabulary, or provide a separately compiled program through the public runtime API.

The current Angular CLI uses `src/app/app.html` by default. Existing projects using the [2016 file naming convention](https://angular.dev/cli/new) may use `src/app/app.component.html`; edit the template referenced by your root component.

## Verify the result
Run the production build and serve its browser output. The heading should be large, heavy and italic. After it appears, run this in the browser console; the text should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('text-decoration-line:underline')
```

Keep the runtime initialization in the browser entry. It does not render styles for Angular’s server output.
