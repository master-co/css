Keep Angular's builder and use the Master CSS CLI to generate a stylesheet it can load. During development, run both watchers: Master CSS updates the generated CSS, and Angular serves the app that imports it.

This setup assumes an existing browser-rendered Angular app with a global `src/styles.css`, a working `npm start` command and a supported Node.js 24 release. It uses Angular's default [emulated encapsulation](https://angular.dev/guide/components/styling#viewencapsulationemulated), which allows global styles to reach component templates. Shadow DOM components need styles inside their own shadow roots.

## Installation

<StepSection>
  <Step>
    ### Add Master CSS

    Run the installer from the Angular project root:

    ```bash
    npm create @master/css@rc -- --framework angular --yes
    ```

    The static setup adds `@master/css` and `@master/css-cli`. For the installer's optional tooling and preview options, see [Installation](/guide/installation#installation).
  </Step>
  <Step>
    ### Check the stylesheet connection

    The installer creates a Master CSS source entry at the project root:

    ```css name=master.css
    @import '@master/css';
    ```

    It also adds this import to Angular's global stylesheet, preserving its existing contents:

    ```css name=src/styles.css
    @import './master.generated.css';
    ```

    Keep `src/styles.css` in the application's `build.options.styles` array in `angular.json`. Angular's [global styles configuration](https://angular.dev/reference/configs/workspace-config#styles-and-scripts-configuration) determines whether the generated CSS reaches the page. For a nonstandard workspace layout, adjust the output path and import together.

    Put Master CSS definitions such as `@theme` and `@utility` in `master.css`. Angular consumes the generated native CSS; its ordinary CSS builder does not compile those definitions. Do not edit `src/master.generated.css` or import it back into `master.css`.
  </Step>
  <Step>
    ### Generate the CSS

    In one terminal, generate the stylesheet and keep watching for changes:

    ```bash
    npx master-css generate --output src/master.generated.css --watch
    ```

    Wait for the initial generation to finish. Then start Angular in a second terminal:

    ```bash
    npm start
    ```

    Keep both processes running. Angular's watcher alone does not regenerate Master CSS when you add a class.
  </Step>
  <Step>
    ### Start using Master CSS

    Add this markup to the template referenced by your root component. With Angular's [current naming convention](https://angular.dev/cli/new#file-name-style-guide), that is usually `src/app/app.html`; an existing project may use `src/app/app.component.html`.

    <DemoConfiguredExample name="angular-check" title="Check the template styles" source="" caption="The paragraph has a neutral surface, a fine border, small corners and 1rem of padding on every side." html={`<p id="master-check" class="w-fit m(0) p-md b-solid b(1) b-line-divider r-md text-sm font-regular bg-surface-raised fg-text-strong">
  Hello Angular
</p>`} />
  </Step>
</StepSection>

## Verify the result

Open the Angular app. The paragraph should match the example's spacing and surface. Change `p-md` to `p-lg` in the template: with both watchers running, its padding should grow from `1rem` to `1.5rem`. Change it back after checking the update.

If the style does not appear, trace the connection in order:

- Check the Master CSS terminal for generation errors and confirm `src/master.generated.css` exists.
- Check the import in `src/styles.css` and that file's registration in `angular.json`.
- Inspect the paragraph in browser devtools for a matching rule and any component style overriding it.

Static generation needs complete class strings in source or an explicit safelist. Keep conditional class names complete; use CSS custom properties for dynamic values. See [Scanning class names](/guide/scanning-and-pruning) when a class is missing from the generated output.

## Build for deployment

Generate CSS before Angular packages the app:

```bash
npx master-css generate --output src/master.generated.css
npm run build
```

Use the same order in CI. Serving an old generated file can hide missing styles, so check the production build after a fresh generation.

Static describes the CSS generation step. A browser-rendered Angular app still needs JavaScript to create its HTML.

## Choose another rendering mode \{#rendering-modes\}

Static rendering is the default. Use runtime rendering when classes must be generated from browser DOM changes rather than known source strings.

| Mode | Installer option | CSS delivery |
| --- | --- | --- |
| Static | None | CLI output imported by `src/styles.css` |
| Runtime | `--mode runtime` | Browser runtime started from `src/main.ts` |

<DocumentDisclosure title="Generate new classes in the browser">

For the runtime setup, run:

```bash
npm create @master/css@rc -- --framework angular --mode runtime --yes
```

The installer starts `MasterCSSRuntime` from `src/main.ts`, loads `@master/css-runtime/default-program` and observes the document for class changes.

**Finish the global stylesheet setup before starting Angular.** The installer currently adds `@import '@master/css';` to `src/styles.css`. Replace that import with the native base stylesheet below. Keep other native CSS imports and rules your app needs. If switching from the static setup, also remove the `./master.generated.css` import; this runtime path does not need the CSS watcher.

```css name=src/styles.css
@import '@master/css/base.css';
```

The default program supplies the preset vocabulary. Adding `@theme` or `@utility` to Angular's ordinary CSS does not compile a custom runtime program. For project-defined vocabulary, use the static CLI path or supply a separately compiled program through the [runtime API](/reference/packages#css-runtime).

Build and serve the Angular app, then run this in its browser console. The example paragraph should gain an underline without rebuilding:

```js
document.querySelector('#master-check').classList.add('underline')
```

This runtime starts in the browser entry. An Angular SSR app needs a separate initial-CSS strategy; this guide covers the browser-rendered setup.
