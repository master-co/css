Angular keeps its own builder; the Master CSS CLI generates a static stylesheet that Angular's global styles import.

<StepSection>
  <Step $row>
    <StepL>
      ### Add Master CSS
      In an existing browser-rendered [Angular project](https://angular.dev/installation) that uses CSS, run the installer from the project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm create @master/css@rc -- --framework angular --yes
      ```
    </StepR>

```html name=src/app/app.html
<h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">Hello World</h1>
```

---

The installer creates `master.css` as the source entry and imports the generated `src/master.generated.css` from `src/styles.css`. Keep `src/styles.css` in Angular's global styles configuration. The generated file is build output; do not edit it or import it from `master.css`.

Before each production build, regenerate the CSS:

```bash
npx master-css generate --output src/master.generated.css
npm run build
```

During development, run `npx master-css generate --output src/master.generated.css --watch` in a separate terminal. Static rendering needs complete class strings in templates or an explicit safelist. CSS custom properties can still supply dynamic values.

The current Angular CLI uses `src/app/app.html` by default. Existing projects using the [2016 file naming convention](https://angular.dev/cli/new) may use `src/app/app.component.html`; edit the template referenced by your root component.

## Verify the result
Build after generating CSS and serve Angular’s browser output. The heading should be large, heavy and italic. To check the watcher, change `italic` to `(font-style:normal)` in the template; the preview should update while the watcher is running.

Static refers to CSS generation. A browser-rendered Angular app still needs JavaScript to create its HTML.

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default. Angular supports static and runtime rendering:

| Mode | Installer option | Delivery |
| --- | --- | --- |
| Static | None | CLI-generated stylesheet imported by `src/styles.css` |
| Runtime | `--mode runtime` | Browser runtime started from `src/main.ts` |

<DocumentDisclosure title="Generate new classes in the browser">

Runtime rendering generates rules in the browser when Angular adds class names that were not known at build time:

```bash name=Terminal
npm create @master/css@rc -- --framework angular --mode runtime --yes
```

The installer adds the runtime and preset packages, initializes `MasterCSSRuntime` in `src/main.ts`, and adds a stylesheet import to `src/styles.css`. Angular's CSS builder does not compile Master CSS directives, so replace that import with the native base stylesheet and keep only native CSS imports there:

```css name=src/styles.css
@import '@master/css/base.css';
```

The runtime startup uses the compiled default program from `@master/css-runtime/default-program`. Adding `@theme` or `@utility` to Angular's ordinary CSS does not compile a custom runtime program; use the static CLI path for project-defined vocabulary, or provide a separately compiled program through the public runtime API.

Serve the production build, then run this in the browser console. The heading should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('underline')
```

The runtime starts only from the browser entry; an Angular SSR server needs a separate initial-CSS strategy.

</DocumentDisclosure>
