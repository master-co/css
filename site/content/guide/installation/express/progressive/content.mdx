Use progressive rendering when Express owns the HTML response. Express renders the template, `@master/css-server` injects the first-response CSS, and the Vite runtime asset adopts that CSS in the browser for later dynamic classes.

      ### <StepNum />Open your project
      Start from an Express project root.
    </StepL>
    <StepR>

      ### <StepNum />Install Master CSS
      Install the server renderer, Vite, and the Vite integration.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install express ejs @master/css@rc @master/css-runtime@rc @master/css-server@rc @master/css-preset@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build the browser runtime entry and base stylesheet into `public/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'runtime' })
        ],
        build: {
          outDir: 'public/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'src/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the browser entry
      Import the Vite-managed runtime and the Master CSS stylesheet.
    </StepL>
    <StepR>
      ```ts name=src/main.ts
      import { MasterCSSRuntime } from '@master/css-runtime'
      import emittedGlobals from 'virtual:master-css-emitted-globals'
      import './app.css'

      const runtime = await MasterCSSRuntime.start({
        program: () => import('virtual:master-css-program').then(module => module.default),
        emittedGlobals
      })
      runtime.observe()
      ```

      ```css name=src/app.css
      @import "@master/css";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Render with Master CSS
      Render the template first, then pass the full document to `@master/css-server`.
    </StepL>
    <StepR>
      ```js name=app.js
      import express from 'express'
      import ejs from 'ejs'
      import { createServerRenderer } from '@master/css-server'
      import manifest from '@master/css-preset/default-manifest.json' with { type: 'json' }

      const app = express()
      const renderer = createServerRenderer({ manifest })

      app.use('/assets', express.static('public/assets'))

      app.get('/', async (_request, response) => {
        const body = await ejs.renderFile('views/index.ejs')
        const document = `<!doctype html>
      <html lang="en">
      <head>
        <meta charset="utf-8">
        <meta name="viewport" content="width=device-width, initial-scale=1">
        <link rel="stylesheet" href="/assets/app.css">
      </head>
      <body>
        ${body}
        <script type="module" src="/assets/app.js"></script>
      </body>
      </html>`

        const rendered = renderer.renderHTML(document, {
          hydrationManifest: 'inject'
        })
        response.send(rendered.html)
      })

      const server = app.listen(3000)
      server.on('close', () => renderer.dispose())
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Add build scripts
      Merge these fields into the existing `package.json`, keeping the dependencies installed above. Build or watch the frontend assets beside the Express server.

      ```json name=package.json

        "type": "module",
        "scripts": {
          "build:assets": "vite build",
          "watch:assets": "vite build --watch",
          "start": "node app.js"
        }
      }
      ```
    </StepR>
  </Step>

Progressive rendering sends the first response with `style#master-css`, then the runtime reads the injected hydration manifest and keeps handling classes added after the initial response. The lazy program loader lets a fully covered page defer the browser engine and compiled runtime program until a new class needs generation. The server manifest stays on the server; it is distinct from the small hydration record injected into the HTML. Use [Express static rendering](/guide/installation/express) when templates contain complete class strings and you want a generated CSS asset instead.

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy every generated stylesheet, import and program asset together.

## Keep server and browser definitions aligned
This example uses the default preset manifest on the server and the same preset in `src/app.css`. If you add project tokens or utilities, compile the project manifest for the server too. Rendering with the preset manifest while the browser uses different definitions can produce mismatched initial CSS.

## Check both phases
Build the assets and start Express. With JavaScript disabled, the heading should already be large, heavy and italic. Inspect the response for `style#master-css` and its hydration record.

Re-enable JavaScript, reload, and add a class in the browser console. The heading should gain an underline without a new server response:

```js
document.querySelector('h1').classList.add('text-decoration-line:underline')
```
