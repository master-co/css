Use static rendering when Express templates contain complete class strings and you want Vite to build a generated CSS asset before the server responds.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Open your project
      Use an existing Express project with a template engine configured. The following additions connect its templates to the CSS build.
    </StepL>
    <StepR>
      ```bash name=Terminal
      cd my-express-app
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build static CSS into `public/assets`.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'static' })
        ],
        build: {
          outDir: 'public/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'src/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import Master CSS and scan the server templates where classes are written.
    </StepL>
    <StepR>
      ```ts name=src/main.ts
      import './app.css'
      ```

      ```css name=src/app.css
      @import "@master/css";

      @source "../views/**/*.{ejs,hbs,pug}";
      @source "../public/**/*.html";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Serve the CSS
      Add the static middleware to your existing Express app and link the generated stylesheet from the layout that renders your page. The snippets below are additions to those files.
    </StepL>
    <StepR>
      ```js name=app.js
      app.use(express.static('public'))
      ```

      ```html name=views/layout.ejs
      <link rel="stylesheet" href="/assets/app.css">
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Now style your first server-rendered template using Master CSS syntax.
  </Step>
  <HelloWorld url="localhost:3000" />
</StepSection>

```html name=views/index.ejs
<h1 class="m-2xl font-style:italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Static rendering depends on complete class strings in scanned source files. If a template assembles class names from fragments, map states to complete class strings or add bounded candidates with [`@safelist`](/reference/directives/candidates#safelist).

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy `app.css` and every CSS file it imports together, preserving their names and relative paths.

## Verify the rendered page
Build the assets, start Express, and load the route that renders the heading. It should be large, heavy and italic with JavaScript disabled. In the Network panel, `/assets/app.css` must return CSS rather than a fallback HTML page.

If the CSS loads but the heading is unstyled, check that the template is under one of the `@source` paths. Those paths are relative to `src/app.css`, so `../views` points to the project's `views` directory.
