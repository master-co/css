Webpack, Rspack and Rsbuild use the same `@master/css-webpack` plugin. It processes the CSS entry and emits the generated stylesheet with the HTML produced by the bundler's HTML plugin.

## Bundler configuration \{#configuration\}
The installer writes the Master CSS part of the configuration. Merge it with the existing configuration, preserving framework plugins, entry points and HTML generation, and register the plugin only once.

### Webpack \{#webpack\}
The plugin needs native CSS handling and `HtmlWebpackPlugin` to deliver the generated stylesheet:

```js name=webpack.config.mjs
import HtmlWebpackPlugin from 'html-webpack-plugin'
import MasterCSSPlugin from '@master/css-webpack'

export default {
  entry: './src/index.js',
  experiments: { css: true },
  module: {
    rules: [{ test: /\.css$/i, type: 'css/auto' }]
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './index.html' }),
    new MasterCSSPlugin({ mode: 'static' })
  ]
}
```

### Rspack \{#rspack\}
Rspack uses the same Webpack-compatible plugin with its built-in CSS support and `HtmlRspackPlugin`:

```js name=rspack.config.mjs
import MasterCSSPlugin from '@master/css-webpack'

export default {
  module: {
    rules: [
      {
        test: /\.css$/i,
        type: 'css/auto'
      }
    ]
  },
  plugins: [
    new MasterCSSPlugin({ mode: 'static' })
  ]
}
```

### Rsbuild \{#rsbuild\}
Rsbuild registers the plugin through its `tools.rspack` hook. Keep the framework plugin and the entry that mounts the application; the hook only adds Master CSS processing.

```ts name=rsbuild.config.ts
import { defineConfig } from '@rsbuild/core'
import MasterCSSPlugin from '@master/css-webpack'

export default defineConfig({
  tools: {
    rspack(config) {
      config.plugins ||= []
      config.plugins.push(new MasterCSSPlugin({ mode: 'static' }))
      return config
    }
  }
})
```

In a React starter, put the heading in `src/App.tsx`:

```tsx name=src/App.tsx
export default function App() {

      Hello World
    </h1>
  )
}
```

## Check the setup \{#check-the-setup\}
Build and serve the production output, for example with `npx webpack --mode production`. The heading should be large, heavy and italic, and the emitted page should load generated CSS without a Master CSS runtime. A client-rendered framework still needs JavaScript to create the heading.

The HTML plugin emits the stylesheet links and any runtime script. A file served directly from a development server's static directory does not receive them.

---

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default. The plugin's `mode` option selects another delivery, and the HTML plugin carries its runtime script:

| Mode | Plugin option | Installer option |
| --- | --- | --- |
| Static | `mode: 'static'` | None |
| Runtime | `mode: 'runtime'` | `--mode runtime` |

<DocumentDisclosure title="Generate new classes in the browser">

Run the installer with `--mode runtime` and your `--framework` value. It sets the plugin option to `mode: 'runtime'`:

```bash
npm create @master/css@rc -- --framework webpack --mode runtime --yes
```

Build and serve the production output. The emitted HTML should load the Master CSS runtime script. After startup, run this in the browser console; the heading should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('underline')
```
