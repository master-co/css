Build Master CSS into a Webpack, Rspack or Rsbuild application. All three use `@master/css-webpack`: the CSS entry supplies definitions, the plugin generates utility rules, and the HTML plugin links the output to the page. Start from a working application with an entry and an HTML template.

## Bundler configuration \{#configuration\}
The installer writes the Master CSS part of the configuration. Merge it with the existing configuration, preserving framework plugins, entry points and HTML generation, and register the plugin only once.

### Webpack \{#webpack\}
The plugin needs native CSS handling and `HtmlWebpackPlugin` to deliver the generated stylesheet:

```js name=webpack.config.mjs
import HtmlWebpackPlugin from 'html-webpack-plugin'
import MasterCSSPlugin from '@master/css-webpack'

export default {
  entry: './src/index.js',
  experiments: { css: true },
  module: {
    rules: [{ test: /\.css$/i, type: 'css/auto' }]
  },
  plugins: [
    new HtmlWebpackPlugin({ template: './index.html' }),
    new MasterCSSPlugin({ mode: 'static' })
  ]
}
```

### Rspack \{#rspack\}
Rspack uses the same Webpack-compatible plugin with its built-in CSS support and `HtmlRspackPlugin`:

```js name=rspack.config.mjs
import { HtmlRspackPlugin } from '@rspack/core'
import MasterCSSPlugin from '@master/css-webpack'

export default {
  entry: './src/index.js',
  module: {
    rules: [
      {
        test: /\.css$/i,
        type: 'css/auto'
      }
    ]
  },
  plugins: [
    new HtmlRspackPlugin({ template: './index.html' }),
    new MasterCSSPlugin({ mode: 'static' })
  ]
}
```

### Rsbuild \{#rsbuild\}
Rsbuild registers the plugin through its `tools.rspack` hook. Keep the framework plugin and the entry that mounts the application; the hook only adds Master CSS processing.

```ts name=rsbuild.config.ts
import { defineConfig } from '@rsbuild/core'
import MasterCSSPlugin from '@master/css-webpack'

export default defineConfig({
  tools: {
    rspack(config) {
      config.plugins ||= []
      config.plugins.push(new MasterCSSPlugin({ mode: 'static' }))
      return config
    }
  }
})
```

In a React starter, put the paragraph in `src/App.tsx`:

```tsx name=src/App.tsx
export default function App() {
  return (
    <p id="master-check" className="w-fit m(0) p-md b-solid b(1) b-line-divider r-md text-sm font-regular bg-surface-raised fg-text-strong">
      Hello World
    </p>
  )
}
```

## Check the setup \{#check-the-setup\}
First change `p-md` to `p-lg` in the source while the dev server is running. The paragraph's padding should grow from `1rem` to `1.5rem`; then restore it.

Build with the command for your bundler:

<DocumentComparison>

| Bundler | Production build |
| --- | --- |
| Webpack | `npx webpack --mode production` |
| Rspack | `npx rspack build --mode production` |
| Rsbuild | `npx rsbuild build` |

</DocumentComparison>

Serve the emitted directory with an HTTP server. The paragraph should have `1rem` padding, a raised surface and rounded corners. In static mode, its utilities come from linked CSS without a Master CSS runtime. HTML-template content stays styled with JavaScript disabled; a client-rendered framework still needs JavaScript to create its content.

The HTML plugin emits the stylesheet links and any runtime script. A file served directly from a development server's static directory does not receive them. If the CSS request is missing, check HTML generation first. If it loads but has no utilities, check the CSS entry, native CSS handling and plugin registration.

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default. The plugin's `mode` option selects another delivery, and the HTML plugin carries its runtime script:

| Mode | Plugin option | Installer option |
| --- | --- | --- |
| Static | `mode: 'static'` | None |
| Runtime | `mode: 'runtime'` | `--mode runtime` |

<DocumentDisclosure title="Generate new classes in the browser">

Run the installer with `--mode runtime` and your `--framework` value. It sets the plugin option to `mode: 'runtime'`:

```bash
npm create @master/css@rc -- --framework webpack --mode runtime --yes
```

Build and serve the production output. The emitted HTML should load the Master CSS runtime script. After startup, run this in the browser console; the paragraph should gain an underline without rebuilding:

```js
document.querySelector('#master-check').classList.add('underline')
```

</DocumentDisclosure>
