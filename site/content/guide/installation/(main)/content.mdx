Choose the setup that fits your project: [Integrations](#integrations) connects Master CSS to a framework or build tool, and [CLI](#cli) generates a stylesheet for projects without a bundler. [CDN](#cdn) provides a plain HTML setup for the default preset; its CSS-first release is pending.

## Integrations \{#integrations\}

Use an integration for an existing app. Static rendering is the default: the build finds complete class names in source and delivers a stylesheet to the browser. Choose your framework for its setup files and instructions, or use the automatic installer below.

<InstallationGuides />

For runtime and server-rendered setups, see [rendering support by integration](/guide/rendering-modes#integration-support).

### Before you start \{#installation\}

Use Node.js 24 and open the app's root directory, where its `package.json` lives. The installer updates an existing project; it does not create a framework starter. Your app should already have a working development command.

For manual setup or framework-specific files, use the [integration guides](/guide/installation#integrations). If your project has no matching build integration, follow the [standalone CLI setup](/guide/installation#cli).

<StepSection>
  <Step>
    ### Add Master CSS

    Run the installer from the project root. It detects the framework and package manager, updates the setup files, and installs the matching Master CSS packages from the `rc` channel.

    ```bash
    npm create @master/css@rc -- --yes
    ```

    <DocumentDisclosure title="Review or limit the setup">

    `--yes` accepts the recommended defaults. These include the core integration, ESLint configuration, the MCP package, and Master CSS guidance in `AGENTS.md`. The printed MCP registration and skill-installation commands are optional next steps for your coding tools; the installer does not run them.

    Add `--dry-run` to inspect the plan without changing project files or installing the planned dependencies:

    ```bash
    npm create @master/css@rc -- --yes --dry-run
    ```

    For only the core framework setup, add `--minimal` to the install command. It skips the ESLint, MCP and agent-guidance additions. If you prefer to install dependencies yourself, add `--no-install`.

    </DocumentDisclosure>
  </Step>
  <Step>
    ### Check the stylesheet connection

    Read the setup summary and finish any framework-specific instructions it prints. Some integrations need a follow-up setup command or a separate CSS generation process; see your [framework's guide](/guide/installation#integrations) for those steps.

    Confirm that your app loads the stylesheet the installer created or updated. That stylesheet should contain:

    ```css
    @import '@master/css';
    ```

    For example, a plain Vite app commonly imports `./style.css` from `src/main.js`. The CSS file's name and import location depend on the framework. Installing the packages alone does not load the stylesheet into your page.

    <InstallationIllustration />
  </Step>
  <Step>
    ### Start using Master CSS

    Start or restart your app's development server with its existing command, such as `npm run dev`. Put this markup in a visible page or component. In JSX, write `className` in place of `class`.

    <DemoConfiguredExample name="installation-check" title="Check your first style" source="" caption="With the preset, p-md adds 1rem of padding on every side of the text." html={`<p class="w-fit mx-auto my(0) p-md r-md b(1) b-solid b-line-divider bg-surface-raised text-sm fg-text-strong">
  Hello World
</p>`} />

    You should see text inside a small bordered surface. Change `p-md` to `p-lg` and save: its padding should grow from `1rem` to `1.5rem` on all four sides. This checks that changes in your source reach the page, beyond the installer completing successfully.
  </Step>
</StepSection>

## CDN \{#cdn\}

A CDN installation runs Master CSS in the browser without a build tool. It suits a plain HTML prototype; generated styles depend on JavaScript. Use an integration or the CLI when the page needs styles without JavaScript.

The CSS-first CDN release is not published yet. The current `rc` channel still serves the earlier RC88 runtime. The template below targets the new runtime: replace every `VERSION` with the same published CSS-first version of the runtime and preset before using it. Until then, use a local build as described below, or choose [Integrations](#integrations) or [CLI](#cli).

Save this template as `index.html`:

```html name=index.html
<!DOCTYPE html>
<html lang="en" hidden>

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="preload" as="style" href="https://cdn.master.co/css-preset@VERSION/src/base.css">
  <link rel="preload" as="script" href="https://cdn.master.co/css-runtime@VERSION">
  <link rel="preload" as="fetch" crossorigin href="https://cdn.jsdelivr.net/npm/@master/css-runtime@VERSION/dist/default-program.bin">
  <link rel="stylesheet" href="https://cdn.master.co/css-preset@VERSION/src/base.css">
  <script src="https://cdn.master.co/css-runtime@VERSION"></script>
</head>

<body>
  <h1 class="m-2xl italic font-5xl font-heavy fg-text-strong">Hello World</h1>
</body>

</html>
```

The heading should have a `3rem` margin, a `2.5rem` italic font at weight `900`, and the preset's strong text color. Change `font-5xl` to `font-6xl`: the text grows to `3rem`. The runtime also observes class changes made by JavaScript.

The stylesheet supplies the base rules and layer order. The classic script starts automatically, loads its matching compiled program, then generates the initial classes after the document finishes parsing. It removes `hidden` when those rules are ready. The three preload links start the stylesheet, script, and program requests early; the binary uses `as="fetch" crossorigin` because the runtime fetches data, not a module. The binary preload and runtime fetch use the jsDelivr destination directly because the Master CDN redirect does not carry CORS headers. The CDN setup uses the default preset; use an integration to compile custom `@theme` or `@utility` definitions.

<DocumentDisclosure title="Try a local build before the CDN release">

From a built checkout, copy `packages/preset/src/base.css`, `packages/runtime/dist/global.min.js`, and `packages/runtime/dist/default-program.bin` into one directory beside `index.html`. Keep the script and program from the same build.

Replace both stylesheet URLs with `./base.css`, both script URLs with `./global.min.js`, and the program preload URL with `./default-program.bin`. Serve the directory over HTTP and open `index.html`. The runtime resolves the program beside an explicit script file; at a Master CDN or jsDelivr npm package entry, it resolves `dist/default-program.bin` inside that package.

</DocumentDisclosure>

`hidden` is optional. It prevents an unstyled first paint; handled program-loading errors and the runtime's three-second startup timeout reveal the content. If JavaScript is disabled or the script itself cannot download, it cannot remove the attribute. Omit `hidden` when content must stay readable in those cases, or deliver static CSS.

For a Content Security Policy, allow the CDN and its jsDelivr redirect target for scripts, stylesheet loading and program fetching (`connect-src`), and allow the runtime's generated stylesheet. No Wasm is fetched. See [Runtime rendering](/guide/rendering-modes#runtime-rendering) for loading and hydration behavior.

## CLI \{#cli\}

Generate a static stylesheet from your HTML without adding a bundler. The CLI scans complete class names and writes CSS that you load with a normal stylesheet link. Use this setup when your project does not have a matching [framework integration](/guide/installation#integrations).

<StepSection>
  <Step>
    ### Install Master CSS
    Install Master CSS [CLI](https://www.npmjs.com/package/@master/css-cli) as a development dependency.

    ```bash
    npm install -D @master/css-cli@rc
    ```
  </Step>
  <Step>
    ### Create your CSS entry
    Create a stylesheet that imports the default Master CSS entry.

    ```css name=main.css
    @import "@master/css";
    ```
  </Step>
  <Step>
    ### Run the build command
    Run the command to scan sources and write `master.css`.

    ```bash
    npx @master/css-cli generate "index.html" --output master.css --watch
    ```
  </Step>
  <Step>
    ### Load the generated stylesheet
    Save the document below as `index.html`. The watcher generates `master.css` from its class names. Serve the directory and open the page to see the styled paragraph.
    <InstallationPreview>

```html name=index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="./master.css"> <!-- [!code highlight] -->
</head>
<body>
  <p id="master-check" class="w-fit m(0) p-md b-solid b(1) b-line-divider r-md text-sm font-regular bg-surface-raised fg-text-strong">Hello World</p>
</body>
</html>
```

    </InstallationPreview>
  </Step>
</StepSection>

### Build for deployment

The watch command stays running and updates the output when a selected source changes. For a production build, omit `--watch` so the command writes its output and exits:

```bash
npx @master/css-cli generate "index.html" --output master.css
```

Deploy `index.html`, `master.css` and the neighboring CSS assets referenced by the generated stylesheet. Preserve their relative paths: copying only `master.css` can leave its imported styles missing. Keep each generated asset set together when publishing a new build.

Load the deployed page and check that every stylesheet request succeeds. The paragraph should keep its generated padding, border and surface colors with JavaScript disabled. [Scanning class names](/guide/scanning-and-pruning) explains how to include sources outside the ordinary application scope.

## If the style does not appear

Check that the page renders the markup you edited and loads the app stylesheet. Then check that the build integration is enabled and scans that source file. Keep class names complete, as in `p-lg`; constructing them from fragments such as `p-${size}` prevents a static scan from seeing the final class.

If the installer reports an unrecognized framework or incomplete setup, follow the matching [integration guide](/guide/installation#integrations) or the [CLI guide](/guide/installation#cli). For files outside the normal application scope, see [Scanning class names](/guide/scanning-and-pruning).

Once the spacing change works, continue with the [Syntax tutorial](/guide/syntax-tutorial) to build a card with interaction states and responsive conditions.
