A browser-only [runtime](/guide/rendering-modes#runtime-rendering) page needs a base stylesheet, a runtime script and its compiled default program. Host the matching files together on your static host or CDN. The browser generates styles for connected classes; no application bundler is needed after those assets are available.

## Host matching assets

Start with matching runtime and preset packages installed in your project. The runtime build must contain both `dist/global.min.js` and `dist/default-program.bin`. Check for both files before choosing a public CDN URL: a moving npm tag does not establish that the program required by this guide is published.

For an application that serves `public/` as its web root, copy the assets into one directory:

```bash
mkdir -p public/master-css
cp node_modules/@master/css-preset/src/base.css public/master-css/base.css
cp node_modules/@master/css-runtime/dist/global.min.js public/master-css/global.min.js
cp node_modules/@master/css-runtime/dist/default-program.bin public/master-css/default-program.bin
```

Deploy all three files from the same matching package build. When using a CDN, keep `global.min.js` and `default-program.bin` in the same release directory. The script derives the program URL from its own directory; renaming or relocating only the program breaks startup.

If your available package does not contain the program, use an [integration](/guide/installation/integrations) with a matching package build. Do not mix a script from one release with a program copied from another.

## Load the page \{#start-in-one-step\}

Save this document as `public/index.html` and serve the `public/` directory over HTTP. The paths below load the files copied above. For a CDN deployment, use their deployed URLs in both the preload hints and the consuming tags.

<HelloWorld>

```html name=index.html
<!DOCTYPE html>
<html lang="en" hidden>
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="preload" as="fetch" crossorigin href="/master-css/default-program.bin">
  <link rel="stylesheet" href="/master-css/base.css">
  <script src="/master-css/global.min.js"></script>
</head>
<body>
  <h1 class="(margin:3rem) (color:#111827) (font-size:40px) italic (font-weight:800)">Hello World</h1>
</body>
</html>
```

</HelloWorld>

The heading becomes visible with a `40px` italic font and `3rem` margin after runtime startup. Check the Network panel for successful stylesheet, script and program responses, and the console for startup errors. Confirm that the later fetch reuses the program preload with your deployed cache headers. [Preload the runtime program](/guide/rendering-modes#preload-runtime-engine) explains the hint and how to verify it.

## Check delivery and startup failures

The script executes a program compiled for its engine. Keep the script and program on the direct CDN origin; a redirect without CORS headers can block the program fetch. A Content Security Policy must allow the script in `script-src` and the program fetch in `connect-src`.

The `hidden` root prevents an unstyled first view. The runtime reveals it after startup and also unhides it on a handled startup error, which can leave the content without generated styles. If JavaScript is disabled or the runtime script never executes, the root stays hidden. Use [static rendering](/guide/rendering-modes#static-rendering) when the page must have styles without JavaScript, and test these failure paths before shipping a runtime-only page.

This default program supplies the preset vocabulary. Use a matching [framework or bundler integration](/guide/installation/integrations) when you need a project program containing custom theme tokens, utilities, mixins or named conditions.
