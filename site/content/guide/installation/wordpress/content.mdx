Use static rendering when WordPress theme templates contain complete class strings and you want Vite to build a generated CSS asset before WordPress serves the page.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Open your theme
      Start from the active theme or child theme directory. These examples add assets to an existing classic PHP theme.
    </StepL>
    <StepR>
      ```bash name=Terminal
      cd wp-content/themes/my-theme
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the theme.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build static CSS into the theme `assets` directory.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'static' })
        ],
        build: {
          outDir: 'assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'resources/master.ts',
            output: {
              entryFileNames: 'master.js',
              assetFileNames: '[name][extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import Master CSS and point the stylesheet at PHP templates in the theme.
    </StepL>
    <StepR>
      ```ts name=resources/master.ts
      import './master.css'
      ```

      ```css name=resources/master.css
      @import "@master/css";

      @source "../**/*.php";
      @source not "../vendor/**";
      @source not "../node_modules/**";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Enqueue the stylesheet
      Add this hook inside the PHP code in `functions.php`, keeping its existing setup. The active-theme helpers also work for a child theme.
    </StepL>
    <StepR>
      ```php name=functions.php
      add_action('wp_enqueue_scripts', function () {
        wp_enqueue_style(
          'master-css',
          get_stylesheet_directory_uri() . '/assets/master.css',
          [],
          filemtime(get_stylesheet_directory() . '/assets/master.css')
        );
      });
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Add the heading inside an existing rendered template. Keep its header, footer and WordPress hooks.
  </Step>
  <HelloWorld url="localhost" />
</StepSection>

```html name=index.php
<h1 class="m-2xl font-style:italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Static rendering depends on complete class strings in scanned source files. For WooCommerce templates, include your theme overrides such as `@source "../woocommerce/**/*.php"` and avoid scanning plugin internals unless your theme stores complete class strings there.

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other theme assets; deploy `master.css` and every CSS file it imports together, preserving their names and relative paths.

## Verify the theme output
Build the assets before loading the page so `filemtime()` can read them. Confirm the active theme serves `assets/master.css`; the [stylesheet-directory helpers](https://developer.wordpress.org/reference/functions/get_stylesheet_directory_uri/) point to the child theme when one is active.

Keep `wp_head()` and `wp_footer()` in the theme: WordPress uses its hooks to print enqueued assets. The example heading is a template fragment, not a replacement for the complete theme index.

The heading should remain large, heavy and italic with JavaScript disabled. Content assembled from database values is not automatically present in scanned PHP source; map choices to complete class strings or safelist bounded candidates.
