Use Vite runtime rendering when WordPress owns the PHP template lifecycle. WordPress renders the theme, while the Vite-built Master CSS runtime generates class rules in the browser for theme and plugin output.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Open your theme
      Start from the active theme or child theme directory. These examples add assets to an existing classic PHP theme.
    </StepL>
    <StepR>
      ```bash name=Terminal
      cd wp-content/themes/my-theme
      npm init -y
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the theme.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm install @master/css@rc @master/css-runtime@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build the runtime entry and base stylesheet into the theme `assets` directory.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'runtime' })
        ],
        build: {
          outDir: 'assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'resources/master.ts',
            output: {
              entryFileNames: 'master.js',
              assetFileNames: '[name][extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import the Vite-managed runtime and the Master CSS stylesheet.
    </StepL>
    <StepR>
      ```ts name=resources/master.ts
      import { MasterCSSRuntime } from '@master/css-runtime'
      import program from 'virtual:master-css-program'
      import emittedGlobals from 'virtual:master-css-emitted-globals'
      import './master.css'

      const runtime = await MasterCSSRuntime.start({ program, emittedGlobals })
      runtime.observe()
      ```

      ```css name=resources/master.css
      @import "@master/css";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Enqueue the assets
      Add this hook inside the PHP code in `functions.php`, keeping its existing setup. The active-theme helpers also work for a child theme.
    </StepL>
    <StepR>
      ```php name=functions.php
      add_action('wp_enqueue_scripts', function () {
        $theme_dir = get_stylesheet_directory();
        $theme_uri = get_stylesheet_directory_uri();

        wp_enqueue_style(
          'master-css',
          $theme_uri . '/assets/master.css',
          [],
          filemtime($theme_dir . '/assets/master.css')
        );

        wp_enqueue_script_module(
          'master-css-runtime',
          $theme_uri . '/assets/master.js',
          [],
          filemtime($theme_dir . '/assets/master.js')
        );
      });
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Hello world
    Add the heading inside an existing rendered template. Keep its header, footer and WordPress hooks.
  </Step>
  <HelloWorld url="localhost" />

Use [WordPress static rendering](/guide/installation/wordpress) when theme template class strings are complete at build time and you want a generated CSS asset. For WooCommerce templates, include your theme overrides and avoid scanning plugin internals unless your theme stores complete class strings there.

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy every generated stylesheet, import and program asset together.

This runtime recipe requires WordPress 6.5 or later for [`wp_enqueue_script_module()`](https://developer.wordpress.org/reference/functions/wp_enqueue_script_module/). A Vite ES module must be loaded as a module, including its generated imports. Runtime styling begins after JavaScript loads. Keep the document visible if scripts are unavailable; see [Flash of Unstyled Content](/guide/flash-of-unstyled-content) before adding page hiding.

## Verify the theme output
Build the assets before loading the page so `filemtime()` can read them. Confirm the active theme serves `assets/master.css`; the [stylesheet-directory helpers](https://developer.wordpress.org/reference/functions/get_stylesheet_directory_uri/) point to the child theme when one is active.

Keep `wp_head()` and `wp_footer()` in the theme: WordPress uses its hooks to print enqueued assets. The example heading is a template fragment, not a replacement for the complete theme index.

After the heading is styled, add `underline` to it in browser developer tools. The runtime should generate the rule without a new build. This observes the page document; plugin content inside a separate iframe or shadow root needs its own CSS delivery.
