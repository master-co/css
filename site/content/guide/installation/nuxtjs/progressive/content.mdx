## Load the project stylesheet

Keep the module registration and explicitly load the CSS entry created by the installer. `~~/` points to the project root, including in Nuxt projects whose application directory is `app/`.

```ts name=nuxt.config.ts
export default defineNuxtConfig({
  modules: [['@master/css-nuxt', { mode: 'progressive' }]],
  css: ['~~/assets/css/master.css']
})
```

```css name=assets/css/master.css
@import '@master/css';
```

Run `npm run build`, then serve the generated Nitro output with `node .output/server/index.mjs`. Check initial styling before JavaScript and a later class absent from the page manifest. Also test the copied deployment artifact in its target directory; an in-place build does not establish that all manifest and program paths are portable.

After startup, run this in the browser console:

```js
document.querySelector('h1').classList.add('underline')
```

The heading should gain an underline without rebuilding. If it does not, inspect the runtime program request and console diagnostics.

If the copied server reports an `ENOENT` path under the original project's `node_modules/.master-css/manifest/`, it still depends on a build-machine manifest. That output is not ready for an independent deployment. Use [static rendering](/guide/installation/nuxtjs) or [runtime rendering](/guide/installation/nuxtjs/runtime) when either meets the application's delivery needs, and verify the chosen output after moving it too.
