Use Vite to build the browser assets for a Blazor app, then let Master CSS scan `.razor`, `.cshtml`, and host HTML files during that asset build. Vite owns the frontend asset pipeline; Blazor and .NET still own the app host page, project files, and server/runtime lifecycle.

<StepSection>
  <Step $row>
    <StepL>
      ### <StepNum />Create a Blazor project
      If you don't have a Blazor project, create one first.
    </StepL>
    <StepR>
      ```bash name=Terminal
      dotnet new blazor -o my-app
      cd my-app
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Install Vite and Master CSS
      Install Vite and the Master CSS Vite integration in the project root.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm init -y
      npm install @master/css@rc
      npm install -D vite @master/css-vite@rc
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Configure Vite
      Build static CSS into `wwwroot/assets` so the Blazor host page can load it as a normal static asset.
    </StepL>
    <StepR>
      ```ts name=vite.config.ts
      import { defineConfig } from 'vite'
      import masterCSS from '@master/css-vite'

      export default defineConfig({
        base: './',
        plugins: [
          masterCSS({ mode: 'static' })
        ],
        build: {
          outDir: 'wwwroot/assets',
          emptyOutDir: false,
          rollupOptions: {
            input: 'src/main.ts',
            output: {
              entryFileNames: 'app.js',
              assetFileNames: 'app[extname]'
            }
          }
        }
      })
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Create the asset entry
      Import the Master CSS entry from the Vite stylesheet and explicitly include Blazor source files.
    </StepL>
    <StepR>
      ```ts name=src/main.ts
      import './app.css'
      ```

      ```css name=src/app.css
      @import "@master/css";

      @source "../**/*.{razor,cshtml,html}";
      @source not "../bin/**";
      @source not "../obj/**";
      @source not "../node_modules/**";
      @source not "../wwwroot/assets/**";
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Add build scripts
      Merge these scripts into the existing `package.json`, keeping the dependencies installed above. Run Vite before serving the app, or keep it watching beside .NET.
    </StepL>
    <StepR>
      ```json name=package.json
      {
        "scripts": {
          "build:assets": "vite build",
          "watch:assets": "vite build --watch"
        }
      }
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Load the built assets
      Reference the Vite output from the Blazor host page your project uses, such as `Components/App.razor`, `wwwroot/index.html`, or `Pages/_Host.cshtml`. Add the stylesheet to `<head>`. Preserve the existing `<base>`, `<HeadOutlet />`, routes, and Blazor bootstrap script.
    </StepL>
    <StepR>
      ```html name=Components/App.razor
      <link rel="stylesheet" href="assets/app.css">
      ```
    </StepR>
  </Step>
  <Step $row>
    <StepL>
      ### <StepNum />Launch the app
      Build or watch the frontend assets, then run the Blazor app.
    </StepL>
    <StepR>
      ```bash name=Terminal
      npm run build:assets
      dotnet run
      ```
    </StepR>
  </Step>
  <Step>
    ### <StepNum />Start using Master CSS
    Now style your first Razor component using Master CSS syntax.
  </Step>
  <HelloWorld url="localhost:5000" />
</StepSection>

```html name=Components/Pages/Home.razor
@page "/"

<h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

Static rendering depends on complete class strings in scanned source files. If a Razor component assembles class names from fragments, map states to complete class strings or add bounded candidates with [`@safelist`](/reference/directives/candidates#safelist).

Build assets with `npx vite build` before starting or publishing the host application. During development, run `npx vite build --watch` in a separate terminal. The output keeps other host assets; deploy `app.css` and every CSS file it imports together, preserving their names and relative paths.

Merge the asset tags into the existing host document; retain its framework bootstrap script and routing setup. For a deployment below a URL prefix, resolve asset URLs through the host’s base path rather than assuming `/` is the application root.

## Keep routing and hosting intact
The `@page "/"` directive makes the component routable. Merge the asset tags into the [host document for your Blazor model](https://learn.microsoft.com/en-us/aspnet/core/blazor/project-structure?view=aspnetcore-10.0); the snippet is not a replacement for `App.razor`. The relative asset paths use the host’s existing `<base>` URL.

New .NET templates can include Bootstrap. Normal unlayered Bootstrap declarations can override layered Master CSS utilities, so check the loaded stylesheets and computed styles when a class appears ineffective. See [Cascade layers](/guide/cascade-layers) for precedence.

## Verify the result
Build Vite assets before `dotnet build` or `dotnet publish`, so .NET includes them in its static asset output. Run `dotnet run` and use the URL printed by the server. The heading should be large, heavy and italic.

For server-rendered HTML, styling should remain with JavaScript disabled. A WebAssembly-only Blazor app still needs its framework JavaScript to render the component.
