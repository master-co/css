Add Master CSS to a SvelteKit application. The add-on registers the Vite integration and imports its CSS entry from the root layout, so every route receives the shared styles.

## Installation

<StepSection>
  <Step $row>
    <StepL>
      ### Add Master CSS
      In an existing [SvelteKit project](https://svelte.dev/docs/kit/creating-a-project), run the Svelte CLI add-on from the project root. It installs static rendering and leaves existing server hooks unchanged.
    </StepL>
    <StepR>
      ```bash
      npx sv add @master/css-svelte-addon
      ```
    </StepR>
  </Step>
  <Step>
    ### Start using Master CSS
    Start the dev server and replace `src/routes/+page.svelte` with this heading. Keep the stylesheet import added to `src/routes/+layout.svelte`.
  </Step>

```svelte name=src/routes/%2Bpage.svelte
<h1 class="m-2xl italic font-5xl font-heavy fg-text-neutral">
  Hello World
</h1>
```

  </HelloWorld>
</StepSection>

## Check the static setup
Run the project's build and preview scripts. With server rendering enabled, the heading should keep its large, heavy italic styling when JavaScript is disabled. If styles are missing, check the Master CSS plugin in `vite.config.ts` and the CSS import in the root layout.

Component `<style>` blocks can use project tokens in native declarations. Keep the global CSS entry loaded for resets, native component rules and generated utilities. Use `@reference` for definition files outside the project context.

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default and needs no Master CSS hooks. Keep the CSS entry when changing modes:

| Mode | Vite mode | Master CSS hooks |
| --- | --- | --- |
| Static | `static` | None |
| Runtime | `runtime` | Client |
| Progressive | `progressive` | Client and server |
| Pre-render only | `pre-render` | Server with hydration manifest disabled |

<DocumentDisclosure title="Generate new classes in the browser">

In `vite.config.ts`, replace the existing `masterCSS()` call with this option. Keep the `sveltekit(...)` call, its adapter configuration, and any other plugins:

```ts
masterCSS({ mode: 'runtime' })
```

Load the bootstrap once from the client hook. Keep any existing hook exports:

```ts name=src/hooks.client.ts
/// <reference types="@master/css/client" />

import 'virtual:master-css-runtime'
```

SvelteKit renders its own HTML, so the Vite mode option alone does not insert a runtime script. The client import starts the runtime with the project program and handles Vite HMR.

After startup, run this in the browser console. The heading should gain an underline without rebuilding:

```js
document.querySelector('h1').classList.add('underline')
```

</DocumentDisclosure>

<DocumentDisclosure title="Include server-rendered styles">

For progressive rendering, change the Vite option above to `mode: 'progressive'`, keep the client hook, and add the server handle:

```ts name=src/hooks.server.ts
export { handle } from '@master/css-svelte/hooks.server'
```

If the application already has a server handle, preserve it and place the Master CSS handle first in SvelteKit's [`sequence()`](https://svelte.dev/docs/kit/@sveltejs-kit-hooks#sequence). Page transforms run in reverse order, so Master CSS then sees the HTML produced by the later handlers.

A page covered by its pre-rendered classes can defer loading the runtime engine. Check initial styling with JavaScript disabled, then re-enable it and test a new class.

For pre-render-only delivery, choose `mode: 'pre-render'`, remove only the Master CSS client bootstrap, and use this server configuration:

```ts name=src/hooks.server.ts
/// <reference types="@master/css/client" />

import manifest from 'virtual:master-css-manifest'
import emittedGlobals from 'virtual:master-css-emitted-globals'
import { createMasterCSSHandle } from '@master/css-svelte/hooks.server'

export const handle = createMasterCSSHandle({
  manifest,
  emittedGlobals,
  hydrationManifest: false
})
```

This supplies CSS for the rendered HTML without a Master CSS browser runtime. Classes introduced later need a separately delivered stylesheet or a mode with runtime generation.

</DocumentDisclosure>
