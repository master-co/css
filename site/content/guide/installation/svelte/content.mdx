Add Master CSS to a SvelteKit application. The add-on registers the Vite integration and imports its CSS entry from the root layout, so every route receives the shared styles.

## Installation \{#installation\}

<StepSection>
  <Step $row>
    <StepL>
      ### Add Master CSS \{#add-master-css\}
      In an existing [SvelteKit project](https://svelte.dev/docs/kit/creating-a-project), run the Svelte CLI add-on from the project root. It installs static rendering and leaves existing server hooks unchanged.
    </StepL>
    <StepR>
      ```bash
      npx sv add @master/css-svelte-addon
      ```
    </StepR>
  </Step>
  <Step>
    ### Check the shared entry \{#check-the-shared-entry\}
    The add-on updates the project's CSS entry with `@import '@master/css';` and imports that entry from `src/routes/+layout.svelte`. Keep the layout's existing script, child rendering and other imports. Do not put the global entry in a page that other routes never load.

    In `vite.config.ts`, keep both `masterCSS()` and `sveltekit(...)`. Static mode does not need a Master CSS client or server hook.
  </Step>
  <Step>
    ### Start using Master CSS \{#start-using-master-css\}
    Start the dev server and replace `src/routes/+page.svelte` with this paragraph. Keep the stylesheet import added to `src/routes/+layout.svelte`.
  </Step>
  <InstallationPreview>

```svelte name=src/routes/%2Bpage.svelte
<p id="master-check" class="w-fit m(0) p-md b-solid b(1) b-line-divider r-md text-sm font-regular bg-surface-raised fg-text-strong">
  Hello World
</p>
```

  </InstallationPreview>
</StepSection>

## Check the static setup \{#check-the-static-setup\}
Run `npm run dev` and change `p-md` to `p-lg` in the page. Its padding should grow from `1rem` to `1.5rem`. Restore it, then check the production build:

```bash
npm run build
npm run preview
```

With server rendering enabled, the paragraph should keep its padding, rounded corners and raised surface when JavaScript is disabled. Visit another route to confirm that the root layout loads the entry there too. If styles are missing, check the Master CSS plugin in `vite.config.ts` and the CSS import in the root layout.

Component `<style>` blocks can use project tokens in native declarations. Keep the global CSS entry loaded for resets, native component rules and generated utilities. Use `@reference` for definition files outside the project context.

## Choose another rendering mode \{#rendering-modes\}
Static mode is the default and needs no Master CSS hooks. Keep the CSS entry when changing modes:

| Mode | Vite mode | Master CSS hooks |
| --- | --- | --- |
| Static | `static` | None |
| Runtime | `runtime` | Client |
| Progressive | `progressive` | Client and server |
| Prerender | `prerender` | Server with hydration manifest disabled |

<DocumentDisclosure title="Generate new classes in the browser">

In `vite.config.ts`, replace the existing `masterCSS()` call with this option. Keep the `sveltekit(...)` call, its adapter configuration, and any other plugins:

```ts
masterCSS({ mode: 'runtime' })
```

Load the bootstrap once from the client hook. Keep any existing hook exports:

```ts name=src/hooks.client.ts
/// <reference types="@master/css/client" />

import 'virtual:master-css-runtime'
```

SvelteKit renders its own HTML, so the Vite mode option alone does not insert a runtime script. The client import starts the runtime with the project program and handles Vite HMR.

After startup, run this in the browser console. The paragraph should gain an underline without rebuilding:

```js
document.querySelector('#master-check').classList.add('underline')
```

</DocumentDisclosure>

<DocumentDisclosure title="Include server-rendered styles">

For progressive rendering, change the Vite option above to `mode: 'progressive'`, keep the client hook, and add the server handle:

```ts name=src/hooks.server.ts
export { handle } from '@master/css-svelte/hooks.server'
```

If the application already has a server handle, preserve it and place the Master CSS handle first in SvelteKit's [`sequence()`](https://svelte.dev/docs/kit/@sveltejs-kit-hooks#sequence). Page transforms run in reverse order, so Master CSS then sees the HTML produced by the later handlers. For example, move your existing handle into `src/hooks.application.ts` without changing its behavior, then compose the two:

```ts name=src/hooks.server.ts
import { sequence } from '@sveltejs/kit/hooks'
import { handle as masterCSS } from '@master/css-svelte/hooks.server'
import { handle as application } from './hooks.application'

export const handle = sequence(masterCSS, application)
```

Keep unrelated exports such as `handleError` in `hooks.server.ts`.

A page covered by its pre-rendered classes can defer loading the runtime engine. Check initial styling with JavaScript disabled, then re-enable it and test a new class.

For prerender mode, choose `mode: 'prerender'`, remove only the Master CSS client bootstrap, and use this server configuration:

```ts name=src/hooks.server.ts
/// <reference types="@master/css/client" />

import manifest from 'virtual:master-css-manifest'
import emittedGlobals from 'virtual:master-css-emitted-globals'
import { createMasterCSSHandle } from '@master/css-svelte/hooks.server'

export const handle = createMasterCSSHandle({
  manifest,
  emittedGlobals,
  hydrationManifest: false
})
```

This supplies CSS for the rendered HTML without a Master CSS browser runtime. Classes introduced later need a separately delivered stylesheet or a mode with runtime generation.

</DocumentDisclosure>
