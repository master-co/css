## Overview [sr-only] \{#overview\}
Compose a page from three decisions: a wrapper that caps the width, spacing tokens for gutters and margins, and a column grid for the regions. Native [Grid](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_grid_layout) and [Flexbox](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_flexible_box_layout) do the layout; Master CSS names the values.

(resize) Adjust the viewport with the slider or arrow keys to see the surface move from a compact stacked layout to an 8-column composition.

```html
<!-- @MARK max-w-3xl --><!-- @MARK grid-cols(4) --><!-- @MARK grid-cols(8)@2xs --><!-- @MARK gap-md@2xs -->
<main class="w-full max-w-3xl mx-auto p-md">
  <section class="grid-cols(4) gap-sm grid-cols(8)@2xs gap-md@2xs">
    <header class="grid-col-span(4) grid-col-span(8)@2xs"><h1>Project overview</h1></header>
    <article class="grid-col-span(4)"><h2>Revenue</h2><p>$128.4k</p></article>
    <article class="grid-col-span(4)"><h2>Activation</h2><p>64.2%</p></article>
    <article class="grid-col-span(4) grid-col-span(5)@2xs"><h2>Weekly demand</h2></article>
    <aside class="grid-col-span(4) grid-col-span(3)@2xs"><h2>Launch tasks</h2></aside>
  </section>
</main>
```

## Choose a spacing value \{#namespace-for-spacing\}

Spacing classes such as `p-`, `m-` and `gap-` accept three forms:

| Form | Class | Generates |
| --- | --- | --- |
| Spacing token | `p-md` | `padding: var(--spacing-md)` |
| Direct value | `p(1)` | `padding: calc(1 * 1px)` |
| Native length | `(padding:0.5rem)` | `padding: 0.5rem` |

<Class2CSS classes={['p-md', 'p(1)', '(padding:0.5rem)']} />

Use tokens for the rhythm a page shares: gutters, padding and section spacing. A direct-value length is expressed in pixels, so `p(1)` is a one-pixel padding, not one step of a scale; use it for hairlines and resets such as `m(0)`. Write other units as a native declaration. See [Spacing](/reference/tokens/spacing) for the scale and [Direct values](/reference/direct-values) for every function.

<a id="do-not-use-numeric-keys-as-tokens"></a>
When a distance becomes a repeated decision, name it by its role. A numeric key such as `--spacing-1` would read like the direct value `p(1)`.

```css name=index.css
@theme {
  --spacing-section: 6rem;
}
```

```html
<!-- @MARK py-section -->
<section class="py-section">…</section>
```

`px-*` and `py-*` set logical inline and block padding. Their physical direction follows the element's writing mode:

<ReferenceIllustration id="logical-inline-axis" />

`p-*` sets all four sides. Add a side-specific class when just one inset should differ:

## Cap widths with container sizes \{#use-container-tokens\}

`w-`, `max-w-`, `h-`, `min-w-` and `basis-` read `--container-*` tokens, so `max-w-5xl` is `max-width: var(--container-5xl)`. The full and intrinsic sizes are fixed utilities instead: `w-full`, `w-fit`, `w-max` and `w-min` always set `100%`, `fit-content`, `max-content` and `min-content`, and a project `--container-full` token does not change them.

<Class2CSS classes={['max-w-5xl', 'w-full', 'w-fit']} />

Container tokens set lengths only; they do not move a container query threshold. See [Container sizes](/reference/tokens/container) for the scale.

## Start with a page wrapper \{#start-with-a-page-container\}

Let the wrapper fill its parent, cap it with a container size, center it and give its content side gutters from the spacing scale:

```html
<!-- @MARK w-full --><!-- @MARK max-w-7xl --><!-- @MARK mx-auto --><!-- @MARK px-md --><!-- @MARK px-xl@md -->
<main class="w-full max-w-7xl mx-auto px-md px-xl@md">…</main>
```

<Class2CSS classes={['w-full', 'max-w-7xl', 'mx-auto', 'px-md', 'px-xl@md']} />

Keep page alignment on the wrapper and content relationships on the grids inside it.

## Build column grids \{#build-column-grids\}

`grid-cols(<count>)` creates a grid of equal columns, and `grid-col-span(<count>)` places an item across several of them. When a breakpoint changes the column count, change the spans at the same breakpoint.

(x) The grid grows to 12 columns, but the article keeps its four-column span and leaves four columns empty.

```html
<section class="grid-cols(4) gap-lg grid-cols(12)@md">
  <article class="grid-col-span(4)">…</article>
  <aside class="grid-col-span(4)">…</aside>
</section>
```

(o) The article spans eight columns at the same breakpoint.

```html
<!-- @MARK grid-col-span(8)@md -->
<section class="grid-cols(4) gap-lg grid-cols(12)@md">
  <article class="grid-col-span(4) grid-col-span(8)@md">…</article>
  <aside class="grid-col-span(4)">…</aside>
</section>
```

<Class2CSS classes={['grid-cols(4)', 'grid-cols(12)@md', 'grid-col-span(8)@md']} />

<ReferenceIllustration id="span-includes-gaps" />

Use `col-gap-*` and `row-gap-*` when the two axes need different spacing tokens. See [Grid tracks](/reference/grid-tracks).

## Add explicit tracks \{#add-explicit-tracks-only-when-needed\}

For fixed or mixed tracks, write the native `grid-template-columns` value. Separate its tracks with `_`, which becomes a space in the generated CSS:

```html
<!-- @MARK (grid-template-columns:4.5rem_minmax(0,1fr)) -->
<section class="grid (grid-template-columns:4.5rem_minmax(0,1fr)) gap-md">
  <nav>…</nav>
  <main class="min-w(0)">…</main>
</section>
```

<Class2CSS classes={['(grid-template-columns:4.5rem_minmax(0,1fr))', 'min-w(0)']} />

`min-w(0)` lets the main region shrink below the width of its content. Keep equal columns and spans for ordinary content; use explicit tracks for app shells and split panes.

## Verify the layout with longer content \{#verify-the-layout-with-longer-content\}

Resize across each breakpoint and check both the grid count and its children's spans. Use a longer heading and task label to make sure the content can grow vertically. Keep fixed dimensions for measured objects or intentional viewports; page cards usually need only padding and a width constraint.

Try the preview's task checkboxes with a keyboard, and follow its section links. The layout should remain usable when the content wraps; shrinking the type to force it into a fixed-height card would hide the underlying constraint.
