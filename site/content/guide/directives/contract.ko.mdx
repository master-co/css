## 진입점 표시 \{#entry-markers\}
`@import`로 스타일시트를 전달하고 그 정의를 사용할 수 있게 합니다. 로컬 컴파일에 정의가 필요하지만 다른 출력이 네이티브 스타일시트를 담당한다면 `@reference`를 사용하세요. 앱 설정은 [설치](/guide/installation), 라우트별 소유 관계는 [라우트 단위 스타일](/guide/route-level-styles)을 참고하세요.

<ReferenceIllustration id="import-reference-output" />

### `@import "@master/css"` \{#import-mastercss\}
이 패키지 가져오기가 유일한 프로젝트 진입점 표시입니다. 안정적인 레이어 순서와 기본 스타일을 포함한 프리셋의 네이티브 CSS를 불러오고 생성 유틸리티 CSS를 받을 스타일시트를 지정합니다.

```css
@import "@master/css";
```

명시적인 독립 컴파일러와 manifest API도 사용할 수 있습니다. manifest만으로는 네이티브 CSS를 불러오지 않습니다. 런타임이나 서버 렌더링을 사용하는 앱도 관련 네이티브 스타일시트를 전달해야 합니다.

### 로컬 파일 URL \{#local-file-urls\}

Node 파일 컴파일은 CSS 이스케이프와 대소문자 규칙으로 CSS 가져오기 이름을 읽습니다. 상대 `@import`와 `@reference` URL의 경로는 소스 파일을 기준으로 해석합니다. 퍼센트 이스케이프는 파일 이름 문자를 나타내며 쿼리 문자열과 프래그먼트는 파일시스템 경로에서 제외합니다. 예를 들어 `"./tokens%20%23.css?v=1#theme"`는 같은 디렉터리의 `tokens #.css`를 읽습니다. 기존의 `"tokens.css"` 같은 단순 상대 CSS 경로도 확장합니다. 일치하는 로컬 파일이 없는 패키지 가져오기는 호스트 리졸버가 계속 처리할 수 있습니다. 참조 파일은 컴파일 시점의 맥락이며 네이티브 CSS를 출력하지 않습니다. 준비된 가상 스타일시트에서는 호스트가 명시한 파일시스템 소스 소유자가 상대 CSS 참조의 기준도 제공합니다. 참조한 테마 토큰의 리소스는 다른 곳에서 사용해도 참조 파일을 기준으로 유지됩니다.

### 스타일시트 경계와 리소스 URL \{#stylesheet-boundaries-and-resource-urls\}

가져오기의 media, supports, layer 한정자는 가져온 스타일시트에 적용됩니다. CSS를 게시할 때 이 경계를 유지하고 이미지와 글꼴 URL은 원래 소스 파일에서 해석하세요. `@reference`로 사용하는 토큰도 정의 파일을 리소스 소유자로 유지합니다.

전역 Master 정의는 한정자 없는 가져오기나 참조에 둡니다. 한정자 있는 가져오기는 이미 사용 가능한 믹스인을 적용하는 네이티브 규칙 등 네이티브 CSS를 포함할 수 있지만 `@theme`, `@utility`, `@mixin`, `@custom-media`, `@custom-container` 정의를 등록할 수는 없습니다.

```css
@import "./tokens.css";
@import "./print.css" print;
@import "./components.css" layer(components);
```

각 `@import`는 스타일시트를 다시 인라인하므로 여러 곳에서 가져온 파일은 반복됩니다. 한 가져오기 그래프는 최대 10,000개 스타일시트와 64 MiB의 CSS를 인라인합니다. 공유 파일은 사용하는 모든 파일에서 가져오지 말고 한 번만 가져오세요.

정의와 스캔 메타데이터를 불러와도 파일을 게시하지는 않습니다. CLI 파일 내보내기와 Vite 프로덕션 빌드는 필요한 스타일시트와 리소스 에셋을 게시합니다. 사용자 정의 컴파일러 호스트는 전달 API가 반환한 모든 에셋을 게시해야 합니다. manifest만으로는 네이티브 규칙을 전달하지 않습니다. [렌더링과 스타일시트 전달](/guide/rendering-modes#native-css-entries), [컴파일러 진입점](/reference/packages#css-compiler)을 참고하세요.


### 전체 에셋 게시 \{#publish-stylesheet-assets\}

컴파일한 CSS 진입점도 다른 CSS 파일을 가져오거나 이미지와 글꼴을 참조할 수 있습니다. 진입점 텍스트만 게시하면 의존 리소스를 사용할 수 없습니다. 반환된 모든 URL과 가져오기 한정자를 유지하세요. 외부 가져오기가 있는 자식 스타일시트를 평탄화하면 로딩 순서나 조건 범위가 바뀔 수 있습니다.

<ReferenceIllustration id="stylesheet-asset-graph" />

| 전달 경로 | 게시 담당 |
| --- | --- |
| CLI `generate --output dist/app.css` | CLI가 로컬 가져오기를 진입점에 평탄화하고 리소스 파일과 유지된 경계에 필요한 별도 CSS를 작성합니다. 전체 파일을 배포하세요. |
| Vite 프로덕션 빌드 | 통합이 관리 대상 가져오기를 Vite CSS 에셋에 평탄화하고 나머지 에셋도 빌드에 출력합니다. 설정한 공개 기본 경로와 함께 전체 출력을 배포하세요. |
| `delivery`를 사용하는 `compileManifestFileSync()` | API가 스타일시트 내용과 리소스 목적지를 반환하며 사용자 정의 호스트가 작성하거나 제공합니다. |
| manifest 또는 CSS 문자열 | 둘 다 파일을 게시하지 않습니다. 호출자가 네이티브 CSS 전달과 참조 리소스를 담당합니다. |

프로덕션 평탄화는 캐스케이드를 유지합니다. 레이어 구문은 제자리에 남고 `layer()`, `supports()`, media 한정자는 동등한 `@layer`, `@supports`, `@media` 블록이 되며 빈 스타일시트는 사라집니다. 앞에 다른 외부 가져오기만 있는 스타일시트 상단의 외부 가져오기는 스타일시트와 함께 위로 이동합니다. 한정자 아래 namespace나 가져오기를 유지하거나 외부 가져오기가 인라인 규칙 뒤에 놓이게 되는 스타일시트는 별도 파일로 유지됩니다. `@import`는 규칙 뒤에 올 수 없으므로 같은 파일에서 그 앞에 있는 가져오기도 별도로 남습니다.

이미지와 글꼴은 `@reference`를 통해 사용하는 리소스도 포함해 정의한 스타일시트를 소스 소유자로 유지합니다. 게시 시 URL을 다시 쓰되 쿼리 문자열과 프래그먼트는 유지합니다. 참조 전용 스타일시트는 정의를 읽었다는 이유만으로 게시되지 않습니다.

CLI의 `--no-export` 경로는 에셋을 복사하지 않고 CSS를 출력합니다. 파일 내보내기의 감시 모드는 가져온 스타일시트나 리소스가 없으면 마지막 성공 출력을 유지하고 오류를 보고한 뒤 복구 후 다시 빌드합니다. 오래된 출력을 최신 빌드의 성공으로 간주하지 마세요.

사용자 정의 호스트는 [컴파일러 전달 규칙](/reference/packages#css-compiler)을 참고하세요. Vite의 처리된 텍스트, 원본 소스, URL 가져오기는 [스타일시트 로딩](/guide/installation/vite#stylesheet-loading)에 있습니다. [라우트 단위 스타일](/guide/route-level-styles)은 어떤 페이지가 로컬 스타일시트를 소유하는지 설명합니다.

## 참조 맥락 \{#reference-context\}
### `@reference` \{#reference\}
다른 스타일시트의 정의가 컴파일에 필요하지만 네이티브 규칙은 가져오지 않을 때 참조를 사용합니다. 이 예제는 앱 진입점에서 간격 토큰과 선택자 믹스인을 불러옵니다.

```css name=app.css
@import "@master/css";

@mixin --manual-dark {
  &:where([data-theme="dark"], [data-theme="dark"] *) { @contents; }
}
```

```css name=Button.module.css
@reference "../app.css";

.button {
  padding: var(--spacing-md);
  @apply --manual-dark { color: white; }
}
```

참조는 해석에 필요한 토큰, 유틸리티, 믹스인, 사용자 정의 미디어와 컨테이너, 네이티브 키프레임 정의를 제공합니다. 참조 파일의 네이티브 CSS를 전달하거나 그 클래스를 생성하거나 스캔 소스를 추가하지 않습니다. 사용하는 관리 대상 토큰과 키프레임은 로컬 출력에 의존 리소스를 포함시킬 수 있습니다. 참조한 네이티브 규칙은 사용 루트가 되지 않습니다. 네이티브 재정의에는 실제 `@import`나 별도로 전달한 스타일시트가 필요합니다. 참조 키프레임은 로컬에서 사용할 때만 출력됩니다.

<ReferenceIllustration id="reference-no-roots" />

참조는 따옴표로 감싼 리소스 하나를 포함하는 최상위 구문이어야 합니다. 상대 경로는 선언한 스타일시트의 디렉터리를 기준으로 합니다. 패키지 참조는 내보낸 CSS 진입점을 해석합니다. 참조는 진입점 표시가 아닙니다.

Vite, Next.js, Webpack은 로컬 스타일시트, CSS Modules, SFC 스타일에 프로젝트 정의 맥락을 제공합니다. 그 맥락 밖의 의존성이나 독립 컴파일에는 명시적 참조가 유용합니다. 로컬 스타일시트는 스캔이나 가지치기 루트가 되지 않습니다. CSS Modules와 범위가 제한된 호스트는 생성 테마 선택자를 전역으로 전달해야 합니다.

정의 맥락은 로컬 정의보다 먼저 불러오므로 로컬 정의가 가져오거나 참조한 정의를 교체할 수 있습니다. CSS 출력을 나누는 컴파일러 호스트는 공유 변수와 키프레임을 어떤 출력이 전달하는지도 추적해야 합니다. [컴파일러 리소스 소유권](/reference/packages#css-compiler)을 참고하세요.

## 테마 선언 \{#theme-declarations\}
`@theme`는 유틸리티 정의에 사용할 토큰을 등록합니다. 수정자는 전달할 토큰 선언과 생성 값에 `var()`를 사용할지 작성한 값을 치환할지를 독립적으로 제어합니다. 프로젝트 설정은 [테마 토큰](/guide/theme), 범위와 상속 및 해석은 [변수와 모드](/reference/rules/modes)를 참고하세요.

### `@theme` \{#theme\}
유틸리티 토큰을 사용자 지정 속성으로 선언합니다. 테마 블록은 최상위에 있어야 하며 사용자 지정 속성 토큰 선언만 허용합니다. 키프레임은 블록 밖의 네이티브 CSS에 선언하세요.

```css
@theme {
  --color-brand: #4f46e5;
  --spacing-card: 1.5rem;
}
```

알 수 없거나 중복된 수정자는 오류입니다. `static`과 `inline`은 어느 순서로든 쓸 수 있습니다.

| 선언 | 토큰 전달 | 생성 값 |
| --- | --- | --- |
| `@theme` | 필요할 때 | `var(--token)` |
| `@theme static` | 항상 | `var(--token)` |
| `@theme inline` | 다른 참조나 의존성으로 유지될 때만 | 선언 값 |
| `@theme static inline` | 항상 | 선언 값 |

토큰은 `@layer theme`의 `:root, :host`에 출력됩니다. 컴파일러는 선언 순서와 중복 값을 유지합니다. 사용하는 토큰은 전이적 변수 의존성을 유지합니다. 선택자와 조건 규칙은 블록 밖의 네이티브 CSS에 둡니다.

유틸리티 패턴의 명명 토큰을 등록하는 것은 `@theme`뿐입니다. `:root { --app-brand: red; }` 같은 네이티브 선언은 일반 CSS로 유지됩니다. `(color:var(--app-brand))`로 직접 사용하거나 inline 테마 토큰으로 연결하세요.

<ReferenceIllustration id="theme-modifier-axes" />

### `@theme inline` \{#theme-inline\}
`inline`을 사용해 토큰의 선언 값을 Master가 생성하는 선언에 치환합니다.

```css
@theme inline { --color-brand: var(--app-brand); }
:root { --app-brand: #4f46e5; }
[data-theme="ocean"] { --app-brand: #0369a1; }
```

`bg-brand`는 `background-color:var(--app-brand)`를 출력하여 클래스를 사용하는 요소에서 네이티브 변수를 해석합니다. 직접 선언 클래스, 유틸리티 클래스, 네이티브 `@apply` 확장에도 같은 치환을 적용합니다. 직접 작성한 네이티브 선언은 원래의 `var()` 참조를 유지합니다.

치환은 한 번만 실행합니다. 치환 값 안의 변수, 함수, 대체 값은 네이티브 CSS 의미를 유지합니다. 의존성은 결과 선언에서 수집하므로 inline 유틸리티 사용만으로는 치환된 토큰의 출력을 강제하지 않습니다. 토큰을 직접 네이티브 방식으로 참조하면 그 선언을 유지할 수 있습니다.

테마 정의가 반복되면 중요도 다음 소스 순서로 inline 값과 모드를 선택합니다. 사용자 지정 속성의 `!important`는 생성 유틸리티를 중요하게 만들지 않습니다. 일반 별칭은 선언한 범위에서 해석됩니다. 연결 값이 사용 위치에서 다른 변수를 읽어야 한다면 inline을 사용하세요.

### `@theme static` \{#theme-static\}
클래스나 네이티브 참조가 없어도 토큰을 출력해야 할 때 `static`을 사용합니다.

```css
@theme static { --color-integration: #4f46e5; }
@theme static inline { --color-brand: var(--app-brand); }
```

`static`은 토큰 전달을, `inline`은 생성 값을 제어하며 어느 순서로든 조합할 수 있습니다. static 선언이 하나라도 있는 토큰은 정의를 제거할 때까지 의존성과 함께 유지됩니다. 참조 스타일시트는 토큰이 static이라는 이유만으로 출력 루트가 되지 않습니다.

### 네이티브 테마 재정의 \{#theme-mode\}
`@theme`에 기본값을 등록한 뒤 네이티브 선택자나 쿼리로 변수를 재정의합니다.

```css
@theme { --color-panel: white; }
[data-theme="ocean"] { --color-panel: #082f49; }
@media (prefers-color-scheme: dark) {
  :root { --color-panel: #111827; }
}
```

네이티브 재정의는 작성한 범위, 레이어, 스타일시트 전달을 유지합니다. 같은 요소에서는 레이어 없는 일반 재정의가 theme 레이어의 일반 선언보다 우선합니다. `defaults` 같은 뒤쪽 레이어도 재정의를 우선하면서 `components`와 `utilities` 레이어에 더 높은 우선순위를 허용합니다. 재정의가 필요한 곳에 네이티브 스타일시트를 가져오세요. `@reference`는 정의만 제공하며 규칙을 전달하지 않습니다.

프리셋은 적응형 색상과 그림자에 네이티브 `light-dark()`를 사용하며 두 변수 분기를 모두 의존성으로 유지합니다. 네이티브 기본 CSS는 루트에 `color-scheme: light dark`를 설정하고 요소와 섀도 호스트에 밝음/어두움 `data-theme` 선택자를 제공합니다. [색상](/guide/colors#native-color-scheme-and-manual-themes)을 참고하세요.

<StylesheetExample title="Scoped tokens in native CSS" source={"@theme { --color-brand: #4f46e5; }  .dark { --color-brand: #111827; } .card { color: var(--color-brand); }"} />

### 토큰 제거 \{#theme-removal\}
값이 `initial`인 테마 선언은 토큰을 선언하지 않고 제거합니다. 프리셋과 기본 manifest의 토큰을 포함해 해당 이름의 이전 정의가 모두 버려지며, 이전 값도 `initial`도 전달되지 않습니다. 유틸리티도 제거된 키를 더 이상 해석하지 않습니다. 이후 같은 이름을 다시 선언하면 토큰이 다시 정의됩니다.

```css
@import "@master/css";
@theme { --duration-fast: initial; }

/* The project's own variable, unrelated to the preset token of the same name */
.panel { --duration-fast: 120ms; transition-duration: var(--duration-fast); }
```

제거하지 않으면 네이티브 `var(--duration-fast)` 참조 때문에 프리셋의 `--duration-fast`가 `:root, :host`에 유지되어 `.panel` 밖의 요소에 원래 없던 값이 생깁니다. 네이티브 CSS가 그 이름을 다른 용도로 쓴다면 토큰을 제거하고, 프로젝트가 여전히 프리셋 기본값을 원한다면 토큰을 유지한 채 네이티브로 재정의하세요.

## 쿼리 정의 \{#query-definitions\}
재사용할 조건에 한 번 이름을 붙이고 네이티브 CSS나 클래스 접미사에서 사용합니다. 미디어 이름은 뷰포트나 기기 조건을, 컨테이너 이름은 사용 위치에서 선택한 컨테이너에 대해 검사할 조건을 나타냅니다. 정의는 최상위이며 무조건적이어야 합니다.

클래스 접미사 구문은 [조건](/reference/rules/conditions), 모든 프리셋 조건은 [명명된 조건](/reference/rules/named-conditions), 레이아웃 경계 선택은 [반응형 디자인](/guide/responsive-design)을 참고하세요.

<ReferenceIllustration id="container-condition-expansion" />

### `@custom-media` \{#custom-media\}
[CSS Media Queries 명세](https://drafts.csswg.org/mediaqueries-5/#custom-mq)에 따라 명명된 미디어 쿼리를 정의합니다.

```css
@custom-media --wide (width >= 60rem);
@custom-media --reading (--wide), print;
@custom-media --outside not (--reading);
@custom-media --enabled true;
@custom-media --disabled false;

@media (--reading) { .article { max-width: 70ch; } }
```

이름은 `--`로 시작합니다. CSS 참조는 `(--name)`, 마크업은 `@name`, 로컬 명명 블록은 `@media (--name)`을 사용합니다. 네이티브 CSS, 유틸리티와 믹스인 정의, 마크업 쿼리는 같은 레지스트리를 사용합니다.

정의는 쿼리 목록, 전방 참조, `true`, `false`, 중첩 불리언 식, 부정, 미디어 타입을 지원합니다. 확장은 논리적으로 동작합니다. 목록의 논리합을 유지하며 부정은 참조한 전체 식에 적용됩니다. 목록의 각 쿼리는 별도 분기가 되고 클래스의 모든 조건 분기 수는 곱해집니다. `@reading`을 열두 번 반복하는 경우처럼 4,096개 분기를 초과하는 클래스는 규칙을 생성하지 않습니다. 컴파일러는 일반 미디어 쿼리를 출력하며 혼합 미디어 타입을 단일 쿼리로 표현할 수 없으면 중첩 블록을 사용합니다. 브라우저 custom-media API나 JavaScript 런타임 등록은 필요하지 않습니다.

정의되지 않거나 순환하거나 유효하지 않은 참조는 컴파일 오류입니다. 같은 이름은 뒤의 정의가 우선합니다. 미디어와 믹스인 이름은 독립적입니다. `@name`은 미디어를 선택하고 `@apply(--name)`은 믹스인을 호출합니다. `@starting-style`이 내장되어 있으므로 `--starting-style`은 예약어입니다. 프리셋에는 `--breakpoint-*` 토큰이 없습니다. 이 접두사를 가진 프로젝트 사용자 지정 속성은 일반 CSS로 남으며 미디어 조건을 암묵적으로 선언하지 않습니다. 너비 상한에는 네이티브 길이나 별도로 명명한 레이아웃 토큰을 사용하세요. 외부 URL을 유지하는 가져오기는 해석되지 않은 custom-media 쿼리를 포함할 수 없습니다. 변환 전에 해당 스타일시트 가져오기를 해석하거나 가져오기에 일반 네이티브 쿼리를 사용하세요.

<StylesheetExample title="A named media condition" source={"@custom-media --card (width >= 40rem); .card { @media (--card) { display: grid; } }"} />

### `@custom-container` \{#custom-container\}
Master CSS는 컴파일 시 `@custom-container` 정의를 확장하며 브라우저는 일반 `@container` 규칙을 받습니다. 정의는 조건만 담고 측정할 컨테이너는 조건을 사용하는 위치에서 선택합니다.

```css
@custom-container --md (width >= 28rem);
@custom-container --max-md not (--md);
@custom-container --compact style(--density: compact);
@custom-container --dense (--md) and (--compact);

@container card (--md) { .title { font-size: 1.25rem; } }
```

이름은 `--`로 시작합니다. CSS 참조는 선택적인 컨테이너 이름 뒤에 `(--name)`을 사용하며 예로 `@container card not (--md)`가 있습니다. 마크업도 컨테이너 쿼리 안에서 같은 참조를 사용합니다. `@container(--md)`는 가장 가까운 컨테이너를, `@container(card|--md)`는 명명된 컨테이너를 측정합니다. 네이티브 CSS, 유틸리티와 믹스인 정의, 마크업은 같은 레지스트리를 공유합니다.

정의는 크기와 스타일 쿼리, `not`, `and`, `or`, 전방 참조를 포함한 다른 사용자 정의 컨테이너 참조 등 모든 컨테이너 조건이 될 수 있습니다. 확장은 참조 조건을 치환하며 이미 하나의 그룹이거나 전체 조건이 아니면 괄호로 감쌉니다. 따라서 `@container card (--dense)`는 `@container card (width >= 28rem) and style(--density: compact)`를 출력합니다. 컨테이너 조건은 항상 하나의 전치부에 들어가며 확장은 분기를 추가하지 않습니다. 컴파일러는 일반 컨테이너 쿼리를 출력하고 각 확장 조건을 manifest의 `customContainers`에 저장합니다.

정의되지 않거나 순환하거나 빈 참조, 컨테이너 이름으로 시작하는 정의는 컴파일 오류입니다. 같은 이름은 뒤의 정의가 우선하며 이를 참조하는 정의도 최종 버전을 사용합니다. 컨테이너 이름은 사용자 정의 미디어 및 믹스인과 독립적입니다. 단독 `@md`는 항상 사용자 정의 미디어를 선택하며 컨테이너 조건을 선택하지 않습니다. `--container-*` 토큰은 요소 크기를 정하며 컨테이너 임계값을 제공하지 않습니다.

## 유틸리티와 네이티브 스타일 \{#managed-definitions\}
`@utility`는 필요할 때 생성할 클래스를 등록합니다. `@mixin`은 재사용할 CSS 본문에 이름을 붙이고 `@apply`는 호출 위치에서 이를 확장합니다. 네이티브 선택자는 일반 CSS로 유지됩니다. 형식을 선택하는 방법은 [스타일 재사용](/guide/reusing-styles)에 있으며 이 페이지는 문법과 교체 규칙을 정의합니다.

### `@utility` \{#utilities\}
최상위에서 클래스 형식을 명시적으로 선언합니다.

```css
@utility card-layout {
  display: grid;
  gap: var(--spacing-md);
  &:hover { outline: 1px solid currentColor; }
}

@utility col-gap-(--spacing) {
  column-gap: var(--spacing);
}

@utility grid-cols(--cols <integer>) {
  display: grid;
  grid-template-columns: repeat(var(--cols), minmax(0, 1fr));
}
```

마크업에서 `card-layout`, `col-gap-sm`, `grid-cols(3)@sm`을 사용합니다. 헤더는 고정 클래스, 토큰 패턴, 함수 중 무엇을 등록할지 결정합니다. 각 형식은 그 형식만 등록하며 토큰 패턴이 함수 호출도 만들지는 않습니다. 선언이나 지원하는 중첩 규칙을 추가해도 등록은 바뀌지 않습니다.

유틸리티 이름이나 토큰 접두사에는 `_`를 넣을 수 없습니다. 클래스에서 `_`가 하위 선택자를 시작하므로 이런 정의는 소스 위치에서 오류를 보고합니다. 토큰 키에는 `_`를 넣을 수 있으며 `var()`에서 쓸 수 있는 유효한 변수로 남지만 단독 토큰 클래스나 자동 완성을 만들지는 않습니다. 믹스인 이름, 사용자 지정 속성, 네이티브 스타일시트 클래스에는 `_`를 계속 쓸 수 있습니다.

### 등록과 프리셋 \{#named-and-enumerated-classes\}
테마는 토큰을 제공하고 유틸리티 정의는 그 토큰으로 생성할 클래스를 결정합니다. 전체 프리셋은 `"@master/css"`를 가져오세요. 스타일시트를 명시적으로 구성할 때는 자신의 토큰과 함께 `"@master/css/utilities.css"`를 불러올 수 있습니다.

전체 토큰과 속성 매핑은 [계열 색인](/reference/tokens/families)에, 해당 등록은 [고정 유틸리티](/reference/rules/declarations#fixed-utilities)와 [직접 숫자 값](/reference/direct-values)에 있습니다. 모두 여기서 설명하는 같은 정의 형식을 사용합니다.

### 토큰 패턴 \{#named-token-patterns\}
패턴에는 끝의 자리표시자 하나가 있습니다. 매개변수는 토큰 네임스페이스를, 고정 부분은 클래스 접두사를 지정합니다. 타입 없는 자리표시자는 토큰 값을 바인딩합니다.

```css
@utility p-(--spacing) { padding: var(--spacing); }
@utility m-(--spacing) { margin: var(--spacing); }
@utility fg-(--color) { color: var(--color); }
@utility size-(--spacing) {
  width: var(--spacing);
  height: var(--spacing);
}
```

`p-md`는 `var(--spacing-md)`를 바인딩하고 `size-md`는 두 선언에 그 참조를 사용합니다. 일반 토큰은 브라우저가 평가하는 참조를 유지하고 inline 토큰은 선언 값을 한 번 치환합니다. 알 수 없는 토큰은 클래스를 만들지 않습니다. 값 패턴은 `--`를 포함하는 키를 비롯해 숫자와 유니코드 키를 허용합니다.

`<string>` 자리표시자는 토큰 키를 바인딩하여 보조 값을 명시적으로 참조할 수 있게 합니다.

```css
@theme {
  --text-hero: var(--font-size-5xl);
  --text-hero--line-height: 1.15;
  --text-hero--letter-spacing: -.03em;
}
@utility text-(--text <string>) {
  font-size: var(ident("--text-" var(--text)));
  line-height: var(ident("--text-" var(--text) "--line-height"), normal);
  letter-spacing: var(ident("--text-" var(--text) "--letter-spacing"), normal);
}
```

`text-hero`는 문자열 `"hero"`를 바인딩하며 일치하는 주 토큰이 필요합니다. `--`를 포함한 보조 키는 클래스를 만들지 않고 보조 값이 없으면 작성한 대체 값을 사용합니다. `ident()`는 정적으로 일반 CSS 식별자로 접힙니다. 네임스페이스는 매개변수에서 오므로 `@utility type-(--text <string>)`는 같은 토큰을 다른 클래스 접두사로 사용합니다. 토큰 자리표시자는 기본값이나 다른 타입을 허용하지 않습니다.

공유 접두사는 여러 네임스페이스를 명시적으로 제공할 수 있습니다.

```css
@utility font-(--font-family) { font-family: var(--font-family); }
@utility font-(--font-size) { font-size: var(--font-size); }
@utility font-(--font-weight) { font-weight: var(--font-weight); }
```

`font-sans`, `font-sm`, `font-bold`는 각각 해당 키가 있는 유일한 네임스페이스를 선택합니다. 여러 분기에 같은 키가 있으면 사용 시 `AMBIGUOUS_TOKEN`을 보고하며 CSS를 생성하지 않습니다. 키를 구분하거나 `(font-size:var(--font-size-brand))` 같은 네이티브 선언을 사용하세요. 이 규칙은 문자열 키 레시피와 다중 선언 본문에도 적용됩니다. 음수와 불투명도는 유일한 분기를 선택한 뒤에만 검사합니다.

고정 클래스는 패턴보다 우선합니다. 예약되는 것은 토큰 키가 아닌 전체 클래스 표기입니다. 따라서 `--text-center`가 있어도 `text-center`는 `text-align`을 설정하지만 `fg-solid`, `b-solid/.5`, `-mx-auto`는 여전히 `solid`나 `auto` 토큰에 접근합니다. 패턴은 가장 긴 접두사를 사용하며 선택한 계열에 토큰이 없으면 짧은 접두사를 다시 시도하지 않고 오류를 보고합니다. 매개변수 네임스페이스가 다른 토큰 패턴은 접두사를 공유할 수 있습니다. 뒤의 패턴은 디코딩한 접두사와 네임스페이스가 같은 정의를 매개변수 모드, 본문, 소스, 의존성과 함께 완전히 교체합니다. 정적 등록과 함수 등록은 같은 형식과 이름의 정의를 독립적으로 교체합니다.

음수와 불투명도는 직접 값 부분집합에 적용됩니다. 타입 없는 자리표시자 하나와 전체 값이 `var(--parameter)`인 네이티브 선언 하나가 필요합니다. `-m-md`는 숫자 간격 토큰을 음수로 만들고 `-p-md`는 padding이 음수를 지원하지 않아 유효하지 않습니다. `fg-red/.5`는 색상 토큰에 0부터 1까지의 불투명도를 적용합니다. 일반 다중 선언이나 문자열 키 레시피에는 이 기능을 적용하지 않습니다.

### 정적 인수 \{#dynamic-values\}
함수 유틸리티와 믹스인은 타입 없음, `<integer>`, `<number>`, `<string>`, `<custom-ident>` 위치 매개변수를 받습니다. 정적 기본값은 `--cols <integer>: 2`처럼 콜론을 사용합니다. 숫자는 숫자 리터럴이어야 하며 그리드 수와 스팬은 양의 정수여야 합니다. 문자열 인수는 따옴표가 필요합니다.

```css
@utility pair(--size) {
  width: var(--size);
  height: var(--size);
}
```

`pair(2rem)`처럼 사용합니다. 일반 함수 인수는 정적으로 알려져 있어야 합니다. 함수나 믹스인에 타입과 기본값이 없는 매개변수 하나와 전체 값이 `var(--parameter)`인 네이티브 선언 하나만 있으면 기호적 `var()` 식도 허용합니다. 호출자의 참조는 브라우저 평가를 위해 그대로 유지됩니다. 다른 함수는 외부 `var()`, `attr()`, 브라우저 의존 인수를 거부합니다. 알려진 외부 매개변수는 `var(--parameter)`로 전달할 수 있습니다.

<StylesheetExample title="A parameter utility" source={"@utility pair(--size) { width: var(--size); height: var(--size); } @safelist 'pair(2rem)';"} />

<ReferenceIllustration id="parameter-known-vs-live" />

### `@mixin`과 `@apply` \{#reusing-a-matched-value\}
Master는 실험적인 [CSS Mixins 명세](https://drafts.csswg.org/css-mixins-1/#mixin-rule)의 정적 부분집합을 컴파일합니다. 정의는 이중 하이픈 이름을 사용하며 무조건적인 스타일시트 수준 규칙이어야 합니다. 믹스인은 CSS 재사용을 제공하며 Master 클래스를 등록하지 않습니다.

```css
@mixin --caption {
  font-size: var(--font-size-sm);
  line-height: 1.5;
}
.caption {
  color: currentColor;
  @apply --caption;
  font-weight: 600;
}
@utility caption {
  @apply --caption;
}
```

`@apply`는 네이티브 규칙, 유틸리티, 다른 믹스인 안에서 믹스인 호출 하나를 받습니다. 유틸리티 이름이나 클래스 목록은 받지 않습니다. 작성한 선언 위치에서 확장하며 중복, 중요도, 선택자, 조건, URL 소유권을 유지합니다.

매개변수는 `&:hover`와 조건 래퍼를 포함해 적용 요소에서 사용할 수 있습니다. 다른 요소에서의 매개변수 사용, 재할당, 선택자나 조건 보간, 재귀 정의, 오버로드, `@private`, 지원하지 않는 타입은 컴파일 오류입니다. 이 정적 부분집합은 브라우저 의존 매개변수 평가, 비공개 속성, 범용 함수를 구현하지 않습니다.

<ReferenceIllustration id="mixin-splice" />

### 콘텐츠와 클래스 래퍼 \{#contents\}
`@contents`로 호출자의 선언이나 중첩 규칙이 재사용 래퍼에 들어갈 위치를 표시합니다.

```css
@mixin --card-wide() {
  @container card (width >= 40rem) { @contents { display: grid; } }
}
.card { @apply --card-wide { gap: 1rem; } }
```

`@contents;`는 제공한 콘텐츠를 삽입합니다. `@contents { … }`는 호출이 블록을 생략했을 때만 대체 콘텐츠를 제공합니다. 명시적으로 빈 `@apply --card-wide {}`는 대체 콘텐츠를 억제합니다. 각 contents 위치는 블록을 한 번 삽입하고 선언, 중복, 중첩 규칙을 유지합니다. `@contents`가 없는 믹스인은 제공한 블록을 무시합니다.

<ReferenceIllustration id="contents-default-vs-empty" />

제공한 콘텐츠는 중첩 적용을 통해 전달해도 호출자의 매개변수 바인딩을 유지합니다. 대체 콘텐츠는 정의한 믹스인의 바인딩을 사용합니다. 일반 사용자 지정 속성은 네이티브 CSS 캐스케이드 동작을 유지합니다. 유한한 중첩 호출은 허용하지만 재귀 정의나 확장 깊이 및 노드 한도 초과는 오류입니다.

```css
@mixin --hocus {
  &:is(:hover, :focus-visible) { @contents; }
}
@utility emphasis { color: red; display: block; }
```

```html
<button class="(color:red)@apply(--hocus)">Save</button>
<div class="grid-cols(3)@apply(--card-wide)"></div>
<div class="emphasis@apply(--hocus)!"></div>
```

`@apply(--name(...))`는 정적 인수를 받습니다. 여러 `@` 래퍼는 왼쪽에서 오른쪽으로 중첩되므로 `(color:red)@apply(--a)@apply(--b)`는 `--a`를 `--b` 밖에 둡니다. 유틸리티는 선언을 하나의 블록으로 제공하므로 래퍼 자체 선언은 클래스당 한 번 출력됩니다. 선택자 접미사는 기존 위치를 유지하며 마지막 `!`는 확장한 모든 선언을 중요하게 표시합니다. 클래스 선두 부분과 `@apply` 이외의 조건 접미사가 클래스 순서를 정합니다. 각 외부 조건 분기는 독립적으로 정렬되는 규칙 하나입니다. 믹스인 내부 선택자와 조건은 출력 텍스트에 남고 클래스를 뒤쪽 단계로 옮기지 않으며 확장은 작성 순서를 유지합니다. 선언, 선택자, 조건을 추가하지 않는 확장은 단일 선언 유틸리티와 정렬되고 선두 부분이 `(property:value)`이면 네이티브 선언과 정렬됩니다. 나머지는 레시피로 정렬됩니다. 검사와 충돌 분석은 확장된 규칙을 사용합니다.

사용하지 않는 정의, 버려진 contents, 사용하지 않는 대체 블록은 토큰이나 키프레임을 유지하지 않습니다. 전달된 네이티브 `@apply`는 emitted-globals 계약을 통해 리소스 루트로 남습니다. 선언 위치와 상대 URL은 정의하거나 호출한 파일을 유지합니다.

<ReferenceIllustration id="contents-insertion" />

### 전체 정의 교체 \{#whole-definition-replacement\}
뒤의 정의는 같은 등록의 본문 전체를 교체하며 선언을 병합하지 않습니다. 같은 이름의 정적 유틸리티와 함수 유틸리티는 별도 등록입니다. 토큰 패턴은 디코딩한 접두사와 네임스페이스가 같은 분기만 교체합니다.

```css
@utility badge { color: red; padding: 1rem; }
@utility badge { color: blue; }
```

이제 `badge`는 `color: blue`만 출력합니다. 이전 padding과 그 의존성은 사라집니다.

<ReferenceIllustration id="definition-replacement" />

믹스인 이름에는 매개변수 목록, 본문, 의존성을 포함한 최종 정의 하나만 있습니다. 빈 정의도 등록된 상태를 유지합니다. 전방 중첩 호출은 최종 레지스트리로 해석하며 매개변수 오버로드는 없습니다.

<ReferenceIllustration id="independent-registrations" />

### 정의 범위와 가져오기 \{#definition-scope-and-imports\}
`@theme`, `@utility`, `@mixin`, `@custom-media`, `@custom-container`는 최상위 정의입니다. 레이어나 조건 래퍼 안의 등록은 오류입니다. 믹스인 본문은 선언, 중첩 선택자, 지원하는 네이티브 조건, 중첩 `@apply`, `@contents`를 포함할 수 있습니다. 레이어 배치는 호출 위치에서 정합니다.

소스 스캔, 세이프리스트, 엔진 API, 런타임 DOM 변경의 클래스는 사용 루트입니다. 전달된 네이티브 CSS의 `@apply`도 루트지만 사용하지 않는 유틸리티나 믹스인 또는 전달하지 않은 `@reference` 스타일시트 안의 것은 아닙니다. 의존성 수집은 매개변수 바인딩과 `ident()` 접기 뒤에 수행됩니다. 사용하는 토큰은 선언 순서와 전이적 의존성을 유지합니다. 정적 토큰은 사용처가 없어도 루트로 남습니다. 마지막 루트를 제거하면 리소스를 해제하며 네이티브 CSS 리소스는 `emittedGlobals`로 고정됩니다.

런타임 manifest는 이후 DOM 클래스에 대비해 사용하지 않는 정의를 유지합니다. 온디맨드 생성은 CSS와 리소스 출력에 관한 것입니다. 네이티브 CSS 가지치기는 명시적으로 활성화해야 하며 키프레임은 선언 파일의 네이티브 보존 및 가지치기 정책을 공유합니다. 한정자 있는 가져오기는 네이티브 CSS만 포함해야 합니다. 정의는 한정자 없는 가져오기나 참조로 불러오세요.

### 네이티브 속성 우선순위 \{#literal-and-raw-values\}
네이티브 `(property:value)` 클래스는 유틸리티 등록과 독립적으로 CSS 속성 의미를 유지합니다. 같은 조건에서 단일 선언 유틸리티와 네이티브 선언 클래스는 레시피의 일부를 재정의할 수 있습니다. 전체 정렬과 재정의 규칙은 [선언과 값](/reference/rules/declarations#combining-declarations)을 참고하세요.

### 네이티브 기본 스타일 \{#defaults\}
네이티브 기본 스타일은 `@layer defaults`에 작성합니다.

### 네이티브 컴포넌트 \{#components\}
네이티브 컴포넌트 선택자는 `@layer components`에 작성합니다.

```css
@layer components {
  .button {
    display: inline-flex;
    padding: var(--spacing-md);
    &:focus-visible { outline: 2px solid currentColor; }
  }
}
```

네이티브 규칙은 스타일시트 가져오기 그래프에 따라 전달됩니다. 유틸리티 정의는 클래스 이름을 등록하고 믹스인 정의는 `@apply`를 통해 CSS 재사용을 제공합니다. 둘 다 컴파일 중 처리되며 사용할 때만 CSS를 출력합니다.

### Sass 상호 운용 \{#sass-interoperability\}

Sass를 사용할 때는 CSS 믹스인 정의를 `.css` 파일에 두세요. 현재 Dart Sass는 향후 CSS 지원을 위해 `@mixin --name`을 예약하고 Sass 믹스인으로는 거부합니다. [Sass 호환성 공지](https://sass-lang.com/documentation/breaking-changes/css-function-mixin/)를 참고하세요. SCSS 파일은 Master CSS가 컴파일하기 전에 보간으로 네이티브 at-rule을 출력할 수 있습니다.

```scss
@#{'mixin'} --card {
  padding: 1rem;
}

.card { @apply --card; }
```

이는 Sass 보간이며 추가 Master CSS 구문이 아닙니다. Sass `@include`와 CSS `@apply`는 별개 구문으로 유지됩니다.

### 테마 선택자 래퍼 \{#theme-wrappers\}
네이티브 선택자와 쿼리가 테마 재정의를 활성화합니다. 믹스인은 일치하는 클래스 조건을 제공할 수 있습니다.

```css
@mixin --ocean {
  &:where([data-theme="ocean"], [data-theme="ocean"] *) { @contents; }
}
```

`(color:white)@apply(--ocean)`을 사용합니다. 섀도 호스트를 대상으로 할 때는 `:host(...)` 선택자를 명시적으로 추가하세요.

## 소스 경계 \{#source-boundaries\}
파일 정책은 후보를 읽을 위치를 정하고 후보 정책은 유효하게 유지할 전체 클래스 문자열을 정합니다. 이 지시문은 파서를 바꾸거나 임의의 소스 텍스트를 유효한 유틸리티로 만들지 않습니다. 설정과 문제 해결은 [클래스 이름 스캔](/guide/scanning-and-pruning), 지원 소스 구문과 수명주기는 [추출](/reference/rules/extraction)을 참고하세요.

<ReferenceIllustration id="scanning-two-filters" />

### `@source` \{#source\}
일반 앱 소스에는 통합과 CLI의 기본 탐색을 사용합니다. 필요하면 명시적 예외를 추가하세요.

```css
@source "../content/**/*.mdx";
```

### `@source not` \{#source-not\}
일치하는 파일을 소스 집합에서 제외합니다.

```css
@source not "../content/drafts/**";
```

`{a,b}` 같은 중괄호 그룹은 별도 패턴으로 확장됩니다. 하나의 패턴은 최대 64개 중괄호 그룹을 포함하고 최대 1,024개 패턴으로 확장할 수 있습니다.

포함 항목의 합집합에서 모든 제외 항목을 뺍니다. 모든 상대 패턴은 이를 선언한 스타일시트를 기준으로 해석하며 단순 `src/**`, `./src/**`, 가져온 파일, `@source not`도 마찬가지입니다. 참조는 스캔 소스를 제공하지 않습니다.

파일을 해석하는 API는 선언 파일이나 명시적 기준 파일이 필요합니다. 소스 전용 지시문 검사는 해석되지 않은 메타데이터를 반환할 수 있지만 파일시스템 기준을 임의로 만들면 안 됩니다. 스캐너의 프로그래밍 방식 `cwd` 옵션은 해당 API로 직접 전달하는 스캐너 옵션에 기존 의미를 유지합니다.

## 후보 정책 \{#candidate-policy\}
### `@safelist` \{#safelist\}
스캔 소스에 리터럴로 나타날 수 없는 전체 클래스 후보를 추가합니다.

```css
@safelist "(opacity:1)";
@safelist "bg-blue-60@dark";
```

후보는 발견한 클래스와 같은 일치 및 진단 정책을 사용합니다. 동적 대안은 유한하고 명시적으로 유지하세요.

클래스나 애니메이션 선언을 생성하지 않고 명명된 애니메이션 정의를 유지하려면 명시적 키프레임 대상을 사용하세요.

```css
@safelist keyframes "fade" "pop";
```

따옴표 문자열 하나는 전체 CSS 애니메이션 이름 하나입니다. 이름은 대소문자를 구분하고 CSS 이스케이프를 지원하며 문자열 안의 공백은 이름의 일부입니다. 와일드카드 확장이나 클래스 분리는 없습니다. 이름 누락, 따옴표 없는 이름, 쉼표, 중첩 세이프리스트 지시문은 오류입니다. 전체 가져오기/참조 그래프에 이름이 없으면 경고합니다. 세이프리스트는 각 진입점 그래프 안에서 병합되며 소스나 지시문을 제거하면 철회됩니다. `@reference`는 세이프리스트 루트를 가져오지 않습니다. 키프레임 블록리스트나 별도의 키프레임 가지치기/보존 대상은 없습니다.

### `@blocklist` \{#blocklist\}
정확한 문자열이나 `*`, `?` 와일드카드 패턴으로 원하지 않는 전체 후보를 제거합니다.

```css
@blocklist "debug-*";
@blocklist "example-token";
```

스타일시트 문법은 슬래시로 감싼 패턴을 정규식으로 해석하지 않습니다. 와일드카드 정책은 블록리스트에 두며 세이프리스트는 전체 클래스를 제공합니다.

## 네이티브 CSS 보존 \{#native-css-preservation\}
네이티브 CSS 가지치기는 사용하지 않는 클래스 선택자 분기를 제거하고 키프레임을 필요할 때 사용할 수 있게 합니다. 이는 유틸리티 클래스 생성과 별개인 스타일시트 정책입니다. 활성화 시점은 [CSS 전달 최적화](/guide/optimizing-css-delivery#native-pruning), 소스와 후보 필터는 [스캔 지시문](/reference/directives/scanning)을 참고하세요.

<ReferenceIllustration id="pruning-file-boundary" />

클래스 목록을 제공해도 네이티브 CSS는 기본적으로 보존됩니다. 통합이나 스타일시트 API에 `pruneNativeCSS: true`를 설정해 프로젝트 소유 소스를 가지치기하세요. 패키지 CSS는 자신의 소스가 명시적으로 활성화하지 않으면 보존됩니다.

### `@prune native` \{#prune-native\}

```css
@prune native;
.used { color: red; }
.unused { color: blue; }
```

이 지시문은 선언 파일만 가지치기에 참여시키며 가져온 스타일시트로 전파되지 않습니다. 통합이 프로젝트 전체 가지치기를 활성화해도 같은 파일의 `@preserve native;`가 우선합니다. 네이티브 출력 스위치 `preserveNativeCSS: false`는 별도이며 두 지시문과 관계없이 네이티브 출력을 억제합니다.

### `@preserve native` \{#preserve-native\}
Master가 관리하는 스타일시트에 네이티브 CSS 가지치기로 제거하면 안 되는 네이티브 클래스 규칙이 있다면 `@preserve native;`를 사용하세요.

```css
@import "@master/css";
@preserve native;

.injected-by-payment-widget {
  color: blue;
}
```

스타일시트는 여전히 Master CSS가 처리합니다. 스캔 소스에서 클래스를 사용하지 않아도 네이티브 클래스 규칙은 유지되며 일반 컴파일러 정규화는 적용됩니다. 이 정책은 사용하지 않는 관리 클래스를 생성 출력에 강제로 넣거나 원래 CSS 바이트를 그대로 보존한다는 뜻이 아닙니다.

### 가져오기 그래프 \{#import-graph\}
해석된 CSS 가져오기는 각 소스 경계를 유지하므로 파일 정책은 해당 파일에만 적용됩니다. 가져오는 파일이 의존 파일의 가지치기를 활성화할 수는 없습니다. `pruneNativeCSS: true`에서는 `@preserve native;`를 선언하지 않은 프로젝트 소유 의존성이 참여합니다. 패키지나 원격 스타일은 프로젝트가 가져온다고 프로젝트 소유가 되지 않습니다. 한정자 있는 가져오기는 media, supports, layer 래퍼를 유지합니다.

```css name=src/style.css
@prune native;
@import "@master/css";
@import "./cards.css";
```

```css name=src/cards.css
@prune native;
.card { border: 1px solid rgb(0 0 0 / 12%); }
.unused-card { color: red; }
```

스캔 소스에 `card`가 있으면 출력은 `.card`를 유지하고 `.unused-card`를 제거합니다. `cards.css`에 지시문이 없으면 둘 다 남습니다.

### 루트 범위 \{#root-scope\}
활성화는 각 소스 파일에 속하며 필터링은 이를 가져오는 루트의 사용 범위를 따릅니다. 따라서 활성화된 같은 공유 파일도 루트마다 다른 클래스를 유지할 수 있습니다. JavaScript나 프레임워크 라우트가 직접 가져오는 파일은 그 가져오기가 Master CSS 파이프라인에 들어갈 때만 자체 루트가 됩니다.

루트는 기본적으로 전역 스캐너 범위를 사용합니다. 루트 가져오기 그래프 어디의 `@source`, `@source not`, `@safelist`, `@blocklist`든 범위를 좁히거나 넓힐 수 있습니다. 가져온 파일의 지시문은 이를 가져오는 모든 루트에 병합되며 상대 패턴은 선언 파일을 기준으로 해석됩니다.

```css name=app/a/a.css
@prune native;
@import "@master/css";
@source "./page.html";
@import "../shared.css";
```

```css name=app/shared.css
@prune native;
@blocklist "debug-*";
.shared-card { border: 1px solid rgb(0 0 0 / 12%); }
.only-used-in-b { color: blue; }
.debug-outline { outline: 1px solid red; }
```

`app/a/page.html`이 `shared-card`만 사용하면 `a.css` 출력은 `.shared-card`를 유지하고 `.only-used-in-b`와 `.debug-outline`을 제거합니다. 다른 루트 `b.css`의 페이지가 `only-used-in-b`를 사용하면 같은 공유 파일에서 그 규칙을 유지합니다.

### 규칙 필터링 \{#rule-filtering\}
클래스 선택자 규칙은 분기 하나의 클래스 중 하나라도 사용하면 유지하며 사용하지 않는 분기는 선택자 목록에서 제거합니다. 검사는 DOM 관계가 아닌 클래스 이름을 기준으로 합니다. `.card .title`에서는 `card`나 `title` 하나만 찾아도 분기를 유지하므로 유지된 규칙이 어떤 요소에도 일치하지 않을 수 있습니다.

```css
@prune native;
body { margin: 0; }
.card, .unused:hover { border: 1px solid rgb(0 0 0 / 12%); }
@media (width >= 48rem) {
  .card .title { font-weight: 700; }
  .debug-card { outline: 1px solid red; }
}
```

`card`와 `title`을 사용하면 출력은 `body`, `.card`, `.card .title`을 유지하고 `.unused:hover`와 `.debug-card`를 제거합니다. `body`, `html`, `:root`처럼 클래스 선택자가 없는 규칙은 항상 유지합니다. 가지치기로 빈 at-rule 블록은 제거합니다.

### manifest 참조 \{#manifest-references\}
유지된 네이티브 규칙이 `var(--*)`를 읽거나 manifest 애니메이션 이름을 지정하면 프로젝트 진입점 그래프의 해당 테마 변수와 키프레임을 유지합니다. 제거된 규칙은 아무 리소스도 유지하지 않습니다. [제거된 토큰](#theme-removal)은 테마 변수가 아니므로 그 이름을 읽어도 아무것도 유지하지 않습니다.

```css
@prune native;
@import "@master/css";
@theme { --color-primary: #175cff; }

.notice { color: var(--color-primary); }
.unused-notice { color: var(--color-primary); }
```

`notice`만 사용하면 `.notice`를 유지하므로 `--color-primary`가 출력되며 `.unused-notice`는 제거됩니다.

### 포함한 클래스 \{#included-classes\}
`@safelist`는 제한된 외부 소스에서 오는 네이티브 클래스를 사용한 것으로 표시하여 가지치기가 규칙을 유지하게 합니다. 스캔 소스에 작성한 앱 클래스를 대체하지는 않습니다.

```css
@prune native;
@safelist "dialog-open dialog-closing";
.dialog-open { overflow: hidden; }
.dialog-closing { pointer-events: none; }
```

### 네이티브 키프레임 \{#native-keyframes\}
네이티브 CSS에 키프레임을 선언하고 소유 파일에서 사용 기반 출력을 활성화합니다.

```css
@prune native;
@theme { --animate-reveal: reveal .2s ease-out both; }
@keyframes reveal {
  from { opacity: 0; }
  to { opacity: 1; }
}
@safelist keyframes "external-enter" "external-exit";
@keyframes external-enter { from { opacity: 0; } to { opacity: 1; } }
@keyframes external-exit { from { opacity: 1; } to { opacity: 0; } }
```

키프레임은 네이티브 클래스 규칙과 같은 파일 정책을 따릅니다. 기본적으로 네이티브 CSS이며 제자리에서 원문 그대로 출력에 남고 Master CSS는 다시 출력하지 않습니다. `@prune native;`는 파일의 키프레임을 토큰 같은 온디맨드 정의로 바꿉니다. 네이티브 출력에서 빠지고 이를 사용하는 출력이 생성 CSS와 함께 출력합니다. 두 지시문이 있으면 `@preserve native;`가 우선합니다. 정책은 선언 파일에만 적용되며 가져오기로 전파되지 않습니다. `pruneNativeCSS` 옵션은 프로젝트 소유 파일 범위를 유지합니다. 패키지 CSS는 명시적으로 가지치기에 참여하지 않으면 보존됩니다. `preserveNativeCSS: false`는 네이티브 전달을 억제하지만 온디맨드 정의는 사용 위치에 계속 출력됩니다.

### 키프레임 사용 루트 \{#keyframe-usage-roots\}

애니메이션 유틸리티, 네이티브 애니메이션 선언, 정적 애니메이션 토큰, 키프레임 세이프리스트는 일치하는 정의를 사용합니다. 분석은 단축 값, animation-name 목록, 중첩 변수, 대체 값, 범위가 있는 재정의, 전이적 토큰 의존성을 추적합니다. 사용한 정의는 프레임이 읽는 토큰도 사용합니다. 네이티브 정의는 스타일시트가 프레임을 전달하므로 해당 토큰만 제공합니다. 해석되지 않은 동적 이름은 보수적으로 컴파일 그래프의 모든 후보 정의를 사용하며 정보 진단을 생성합니다.

### 키프레임 조건과 제한 \{#keyframe-conditions-and-restrictions\}

출력된 온디맨드 정의는 한정자 있는 가져오기의 레이어를 포함해 선언 위치의 조건과 레이어 규칙으로 감싸지며 생성 레이어 뒤에 옵니다. 같은 컨테이너의 정의는 래퍼 하나를 공유합니다. 같은 이름의 정의도 선언 순서대로 별도로 유지되며 브라우저가 우선할 정의를 결정합니다. 이름은 디코딩하고 대소문자를 구분합니다. 익명 레이어에는 다시 진입할 수 없으므로 그 안의 또는 그 안으로 가져온 온디맨드 키프레임은 컴파일 오류입니다. 레이어에 이름을 붙이거나 파일을 보존하세요. 프레임은 원래 스타일시트 밖에 출력되므로 내부 상대 `url()`도 컴파일 오류입니다. 절대 URL을 사용하거나 파일을 보존하세요. 정의 ID는 선언 파일에서 가장 가까운 명명된 `package.json`과 패키지 상대 경로에서 생성되므로 같은 프로젝트는 체크아웃이나 설치 디렉터리와 관계없이 같은 CSS를 출력합니다. 패키지 이름을 바꾸면 ID가 바뀌며 명명된 패키지 밖의 파일은 절대 경로를 대안으로 사용합니다.

### 키프레임 리소스 소유권 \{#keyframe-resource-ownership\}

프레임은 네이티브 선언을 포함하며 프레임 내부 중첩 지시문과 `@apply`는 지원하지 않습니다. 사용하지 않는 유틸리티와 믹스인, 가지치기한 네이티브 규칙, 전달하지 않은 참조 스타일은 사용 루트를 만들지 않습니다. `@reference`는 보존 정책이나 세이프리스트를 가져오지 않고 정의를 필요할 때 사용할 수 있게 합니다. 상대 URL이 있는 네이티브 키프레임은 원래 스타일시트에 남습니다. 프로젝트나 기본 manifest의 네이티브 키프레임도 이를 전달하지 않는 스타일시트에서는 온디맨드입니다. emitted globals는 출력이 네이티브 또는 온디맨드로 전달하는 키프레임을 나열해 다른 출력의 중복을 막습니다. JavaScript로만 도입하는 애니메이션 이름은 `@safelist keyframes "reveal";`을 사용하세요.

### 런타임 키프레임 수명주기 \{#runtime-keyframe-lifetime\}

런타임은 정의 ID와 이름을 별도로 추적하고 온디맨드 정의를 자신의 스타일시트에 삽입합니다. DOM 제거는 네이티브 사용, 정적 토큰, 세이프리스트 중 어느 것도 정의를 사용하지 않을 때만 이를 해제합니다. HMR은 정의와 emitted globals를 함께 교체하고 SSR 하이드레이션은 같은 ID와 리소스 순서를 사용합니다. 연결된 스타일시트는 동반 파일이나 표시 없이 일반 CSS로 유지됩니다.
