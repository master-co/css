## Overview [sr-only]

Build interface color from roles: surface, line and text colors whose class stays the same in light and dark modes. Use a palette step only when the color itself is the point, such as an illustration or a brand accent.

---

## Choose roles or palette steps \{#choose-a-color-token\}

| Decision | Use | Examples |
| --- | --- | --- |
| Page structure and text hierarchy | Color roles | `bg-surface-raised`, `b-line-divider`, `fg-text-muted` |
| A particular swatch | Palette steps | `bg-blue-5`, `fg-blue-60` |

<FoundationColorRoles />

```html
<!-- @MARK bg-surface-raised --><!-- @MARK b-line-divider --><!-- @MARK fg-text-strong --><!-- @MARK fg-text-muted --><!-- @MARK fg-text-link -->
<section class="p-md r-lg b(1) b-solid b-line-divider bg-surface-raised fg-text-body">
  <h2 class="fg-text-strong">Project updates</h2>
  <p class="fg-text-muted">Three milestones changed this week.</p>
  <a class="fg-text-link underline" href="/updates">Continue</a>
</section>
```

<Class2CSS>{['bg-surface-raised', 'b-line-divider', 'fg-text-muted']}</Class2CSS>

The role is part of the color key: `bg-surface-raised` reads `--color-surface-raised`, and `b-line-divider` reads `--color-line-divider`. A line role sets only the color, so give the border its width and style separately. See [Color roles](/reference/tokens/color-roles) for every role and [Color](/reference/tokens/color) for the palette.

## Fixed and adaptive hue aliases \{#mode-aware-hue-aliases\}

A hue alias such as `fg-yellow` is a fixed swatch with the same value in every mode. A text hue alias such as `fg-text-yellow` chooses a readable foreground step for each mode.

```html
<!-- @MARK fg-yellow --><!-- @MARK fg-text-yellow -->
<svg class="fg-yellow" aria-hidden="true">…</svg>
<p class="fg-text-yellow">Pending review</p>
```

<Class2CSS>{['fg-yellow', 'fg-text-yellow']}</Class2CSS>

Use text hue aliases for colored labels. Keep body copy, emphasis and links on the text roles.

## Raised surfaces \{#raised-surfaces\}

A raised surface combines a surface role, a radius token and a shadow token. Raise the shadow one step for interaction, and use `pill` for fully rounded badges and buttons.

<DemoRaisedSurface />

```html
<!-- @MARK r-lg --><!-- @MARK shadow-sm --><!-- @MARK shadow-md:hover --><!-- @MARK shadow-md:focus-visible --><!-- @MARK pill -->
<a class="block p-md r-lg bg-surface-raised fg-text-body shadow-sm shadow-md:hover shadow-md:focus-visible" href="/notes">
  <span class="flex items-center justify-between gap-sm">
    <span class="fg-text-strong">Field notes</span>
    <span class="px-xs py-3xs pill bg-line-subtle text-xs fg-text-muted">12 new</span>
  </span>
</a>
```

<Class2CSS>{['r-lg', 'shadow-sm', 'shadow-md:hover', 'pill']}</Class2CSS>

Preset shadows use `light-dark()` for their colors, so `shadow-sm` keeps its geometry and follows the element's color scheme. `pill` is a fixed utility, not a radius token; with equal width and height it draws a circle. Round single corners with `rtl-lg`, `rtr-lg`, `rbl-lg` and `rbr-lg`. See [Radius](/reference/tokens/radius) and [Shadow](/reference/tokens/shadow) for the scales and their customization.

## Light and dark modes \{#native-color-scheme-and-manual-themes\}

The preset sets `color-scheme: light dark` on the root, and its roles and shadows use `light-dark()`, so a page follows the system preference with no extra classes. To choose a mode, set `data-theme="light"` or `data-theme="dark"` on the root, a nested region or a shadow host:

<DemoConfiguredExample name="nested-color-schemes" title="One token, two local color schemes" source={`@theme {
  --color-surface-notes: light-dark(#f4f4f5, #27272a);
}

@layer base {
  [data-theme="light"] { color-scheme: light; }
  [data-theme="dark"] { color-scheme: dark; }
}`} html={'<section data-theme="dark" class="p-md r-lg bg-surface-notes fg-text-body wrap-anywhere"><h2 class="m(0) text-lg font-regular">Dark notes</h2><p class="mt-xs mb-md text-sm">This region chooses dark.</p><article data-theme="light" class="p-md r-md bg-surface-notes fg-text-body"><h3 class="m(0) text-md font-regular">A light region inside</h3><p class="mt-xs mb(0) text-sm">The same surface token follows this article’s light scheme.</p></article></section>'} caption="Both regions use bg-surface-notes. Their data-theme attributes choose different color schemes, so light-dark() supplies a dark outer surface and a light inner one." />

The preset already ships these two `data-theme` selectors; the CSS repeats them to show the activation. A custom color with `light-dark()` adapts the same way, and changing the mode needs no recompilation. A nested region inherits its parent's tokens unless it redeclares them; give a brand theme its own selector, such as `[data-brand="ocean"]`, and redeclare its role tokens there.

The `@light` and `@dark` suffixes are `prefers-color-scheme` media queries. A manual `data-theme` changes the tokens but does not activate them. When a class must react to the manual choice, declare a selector mixin and apply it:

```css name=index.css
@mixin --manual-dark {
  &:where([data-theme="dark"], [data-theme="dark"] *) { @contents; }
}
```

```html
<!-- @MARK @apply(--manual-dark) -->
<img class="(opacity:.85)@apply(--manual-dark)" src="/chart.png" alt="Weekly usage" />
```

The mixin also matches inside a nested light region, because it tests the attribute rather than the used color scheme. Prefer adaptive tokens; see [Variables & modes](/reference/rules/modes) for scope and resolution.
