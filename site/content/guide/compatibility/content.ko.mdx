Master CSS는 CSS를 생성하고 브라우저는 적용 가능한 속성, 값, 선택자를 결정합니다. 사용 가능한 기본 동작을 만들고 개선에 도움이 되는 새 기능을 추가하며 기존 스타일이 캐스케이드에 어떻게 참여하는지 확인하세요.

다음 예제들은 [설치](/guide/installation)를 완료하고 앱이 `@import '@master/css';`를 불러오는 상태를 전제로 합니다.

## 브라우저 기본 요구 사항 확인하기 \{#overview\}

기본 프리셋은 캐스케이드 레이어, OKLCH 색상, 적응형 값을 위한 `light-dark()`를 사용합니다. 향상 기능에 폴백을 제공해도 이 기본 요구 사항이 사라지지는 않습니다. 지원할 브라우저를 기준으로 [브라우저 기본 요구 사항과 벤더 접두사](/reference/rules/declarations#vendor-prefixes)를 확인하세요.

클래스가 인식된다고 브라우저 호환성이 보장되지는 않습니다. Master는 일부 속성의 호환 접두사를 출력하며 모든 새 기능을 폴리필하지는 않습니다. 도구 결과의 `unknown` 역시 해당 검사가 CSS를 검증하지 못했다는 뜻이며, CSS가 유효하지 않거나 배포해도 안전하다는 증거가 아닙니다.

## 폴백을 유지하면서 기능 추가하기 \{#new-css-features\}

### 네이티브 선언 \{#native-declarations\}

자동 크기 조절을 사용할 수 없어도 메모 필드는 편집 가능해야 합니다. 일반 textarea 크기를 지정하고 세로 크기 조절을 허용한 뒤 [`field-sizing: content`](https://drafts.csswg.org/css-forms/#field-sizing)를 향상 기능으로 추가하세요. 이 네이티브 속성은 내용에 따라 컨트롤 크기를 조절하며 최소 및 최대 높이가 유용한 범위로 제한합니다.

`(field-sizing:content)`는 네이티브 선언을 제공합니다. `@supports(field-sizing:content)` 접미사는 해당 선언을 [CSS 기능 쿼리](https://www.w3.org/TR/css-conditional-3/#at-supports) 안에 둡니다. 쿼리가 일치하지 않으면 기본 스타일과 일반 textarea 동작이 유지됩니다.

<CompatibilityIllustration />

미리보기는 현재 브라우저의 문법 지원을 확인합니다. 대상 브라우저에서 실제 편집 동작도 테스트하세요. 지원 브라우저에서 폴백을 확인하려면 조건부 클래스를 잠시 제거합니다. 필드의 자동 확장은 멈추지만 스크롤로 모든 텍스트에 접근할 수 있어야 합니다. 이는 향상 기능을 분리하는 것으로, 이전 브라우저를 흉내 내는 것은 아닙니다.

**생성된 CSS**에서 출력된 조건을 확인하세요. [조건](/reference/rules/conditions#supportsfeature)에 클래스 문법이 설명되어 있습니다. 네이티브 CSS는 더 복잡한 기능 쿼리를 표현할 수 있습니다.

## 서드 파티 CSS를 캐스케이드에 배치하기 \{#third-party-styles\}

일반 유틸리티가 라이브러리의 일반 스타일을 덮어써야 한다면 해당 CSS를 앞선 `defaults` 레이어로 가져오세요. Master 통합이 처리하는 앱 CSS 진입점에서 이 가져오기보다 먼저 레이어 순서를 선언합니다.

[Swiper 코어, 탐색, 페이지 매김 스타일](https://swiperjs.com/get-started)을 이미 사용하는 프로젝트라면 이 진입점으로 불러오고 다른 곳에서 레이어 없는 사본을 추가로 가져오지 마세요:

```css name=app.css
@layer theme, base, defaults, components, utilities;
@import 'swiper/css' layer(defaults);
@import 'swiper/css/navigation' layer(defaults);
@import 'swiper/css/pagination' layer(defaults);
@import '@master/css';

@layer components {
  .swiper-slide {
    background-color: var(--color-surface-raised);
  }
}
```

슬라이더의 기존 마크업에서 한 슬라이드는 컴포넌트 표면을 유지하고 다른 슬라이드는 로컬 유틸리티를 추가할 수 있습니다:

```html
<div class="swiper-slide">Default surface</div>
<div class="swiper-slide bg-blue-60 fg-white">Featured slide</div>
```

`utilities`의 일반 배경 선언은 `components`보다 우선하고, 후자는 `defaults`보다 우선합니다. HTML 클래스 이름의 순서를 바꾸어도 결과는 달라지지 않습니다.

더 강한 재정의를 추가하기 전에 브라우저 개발자 도구에서 경쟁하는 선언을 확인하세요. 같은 작성자 출처와 컨텍스트에서는 레이어 없는 일반 스타일이 레이어 안의 일반 스타일보다 우선합니다. 벤더의 `!important` 선언도 일반 유틸리티보다 우선하며 중요한 선언은 레이어 순서를 뒤집습니다. 이는 Master 전용 우선순위 체계가 아닌 [네이티브 캐스케이드 규칙](https://www.w3.org/TR/css-cascade-5/#layer-order)입니다. [캐스케이드 레이어](/guide/cascade-layers)에 진단 절차가 나와 있습니다.

Master가 관리하는 스타일시트의 네이티브 선택자는 기본적으로 유지됩니다. 네이티브 가지치기를 활성화한다면 자신이 관리하는 스타일시트에서 [`@preserve native`](/reference/directives/pruning#preserve-native)로 벤더, CMS, 외부 주입 선택자를 보호하거나 해당 소스를 가지치기 대상 밖에 두세요. 서드 파티 위젯이 사용하는 선택자는 앱이 스캔하는 마크업에 나타나지 않을 수 있습니다.
