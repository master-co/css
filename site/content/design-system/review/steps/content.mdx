Use `StepSection` for a setup sequence with authored headings and code. The list numbers each `Step` beside its authored heading with plain, tabular `01`, `02`, `03` labels and a fine connecting line. Do not enclose the numbers in circles or badges. Keep the action in the heading and its expected result in the prose. Reading order stays in the document.

```jsx
import Code from '~/site/docs-shell/components/Code'
import StepSection, { Step, StepL, StepR } from '~/site/docs-shell/components/StepSection'

<StepSection>
  <Step $row>
    <StepL>
      <h3>Connect the stylesheet</h3>
      <p>Import the entry in your app.</p>
    </StepL>
    <StepR>
      <Code lang="css">{"@import '@master/css';"}</Code>
    </StepR>
  </Step>
</StepSection>
```

The components are server rendered. Supply native headings at the appropriate level and preserve their stable IDs. Numbering is decorative, not a replacement for headings or a progress indicator. The numbered rail and optional columns are the same treatment used in Guide. The 46rem container threshold controls the optional two-column layout; narrower columns stack in reading order, and code retains its own horizontal scroll. Keep a preview with the step whose result it demonstrates; its tray owns the spacing between preview and source.

Use the same sequence pattern across installations:

- [Quick start](/guide/installation), [Vite](/guide/installation/vite), [CLI](/guide/installation#cli) and [VS Code](/guide/language-service#set-up-vs-code) pair each action with its result.
- [Webpack](/guide/installation/webpack), [Rspack](/guide/installation/webpack#rspack) and [Rsbuild](/guide/installation/webpack#rsbuild) keep full configuration files readable.
- [Astro](/guide/installation/astro) and [SvelteKit](/guide/installation/svelte) connect layouts with server hooks.
- [Express](/guide/installation/server-rendered#express), [PHP](/guide/installation/server-rendered#php) and [Rails](/guide/installation/server-rendered#rails) connect independently built assets with complete server templates.
- [Laravel](/guide/installation/server-rendered#laravel), [WordPress](/guide/installation/server-rendered#wordpress) and [Shopify](/guide/installation/server-rendered#shopify) preserve the host's asset helpers and layout hooks.
- [ASP.NET Core](/guide/installation/server-rendered#aspnet-core) and [Blazor](/guide/installation/server-rendered#blazor) make asset-build, host-build and publication order explicit.

Keep the complete template and its appearance preview together in one tray. `DemoConfiguredExample`
uses literal source to keep displayed classes and rendered samples aligned; a
preview does not run the host framework. Keep setup constraints in the lesson.
