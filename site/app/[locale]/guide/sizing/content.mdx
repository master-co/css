## Overview [sr-only]
Sizing describes the space an element should claim, the limits it should respect, and the boundary where that decision changes. In CSS this includes [width](https://developer.mozilla.org/en-US/docs/Web/CSS/width), [height](https://developer.mozilla.org/en-US/docs/Web/CSS/height), min and max constraints, intrinsic keywords, percentages, viewport units, container values, and CSS functions.

Master CSS keeps sizing decisions close to the element that owns them. Use `w:*` and `h:*` for one axis, `size:*` when both axes intentionally match, `min-*` and `max-*` for constraints, container tokens for shared layout surfaces, and responsive variants when the size changes by viewport or container.

                </div>

            <section className="min-w:0 surface:base r:lg p:lg shadow:xs">

</Demo>

## Choose a sizing role
A sizing class should have one clear job. It can set the preferred size, keep an element from collapsing, cap growth, tie both axes together, or move the decision to a responsive boundary.

<SizingRoleTable />

Use one-axis rules when the element is rectangular by role. Use `size:*`, `min:*`, or `max:*` only when both axes genuinely share the same decision.

```html
<!-- @MARK w:full --><!-- @MARK max-w:7xl --><!-- @MARK min-h:100dvh -->
<main class="w:full max-w:7xl min-h:100dvh mx:auto">
    ...
</main>
```

## Start fluid, then constrain
Most layout should fill the space it receives and then stop at a cap. A fluid wrapper with `w:full max-w:*` behaves better across viewports than one fixed width that only fits one screen.

```html
<!-- @MARK w:full --><!-- @MARK max-w:7xl --><!-- @MARK px:md --><!-- @MARK px:xl@md -->
<main class="w:full max-w:7xl mx:auto px:md px:xl@md">
    ...
</main>

<!-- @MARK w:full --><!-- @MARK max-w:72ch -->
<article class="w:full max-w:72ch">
    ...
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'max-w:7xl', 'mx:auto', 'px:md', 'px:xl@md', 'max-w:72ch']}
    </Class2CSS>
</details>

Use `w:full` when the element should follow its parent, percentages such as `w:50%` for proportional regions, `max-w:*` for caps, and CSS functions such as `clamp()` when the bound itself should be fluid.

```html
<!-- @MARK w:full --><!-- @MARK w:50%@sm -->
<aside class="w:full w:50%@sm">...</aside>

<!-- @MARK w:clamp(18rem,50vw,42rem) -->
<section class="w:clamp(18rem,50vw,42rem)">...</section>
```

Percentage widths and heights follow native CSS behavior. The parent needs a definite height before `h:full` or `h:50%` can resolve predictably.

## Use container tokens
Sizing utilities read the `container` namespace contextually. `w:md`, `max-w:5xl`, `size:sm`, `min-w:xs`, and `flex-basis:lg` use `--container-*` tokens without repeating the namespace in markup.

<ContainerTokenTable />

```html
<!-- @MARK w:full --><!-- @MARK max-w:5xl -->
<main class="w:full max-w:5xl mx:auto">
    ...
</main>

<!-- @MARK w:md --><!-- @MARK max-w:full -->
<aside class="w:md max-w:full">...</aside>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'max-w:5xl', 'mx:auto', 'w:md', 'max-w:full']}
    </Class2CSS>
</details>

Use container tokens for shared layout surfaces: page wrappers, panels, modals, sidebars, drawer widths, and component caps. Use local `ch`, `x`, or CSS functions when the dimension belongs to content measure or one component's private geometry.

For the full container query model, see [containers](/guide/containers).

## Use measured sizes
The `x` suffix multiplies the [base unit](/guide/theme#project-settings), which defaults to **4 pixels**. For example, `1x` is `0.25rem`, `4x` is `1rem`, and `10x` is `2.5rem`.

Use `x` values for measured component geometry such as icons, avatars, handles, skeleton blocks, and fixed media slots. For page structure, reach for `w:full`, percentages, container tokens, viewport units, text units, or `clamp()` first.

```html
<!-- @MARK size:10x -->
<img class="size:10x round object-cover" src="..." alt="" />

<!-- @MARK w:36x --><!-- @MARK h:20x -->
<figure class="w:36x h:20x">...</figure>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['size:10x', 'w:36x', 'h:20x']}
    </Class2CSS>
</details>

## Pair axes deliberately
`size:*` is not a shorter way to avoid thinking about dimensions. It is the right tool when an element is square by design.

<Demo>
    <div className="flex gap:lg items-center w:full">
        <div className="flex:0">
            <DemoLabel>size:14x</DemoLabel>
            <div className="size:14x grid place-content:center bg:blue-60/.15 r:lg font:medium">A</div>
        </div>
        <div className="flex:1 min-w:0">
            <DemoLabel>w:full h:14x</DemoLabel>
            <div className="w:full h:14x grid place-content:center bg:blue-60/.15 r:lg font:medium">Banner</div>
        </div>
    </div>
</Demo>

```html
<!-- @MARK size:14x -->
<button class="size:14x grid place-content:center">...</button>

<!-- @MARK w:full --><!-- @MARK h:14x -->
<div class="w:full h:14x">...</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['size:14x', 'w:full', 'h:14x']}
    </Class2CSS>
</details>

When an element should keep a non-square ratio, use [aspect ratio](/reference/aspect-ratio) with a width instead of locking both dimensions.

```html
<!-- @MARK w:full --><!-- @MARK aspect-ratio:16/9 -->
<video class="w:full aspect-ratio:16/9" controls></video>
```

## Constrain instead of forcing
Min and max rules are often more stable than fixed widths. They let content, containers, and responsive variants negotiate space without overflow.

<Demo>
    <div className="w:full max-w:96x mx:auto surface:base r:lg p:lg shadow:xs">
        <DemoLabel>min-w:0 max-w:96x</DemoLabel>
        <div className="flex gap:md">
            <div className="size:10x flex:0 bg:blue-60/.15 r:lg"></div>
            <div className="min-w:0 flex:1">
                <div className="font:medium text:strong">Shrinkable content</div>
                <div className="text:muted text:sm white-space:nowrap overflow:hidden text-overflow:ellipsis">Long text can shrink inside the row without forcing the wrapper wider.</div>
            </div>
        </div>
    </div>
</Demo>

```html
<!-- @MARK flex --><!-- @MARK min-w:0 --><!-- @MARK max-w:96x -->
<article class="flex gap:md max-w:96x">
    <img class="size:10x flex:0" alt="" />
    <div class="min-w:0">Long content...</div>
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['flex', 'gap:md', 'max-w:96x', 'size:10x', 'flex:0', 'min-w:0']}
    </Class2CSS>
</details>

In flex and grid layouts, `min-w:0` is the common fix for text or media that refuses to shrink. Without it, intrinsic content can force a row wider than its container even when the parent has a max width.

Use `min-h:*` for baseline regions that may grow, such as app shells, empty states, and hero sections. Use `max-h:*` for scrollable panels, menus, and media regions that must stay inside the viewport.

## Adapt at the right boundary
Sizing classes can use the same [breakpoints](/guide/breakpoints), [containers](/guide/containers), selectors, and media queries as other utilities. Choose the boundary that owns the decision.

```html
<!-- @MARK w:full --><!-- @MARK w:50%@sm --><!-- @MARK max-w:7xl@lg -->
<section class="w:full w:50%@sm max-w:7xl@lg">...</section>

<!-- @MARK container --><!-- @MARK size:10x@container(md) -->
<article class="container">
    <button class="size:8x size:10x@container(md)">...</button>
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'w:50%@sm', 'max-w:7xl@lg', 'container', 'size:8x', 'size:10x@container(md)']}
    </Class2CSS>
</details>

Use viewport breakpoints when the whole page shell changes. Use container queries when a reusable component should adapt to the space it receives in a sidebar, modal, card grid, or main content column.

## Customize sizing tokens
When a dimension becomes part of the product language, add a named container variable in the project CSS entry. Use explicit CSS lengths for fixed values; functions are preserved.

```css name=index.css
@theme {
    --container-sidebar: 17.5rem;
    --container-measure: 72ch;
    --container-panel: clamp(18rem, 50vw, 42rem);
}
```

```html
<!-- @MARK w:sidebar --><!-- @MARK max-w:measure --><!-- @MARK w:panel -->
<aside class="w:sidebar">...</aside>
<article class="max-w:measure">...</article>
<section class="w:panel">...</section>
```

Use descriptive names such as `sidebar`, `measure`, `panel`, or `media` instead of numeric keys. Numeric keys are easy to confuse with raw values such as `w:1px` or `w:2px`.

## Avoid brittle sizing
(x) A page wrapper is fixed, so small screens overflow.

```html
<main class="w:320x">...</main>
```

(o) The wrapper fills available space and stops at a shared cap.

```html
<main class="w:full max-w:7xl mx:auto">...</main>
```

(x) A square component repeats separate width and height values that can drift.

```html
<button class="w:10x h:12x">...</button>
```

(o) The component uses one sizing decision.

```html
<button class="size:10x">...</button>
```

(x) A flex child has a max width, but its content can still force overflow.

```html
<div class="flex">
    <main class="max-w:5xl">Long unbroken content...</main>
</div>
```

(o) The flexible child is allowed to shrink.

```html
<div class="flex">
    <main class="min-w:0 max-w:5xl">Long unbroken content...</main>
</div>
```
