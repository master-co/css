## Overview [sr-only]
Sizing controls the space an element asks for, the bounds it must stay within, and the conditions that can change those dimensions. In CSS this touches [width](https://developer.mozilla.org/en-US/docs/Web/CSS/width), [height](https://developer.mozilla.org/en-US/docs/Web/CSS/height), min and max constraints, percentages, intrinsic keywords, viewport units, container values, and CSS functions.

Master CSS keeps those sizing decisions readable in markup. Use `w:*` and `h:*` for one axis, `size:*` for both axes, `min-*` and `max-*` for constraints, and responsive variants when the dimension changes by viewport or container.

## Start with the sizing decision
Sizing rules work best when each class has a clear job: set a preferred size, set a lower bound, set an upper bound, or keep two axes together.

| Decision | Utility | CSS declarations |
| --- | --- | --- |
| Preferred width | `w:<size>` | `width` |
| Preferred height | `h:<size>` | `height` |
| Same width and height | `size:<size>` | `width`, `height` |
| Lower width bound | `min-w:<size>` | `min-width` |
| Lower height bound | `min-h:<size>` | `min-height` |
| Lower bound on both axes | `min:<size>` | `min-width`, `min-height` |
| Upper width bound | `max-w:<size>` | `max-width` |
| Upper height bound | `max-h:<size>` | `max-height` |
| Upper bound on both axes | `max:<size>` | `max-width`, `max-height` |

```html
<!-- @MARK w:80x --><!-- @MARK h:48x --><!-- @MARK min:10x --><!-- @MARK max-w:md -->
<aside class="w:80x h:48x min:10x max-w:md">...</aside>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:80x', 'h:48x', 'min:10x', 'max-w:md']}
    </Class2CSS>
</details>

Use one-axis rules when the element is naturally rectangular. Use pair rules when the element should stay square, or when a minimum or maximum box needs the same value on both axes.

## Use the `x` scale for measured UI
The `x` suffix multiplies the configured [base unit](/guide/theme#project-settings), which defaults to **4px**. It is the direct sizing scale for measured interface pieces.

<XScale />

```html
<!-- @MARK size:6x -->
<span class="size:6x">...</span>

<!-- @MARK w:16x --><!-- @MARK h:10x -->
<div class="w:16x h:10x">...</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['size:6x', 'w:16x', 'h:10x']}
    </Class2CSS>
</details>

Use the `x` scale for icons, avatars, handles, checkboxes, skeleton blocks, fixed media slots, and components with deliberate measured geometry. For page wrappers and fluid regions, prefer `w:full`, fractions, container values, native units, or CSS functions.

## Size one axis or both axes
Use `size:*` for square UI pieces. Use `w:*` and `h:*` separately when the element has a rectangular role or when each axis answers a different design question.

<Demo>
    <div className="flex gap:lg items:center w:full">
        <div>
            <DemoLabel>size:14x</DemoLabel>
            <div className="size:14x grid place-content:center bg:primary/.15 b:1|primary/.25 r:lg font:medium">A</div>
        </div>
        <div className="flex:1">
            <DemoLabel>w:full h:14x</DemoLabel>
            <div className="w:full h:14x grid place-content:center bg:primary/.15 b:1|primary/.25 r:lg font:medium">Banner</div>
        </div>
    </div>
</Demo>

```html
<!-- @MARK size:14x -->
<img class="size:14x round object:cover" src="..." alt="" />

<!-- @MARK w:full --><!-- @MARK h:14x -->
<div class="w:full h:14x">...</div>
```

When the element should keep a ratio rather than equal axes, use [aspect ratio](/reference/aspect-ratio) with a width instead of forcing both dimensions.

## Use fluid values for layout
Most layout should be flexible first. Use keywords, fractions, viewport units, text-relative units, and CSS functions when the dimension describes behavior rather than a fixed object size.

| Value form | Example | Use for |
| --- | --- | --- |
| Keyword | `w:full`, `w:fit`, `w:min`, `w:max` | Parent-sized or intrinsic elements |
| Fraction | `w:1/2`, `h:3/4` | Proportional columns and split regions |
| Viewport unit | `min-h:100dvh` | Full-height sections and app shells |
| Text unit | `max-w:72ch` | Reading measure |
| Function | `w:clamp(18rem,50vw,42rem)` | Fluid bounds without a named token |

```html
<!-- @MARK w:full --><!-- @MARK max-w:72ch -->
<article class="w:full max-w:72ch">...</article>

<!-- @MARK w:1/2 --><!-- @MARK min-h:100dvh -->
<aside class="w:1/2 min-h:100dvh">...</aside>

<!-- @MARK w:clamp(18rem,50vw,42rem) -->
<section class="w:clamp(18rem,50vw,42rem)">...</section>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'max-w:72ch', 'w:1/2', 'min-h:100dvh', 'w:clamp(18rem,50vw,42rem)']}

</details>

Fractions become percentages. Height percentages still follow native CSS behavior: the parent needs a definite height before `h:1/2` or `h:full` can resolve predictably.

## Cap wrappers with container values
Container size values are the shared scale for page wrappers, panels, modal widths, and component caps. Sizing utilities read that namespace contextually, so write `max-w:5xl`, not a longer namespace-prefixed value.

```html
<!-- @MARK w:full --><!-- @MARK max-w:7xl --><!-- @MARK mx:auto -->
<main class="w:full max-w:7xl mx:auto">
    ...
</main>

<!-- @MARK w:full --><!-- @MARK max-w:md -->
<aside class="w:full max-w:md">...</aside>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'max-w:7xl', 'mx:auto', 'max-w:md']}
    </Class2CSS>
</details>

Use [containers](/guide/containers) when the size belongs to shared responsive surfaces. Use local `x`, `ch`, or `clamp()` values when the size belongs to content measure or one component's local geometry.

## Constrain flexible children
Min and max rules are often more important than fixed widths. They let a layout absorb different content sizes without overflowing or becoming unreadable.

<Demo>
    <div className="w:full max-w:96x mx:auto bg:surface r:lg b:1|lightest p:lg">
        <DemoLabel>w:full max-w:96x min-w:0</DemoLabel>
        <div className="flex gap:md">
            <div className="size:10x bg:primary/.15 r:lg"></div>
            <div className="min-w:0 flex:1">
                <div className="font:medium">Shrinkable content</div>
                <div className="fg:muted text:sm white-space:nowrap overflow:hidden text-overflow:ellipsis">Long text can shrink inside the row without forcing the wrapper wider.</div>
            </div>
        </div>
    </div>
</Demo>

```html
<!-- @MARK w:full --><!-- @MARK max-w:96x --><!-- @MARK min-w:0 -->
<article class="w:full max-w:96x">
    <div class="min-w:0">...</div>
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'max-w:96x', 'min-w:0']}
    </Class2CSS>
</details>

In flex and grid layouts, `min-w:0` is the common fix for text or media that refuses to shrink. Without it, intrinsic content can force a row wider than its container even when the parent has a max width.

## Adapt sizing by viewport or container
Sizing classes can use [breakpoints](/guide/breakpoints), [containers](/guide/containers), selectors, and media queries like any other utility.

```html
<!-- @MARK w:full --><!-- @MARK w:1/2@sm --><!-- @MARK max-w:7xl@lg -->
<div class="w:full w:1/2@sm max-w:7xl@lg">...</div>

<div class="container">
    <!-- @MARK size:10x@container(md) -->
    <button class="size:8x size:10x@container(md)">...</button>
</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'w:1/2@sm', 'max-w:7xl@lg', 'container', 'size:8x', 'size:10x@container(md)']}
    </Class2CSS>
</details>

Use viewport breakpoints when the whole page changes. Use container queries when a reusable component should adapt to the space it receives.

## Add product sizing tokens
When a dimension becomes part of the product language, add a named variable in the project CSS entry. Numeric values use the utility's default unit; explicit units and functions are preserved.

```css name=index.css
@theme {
    --width-sidebar: 280;
    --container-measure: 72ch;
    --width-panel: clamp(18rem,50vw,42rem);
}
```

```html
<!-- @MARK w:sidebar --><!-- @MARK max-w:measure --><!-- @MARK w:panel -->
<aside class="w:sidebar">...</aside>
<article class="max-w:measure">...</article>
<section class="w:panel">...</section>
```

Use descriptive names such as `sidebar`, `measure`, `panel`, or `media` instead of numeric variable keys. Numeric keys can be confused with raw unitless values.

## Avoid brittle sizing
(x) A page wrapper is fixed, so small screens overflow.

```html
<main class="w:320x">...</main>
```

(o) The wrapper fills available space and stops at a cap.

```html
<main class="w:full max-w:7xl mx:auto">...</main>
```

(x) A square component uses separate width and height values that can drift.

```html
<button class="w:10x h:12x">...</button>
```

(o) The component uses one size decision.

```html
<button class="size:10x">...</button>
```

(x) A flex child has a max width, but its content still forces overflow.

```html
<div class="flex">
    <main class="max-w:5xl">Long unbroken content...</main>
</div>
```

(o) The flexible child is allowed to shrink.

```html
<div class="flex">
    <main class="min-w:0 max-w:5xl">Long unbroken content...</main>
</div>
```

---

## Common patterns
* Page wrapper: `w:full max-w:7xl mx:auto`
* Reading measure: `w:full max-w:72ch`
* Square avatar: `size:10x round object:cover`
* Icon button: `size:9x grid place-content:center`
* Fluid panel: `w:clamp(18rem,50vw,42rem)`
* Shrinkable flex child: `min-w:0`
* Full viewport section: `min-h:100dvh`
