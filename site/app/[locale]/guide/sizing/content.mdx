## Overview [sr-only]
CSS sizing controls an element's [width](https://developer.mozilla.org/en-US/docs/Web/CSS/width), [height](https://developer.mozilla.org/en-US/docs/Web/CSS/height), and the constraints that keep a layout usable as its content or container changes. Master CSS keeps those decisions close to the markup with compact rules for one axis, both axes, minimums, maximums, fractions, breakpoint variants, container queries, and native CSS functions.

Use sizing rules to answer three layout questions:

* What should the element try to be? Use `w:*`, `h:*`, or `size:*`.
* How far can it grow or shrink? Add `min-*` or `max-*` constraints.
* When should it change? Attach selectors, viewport breakpoints, or container queries.

## Choose a sizing rule
Use one-axis rules when width and height are independent. Use pair rules when an element should keep the same value on both axes.

| Goal | Rule | CSS declarations |
| --- | --- | --- |
| Set width | `w:<size>` | `width` |
| Set height | `h:<size>` | `height` |
| Set both axes | `size:<size>` | `width`, `height` |
| Set minimum width | `min-w:<size>` | `min-width` |
| Set minimum height | `min-h:<size>` | `min-height` |
| Set both minimum axes | `min:<size>` | `min-width`, `min-height` |
| Set maximum width | `max-w:<size>` | `max-width` |
| Set maximum height | `max-h:<size>` | `max-height` |
| Set both maximum axes | `max:<size>` | `max-width`, `max-height` |

```html
<!-- @MARK w:80x --><!-- @MARK h:48x --><!-- @MARK min:10x --><!-- @MARK max-w:md -->
<aside class="w:80x h:48x min:10x max-w:md">...</aside>
```

## Use the `x` sizing scale
The `x` suffix multiplies the configured [base unit](/guide/theme#project-settings), which defaults to **4px**. It is the most direct way to create fixed dimensions that stay aligned with spacing, radius, and component rhythm.

<XScale />

```html
<!-- @MARK 6x --><!-- @MARK 16x -->
<div class="size:6x">24px square</div>
<div class="w:16x h:10x">64px by 40px</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['size:6x', 'w:16x', 'h:10x']}

Use this scale for icons, avatars, fixed controls, columns with intentional widths, and skeleton blocks. For fluid page layout, pair it with `w:full`, fractions, `container-*`, or CSS functions.

## Size one axis or both axes
Use `size:*` for elements that should remain square, such as avatars, swatches, icon buttons, and fixed indicators. Use `w:*` and `h:*` separately when the element has a rectangular role.

## Use fluid and keyword sizes
Sizing values can use shared keywords, configured container variables, fractions, native CSS units, and CSS functions.

| Value form | Example | Use for |
| --- | --- | --- |
| Keyword | `w:full`, `w:fit`, `w:min`, `w:max` | Content-sized or parent-sized elements |
| Container variable | `max-w:5xl` | Page wrappers and responsive reading widths |
| Fraction | `w:1/2`, `h:3/4` | Percent-based columns or proportional children |
| Native unit | `h:100dvh`, `w:72ch` | Viewport- or text-relative sizing |
| Function | `w:clamp(16rem,50vw,40rem)` | Fluid bounds without custom CSS |

```html
<!-- @MARK w:full --><!-- @MARK max-w:5xl -->
<main class="w:full max-w:5xl">...</main>

<!-- @MARK w:1/2 --><!-- @MARK h:100dvh -->
<aside class="w:1/2 h:100dvh">...</aside>

<!-- @MARK w:clamp(16rem,50vw,40rem) -->
<section class="w:clamp(16rem,50vw,40rem)">...</section>
```

## Constrain flexible layouts
Most page and component layouts should be flexible first, then constrained. A common pattern is `w:full` with a `max-w:*` cap, plus `min-w:0` on flex or grid children that need to shrink instead of overflowing.

<Demo>
    <div className="w:full max-w:96x mx:auto bg:surface r:lg b:1|lightest p:lg">
        <DemoLabel>w:full max-w:96x</DemoLabel>
        <div className="flex gap:md">
            <div className="size:10x bg:primary/.15 r:lg"></div>
            <div className="min-w:0 flex:1">
                <div className="font:medium">Constrained content</div>
                <div className="fg:muted text:sm white-space:nowrap overflow:hidden text-overflow:ellipsis">Long text can shrink inside the row without forcing the wrapper wider.</div>
            </div>
        </div>
    </div>
</Demo>

```html
<!-- @MARK w:full --><!-- @MARK max-w:96x --><!-- @MARK min-w:0 -->
<article class="w:full max-w:96x">
    <div class="min-w:0">...</div>
</article>
```

<details>
    <summary>Generated CSS</summary>

Use `max-w:*` for wrappers that should align with your [container size scale](/guide/containers), and use local `x` values when a component has its own measured maximum.

## Adapt sizing responsively
Sizing rules can use the same [selectors](/guide/state-selectors), [viewport breakpoints](/guide/responsive-design#based-on-viewport-breakpoints), and [container queries](/guide/responsive-design#based-on-container-sizes) as other Master CSS rules.

```html
<!-- @MARK w:full --><!-- @MARK w:1/2@sm --><!-- @MARK max-w:7xl@lg -->
<div class="w:full w:1/2@sm max-w:7xl@lg">...</div>

<div class="container">
    <!-- @MARK size:10x@container(md) -->
    <button class="size:8x size:10x@container(md)">...</button>
</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['w:full', 'w:1/2@sm', 'max-w:7xl@lg', 'container', 'size:8x', 'size:10x@container(md)']}
    </Class2CSS>
</details>

Start from the smallest reliable size, then add conditions only where the component needs a different dimension.

## Add reusable sizing tokens
For repeated product dimensions, add named variables in the project CSS entry and use those names in sizing rules. Numeric values are converted with the rule's default unit, while explicit CSS units and functions are preserved.

```css name=index.css
@theme {
    --width-sidebar: 280;
    --max-width-measure: 72ch;
    --width-panel: clamp(18rem,50vw,42rem);
}
```

```html
<!-- @MARK w:sidebar --><!-- @MARK max-w:measure --><!-- @MARK w:panel -->
<aside class="w:sidebar">...</aside>
<article class="max-w:measure">...</article>
<section class="w:panel">...</section>
```

(i) Use descriptive names such as `sidebar`, `measure`, or `panel` instead of numeric variable keys. Numeric keys can be confused with raw unitless values.

## Common patterns
* Page wrapper: `w:full max-w:7xl`
* Reading measure: `w:full max-w:72ch`
* Square avatar: `size:10x round`
* Icon button: `size:9x grid place-content:center`
* Fluid panel: `w:clamp(18rem,50vw,42rem)`
* Shrinkable flex child: `min-w:0`
* Full viewport section: `min-h:100dvh`
