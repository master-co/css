## Overview [sr-only]
Sizing describes the space an element should claim, the limits it should respect, and the boundary where that decision changes. In CSS this includes [width](https://developer.mozilla.org/en-US/docs/Web/CSS/width), [height](https://developer.mozilla.org/en-US/docs/Web/CSS/height), min and max constraints, intrinsic keywords, percentages, viewport units, container values, and CSS functions.

Master CSS keeps sizing decisions close to the element that owns them. Use `w:*` and `h:*` for one axis, `size:*` when both axes intentionally match, `min-*` and `max-*` for constraints, container tokens for shared layout surfaces, and responsive variants when the size changes by viewport or container.

  <div className="container w:100%">
    <div className="grid grid-cols:1 gap-md w:100% grid-cols:2@container((width>=18rem))">

          <div className="h:2.5rem r-lg bg-blue-60/.15"></div>
          <div className="h:1rem w:75% mt-sm r-sm bg-blue-60/.1"></div>
        </div>
      </section>
      <section className="min-w:0 p-lg r-lg surface-raised shadow-xs">
        <DemoLabel>Measured object</DemoLabel>
        <div className="flex items-center gap-md">
          <div className="size:3rem round bg-blue-60/.15"></div>
          <div className="flex:1 min-w:0">
            <div className="h:1rem w:100% max-w:7rem r-sm bg-blue-60/.16"></div>

          </div>
        </div>
      </section>
    </div>
  </div>
</Demo>

## Choose a sizing role
A sizing class should have one clear job. It can set the preferred size, keep an element from collapsing, cap growth, tie both axes together, or move the decision to a responsive boundary.

<SizingRoleTable />

Use one-axis rules when the element is rectangular by role. Use `size:*`, `min:*`, or `max:*` only when both axes genuinely share the same decision.

```html
<!-- @MARK w:100% --><!-- @MARK max-w-7xl --><!-- @MARK min-h:100dvh -->
<main class="w:100% min-h:100dvh max-w-7xl mx:auto">
  ...
</main>
```

## Start fluid, then constrain
Most layout should fill the space it receives and then stop at a cap. A fluid wrapper with `w:100% max-w:*` behaves better across viewports than one fixed width that only fits one screen.

```html
<!-- @MARK w:100% --><!-- @MARK max-w-7xl --><!-- @MARK px-md --><!-- @MARK px-xl@md -->
<main class="w:100% max-w-7xl mx:auto px-md px-xl@md">
  ...
</main>

<!-- @MARK w:100% --><!-- @MARK max-w:72ch -->
<article class="w:100% max-w:72ch">
  ...
</article>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['w:100%', 'max-w-7xl', 'mx:auto', 'px-md', 'px-xl@md', 'max-w:72ch']}
  </Class2CSS>
</details>

Use `w:100%` when the element should follow its parent, percentages such as `w:50%` for proportional regions, `max-w:*` for caps, and CSS functions such as `clamp()` when the bound itself should be fluid.

```html
<!-- @MARK w:100% --><!-- @MARK w:50%@sm -->
<aside class="w:100% w:50%@sm">...</aside>

<!-- @MARK w:clamp(18rem,50vw,42rem) -->
<section class="w:clamp(18rem,50vw,42rem)">...</section>
```

Percentage widths and heights follow native CSS behavior. The parent needs a definite height before `h:100%` or `h:50%` can resolve predictably.

## Use container tokens
Sizing utilities read the `container` namespace contextually. `w-md`, `max-w-5xl`, `size-sm`, `min-w-xs`, and `flex-basis-lg` use `--container-*` tokens without repeating the namespace in markup.

<ContainerTokenTable />

```html
<!-- @MARK w:100% --><!-- @MARK max-w-5xl -->
<main class="w:100% max-w-5xl mx:auto">
  ...
</main>

<!-- @MARK w-md --><!-- @MARK max-w:100% -->
<aside class="w-md max-w:100%">...</aside>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['w:100%', 'max-w-5xl', 'mx:auto', 'w-md', 'max-w:100%']}
  </Class2CSS>
</details>

Use container tokens for shared layout surfaces: page wrappers, panels, modals, sidebars, drawer widths, and component caps. Use local `ch`, `rem`, or CSS functions when the dimension belongs to content measure or one component's private geometry.

For the full container namespace and query model, see [containers](/guide/containers#namespace-for-container-values).

## Use measured sizes
Use explicit native lengths for component geometry such as icons, avatars, handles, skeleton blocks, and fixed media slots. For page structure, reach for `w:100%`, percentages, container tokens, viewport units, text units, or `clamp()` first. Master CSS preserves the unit you write.

```html
<!-- @MARK size:2.5rem -->
<img class="size:2.5rem round object-cover" src="..." alt="" />

<!-- @MARK w:9rem --><!-- @MARK h:5rem -->
<figure class="h:5rem w:9rem">...</figure>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['size:2.5rem', 'w:9rem', 'h:5rem']}
  </Class2CSS>
</details>

## Pair axes deliberately
`size:*` is not a shorter way to avoid thinking about dimensions. It is the right tool when an element is square by design.

<Demo>
  <div className="flex items-center gap-lg w:100%">
    <div className="flex:0">
      <DemoLabel>size:3.5rem</DemoLabel>
      <div className="grid place-content:center size:3.5rem r-lg font-medium bg-blue-60/.15">A</div>
    </div>
    <div className="flex:1 min-w:0">
      <DemoLabel>w:100% h:3.5rem</DemoLabel>
      <div className="grid place-content:center h:3.5rem w:100% r-lg font-medium bg-blue-60/.15">Banner</div>
    </div>
  </div>
</Demo>

```html
<!-- @MARK size:3.5rem -->
<button class="grid place-content:center size:3.5rem">...</button>

<!-- @MARK w:100% --><!-- @MARK h:3.5rem -->
<div class="h:3.5rem w:100%">...</div>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['size:3.5rem', 'w:100%', 'h:3.5rem']}
  </Class2CSS>
</details>

When an element should keep a non-square ratio, use [aspect ratio](/reference/aspect-ratio) with a width instead of locking both dimensions.

```html
<!-- @MARK w:100% --><!-- @MARK aspect-ratio:16/9 -->
<video class="w:100% aspect-ratio:16/9" controls></video>
```

## Constrain instead of forcing
Min and max rules are often more stable than fixed widths. They let content, containers, and responsive variants negotiate space without overflow.

<Demo>
  <div className="w:100% max-w-sm mx:auto p-lg r-lg surface-raised shadow-xs">
    <DemoLabel>min-w:0 max-w:24rem</DemoLabel>
    <div className="flex gap-md">
      <div className="flex:0 size:2.5rem r-lg bg-blue-60/.15"></div>
      <div className="flex:1 min-w:0">
        <div className="font-medium text-strong">Shrinkable content</div>
        <div className="overflow:hidden text-sm text-ellipsis white-space:nowrap text-muted">Long text can shrink inside the row without forcing the wrapper wider.</div>
      </div>
    </div>
  </div>
</Demo>

```html
<!-- @MARK flex --><!-- @MARK min-w:0 --><!-- @MARK max-w:24rem -->
<article class="flex gap-md max-w-sm">
  <img class="flex:0 size:2.5rem" alt="" />
  <div class="min-w:0">Long content...</div>
</article>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['flex', 'gap-md', 'max-w:24rem', 'size:2.5rem', 'flex:0', 'min-w:0']}
  </Class2CSS>
</details>

In flex and grid layouts, `min-w:0` is the common fix for text or media that refuses to shrink. Without it, intrinsic content can force a row wider than its container even when the parent has a max width.

Use `min-h:*` for baseline regions that may grow, such as app shells, empty states, and hero sections. Use `max-h:*` for scrollable panels, menus, and media regions that must stay inside the viewport.

## Adapt at the right boundary
Sizing classes can use the same [breakpoints](/guide/breakpoints), [containers](/guide/containers), selectors, and media queries as other utilities. Choose the boundary that owns the decision.

```html
<!-- @MARK w:100% --><!-- @MARK w:50%@sm --><!-- @MARK max-w-7xl@lg -->
<section class="w:100% w:50%@sm max-w-7xl@lg">...</section>

<!-- @MARK container --><!-- @MARK size:2.5rem@container((width>=28rem)) -->
<article class="container">
  <button class="size:2rem size:2.5rem@container((width>=28rem))">...</button>
</article>
```

<details>
  <summary>Generated CSS</summary>
  <Class2CSS>
    {['w:100%', 'w:50%@sm', 'max-w-7xl@lg', 'container', 'size:2rem', 'size:2.5rem@container((width>=28rem))']}
  </Class2CSS>
</details>

Use viewport breakpoints when the whole page shell changes. Use container queries when a reusable component should adapt to the space it receives in a sidebar, modal, card grid, or main content column.

## Customize sizing tokens
When a dimension becomes part of the product language, add a named container variable in the project CSS entry. Use explicit CSS lengths for fixed values; functions are preserved.

```css name=index.css
@theme {
  --container-sidebar: 17.5rem;
  --container-measure: 72ch;
  --container-panel: clamp(18rem, 50vw, 42rem);
}
```

```html
<!-- @MARK w-sidebar --><!-- @MARK max-w-measure --><!-- @MARK w-panel -->
<aside class="w-sidebar">...</aside>
<article class="max-w-measure">...</article>
<section class="w-panel">...</section>
```

Use descriptive names such as `sidebar`, `measure`, `panel`, or `media` instead of numeric keys. Numeric keys are easy to confuse with raw values such as `w:1px` or `w:2px`.

## Avoid brittle sizing
(x) A page wrapper is fixed, so small screens overflow.

```html
<main class="w-7xl">...</main>
```

(o) The wrapper fills available space and stops at a shared cap.

```html
<main class="w:100% max-w-7xl mx:auto">...</main>
```

(x) A square component repeats separate width and height values that can drift.

```html
<button class="h:3rem w:2.5rem">...</button>
```

(o) The component uses one sizing decision.

```html
<button class="size:2.5rem">...</button>
```

(x) A flex child has a max width, but its content can still force overflow.

```html
<div class="flex">
  <main class="max-w-5xl">Long unbroken content...</main>
</div>
```

(o) The flexible child is allowed to shrink.

```html
<div class="flex">
  <main class="min-w:0 max-w-5xl">Long unbroken content...</main>
</div>
```
