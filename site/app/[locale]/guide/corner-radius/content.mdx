## Overview [sr-only]
Corner radius controls the curvature of surfaces, controls, media, and badges. Master CSS maps the default radius scale to `radius` variables, so repeated UI shapes use stable tokens instead of raw pixel values.

<Overview />

Use radius tokens to answer what kind of shape the element needs:

* `r:xs` to `r:md` keep inputs, compact buttons, tables, and dense cards crisp.
* `r:lg` to `r:2xl` suit standard cards, panels, dialogs, and media frames.
* `r:3xl` and `r:4xl` are expressive values for banners, illustrations, and large feature surfaces.
* `rounded` and `round` are semantic shortcuts for pill and circular shapes.

```html
<!-- @MARK r:md --><!-- @MARK r:lg --><!-- @MARK rounded --><!-- @MARK round -->
<input class="r:md" />
<article class="r:lg">...</article>
<span class="rounded">Beta</span>
<img class="round" alt="" />
```

## Choose radius by role
Use the smallest radius that communicates the intended surface. Radius should reinforce hierarchy instead of becoming decoration.

| Role | Prefer | Use for |
| --- | --- | --- |
| Dense control | `r:xs`, `r:sm`, `r:md` | Inputs, buttons, table cells, menus |
| Standard surface | `r:lg`, `r:xl`, `r:2xl` | Cards, modals, popovers, image frames |
| Expressive surface | `r:3xl`, `r:4xl` | Hero panels, illustrations, large media |
| Pill shape | `rounded` | Tags, segmented controls, pill buttons |
| Circle shape | `round` | Avatars, icon buttons, indicators |

Use the same token for surfaces that should feel related. For example, a card, its image, and its nested action group can share `r:lg` or step down one level for nested elements.

---

## Namespace for corner radius
Corner radius tokens are defined with the `radius-*` namespace. Radius utilities search this namespace, so `r:lg`, `rt:lg`, and `border-radius:lg` all resolve `radius-lg` without requiring the `radius-` prefix in markup.

The following rules share the same namespace:

* `border-radius` for all corners
* `border-top-left-radius` and `border-top-right-radius`
* `border-bottom-left-radius` and `border-bottom-right-radius`
* axis and corner shorthands such as `rt:*`, `rb:*`, `rl:*`, and `rr:*`

```css name=index.css
@theme {
    radius-card: 12;
    radius-control: 6;
}
```

```html
<!-- @MARK r:card --><!-- @MARK r:control -->
<article class="r:card">...</article>
<button class="r:control">Save</button>
```

See the [border radius](/reference/border-radius) reference for every radius utility and corner shorthand.

---

## Avoid numeric token keys
(x) Numeric token names are hard to distinguish from raw values.

```css name=index.css
@theme {
    radius-1: 4;
    radius-2: 8;
}
```

(o) Name tokens by scale or role.

```css name=index.css
@theme {
    radius-sm: 4;
    radius-card: 12;
}
```

Use raw values such as `r:1` or `r:2x` only when the guide is teaching value syntax or the element has a local measured requirement.
