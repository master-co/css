## Overview [sr-only]
Master CSS utilities are the class syntax definitions that map class names to CSS declarations. Some utilities are fixed class names like `block` and `round`; others are value-based syntax like `font:16`, `bg:primary`, or `grid-cols:3`.

Utilities work with [selector tokens](/guide/selector-tokens), [at tokens](/guide/at-tokens), modes, functions, variables, and `@compose`. Use them for reusable styling primitives. If you are defining semantic classes such as `.btn` or `.card`, use [component classes](/guide/reusing-styles#components) instead.

---

## Add a custom utility
Use top-level `@layer utilities` only when your design system needs a reusable primitive that cannot be represented cleanly by existing utilities or components. CSS-defined utilities are static utilities: a class name maps to native declarations, composed declarations, nested selectors, and conditional rules.
<Overview />

Use `@compose` when a primitive should reuse existing Master CSS utilities. The composed utility list is resolved with the same rule priority as markup classes, then merged with native declarations in source order.

```css name=index.css
@layer utilities {
    .flow {
        @compose "grid gap:md";
    }

    .content-auto {
        content-visibility: auto;
        contain-intrinsic-size: auto 32rem;
    }

    .print-hidden {
        @at print {
            display: none;
        }
    }
}
```

Use the utility in markup:

```html
<!-- @MARK flow --><!-- @MARK content-auto --><!-- @MARK print-hidden -->
<section class="flow content-auto print-hidden">…</section>
```

Like components, utility definitions in the project CSS entry are converted into config. A custom utility is generated only when its class appears in markup, is scanned from source, or is composed by another CSS-defined style.

(i) Use custom utilities for reusable primitives. Use [component classes](/guide/reusing-styles#components) when the class name describes a product UI pattern such as `.btn`, `.card`, or `.field`.
