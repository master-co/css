## Overview [sr-only]
Master CSS utilities are the class syntax definitions that map class names to CSS declarations. Some utilities are fixed class names like `block` and `round`; others are value-based syntax like `font:16`, `bg:primary`, or `grid-cols:3`.

Utilities work with [selector tokens](/guide/selector-tokens), [at tokens](/guide/at-tokens), modes, functions, and variables. Use them for reusable styling primitives. If you are defining semantic classes such as `.btn` or `.card`, use [components](/guide/components) instead.

---

## Add a custom utility
Use `@layer utilities` inside `@master` only when your design system needs a reusable primitive that cannot be represented cleanly by existing utilities or components. CSS-defined utilities are currently static utilities: a class name maps to native declarations.
<Overview />

Custom utilities cannot use `@compose`. If you want to compose existing Master CSS utilities into a semantic class such as `.btn` or `.card`, use [components](/guide/components).

```css name=index.css
@master {
    @layer utilities {
        .content-auto {
            content-visibility: auto;
            contain-intrinsic-size: auto 32rem;
        }

        .print-hidden {
            @at print {
                display: none;
            }
        }
    }
}
```

Use the utility in markup:

```html
<!-- @MARK content-auto --><!-- @MARK print-hidden -->
<section class="content-auto print-hidden">…</section>
```

Like components, utility definitions in the project CSS entry are converted into config. A custom utility is generated only when its class appears in markup or is extracted from source.
