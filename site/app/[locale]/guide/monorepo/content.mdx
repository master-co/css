## Foreword [sr-only]
The [Language Server](/reference/language-server) and [ESLint](/reference/eslint) both support the monorepo.

By default, language server will form independent workspaces based on the location of the __master.css__ configuration files, independent of the package manager's workspace. The same goes for ESLint, which forms a new working directory based on the location of its configuration file.

Officially integrated packages or extensions will automatically read the __master.css__ configuration based on the current running directory. This means that you can start using it with zero configuration as long as you create a configuration file in the workspace.

---

## One root master.css
Whether it's a single repository or a monorepo, create a __master.css__ file in the root directory for your design system.
<ExplorerView>
{[
    { name: 'src', children: [
        { name: 'eslint.config.js' },
        { name: 'master.css' }
    ]}
]}
</ExplorerView>
The language service will create at least a root workspace regardless of whether `master.css` exists.

---

## One master.css per microservice
When there are different design systems or complex requirements in a monorepo, you may need to create __master.css__ and __eslint.config.js__ for multiple folders to serve as [workspaces](/reference/language-server#workspaces).

(i) This will create two workspaces, `/` and `/apps/a`.
<ExplorerView>
{[
    { name: 'apps', children: [
        { name: 'a', children: [
            { name: 'eslint.config.js' },
            { name: 'master.css' }
        ]},
        { name: 'b' }
    ]},
    { name: 'eslint.config.js' },
    { name: 'master.css' }
]}
</ExplorerView>

Note that `/apps/b` will be considered part of the root workspace `/`.

### Share the configuration
In each workspace, import the shared CSS config files and add workspace-specific definitions after them.
```css name=apps/a/master.css
@import '../../master.css';

@master {
    --color-primary: #4f46e5;
}

@master components {
    .app-shell {
        @compose "min-h:100vh bg:base";
    }
}
```
Later definitions in the workspace file can override root options, variables, tokens, animations, utilities, and matching component buckets.

(x) Forgot to create __/apps/a/master.css__ in the workspace and import the root configuration.
<ExplorerView>
{[
    { name: 'apps', children: [
        { name: 'a', children: [
            { name: 'eslint.config.js' },
            { name: 'master.css' }
        ]},
        { name: 'b' }
    ]},
    { name: 'eslint.config.js' },
    { name: 'master.css' }
]}
</ExplorerView>

Unless this workspace is not using Master CSS, this is a common oversight.

Finally, using a monorepo and having multiple workspaces doesn't mean you have to create multiple configurations. In most cases, you just need [one root master.css](#one-root-mastercss).
