## Overview [sr-only]
Spacing controls the rhythm inside components, between related elements, and across page sections. Master CSS maps the default spacing scale to `spacing` variables, so padding, margin, gap, and inset can share the same design language.

<Overview />

Use the scale by relationship:

* `4xs` to `2xs` for micro spacing between icons, tags, compact controls, and inline text.
* `xs` to `sm` for form fields, list rows, toolbar controls, and tight component groups.
* `md` as the default component rhythm.
* `lg` to `xl` for card padding, grouped content, and larger component separation.
* `2xl` to `5xl` for layout gutters, section spacing, and large editorial rhythm.

## Namespace for spacing
The `spacing` variable namespace is shared across padding, margin, gap, inset, scroll spacing, and similar layout rules.

<SpacingHeirs />

This lets spacing-related utilities use `md`, `lg`, or project token names without the `spacing-` prefix.

```css name=index.css
@theme {
    --spacing-sm: 0.75rem;
    --spacing-md: 1rem;
    --spacing-lg: 1.5rem;
    --spacing-section: 6rem;
}
```

Apply the custom spacing tokens in your markup:

```html
<!-- @MARK mt:md --><!-- @MARK p:sm --><!-- @MARK gap:lg --><!-- @MARK py:section -->
<section class="py:section">
    <div class="mt:md p:sm gap:lg">...</div>
</section>
```

## Using spacing multiplier
The `x` suffix multiplies the [base unit](/guide/theme#project-settings) theme setting, which defaults to **4 pixels**. Use it for measured geometry that should stay aligned with the spacing grid but does not need a named token.

<XScale />

Use the `x` suffix to indicate a multiplier of the base unit.

```html
<!-- @MARK 1x -->
<div class="m:1x"></div>       <!--  4px, margin: 0.25rem -->
<!-- @MARK 2x -->
<div class="p:2x"></div>       <!--  8px, padding: 0.5rem -->
<!-- @MARK 8x -->
<div class="w:8x"></div>       <!-- 32px, width: 2rem -->
<!-- @MARK 3x -->
<div class="gap:3x"></div>     <!-- 12px, gap: 0.75rem -->
```

For product surfaces, prefer named spacing tokens such as `sm`, `md`, and `lg`. Use `x` values for measured local geometry, such as icon size, avatar size, skeleton blocks, or a component-specific fixed width.

## Unitless values
Raw unitless values such as `0`, `1`, and `2` are low-level pixel values. They bypass the base unit system and are useful for resets, hairline adjustments, and exact pixel alignment.

```html
<!-- @MARK m:0 -->
<div class="m:0">0px, margin: 0rem</div>
<!-- @MARK p:1 -->
<div class="p:1">1px, padding: 0.0625rem</div>
<!-- @MARK w:2px -->
<div class="w:2px">2px, width: 0.125rem</div>
```

(!) Avoid mixing named spacing tokens, `x` multipliers, and unitless values arbitrarily. Prefer named tokens for layout rhythm, `x` values for measured local geometry, and unitless values only for resets or pixel-grid adjustments.

## Common mistakes
### Do not use numeric keys as tokens
(x) Avoid defining spacing tokens with numeric keys.

```css name=index.css
@theme {
    --spacing-1: 0.25rem; /* [!code --] */
    --spacing-2: 0.5rem; /* [!code --] */
}
```

Numeric keys create ambiguity with [unit sensing](/guide/style-declarations#unit-sensing), because `p:1` reads as a low-level value while `p:sm` reads as a spacing token.

(o) Use descriptive scale or role keys.

```css name=index.css
@theme {
    --spacing-sm: 0.75rem;
    --spacing-card: 1.25rem;
    --spacing-section: 6rem;
}
```

---

## Summary

Master CSS provides a unified system for defining spacing:

* Use named spacing tokens for shared rhythm.
* Use `x` multipliers for measured local geometry.
* Use raw unitless values sparingly for resets and exact pixel adjustments.
* Avoid numeric token keys so markup stays clear.
