## Overview [sr-only]
Variables are design tokens. Modes are named contexts such as light, dark, high contrast, or a product theme. Together they let one semantic class such as `bg:primary` generate the right CSS for every mode.

<ModeImg src="/master-css-variables-and-modes.svg" alt='Master CSS Variables and Modes' />

Define variables and modes in the [project CSS entry](/guide/theme) so tokens, screens, mode defaults, and mode triggers live next to the rest of the theme. The file stays close to native CSS: variables are custom property declarations, and mode-specific values are nested blocks.

For a classic example, use the `primary` token in markup instead of writing separate values for each theme:

```html
<div class="bg:#000000@light">…</div> <!-- [!code --] -->
<div class="bg:#ffffff@dark">…</div> <!-- [!code --] -->
<div class="bg:primary">…</div>
```

## Define variables
In the project CSS entry, define variables with native CSS custom property declarations inside `@master`.

```css name=index.css
@master {
    --color-primary: #4f46e5;
    --color-surface: #ffffff;
    --font-family-sans: Inter, ui-sans-serif, system-ui, sans-serif;
    --spacing-card: 24;
    --screen-md: 768;
}
```

The compiler converts these declarations into `config.variables`:

```js
{
    variables: [
        { namespace: 'color', key: 'primary', value: '#4f46e5' },
        { namespace: 'color', key: 'surface', value: '#ffffff' },
        { namespace: 'font-family', key: 'sans', value: 'Inter, ui-sans-serif, system-ui, sans-serif' },
        { namespace: 'spacing', key: 'card', value: 24 },
        { namespace: 'screen', key: 'md', value: 768 }
    ]
}
```

Use the token in markup through the property namespace:

```html
<!-- @MARK bg:primary --><!-- @MARK font:sans --><!-- @MARK p:card --><!-- @MARK @md -->
<div class="bg:primary font:sans p:card grid-cols:2@md">…</div>
```

`screen` variables also become responsive at tokens. A declaration such as `--screen-md: 768;` lets `grid-cols:2@md` generate a media query without separately defining an at token.

---

## Contextual resolution
Master CSS resolves token names by the property that uses them. `primary` maps to `color.primary` when used by color-related utilities, while `sans` maps to `font-family.sans` when used by font-family utilities.

```html
<div class="background-color:primary">…</div>
<div class="bg:primary">…</div>
<div class="font-family:sans">…</div>
<div class="font:sans">…</div>
```

This keeps markup concise while avoiding global token collisions across namespaces.

## Modes
Define mode-specific variables with mode blocks inside `@master`.

```css name=index.css
@master {
    light {
        --color-primary: #4f46e5;
        --color-surface: #ffffff;
    }

    dark {
        --color-primary: #818cf8;
        --color-surface: #111827;
    }
}
```

`light` and `dark` are always available modes. If you define a new mode, the compiler adds it automatically.

```css name=index.css
@master {
    chrisma {
        --color-primary: #ff0;
    }
}
```

When a variable has mode-specific values, Master CSS emits a CSS custom property and references it from generated utilities and components.

```css
@layer theme {
    .light,
    :root {
        --color-primary: rgb(79 70 229);
    }

    .dark {
        --color-primary: rgb(129 140 248);
    }
}

@layer utilities {
    .bg\:primary {
        background-color: var(--color-primary);
    }
}
```

The same mechanism applies when native declarations inside managed definitions or native composed style rules use `var(--color-primary)`: the theme variables are still generated when a component, utility, or lowered native rule references them.

## Mode triggers
`mode-trigger` controls how mode-specific output is written.

```css name=index.css
@master {
    mode-trigger: media;
}
```

| Trigger | Output behavior |
|---------|-----------------|
| `media` | Uses `@media (prefers-color-scheme: <mode>)` for light/dark modes. |
| `class` | Uses class wrappers such as `.dark &`. |
| `host` | Uses shadow host wrappers such as `:host(.dark) &`. |

For CSS-defined style rules, `@at dark` follows the same trigger:

```css name=index.css
@master {
    mode-trigger: class;
}

@layer components {
    .btn {
        @at dark {
            @compose "bg:neutral-90";
        }
    }
}

.notice {
    @at dark {
        @compose "fg:neutral-20";
    }
}
```

With `mode-trigger: class`, the selectors become `.dark .btn` and `.dark .notice`.

## Default mode
`default-mode` controls which class-triggered mode is also attached to `:root`.

```css name=index.css
@master {
    default-mode: light;
    mode-trigger: class;
}
```

With default `light` mode:

```css
.light,
:root {
    --color-primary: rgb(79 70 229);
}
```

Set `default-mode: false;` when no mode should be applied by default.

```css name=index.css
@master {
    default-mode: false;
}
```

`default-mode` has no effect with `mode-trigger: media`, because the browser decides the active color scheme from user/system preferences.

## Implementing mode switching
Use `mode-trigger: class` when users can switch modes manually.

```css name=index.css
@master {
    mode-trigger: class;
}
```

Then control the theme by adding the mode class to `<html>`:

```html
<!-- @MARK dark -->
<html class="dark">
    <body>
        <div class="bg:primary">…</div>
    </body>
</html>
```

```js
const key = 'theme-preference'
const preference = localStorage.getItem(key) || 'system'
const value = preference === 'system'
    ? matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
    : preference

document.documentElement.classList.add(value)
document.documentElement.style.colorScheme = value
```
