## Overview [sr-only] \{#overview\}
Theme variables connect project vocabulary to ordinary CSS custom properties. Write explicit selectors and native conditions inside `@theme`. Master CSS keeps the declarations needed by generated classes or native stylesheet references; the browser resolves inheritance, the cascade, and computed values.

```css name=index.css
@import '@master/css';

@theme {
  :root, :host {
    --color-brand: #4f46e5;
    --spacing-card: 1.5rem;
    --color-surface-card: white;
  }
  @media (prefers-color-scheme: dark) {
    :root, :host { --color-surface-card: #111827; }
  }
}
```

```html
<article class="bg-surface-card p-card">
  <button type="button" class="fg-white bg-brand">Save</button>
</article>
```

## Variable lifecycle \{#variable-lifecycle\}
### Check a custom spacing token \{#custom-spacing-example\}

<ConfiguredExample source={'@theme { :root, :host { --spacing-card: 1.5rem; } }'} classes={['p-card']} />

The class emits `padding:var(--spacing-card)`. Its dependency emits in `@layer theme` under the authored selector. When a variable is live, every authored scope and duplicate declaration for that name stays in source order. Dependencies referenced by any of those values are also retained. Scanning does not discard theme branches whose selectors are absent from markup.

Cycles, fallbacks, inheritance and functions keep native custom-property behavior. Master CSS does not select a light, dark or viewport-specific value during compilation. Editor inspection reports the authored scope paths and values, not a computed result.

Keyframes are ordinary stylesheet rules. Keep them outside `@theme` and import their stylesheet. An animation name does not register or retain a keyframe resource in the engine, SSR manifest or runtime.

## Namespace resolution \{#namespace-resolution\}
Write custom properties as `--<namespace>-<key>`. Namespace lookup uses the longest registered prefix: `color-line-divider` belongs to `color-line` before `color`.

```css
@theme {
  :root, :host {
    --color-brand: #4f46e5;
    --color-text-action: var(--color-brand);
    --color-line-divider: rgb(0 0 0 / 12%);
    --spacing-card: 1.5rem;
    --radius-card: .75rem;
  }
}
```

```html
<article class="r-card p-card b:1px|solid|var(--color-line-divider)">
  <a class="text-action" href="/settings">Settings</a>
</article>
```

## Contextual token lookup \{#contextual-token-lookup\}

| Class | Token source |
| --- | --- |
| `p-card` | `--spacing-card` |
| `r-card` | `--radius-card` |
| `text-action` | `--color-text-action` |
| `bg-brand` | `--color-brand` |

An explicit parameter utility can declare ordered sources with `@utility outline-* from(--color-line-*, --color-*)`. The first matching namespace wins. Use direct native values such as `padding:1rem` for values without a project token.

## Native values and unconditional declarations \{#inline-and-static-variables\}
`@theme inline` and `@theme static` are removed. Token utilities retain `var()` references. For unconditional declarations, write native CSS:

```css
@layer theme {
  :root, :host { --app-version: 1; }
}
@keyframes fade-in { to { opacity: 1; } }
```

## Authored scopes \{#mode-buckets\}
Selectors and queries express alternate values inside a single theme tree. The same class follows the browser's cascade:

```css
@theme {
  :root, :host { --color-panel: white; --color-text-panel: #111827; }
  .dark { --color-panel: #111827; --color-text-panel: #f9fafb; }
  [data-theme="contrast"] { --color-panel: black; --color-text-panel: yellow; }
}
```

### Derived scoped values \{#derived-mode-aware-values\}
Derived values remain CSS functions, including `var()` fallbacks and `color-mix()`. Place a derived declaration on the scopes where it should compute; CSS custom properties resolve references where they are declared and then inherit that value.

```css
@theme {
  :root, .dark {
    --color-link: var(--color-brand);
    --color-link-hover: color-mix(in oklab, var(--color-brand), black 15%);
  }
}
```

## Theme activation and named variants \{#mode-triggers\}
`@mode` is removed. Theme selectors activate values. A separate `@custom-variant` defines where a markup suffix applies; it never changes the theme tree or inserts descendant selectors automatically.

```css
@custom-variant ocean {
  &:where([data-theme="ocean"], [data-theme="ocean"] *) { @slot; }
}
@theme {
  :root, :host { --color-surface: white; }
  [data-theme="ocean"] { --color-surface: #082f49; }
}
```

`bg-surface` follows the variable wherever it inherits. `padding:1rem@ocean` uses the explicitly authored variant selector.

### System preference with a manual override
The full preset uses native `light-dark()` and `color-scheme`. Choose `data-theme="light"` or `data-theme="dark"` on the root or a nested region; the preset's native stylesheet sets that region's scheme. A custom adaptive token needs only one declaration:

```css
@theme {
  :root, :host { --color-panel: light-dark(white, #111827); }
}
```

Preset `@dark` and `@light` suffixes still test system media preferences. Manual token switching does not activate them. See [Colors](/guide/colors#native-color-scheme-and-manual-themes).

### Local themes and overlap
Local selectors participate in the normal cascade. If themes overlap or nest, selector specificity, layer order and source order decide which declaration wins. Master CSS retains those authored relationships.

### Shadow DOM
Use `:host` explicitly when a theme is intended for a shadow tree. Load the native stylesheet and any keyframes in the tree where they are consumed.

```css
@theme {
  :host { --color-panel: white; }
  :host([data-theme="dark"]) { --color-panel: #111827; }
}
```

## Removed project settings \{#project-settings\}
`@settings` is removed. Use native selectors for scoping, explicit CSS units, and the per-class `!` modifier for importance. Use `@custom-media` for named media conditions; theme variables do not register breakpoint suffixes.

See the [directive contract](/reference/directives/theme) and [RC migration guide](/guide/migration/v2-rc) for the coordinated compiler, runtime and tooling upgrade.
