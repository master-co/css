## Using breakpoints and containers [sr-only]
Responsive layout uses two size scales. `--breakpoint-*` variables define viewport thresholds for page-level changes. `--container-*` variables define container query thresholds and reusable width caps for content and components.

<Overview />

Master CSS includes predefined breakpoint sizes from `4xs` to `4xl` and container sizes from `3xs` to `7xl`. Define or override them in the project CSS entry when your product has a different responsive scale.

```css name=index.css
@theme {
    --breakpoint-md: 1024;
    --container-md: 448;
    --container-4xl: 896;
}
```

For example, `md` can exist in both scales while keeping different meanings:

```html
<!-- @MARK @md -->
<div class="font:3xl@md">...</div>
<!-- @MARK @container(md) -->
<div class="hidden@container(md)">...</div>
<!-- @MARK max-w:md -->
<div class="max-w:md">...</div>
```

---

## Viewport breakpoints
Use `@<name>` to apply styles when the viewport reaches a configured breakpoint. Viewport breakpoints are best for page-level decisions such as navigation mode, shell layout, and major content columns.

<ResponsiveBreakpoints />

```html
<!-- @MARK @md -->
<div class="font:2xl font:3xl@md">…</div>
```

</details>

## Container size variables
Use contextual size values such as `max-w:md`, `w:3xl`, or `flex-basis:lg` when a utility reads from the container namespace. This keeps wrappers, reading widths, panel caps, and reusable component dimensions aligned with the same scale that drives container queries.

<ContainerVariables />

```html
<!-- @MARK max-w:md -->
<div class="max-w:md w:full">…</div>
```

## Container query sizes
Use `@container(<name>)` to apply styles when the nearest container reaches a configured container size. Container query sizes are best for reusable components that may appear in a sidebar, modal, split pane, or full-width page.

<ContainerQuerySizes />

```html
<div class="container">
    <!-- @MARK @container(md) -->
    <div class="grid-cols:1 grid-cols:2@container(md)">…</div>
</div>
```

## Choose viewport or container
Use viewport breakpoints when the whole page changes. Use container queries when a component should adapt to the space it actually receives.

| Decision | Prefer | Example |
| --- | --- | --- |
| Page shell changes | `@md`, `@lg` | Sidebar appears, top nav changes, page grid expands |
| Wrapper width | `max-w:4xl`, `max-w:7xl` | `max-w:7xl mx:auto` |
| Reusable component layout | `@container(md)` | Card changes from stacked to horizontal inside any parent |

(x) A reusable card responds to the viewport even inside a narrow parent.

```html
<article class="grid-cols:1 grid-cols:2@md gap:lg">...</article>
```

(o) The card responds to its own container.

```html
<section class="container">
    <article class="grid-cols:1 grid-cols:2@container(md) gap:lg">...</article>
</section>
```
