## Default color palette [sr-only]

Master CSS provides a P3-compatible raw palette, preset light and dark color aliases, canvas and surface roles, and text hue aliases.

<ColorPalette />

Each preset color family ranges from `0`, `5`, `10`, and then by tens through `100`. Choose a palette step directly for swatches, illustrations, and intentional brand or status accents.

```html
<!-- @MARK bg:blue-5 --><!-- @MARK fg:blue-60 -->
<div class="bg:blue-5 fg:blue-60">…</div>
```

Use palette tokens such as `bg:blue-60` for direct swatches, `bg:canvas` for the page background, `surface:base` or `surface:raised` for UI layers, and text aliases such as `text:blue` or `text:neutral` for readable foreground color.

```html
<!-- @MARK bg:canvas --><!-- @MARK text:neutral --><!-- @MARK surface:base --><!-- @MARK surface:raised -->
<main class="bg:canvas text:neutral">
    <section class="surface:base">
        <button class="surface:raised text:blue">Continue</button>
    </section>
</main>
```

## Preset mode-aware colors
The default preset ships mode-aware aliases for foundational UI color decisions. Palette steps such as `blue-60` stay fixed, while aliases such as `blue`, `text:blue`, `canvas`, and `surface:base` resolve to different preset references in light and dark modes.

`surface:*` is a dedicated surface shorthand backed by `--color-surface-*` tokens. Use `bg:canvas` for the page canvas and `surface:base`, `surface:muted`, `surface:raised`, `surface:overlay`, or `surface:inverse` for UI surfaces.

### Canvas
Canvas is the page or app background role. Use it with the regular background color shorthand.

### Surfaces
Surface tokens are for panels, cards, floating layers, and inverse blocks. Use the dedicated surface shorthand so only surface roles match.

## With variable modes
Use [variable modes](/guide/theme#modes) to define project color roles for light and dark modes. Keep mode-specific decisions in theme variables when a foreground, separator, brand, or status role repeats across the product.

(x) Markup owns the light and dark color choice.

```html
<div class="fg:white@dark fg:black@light">...</div>
```

(o) The theme owns the project-specific role.

```css name=index.css
@theme light {
    --color-text-body: $color-neutral-70;
    --color-line-divider: oklch(0% 0 none / 0.12);
}

@theme dark {
    --color-text-body: $color-gray-30;
    --color-line-divider: oklch(100% 0 none / 0.12);
}
```

```html
<div class="text:body b:1px|solid|divider">...</div>
```

Use conditional color classes when a one-off interaction genuinely differs by mode. For shared product foreground or separator color, prefer a named token that can resolve differently per mode.

## Border and line colors
Preset border and outline colors resolve palette and color tokens by default. The `color-line` namespace is available for project-defined separator roles when borders or outlines need semantic, mode-aware names.

```css name=index.css
@theme light {
    --color-line-divider: oklch(0% 0 none / 0.12);
}

@theme dark {
    --color-line-divider: oklch(100% 0 none / 0.12);
}
```

```html
<div class="b:1px|solid|divider">...</div>
```

Palette border colors are available without adding custom line tokens.

```html
    <!-- @MARK b:3x|solid|gray-20 -->
    <div class="b:3x|solid|gray-20 size:24x"></div>

```

See the [border color](/reference/border-color#use-custom-border-colors) reference for more details on how to add custom border colors.
