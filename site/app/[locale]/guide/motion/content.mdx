## Using animations [sr-only]
[CSS animations](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_animations) interpolate styles over time with [`@keyframes`](https://developer.mozilla.org/en-US/docs/Web/CSS/@keyframes) and animation properties. Master CSS keeps motion close to the element with `animate:` tokens, native `animation:` shorthand syntax, managed `@theme` keyframes, shared duration tokens, shared easing tokens, and conditional queries such as `@motion`.

The default preset provides duration and easing scales plus common animation recipes such as `fade`, `ping`, `pulse`, `rotate`, and `zoom`. Override or add shared animation names and keyframes in your project CSS entry when your product needs different motion decisions.

```css name=index.css
@theme {
    --animate-fade: fade 180ms both;
    --animate-zoom: zoom 300ms both;

    @keyframes fade {
        from { opacity: 0; }
        to { opacity: 1; }
    }

    @keyframes zoom {
        from { transform: scale(.92); opacity: 0; }
        to { transform: scale(1); opacity: 1; }
    }
}
```

```html
<!-- @MARK animation:ping|slow|ease-out|infinite -->
<span class="animation:ping|slow|ease-out|infinite@motion"></span>
```

Use motion foundations to answer three questions:

* What should move? Use a managed keyframe such as `fade`, `pulse`, `zoom`, or your own animation name.
* How long should it take? Use the duration scale from `fastest` to `slowest`.
* How should it move? Use native timing functions or a custom easing token such as `smooth`, `crisp`, or `overshoot`.

## Duration tokens
The `duration` namespace is intentionally named with the `fast` and `slow` families so the token remains readable in shorthands such as `animation:fade|fast|smooth` and `transition:opacity|faster|crisp`. Use duration tokens directly with `animation-duration`:

## Easing tokens
The `easing` namespace only includes custom curves. Native CSS values such as `linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, `step-start`, `step-end`, `steps()`, and `cubic-bezier()` can be written directly when you need them.

```html

<!-- Native CSS timing functions stay native. -->
<div class="animation:fade|slow|ease-in-out"></div>
<div class="animation:fade|slow|steps(4,end)"></div>
```

## Namespace for motion
The `duration` and `easing` variable namespaces are shared across related rules:
<MotionHeirs />
This lets animation and transition use the same motion language without writing the `duration-` or `easing-` prefix in markup. Master CSS ships duration and easing defaults; add extra duration tokens when your product needs named delay decisions.

```css name=index.css
@theme {
    --duration-fast: 150ms;
    --duration-slow: 300ms;
    --duration-slower: 500ms;
    --duration-stagger: 120ms;
    --easing-smooth: cubic-bezier(.4,0,.2,1);
    --easing-crisp: cubic-bezier(.16,1,.3,1);
}
```

Apply the custom motion tokens in your markup:
```html
<!-- @MARK animation-duration:fast --><!-- @MARK animation-timing-function:smooth --><!-- @MARK transition:opacity|fast|crisp -->
<div class="animation-duration:fast animation-timing-function:smooth transition-delay:stagger transition:opacity|fast|crisp">...</div>
```

## Use animation shorthands
Use the `animation:` shorthand when the animation name, duration, easing, direction, iteration count, fill mode, or delay should travel together.

```html
<!-- @MARK animation:fade|fast|smooth -->
<div class="animation:fade|fast|smooth"></div>
<!-- @MARK animation:rotate|slowest|linear|infinite -->
<svg class="animation:rotate|slowest|linear|infinite@motion">...</svg>
<!-- @MARK animation:zoom|faster|overshoot|both -->
<div class="animation:zoom|faster|overshoot|both"></div>
```

## Use transition shorthands
Use the `transition:` shorthand for transitions. The property, duration, easing, and delay will travel together, but the transition only runs on state change instead of automatically like an animation.
```html
<!-- @MARK transition:opacity|fast|smooth -->
<div class="transition:opacity|fast|smooth">...</div>
<!-- @MARK transition:transform|slow|overshoot|150ms -->
<div class="transition:transform|slow|overshoot|150ms">...</div>
```

## Use motion conditions
Use `@motion` for non-essential motion so it only runs when the user has not asked the system to reduce motion.

```html
<!-- @MARK @motion -->
<div class="animation:pulse|slowest|ease-in-out|infinite@motion"></div>
```

Use `@reduce-motion` to replace motion-heavy effects with a simpler state.

```html
<!-- @MARK animation-duration:fast@motion --><!-- @MARK opacity:1@reduce-motion -->
<div class="animation:fade|fast|smooth@motion opacity:1@reduce-motion"></div>
```

## Customize motion tokens
Override motion tokens in the project CSS entry when your product needs a different rhythm. Keep duration and easing keys distinct because the namespaces are shared by animation and transition utilities.

```css name=index.css
@theme {
    --duration-fast: 120ms;
    --duration-slow: 280ms;
    --duration-slowest: 700ms;
    --duration-stagger: 120ms;
    --easing-smooth: cubic-bezier(.4,0,.2,1);
    --easing-crisp: cubic-bezier(.2,0,0,1);
}
```

```html
<!-- @MARK animation:fade|fast|smooth --><!-- @MARK transition:opacity|fast|crisp -->
<div class="animation:fade|fast|smooth transition:opacity|fast|crisp"></div>
```

Avoid adding easing tokens named `fast`, `slow`, or `slowest`; those names belong to duration. Avoid adding duration tokens named `smooth`, `crisp`, or `overshoot`; those names belong to easing.
