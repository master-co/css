This Styled Components migration guide is being rebuilt. Use the [quick start](/guide/migration) to direct your local coding agent, then ask it to inspect component styling before changing code.

## Inspect first
- `styled.*` declarations, `css` helper usage, and transient prop variants.
- Theme providers, global styles, shared style fragments, and polymorphic components.
- Components where markup classes would be clearer than generated styled wrappers.
- Dynamic styles that should stay in component logic until there is a simpler Master CSS form.
