## Overview [sr-only]
Your theme is the shared design vocabulary for a Master CSS project. It defines the values your markup reaches for every day: color roles, spacing, type, radius, shadows, motion, breakpoints, container sizes, mode-specific values, named conditions, and shared selector aliases.

In Master CSS, that vocabulary usually lives in the project CSS entry: `@theme` for tokens and modes, `@settings` for project settings, `@custom-at` for named conditions, and `@custom-selector` for selector shortcuts. The file still feels like CSS, while markup keeps using short semantic classes.

```css name=index.css
@import '@master/css';

@theme {
    --color-primary: #4f46e5;
    --color-surface: #ffffff;
    --spacing-card: 24;
    --border-radius-card: 16;
    --shadow-card: 0 16px 40px rgb(15 23 42 / .12);
    --breakpoint-md: 768;
    --container-md: 448;
}

@custom-at motion-safe @media (prefers-reduced-motion: no-preference);
@custom-selector :interactive :is(:hover, :focus-visible);
```

```html
<section class="bg:surface fg:strong p:card r:card shadow:card grid-cols:2@md">
    <button class="bg:primary fg:white px:md py:xs r:md fg:primary:interactive">Save</button>
</section>
```

The `@theme`, `@settings`, `@custom-at`, and `@custom-selector` directives are configuration, not regular stylesheet output. Master CSS resolves them first, then generates only the variables, utilities, components, and keyframes that the application actually uses.

---

## Project CSS entry
A project only needs a CSS entry that marks the Master CSS graph. Put theme directives in the stylesheet that imports `@master/css`, or in CSS already imported by that entry.

```css name=index.css
@import '@master/css';

@theme {
    --color-primary: #4f46e5;
}
```

The important part is the graph, not a special file name. Tokens, modes, motion, named conditions, and selector shortcuts can live wherever the project CSS entry already reaches them.

## Theme tokens
Theme tokens are native custom properties inside `@theme` blocks. Their prefixes place them in the namespace that Master CSS utilities already understand.

### Define tokens
```css name=index.css
@theme {
    --content-hash: " #";
    --color-primary: #4f46e5;
    --color-primary-soft: rgb(79 70 229 / .16);
    --color-surface: #ffffff;
    --color-text-strong: #111827;
    --spacing-card: 24;
    --font-family-sans: Inter, ui-sans-serif, system-ui, sans-serif;
    --border-radius-card: 16;
    --shadow-card: 0 16px 40px rgb(15 23 42 / .12);
    --breakpoint-md: 768;
    --container-md: 448;
}
```

### How namespaces are resolved
A theme token name has the shape `--<namespace>-<key>`. Master CSS resolves the namespace by longest prefix, so `--color-line-lightest` belongs to `color-line`, not `color`.

Namespaces come from three places:

* `breakpoint` is built in because viewport query suffixes such as `@md` need to resolve `--breakpoint-md`.
* Utilities can declare shared namespaces. For example, border and outline color utilities search `color-line` before `color`, while spacing utilities search `spacing`.
* Each non-static, non-function utility name is also a namespace. This is why `--animation-duration-fast`, `--line-height-body`, and `--tab-size-code` can be used as `animation-duration:fast`, `line-height:body`, and `tab-size:code`.

Function utilities do not become namespaces by name. Tokens such as `--blur-sm`, `--drop-shadow-soft`, and `--perspective-near` are ordinary custom properties unless a utility explicitly owns that namespace.

```css name=index.css
@theme {
    --animation-duration-fast: 120ms;
    --line-height-body: 1.6;
    --tab-size-code: 4;
}
```

```html
<pre class="animation-duration:fast line-height:body tab-size:code">...</pre>
```

### Use contextual tokens
The same short token can resolve differently by context. `primary` is a color in `bg:primary`, `card` is spacing in `p:card`, radius in `r:card`, and shadow in `shadow:card`.

```html
<!-- @MARK bg:surface --><!-- @MARK p:card --><!-- @MARK r:card --><!-- @MARK font:sans -->
<article class="bg:surface fg:strong p:card r:card shadow:card font:sans">
    <h2 class="font:sans">Dashboard</h2>
    <a class="fg:primary" href="/settings">Settings</a>
</article>
```

### Alias and override tokens
Use `$` when a token should reference another token.

```css name=index.css
@theme {
    --color-brand: #4f46e5;
    --color-primary: $color-brand;
    --color-primary-soft: $color-brand/.16;
}
```

Define the same token key as a preset token when you want to override it. Later definitions in the project CSS graph win.

```css name=index.css
@theme {
    --color-blue: #4589ff;
}
```

### Breakpoint and container tokens
Responsive thresholds are theme tokens too. Define `breakpoint` variables for viewport at-rule suffixes, and define `container` variables for container query thresholds and width caps.

```css name=index.css
@theme {
    --breakpoint-sm: 640;
    --breakpoint-md: 768;
    --breakpoint-lg: 1024;

    --container-sm: 384;
    --container-md: 448;
    --container-lg: 512;
}
```

```html
<div class="grid-cols:1 grid-cols:2@md grid-cols:3@lg gap:md">
    ...
</div>

<aside class="container max-w:lg">
    <article class="grid-cols:1 grid-cols:2@container(md)">
        ...
    </article>
</aside>
```

Keep breakpoint tokens broad and product-wide. Use container tokens when a reusable component should respond to the space it receives. Use raw media or container syntax only when the condition belongs to one local component. See [Breakpoints](/guide/breakpoints) and [Containers](/guide/containers) for the responsive scales.

For token strategy and naming discipline, use [Design Tokens](/guide/design-tokens). For the exact color, spacing, typography, radius, elevation, motion, breakpoint, and container scales, continue into the foundation guides.

## Modes
Modes let one token name adapt across light, dark, high-contrast, or product-specific themes.

### Define mode values
Mode-specific `@theme` blocks keep markup semantic while values change by mode.

```css name=index.css
@theme light {
    --color-surface: #ffffff;
    --color-text-strong: #111827;
    --color-primary: #4f46e5;
}

@theme dark {
    --color-surface: #111827;
    --color-text-strong: #f9fafb;
    --color-primary: #818cf8;
}

@theme brand {
    --color-primary: #ff0;
}
```

```html
<section class="bg:surface fg:strong">
    <button class="bg:primary fg:white">Save</button>
</section>
```

`light` and `dark` are always available. Defining another mode adds it to the theme automatically. When a token has mode-specific values, Master CSS emits a CSS custom property in the theme layer and generated utilities reference that property.

### Choose a mode trigger
Most projects leave light and dark mode behavior system-driven:

```css name=index.css
@settings {
    default-mode: light;
    mode-trigger: media;
}
```

| Trigger | Output behavior |
|---------|-----------------|
| `media` | Uses `@media (prefers-color-scheme: <mode>)` for light and dark modes. |
| `class` | Uses class wrappers such as `.dark &`. |
| `host` | Uses shadow host wrappers such as `:host(.dark) &`. |

`default-mode` controls which class-triggered mode also attaches to `:root`. Set `default-mode: none;` when no mode should be applied by default. It has no effect with `mode-trigger: media`, because the browser decides the active color scheme from user or system preferences.

### Switch modes manually
Use `mode-trigger: class` when your app switches modes manually. Put the active mode class on `<html>` and keep `color-scheme` in sync.

```html
<!-- @MARK dark -->
<html class="dark">
    <body>
        <div class="bg:surface fg:strong">...</div>
    </body>
</html>
```

```js
const key = 'theme-preference'
const preference = localStorage.getItem(key) || 'system'
const value = preference === 'system'
    ? matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
    : preference

document.documentElement.classList.add(value)
document.documentElement.style.colorScheme = value
```

## Named conditions and selectors
Named conditions and selector shortcuts belong in the theme when they become shared product vocabulary. Use them to keep repeated media queries, support checks, container queries, and selectors out of markup.

### At tokens
Native CSS cannot store full `@media`, `@supports`, or `@container` rules in CSS variables. Master CSS uses `@custom-at` to name those reusable conditions.

```css name=index.css
@custom-at motion-safe @media (prefers-reduced-motion: no-preference);
@custom-at supports-backdrop @supports (backdrop-filter: blur(0));
@custom-at card-wide @container card (width >= 42rem);
@custom-at start @starting-style;
```

The token name is written without a leading `@` in the definition. Use the token as an `@` suffix in markup:

```html
<!-- @MARK @motion-safe --><!-- @MARK @supports-backdrop -->
<div class="animation:fade-in|fast@motion-safe bg:white/.8@supports-backdrop">
    ...
</div>
```

### At tokens in CSS rules
Inside managed definitions and native style rules, use `@at` blocks instead of putting conditional suffixes inside `@compose`.

```css name=index.css
@custom-at motion-safe @media (prefers-reduced-motion: no-preference);

@layer components {
    .card {
        @compose "p:md r:xl";

        @at motion-safe {
            @compose "animation:fade-in|fast";
        }

        @at <sm {
            @compose "block";
        }
    }
}
```

`@at` accepts custom at tokens, breakpoint tokens such as `md`, mode names such as `dark`, and raw Master CSS at syntax such as `<sm`.

### Selector tokens
Selector tokens name selectors that repeat across markup or CSS-defined styles. Define them with `@custom-selector`.

```css name=index.css
@custom-selector :headings :is(h1, h2, h3, h4, h5, h6);
@custom-selector :interactive :is(:hover, :focus-visible);
@custom-selector ::scrollbar ::-webkit-scrollbar;
```

Use selector tokens anywhere Master CSS accepts a selector suffix:

```html
<!-- @MARK :headings --><!-- @MARK :interactive --><!-- @MARK ::scrollbar -->
<article class="font:semibold_:headings">
    <button class="fg:primary:interactive">Save</button>
    <div class="w:.5rem::scrollbar">...</div>
</article>
```

### Selector tokens in CSS rules
Inside CSS-defined style rules, prefer native nested selectors instead of putting selector suffixes inside `@compose`.

```css name=index.css
@custom-selector :interactive :is(:hover, :focus-visible);

@layer components {
    .btn {
        @compose "inline-flex ai:center jc:center";

        &:interactive {
            @compose "fg:primary";
        }
    }
}
```

### Naming rules
Breakpoint variables automatically create at tokens such as `@md`, and modes automatically create at tokens such as `@dark`. Custom at token names cannot start with `@`, `:`, or `::`, and cannot conflict with breakpoint or mode names.

Selector token names must start with `:` or `::`. Names that look like conditions belong in `@custom-at`, not `@custom-selector`.

## Motion
Motion belongs in the theme when timing, easing, and keyframes are shared by more than one surface.

```css name=index.css
@theme {
    --duration-fast: 150ms;
    --duration-slow: 300ms;
    --easing-smooth: cubic-bezier(.4, 0, .2, 1);
}

@custom-at motion-safe @media (prefers-reduced-motion: no-preference);

@keyframes fade-in {
    from {
        opacity: 0;
        transform: translateY(.25rem);
    }

    to {
        opacity: 1;
        transform: translateY(0);
    }
}
```

```html
<div class="animation:fade-in|slow|smooth@motion-safe">
    ...
</div>
```

Keyframes are emitted outside cascade layers, while animation utilities still generate in the utilities layer. For the complete animation syntax, see [Animation](/reference/animation).

## Project settings
Most theme work is tokens, but a few root settings shape every generated rule. Keep those settings in `@settings` and change them only when the project has a clear convention.

```css name=index.css
@settings {
    root-size: 16;
    base-unit: 4;
    scope: #app;
}
```

`root-size` controls how numeric values convert to `rem` and `em`. `base-unit` controls multiplier units such as `1x`, `2x`, and `4x`. `scope` prefixes generated selectors when Master CSS should only style a specific application root.

```html
<div id="app">
    <button class="p:4x font:16">Save</button>
</div>
```

You do not need to set these in every project. Treat them as theme-level defaults, not a list of options to fill out.

For the complete settings syntax, see [CSS directives](/reference/directives#settings).

## Style patterns
The theme should describe shared values and named conditions. Reusable UI patterns can live next to it, but they have a different job.

```css name=components.css
@layer components {
    .btn {
        @compose "inline-flex ai:center jc:center gap:xs px:md py:xs r:md font:sm font:medium";
        background: var(--color-primary);
        color: white;

        &:disabled {
            @compose "opacity:.55 pointer-events:none";
        }
    }
}
```

```html
<button class="btn">Save changes</button>
```

Use [Reusing Styles](/guide/reusing-styles) for abstraction strategy, [component classes](/guide/reusing-styles#component-classes) for semantic UI classes, and [custom utilities](/guide/reusing-styles#create-custom-utilities) for low-level project primitives.
