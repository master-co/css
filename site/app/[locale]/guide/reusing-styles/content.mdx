## Overview [sr-only]
As the styles grow, the class name combinations and the same design patterns appear over and over again in the code. To improve development efficiency and maintain design consistency, you should reuse or access them in some way.

Traditionally, we define components like `.btn` or `.card` by writing CSS rules. In Master CSS, define reusable styles in `@master` so they become config-backed, on-demand component classes. This guide focuses on the strategy of when to abstract; for the full configuration surface, start with [CSS Configuration](/guide/configuration), and for exact component behavior, see [Components](/guide/components).
```css name=master.css
@master {
    .btn {
        display: inline-flex;
        font-weight: 600;
    }

    .btn-sm {
        border-radius: 0.375rem;
        padding-left: 0.75rem;
        padding-right: 0.75rem;
        font-size: 0.75rem;
        height: 2rem;
    }

    .btn-md {
        border-radius: 0.375rem;
        padding-left: 1rem;
        padding-right: 1rem;
        font-size: 0.875rem;
        height: 2.5rem;
    }
}
```
An abstract style consists of one or more declarations. You can provide a class name for this set of declarations and reuse it anywhere.

## Creating Components
Master CSS introduces a concise syntax system for defining abstract, reusable styles called components. These components encapsulate styling logic that can be applied directly to HTML elements, enabling consistent design patterns, improved maintainability, and scalable UI development across your project.

### Add a style
Create an abstract style using Master CSS syntaxes.

### Add a style with states
Create an abstract style with [state selectors](/guide/state-selectors) and [conditional queries](/guide/conditional-queries).
```css name=master.css
@master {
    .btn:focus {
        outline: 0.125rem var(--color-invert) solid;
        outline-offset: 0.125rem;
    }
}
```

### Add styles in a nested structure
Create and manage a set of abstract styles for a shared structure. Keep each generated class explicit so markup, output, and config stay easy to trace.
```css name=master.css
@master {
    .card {
        border-radius: 0.5rem;
    }

    .card-header {
        border-bottom: 0.0625rem solid oklch(0% 0 none);
    }

    .card-content {
        padding: 1.25rem;
    }

    .card-footer {
        border-top: 0.0625rem solid oklch(0% 0 none);
    }
}
```

### Create button styles
Let's implement a rich button.
```css name=styles/button.css
@master {
    .btn {
        @compose "inline-flex ai:center jc:center";
        font-weight: 600;
        outline-offset: -0.0625rem;
    }

    .btn-xs {
        @compose "r:sm px:xs font:xs h:6x";
    }

    .btn-sm {
        @compose "r:md px:sm font:xs h:8x";
    }

    .btn-md {
        @compose "r:md px:md font:sm h:10x";
    }

    .btn-lg {
        @compose "r:lg px:lg font:md h:12x";
    }

    .btn-xl {
        @compose "r:xl px:lg font:md h:14x";
    }
}
```
Import component files from the CSS config entry.
```css name=master.css
@import './styles/button.css';
```

### Create common variables and styles
We define [variables and modes](/guide/variables-and-modes) to create tokens supporting light/dark modes in advance. This not only simplifies template markup but also reduces CSS rule output.
```css name=styles/base.css
@master {
    light {
        --color-yellow-ring: $(color-black/.1);
        --color-touch-yellow: $(color-yellow-30);
        --color-text-yellow-contrast: $(color-yellow-90);
    }

    dark {
        --color-yellow-ring: $(color-white/.3);
        --color-touch-yellow: $(color-yellow-40);
        --color-text-yellow-contrast: $(color-yellow-95);
    }

    .yellow {
        outline: 0.0625rem var(--color-yellow-ring) solid;
        background-color: var(--color-yellow);
        color: var(--color-text-yellow-contrast);
    }

    .touch-yellow:hover {
        background-color: var(--color-touch-yellow);
    }
}
```
- Variables
    - `yellow-ring` is an outline color that complements a yellow background.
    - `touch-yellow` is a background color on hover.
    - `text-yellow-contrast` is a contrasting color fine-tuned against a yellow background.
- Components
    - `.yellow` sets a background, foreground and outline style for a yellow theme.
    - `.yellow-touch` sets a background, foreground and outline style for a yellow theme interaction.

## Summary

- Moderately abstracting styles make design easier to manage and maintain consistency, but it doesn't mean that all styles should be abstracted.
- Only abstract styles that have the potential for reuse, rather than naming them simply for brevity or naming's sake.
- Keep utilities for primitives and one-off layout decisions; move repeated UI patterns into components when the class name becomes a product concept.
- A good CSS structure combines abstract classes and utility classes — don’t get hung up on specific approaches.
