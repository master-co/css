## Overview [sr-only]
Elevation creates perceived depth between surfaces. In CSS, that depth is usually expressed with [box-shadow](https://developer.mozilla.org/en-US/docs/Web/CSS/box-shadow), but the design decision is larger than the property: elevation tells users which surface is resting on the page, which surface is floating, and which surface is interrupting the workflow.

Master CSS maps elevation to the `shadow` namespace. Use tokens such as `shadow:xs`, `shadow:sm`, and `shadow:lg` for product surfaces instead of repeating raw multi-part shadow values in markup.

## Define shadow variables
Elevation tokens live in the theme layer as `--shadow-*` variables. The default scale runs from `xs` to `2xl`; each step increases offset, blur, and opacity while staying practical for application UI.

```css name=index.css
@theme {
    --shadow-xs: 0 1px 2px oklch(0% 0 none / .08);
    --shadow-sm: 0 1px 2px oklch(0% 0 none / .06), 0 2px 4px oklch(0% 0 none / .06);
    --shadow-md: 0 2px 4px -1px oklch(0% 0 none / .08), 0 6px 12px -2px oklch(0% 0 none / .08);
}
```

Keep the token names size-based. A token such as `shadow:popover` can be useful for a product-specific role, but the foundation scale should stay portable across cards, menus, drawers, and dialogs.

---

## Use shadow tokens
Use `shadow:<token>` for the common elevation levels. The utility resolves values from the `--shadow-*` variables.

```html
<!-- @MARK shadow:sm -->
<article class="bg:base r:lg b:1|lightest shadow:sm">
    ...
</article>

<!-- @MARK shadow:lg -->
<div class="bg:base r:lg b:1|lightest shadow:lg">
    ...
</div>
```

<details>
    <summary>Generated CSS</summary>

Use `shadow:*` in product markup. Use the more explicit `box-shadow:*` form when the page is teaching native property mapping or when the surrounding code benefits from the native property name.

## Elevation scale
Choose the lowest token that makes the surface relationship clear. More shadow is not more hierarchy if every surface is elevated.

<ShadowTokens />

| Surface role | Recommended token | Notes |
| --- | --- | --- |
| Quiet separation | `shadow:xs` | Small controls, table rows, subtle raised states |
| Standard card | `shadow:sm` | Default surface elevation for reusable cards and panels |
| Temporary lift | `shadow:md` | Hover lift, floating toolbars, command surfaces |
| Detached overlay | `shadow:lg` | Dropdowns, popovers, toasts, menus |
| Workflow interruption | `shadow:xl` | Drawers, dialogs, focused panels |
| Blocking layer | `shadow:2xl` | Modals and spotlight surfaces above a dimmed page |

The scale should describe the relationship between surfaces, not the visual drama of a single element.

---

## Build surfaces, not shadows
Elevation only works when the surface has a clear ground. Pair shadows with background, border, and radius tokens so low elevations remain visible in both light and dark themes.

```html
<!-- @MARK bg:surface --><!-- @MARK b:1|lightest --><!-- @MARK r:lg --><!-- @MARK shadow:sm -->
<article class="bg:surface b:1|lightest r:lg shadow:sm p:lg">
    ...
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['bg:surface', 'b:1|lightest', 'r:lg', 'shadow:sm', 'p:lg']}
    </Class2CSS>
</details>

Use borders for edges and shadows for separation. A low shadow without a border can disappear on light backgrounds; a high shadow without a clear background can make the layout feel muddy.

## Change elevation by state
State changes should communicate interaction, not decoration. A hover shadow can make a card feel liftable; a focus shadow should not replace an accessible focus indicator.

```html
<!-- @MARK shadow:sm --><!-- @MARK shadow:md:hover --><!-- @MARK shadow:none@print -->
<article class="shadow:sm shadow:md:hover shadow:none@print">
    ...
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['shadow:sm', 'shadow:md:hover', 'shadow:none@print']}
    </Class2CSS>
</details>

Keep state elevation small. Moving from `shadow:sm` to `shadow:md` is usually enough for hover. Jumping from `shadow:sm` to `shadow:2xl` makes a normal card feel like a modal.

## Customize the scale
Override shadow variables when your product needs softer depth, sharper enterprise surfaces, or a stronger overlay system. Keep the same progression so existing markup remains meaningful.

```css name=index.css
@theme {
    --shadow-xs: 0 1px 1px oklch(0% 0 none / .06);
    --shadow-sm: 0 2px 4px oklch(0% 0 none / .08);
    --shadow-md: 0 6px 16px oklch(0% 0 none / .10);
    --shadow-lg: 0 12px 32px oklch(0% 0 none / .12);
    --shadow-xl: 0 20px 48px oklch(0% 0 none / .14);
    --shadow-2xl: 0 32px 80px oklch(0% 0 none / .18);
}
```

Promote repeated raw values into the scale. Keep one-off art direction in local markup or component CSS until it proves reusable.

## Avoid elevation noise
(x) Every panel competes for depth.

```html
<main class="shadow:lg">
    <section class="shadow:xl">
        <article class="shadow:2xl">...</article>
    </section>
</main>
```

(o) Only the surfaces that need separation are elevated.

```html
<main class="bg:base">
    <section class="bg:surface b:1|lightest">
        <article class="bg:base b:1|lightest shadow:sm">...</article>
    </section>
</main>
```

(x) Raw shadows become repeated product decisions without a name.

```html
<article class="shadow:0|4px|12px|black/.12">...</article>
<aside class="shadow:0|4px|12px|black/.12">...</aside>
```

(o) Repeated decisions become shadow tokens.

```css name=index.css
@theme {
    --shadow-popover: 0 4px 8px -2px oklch(0% 0 none / .08), 0 12px 24px -4px oklch(0% 0 none / .10);
}
```

```html
<aside class="shadow:popover">...</aside>
```
