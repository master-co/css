## Overview [sr-only]
Elevation creates perceived depth between surfaces. In CSS, that depth is usually expressed with [box-shadow](https://developer.mozilla.org/en-US/docs/Web/CSS/box-shadow), but the design decision is larger than the property: elevation tells users which surface is resting on the page, which surface is floating, and which surface is interrupting the workflow.

Master CSS maps elevation to the `shadow` namespace. Use tokens such as `shadow:xs`, `shadow:sm`, and `shadow:lg` for product surfaces instead of repeating raw multi-part shadow values in markup. The preset shadow scale is mode-aware: the same class resolves to a lighter shadow recipe in light mode and a stronger dark-mode recipe with a subtle edge highlight.

## Define mode-aware shadow variables
Elevation tokens live in the theme layer as `shadow-*` tokens. The default scale runs from `xs` to `2xl`; each step increases offset, blur, and opacity while staying practical for application UI. The preset defines the same token keys in `@theme light` and `@theme dark`, so markup stays stable while the active mode changes the value.

<ShadowTokens />

Use the same token names across modes:

```css name=index.css
@theme light {
    --shadow-sm: 0 1px 2px -1px oklch(0% 0 none / .06), 0 3px 6px -2px oklch(0% 0 none / .08);
    --shadow-lg: 0 4px 8px -4px oklch(0% 0 none / .08), 0 16px 32px -8px oklch(0% 0 none / .12);
}

@theme dark {
    --shadow-sm: 0 0 0 1px oklch(100% 0 none / .06), 0 1px 2px -1px oklch(0% 0 none / .34), 0 3px 6px -2px oklch(0% 0 none / .26);
    --shadow-lg: 0 0 0 1px oklch(100% 0 none / .08), 0 4px 8px -4px oklch(0% 0 none / .42), 0 16px 32px -8px oklch(0% 0 none / .34);
}
```

Keep token names size-based and mode-neutral. Avoid names like `shadow:dark-lg`; define the same key in `@theme light` and `@theme dark` so existing markup remains stable.

## Use shadow tokens
Use `shadow:<token>` for the common elevation levels. The utility resolves values from the `shadow-*` tokens and emits a stable `box-shadow: var(--shadow-*)` declaration. The variable value changes with the active mode.

```html
<!-- @MARK shadow:sm -->
<article class="surface:base r:lg b:1px|solid|base shadow:sm">
    ...
</article>

<!-- @MARK shadow:lg -->
<div class="surface:base r:lg b:1px|solid|base shadow:lg">
    ...
</div>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['shadow:sm', 'shadow:lg']}
    </Class2CSS>
</details>

Use `shadow:*` in product markup. Use the more explicit `box-shadow:*` form when the page is teaching native property mapping or when the surrounding code benefits from the native property name.

## Elevation scale
Choose the lowest token that makes the surface relationship clear. More shadow is not more hierarchy if every surface is elevated.

| Surface role | Recommended token | Notes |
| --- | --- | --- |
| Quiet separation | `shadow:xs` | Small controls, table rows, subtle raised states |
| Standard card | `shadow:sm` | Default surface elevation for reusable cards and panels |
| Temporary lift | `shadow:md` | Hover lift, floating toolbars, command surfaces |
| Detached overlay | `shadow:lg` | Dropdowns, popovers, toasts, menus |
| Workflow interruption | `shadow:xl` | Drawers, dialogs, focused panels |
| Blocking layer | `shadow:2xl` | Modals and spotlight surfaces above a dimmed page |

The scale should describe the relationship between surfaces, not the visual drama of a single element. Because light and dark modes share token keys, the role of each step should stay the same in both modes even when the shadow recipe changes.

## Build surfaces, not shadows
Elevation only works when the surface has a clear ground. Pair shadows with background, border, and radius tokens so low elevations remain visible in both light and dark themes. Dark-mode shadows often need a subtle light edge in addition to darker depth layers, so do not judge a token from only one mode.

```html
<!-- @MARK surface:base --><!-- @MARK b:1px|solid|base --><!-- @MARK r:lg --><!-- @MARK shadow:sm -->
<article class="surface:base b:1px|solid|base r:lg shadow:sm p:lg">
    ...
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['r:lg', 'shadow:sm', 'p:lg']}
    </Class2CSS>
</details>

Use borders for edges and shadows for separation. A low shadow without a border can disappear on light backgrounds; in dark mode, the edge highlight in the shadow helps but should still be paired with surface and line tokens for clear structure.

## Change elevation by state
State changes should communicate interaction, not decoration. A hover shadow can make a card feel liftable; a focus shadow should not replace an accessible focus indicator.

```html
<!-- @MARK shadow:sm --><!-- @MARK shadow:md:hover --><!-- @MARK shadow:none@print -->
<article class="shadow:sm shadow:md:hover shadow:none@print">
    ...
</article>
```

<details>
    <summary>Generated CSS</summary>
    <Class2CSS>
        {['shadow:sm', 'shadow:md:hover', 'shadow:none@print']}
    </Class2CSS>
</details>

Keep state elevation small. Moving from `shadow:sm` to `shadow:md` is usually enough for hover. Jumping from `shadow:sm` to `shadow:2xl` makes a normal card feel like a modal.

## Customize the scale
Override shadow variables when your product needs softer depth, sharper enterprise surfaces, or a stronger overlay system. Customize light and dark values together so the same `shadow:*` classes preserve their meaning across modes.

```css name=index.css
@theme light {
    --shadow-sm: 0 2px 4px -2px oklch(0% 0 none / .08), 0 8px 20px -6px oklch(0% 0 none / .12);
    --shadow-lg: 0 10px 20px -8px oklch(0% 0 none / .12), 0 24px 56px -16px oklch(0% 0 none / .16);
}

@theme dark {
    --shadow-sm: 0 0 0 1px oklch(100% 0 none / .06), 0 2px 8px -4px oklch(0% 0 none / .36);
    --shadow-lg: 0 0 0 1px oklch(100% 0 none / .09), 0 12px 28px -10px oklch(0% 0 none / .48), 0 28px 64px -18px oklch(0% 0 none / .40);
}
```

Promote repeated raw values into the scale. Keep one-off art direction in local markup or component CSS until it proves reusable. If a one-off raw shadow must differ by mode, prefer promoting it to a token instead of duplicating conditional raw values in markup.

## Avoid elevation noise
(x) Every panel competes for depth.

```html
<main class="shadow:lg">
    <section class="shadow:xl">
        <article class="shadow:2xl">...</article>
    </section>
</main>
```

(o) Only the surfaces that need separation are elevated.

```html
<main class="bg:canvas">
    <section class="surface:base b:1px|solid|base">
        <article class="surface:base b:1px|solid|base shadow:sm">...</article>
    </section>
</main>
```

(x) Raw shadows become repeated product decisions without a name.

```html
<article class="shadow:0|4px|12px|black/.12">...</article>
<aside class="shadow:0|4px|12px|black/.12">...</aside>
```

(o) Repeated decisions override a shadow scale token.

```css name=index.css
@theme light {
    --shadow-sm: 0 4px 8px -2px oklch(0% 0 none / .08), 0 12px 24px -4px oklch(0% 0 none / .10);
}

@theme dark {
    --shadow-sm: 0 0 0 1px oklch(100% 0 none / .08), 0 8px 18px -8px oklch(0% 0 none / .44), 0 18px 40px -12px oklch(0% 0 none / .36);
}
```

```html
<aside class="shadow:sm">...</aside>
```
