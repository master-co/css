## Features
### Consistent class order
In practice, you pay less attention to the order of classes, and as the number of classes increases, the template markup becomes less readable.

(i) With the [class order rule](/reference/eslint#class-order), you can enforce a consistent and fixed order for classes.
<Image className="aspect-ratio:2/1 r:lg max-w:3xl w:full" src={require('~/site/public/consistent-class-order.webp').default} alt="Consistent class order" unoptimized />

(!) <span className="text:amber">No consistent class order followed.</span>
```html
<div class="font:xs font:2xl@sm m:xl block font:3xl@md mb:2xl">…</div>
```
(o) Fix this @master/css/class-order problem.
```html
<div class="block font:xs font:2xl@sm font:3xl@md m:xl mb:2xl">…</div>
```

### Syntax error checks
In the past, you added utility classes to your templates unsafely, lacking the capability to verify their validity or legality directly within the source code.

(i) With the [class validation rule](/reference/eslint#class-order), you can check the validity of classes early as you write them.
<Image className="aspect-ratio:2/1 r:lg max-w:3xl w:full" src={require('~/site/public/syntax-error-checks.webp').default} alt="Syntax error checks" unoptimized />

(x) <span className="text:error">Invalid value for \`font\` property.</span>
```html
<!-- @MARK font: -->
<div class="font:">…</div>
```
This is helpful if you make a typo or are unfamiliar with Master CSS syntax!

### Disallow unknown classes
You can also restrict teams to using [theme](/guide/theme) and [component classes](/guide/reusing-styles#component-classes) instead of defining classes through traditional `html <style>` or CSS files.

(i) Based on syntax error checking, you can [disallow unknown classes](/reference/eslint#class-validation).
<Image className="aspect-ratio:2/1 r:lg max-w:3xl w:full" src={require('~/site/public/disallow-unknown-class.webp').default} alt="Disallow unknown classes" unoptimized />

(x) <span className="text:error">"btn" is not a valid or known class.</span>
```html
<!-- @MARK btn -->
<button class="btn">…</button>
```
(o) Fix this @master/css/class-validation problem using the Master CSS syntax.
```html
<button class="inline-flex pi:md">…</button>
```
(o) Or create the custom style `btn` using [component classes](/guide/reusing-styles#component-classes) in the project CSS entry.
```css name=index.css
@components {
    btn {
        @compose inline-flex pi:md; /* [!code highlight] */
    }
}
```
Archive and see the changes.
```html
<button class="btn">…</button>
```

### Class collision detection
The class you added may collide with existing classes due to human error or having the same declarations as a third-party custom syntax.

(i) With the [class collision rule](/reference/eslint#class-collision), you'll no longer collide with existing classes.
<Image className="aspect-ratio:2/1 r:lg max-w:3xl w:full" src={require('~/site/public/class-collision-detection.webp').default} alt="Class collision detection" unoptimized />

(!) <span className="text:amber">"m:0.625rem" applies the same CSS declarations as "m:5x".</span><br/><span className="text:amber">"m:5x" applies the same CSS declarations as "m:0.625rem".</span>
```html
<!-- @MARK m:0.625rem m:5x -->
<div class="m:0.625rem m:5x">…</div>
```
(o) Fix this @master/css/class-collision problem by removing other colliding classes.
```html
<div class="m:0.625rem">…</div>
```
It can also detect whether declarations with the same selector and media query state collide!

(!) <span className="text:amber">"m:10x@sm" applies the same CSS declarations as "m:3.125rem@sm".</span><br/><span className="text:amber">"m:3.125rem@sm" applies the same CSS declarations as "m:10x@sm".</span>
```html
<!-- @MARK m:10x@sm m:3.125rem@sm -->
<div class="m:10x@sm m:3.125rem@sm">…</div>
```
(o) Fix this @master/css/class-collision problem by removing other colliding classes.
```html
<!-- @MARK m:3.125rem@sm -->
<div class="m:3.125rem@sm">…</div>
```

### Supports JS utilities
You may be using [clsx](https://github.com/lukeed/clsx) or [class variant](https://github.com/master-co/styled) to conditionally apply classes, but unfortunately, they're just pure strings in JavaScript.

(i) You can make arguments of JavaScript [callees](/reference/eslint#calleematching) have Master CSS code linting.
<Image className="aspect-ratio:2/1 r:lg max-w:3xl w:full" src={require('~/site/public/supports-js-utilities.webp').default} alt="Supports JS utilities" unoptimized />

(x) <span className="text:error">Invalid value for `display` property.</span>
```tsx
import clsx from 'clsx'

export default () => (
    // @MARK display:bloc
    <h1 className={clsx('display:bloc')}>Hello World</h1>
)
```
(x) <span className="text:error">Invalid value for `text-align` property.</span>
```tsx
import styled from '@master/styled.react'

// @MARK text-align:cente
const Block = styled`text-align:cente`

export default () => <Block>Hello World</Block>
```
Common JavaScript utility names are supported by [default](/reference/eslint#calleematching).
