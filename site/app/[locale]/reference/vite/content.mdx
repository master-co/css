## Installation [sr-only]
```bash action=install
@master/css.vite@rc
```
```js name=vite.config.js
import { defineConfig } from 'vite'
import masterCSS from '@master/css.vite' // [!code highlight]

export default defineConfig({
    plugins: [
        masterCSS(options) // [!code highlight]
    ]
})
```

### Client types
Add `@master/css-integration/client` to the project environment file when TypeScript source files import Master CSS virtual modules.

```ts name=src/vite-env.d.ts
/// <reference types="vite/client" />
/// <reference types="@master/css-integration/client" />
```

### Master CSS imports
In static mode, import the generated stylesheet from a source stylesheet.

```css name=src/style.css
@import '@master/css';
```

Source stylesheets that import `@master/css` are treated as native CSS pruning roots by default. Ordinary CSS outside Master CSS directives is pruned against detected classes, and the import inserts generated Master CSS. Add `@preserve native;` when native CSS must be preserved. If the same stylesheet contains `@settings`, `@theme`, `@custom-variant`, or `@custom-variant` manifest directives, that stylesheet can also serve as the project CSS entry because `@import '@master/css'` is an entry marker.

`@import '@master/css'` may appear anywhere inside the top-level CSS import block. The Vite integration keeps ordinary CSS imports before generated Master CSS, but the Master CSS import still needs to come before normal style rules.

### Runtime input imports
The plugin exposes canonical project-level runtime input modules:

```ts
import manifest from 'virtual:master-css-manifest'
import emittedGlobals from 'virtual:master-css-emitted-globals'
```

Use these virtual modules when application code should receive the same manifest graph and emittedGlobals global CSS state that the plugin discovered from the project CSS entry. The manifest module is backed by [`@master/css-manifest`](/reference/manifest).
