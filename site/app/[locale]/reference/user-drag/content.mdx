## Overview [sr-only] \{#overview\}
<Overview />

`user-drag:*` emits the vendor `-webkit-user-drag` declaration as well as its unprefixed spelling. This is a nonstandard, platform-dependent feature. Prefer the HTML [`draggable` attribute](https://html.spec.whatwg.org/multipage/dnd.html#the-draggable-attribute) for explicit native drag intent.

## Examples \{#examples\}
### Prevent dragging media \{#prevent-dragging-media\}
In supporting browsers, `user-drag:none` prevents the image from starting a native drag. Compare it with the default image and the standard HTML `draggable="false"` alternative.

<DemoExample page="user-drag" section="prevent-dragging-media" />

```html
<!-- CSS · native image drag disabled -->
<img id="target" src="/demo/landscape.svg" alt="Sun above layered mountains"
  width="240" height="144" class="block h:auto w:240px max-w:full r:sm user-drag:none">
```

```html
<!-- Default image · native drag allowed -->
<img id="target" src="/demo/landscape.svg" alt="Sun above layered mountains"
  width="240" height="144" class="block h:auto w:240px max-w:full r:sm user-drag:auto">
```

```html
<!-- HTML · explicit false -->
<img id="target" src="/demo/landscape.svg" alt="Sun above layered mountains"
  width="240" height="144" class="block h:auto w:240px max-w:full r:sm " draggable="false">
```

The artwork is the same loaded image in every specimen. Try dragging with a pointer. Native touch dragging and long-press behavior vary by platform; computed support alone does not prove that a drag starts.

### Keep draggable elements explicit \{#keep-draggable-elements-explicit\}
`user-drag:element` requests a native drag for the whole element in supporting browsers. The second specimen expresses that intent with `draggable="true"`.

<DemoExample page="user-drag" section="keep-draggable-elements-explicit" />

```html
<!-- Vendor CSS request -->
<div id="target"
  class="p:md b:1px|solid|base r:sm user-select:none
         user-drag:element">
  Canvas asset
</div>
```

```html
<!-- Standard HTML request -->
<div id="target" draggable="true"
  class="p:md b:1px|solid|base r:sm user-select:none">
  Canvas asset
</div>
```

Neither declaration creates a drop target or a reordering feature. A complete application also needs data handling and an accessible way to perform its action without dragging.

### Reset to browser behavior \{#reset-to-browser-behavior\}
Use `user-drag:auto` to return to the browser’s normal drag rules. Resize from `none` below `sm` to `auto` at the breakpoint.

<DemoExample page="user-drag" section="reset-to-browser-behavior" />

```html
<img id="target" src="/demo/landscape.svg" alt="Sun above layered mountains"
  width="240" height="144"
  class="block h:auto w:240px max-w:full r:sm
         user-drag:none user-drag:auto@screen&sm">
```

Automatic behavior depends on the element. Images and links normally have native drag behavior; an ordinary `div` does not become draggable merely because its value is `auto`.

### Apply conditionally \{#apply-conditionally\}
Use a stable native checkbox to change the image’s drag policy. When Lock image dragging is checked, the parent selector applies `user-drag:none` to the image.

<DemoExample page="user-drag" section="apply-conditionally" />

```html
<div class="user-drag:none:has(>label>input:checked)>img">
  <label class="flex items-center gap:sm mb:md">
    <input type="checkbox"> Lock image dragging
  </label>
  <img id="target" src="/demo/landscape.svg" alt="Sun above layered mountains"
    width="240" height="144" class="block h:auto w:240px max-w:full r:sm user-drag:auto">
</div>
```

The checkbox remains available to keyboard users. Toggle it before starting a drag; the lesson changes an actual CSS property rather than canceling a synthetic drag event.
