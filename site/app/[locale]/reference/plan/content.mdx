## Installation [sr-only]
```bash action=install
@master/css-plan@rc
```

`@master/css-plan` is the shared project plan boundary for CLI commands, ESLint, language tooling, and build integrations such as Vite, Next.js, Webpack, and Nuxt.

It discovers project CSS entries and Master CSS workspace roots, then delegates CSS parsing, import graph resolution, and plan compilation to `@master/css-compiler`. The extractor stays focused on class/source scanning; callers pass it the compiled plan and source directives.

Project entry discovery only treats CSS files with top-level `@master;` or `@import '@master/css'` as entries. Imported `@settings`, `@theme`, `@custom-variant`, and `@custom-variant` directives participate in the entry graph, but they are not independent project entries. JavaScript/TypeScript config files are intentionally unsupported.

---

## Load project plan
Use `loadProjectPlan()` when a tool should load the canonical project-level plan for a directory.

```ts
import { loadProjectPlan, loadProjectPlanJSON } from '@master/css-plan/load'

const result = await loadProjectPlan('/project')
const jsonResult = await loadProjectPlanJSON('/project')
```

`loadProjectPlan()` discovers project CSS entries unless explicit `entries` are passed. It returns the compiled plan and dependency list. `loadProjectPlanJSON()` returns JSON source for virtual JSON modules and loader output.

```ts
import { loadProjectPlanSync, loadProjectPlanJSONSync } from '@master/css-plan/load-sync'

const result = loadProjectPlanSync('/project')
const jsonResult = loadProjectPlanJSONSync('/project')
```

---

## Load explicit CSS resources
Use `loadPlan()` when the CSS resource path is already known and should be compiled directly.

```ts
import { loadPlan, loadPlanJSON } from '@master/css-plan/load'

const result = await loadPlan('/project/src/index.css')
const jsonResult = await loadPlanJSON('/project/src/index.css')
```

`loadPlan()` and `loadPlanJSON()` only accept CSS resources. They do not search the workspace and do not load JavaScript or TypeScript config files.

```ts
import { loadPlanSync, loadPlanJSONSync } from '@master/css-plan/load-sync'

const result = loadPlanSync('/project/src/index.css')
const jsonResult = loadPlanJSONSync('/project/src/index.css')
```

## Discover entries and workspaces
Use `@master/css-plan/css` when tooling needs the same project entry and workspace discovery rules without loading a plan.

```ts
import {
    findCSSPlanEntryFiles,
    findMasterCSSWorkspaceDirectories,
    hasMasterCSSPlanEntrypoint,
} from '@master/css-plan/css'
```

`findCSSPlanEntryFiles(projectDir)` searches CSS files for entry markers. `findMasterCSSWorkspaceDirectories(rootDir)` creates workspace roots from discovered CSS entries and `package.json` files that declare Master CSS package dependencies.

## Plan modules
The module utilities define the plan import contract used by official integrations. They live in `@master/css-integration`; `@master/css-plan` owns loading and discovery.

```ts
import {
    MASTER_CSS_PLAN_QUERY,
    VIRTUAL_PLAN_ID,
    toPlanJSON,
    toVirtualDefaultPlanModulePath,
    toVirtualCSSPlanModulePath,
} from '@master/css-integration/plan-module'
```

| API | Purpose |
| --- | --- |
| `VIRTUAL_PLAN_ID` | The default plan JS facade module id, `virtual:master-css-plan`. |
| `VIRTUAL_PRELOADED_ID` | The default preloaded module id, `virtual:master-css-preloaded`. |
| `MASTER_CSS_PLAN_QUERY` | The query suffix, `?master-css-plan`, used to compile one explicit CSS resource. |
| `toPlanJSON(plan)` | Serializes a plan object into normalized JSON source. |
| `toPreloadedModule(preloaded)` | Serializes preloaded variable and animation counts into an ESM default export. |
| `toVirtualDefaultPlanModulePath(context)` | Creates the virtual path for the default plan module. |
| `toVirtualCSSPlanModulePath(context, file)` | Creates a virtual path for one explicit queried CSS resource. |

Use `virtual:master-css-plan` and `virtual:master-css-preloaded` when application code should receive the integration's canonical project-level runtime inputs. Use `./index.css?master-css-plan` only when the code intentionally compiles one explicit CSS resource through the active integration.
