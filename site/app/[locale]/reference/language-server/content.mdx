## Basic usage
### Create a language server
The main body of this package is the class `CSSLanguageServer`, which is built on top of [VSCode Language Server](https://github.com/Microsoft/vscode-languageserver-node ).
```js
import CSSLanguageServer from '@master/css-language-server'

const languageServer = new CSSLanguageServer(connection, customSettings)
```
Check out the [source code](https://github.com/master-co/css/blob/rc/packages/language-server/src/core.ts) for arguments and properties.

### Semantic tokens
The language server supports both full-document and active-position semantic tokens.

When `settings.embeddedSyntaxHighlighting` is `always`, the server advertises `semanticTokensProvider` and handles `textDocument/semanticTokens/full` requests for open documents. When the mode is `active`, VS Code uses the `masterCSS/renderActiveSemanticTokens` request to highlight only the embedded Master CSS span at the active editor position. The `off` mode disables embedded utility highlighting. Master CSS syntax inside CSS documents is available through `masterCSS/renderDocumentSemanticTokens` and is always highlighted by the VS Code extension.

Semantic tokens are resolved from the nearest workspace language service. This lets the server highlight config-dependent Master CSS tokens such as custom variables and components after loading the project CSS entry, while also classifying CSS directives such as `@master`, `@theme`, `@custom-at`, `@custom-selector`, `@compose`, and `@at`.

When configuration or Master CSS settings change in `always` mode, the server requests a semantic token refresh from clients that support `workspace/semanticTokens/refresh`.

## API Reference
### `settings`
The default language server settings. It inherits the [language service settings](/reference/language-service#settings).
```js
import { settings } from '@master/css-language-server'
```

### `settings.workspaces`
Specify the workspace where the independent [`CSSLanguageService`](/reference/language-service#csslanguageservice) should be created, always including the root workspace. See the [Monorepo](/guide/monorepo) documentation to understand the purpose of this option.
<DocProp defaultValue={settings.workspaces} types={["FastGlobPattern[] | 'auto'"]} />

By default `auto`, a new workspace is automatically created based on the location of a CSS file containing `@master;` or `@import '@master/css'`, or a `package.json` that declares a Master CSS package dependency. Dependency-based detection reads `dependencies`, `devDependencies`, `peerDependencies`, and `optionalDependencies`, so it works before `node_modules` is installed.

(i) Automatically creates `/`, `/apps/a`, and `/apps/b` workspaces.
<ExplorerView>
{[
    { name: 'apps', children: [
        { name: 'a', children: [
            { name: 'index.css' }
        ]},
        { name: 'b', children: [
            { name: 'package.json' }
        ]},
    ]},
    { name: 'index.css' }
]}
</ExplorerView>

`/apps/b/package.json` can be detected without a config file when it declares `@master/css` or an official runtime/integration package such as `@master/css-runtime`, `@master/css.vite`, `@master/css.webpack`, `@master/css.react`, `@master/css.vue`, `@master/css.svelte`, `@master/css.astro`, `@master/css.nuxt`, or `@master/css.next`.

(i) A root workspace will still be automatically created without a root configuration.
<ExplorerView>
{[
    { name: 'apps', children: [
        { name: 'a', children: [
            { name: 'index.css' }
        ]},
        { name: 'b' }
    ]}
]}
</ExplorerView>
In most cases, keeping the default `'auto'` is sufficient, but you can also manually specify the workspace.

Specify `/apps/b` as a workspace:
```js
{
    workspaces: ['apps/b']
}
```
It creates `/` and `/apps/b` workspaces.
<ExplorerView>
{[
    { name: 'apps', children: [
        { name: 'a', children: [
            { name: 'index.css' }
        ]},
        { name: 'b' }
    ]},
    { name: 'index.css' }
]}
</ExplorerView>

### `settings.verbose`
Print all console logs.
<DocProp defaultValue={JSON.stringify(settings.verbose)} types={['boolean']} />

### `settings.embeddedSyntaxHighlighting`
Control embedded semantic token highlighting mode.
<DocProp defaultValue={JSON.stringify(settings.embeddedSyntaxHighlighting)} types={['"active" | "always" | "off"']} />

Set this to `always` to advertise the standard LSP `semanticTokensProvider`, `active` to use active-position highlighting through the VS Code extension, or `off` to disable embedded utility highlighting. This setting is inherited from the [language service](/reference/language-service#settingsembeddedsyntaxhighlighting).
