## Basic usage
### Create a language service
The main body of this package is the class `CSSLanguageService`, which encapsulates the language service features.
```js
import CSSLanguageService from '@master/css-language-service'

const languageService = new CSSLanguageService(customSettings)
```
Check out the [source code](https://github.com/master-co/css/blob/rc/packages/language-service/src/core.ts) for arguments and properties.

### Render semantic tokens
`renderSemanticTokens()` returns [LSP semantic tokens](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_semanticTokens) for Master CSS class spans and CSS directives discovered in a text document.
```ts
const semanticTokens = languageService.renderSemanticTokens(textDocument)
```

Semantic tokens are generated with the project plan and Master CSS engine, so custom variables, components, utilities, modes, and other plan-dependent tokens can be classified after the project plan is loaded by the caller.

Use `renderSemanticTokensAtPosition()` when a client wants active-only highlighting for the embedded class context or CSS directive at the current editor position.
```ts
const semanticTokens = languageService.renderSemanticTokensAtPosition(textDocument, position)
```

The default legend is exported for clients that need to decode or register the token types:
```js
import { SEMANTIC_TOKENS_LEGEND } from '@master/css-language-service'
```
<DocProp defaultValue={SEMANTIC_TOKENS_LEGEND} types={['SemanticTokensLegend']} />

### Browser semantic tokens
Use the browser subpath when a web editor needs Master CSS semantic tokens without the Node-oriented `CSSLanguageService` class.
```ts
import {
    SEMANTIC_TOKENS_LEGEND,
    renderBrowserSemanticTokens
} from '@master/css-language-service/browser'

const semanticTokens = renderBrowserSemanticTokens(source, 'html', { plan })
```

The browser helper supports CSS documents and quoted `class` or `className` attributes in HTML. It returns encoded semantic token data that can be passed to editors such as Monaco together with `SEMANTIC_TOKENS_LEGEND`.

## API Reference
### `settings`
The default language service settings.
```js
import { settings } from '@master/css-language-service'
```

### `settings.includedLanguages`
Set which languages ​​should provide language services.
<DocProp defaultValue={settings.includedLanguages} types={['string[]']} />

### `settings.exclude`
Set a glob pattern to prevent specific folders or files from providing language services.
<DocProp defaultValue={settings.exclude} types={['string[]']} />

### `settings.classAttributes`
Specify which markup attributes should provide features of the Master CSS syntax.
<DocProp defaultValue={JSON.stringify(settings.classAttributes)} types={['string[]']} />

By default, `class` and `className` attributes in HTML and JSX provide language features.
```html name=html
<!-- @MARK target -->
<div class="target"></div>
```
```jsx name=jsx
// @MARK target
<div className="target"></div>
```
This only matches attributes with string tokens, such as `class=""` or `class=''`. For markup binding or assignment forms see the next option.

### `settings.classAttributeBindings`
Specify which markup attributes with bindings should provide features of the Master CSS syntax.
<DocProp defaultValue={JSON.stringify(settings.classAttributeBindings)} types={['Record<string, [string, string] | false>']} />

By default, we have matched the class attribute bindings for popular frameworks.
```jsx name=jsx
// @MARK target
<div className={isActive && "target"}></div>
```
```html name=vue
// @MARK target
<div :class="{ 'target': isActive }"></div>
```
```svelte name=svelte
<!-- @MARK target -->
<div class={isActive && "target"}></div>
```
```astro name=astro
<!-- @MARK target -->
<div class:list={isActive && "target"}></div>
```
```angular-html name=angular
<!-- @MARK target -->
<div [ngClass]="isActive && 'target'"></div>
```

### `settings.classFunctions`
Specify which function arguments should provide features of the Master CSS syntax.
<DocProp defaultValue={JSON.stringify(settings.classFunctions)} types={['string[]']} />

[`clsx`](https://github.com/lukeed/clsx):
```js
import clsx from 'clsx'

/* @MARK target-1 *//* @MARK target-2 */
clsx('target-1', 'target-2');
```
`classList`:
```js
// @MARK target
element.classList.add('target');
// @MARK target
element.classList.remove('target');
```
[`styled`](https://github.com/master-co/styled):
```js
import styled from '@master/styled.react'

/* @MARK target-1 *//* @MARK target-2 */
const Button = styled.button`target-1 target-2`
```

### `settings.classDeclarations`
Specify which variable declarations or object properties should provide features of the Master CSS syntax.
<DocProp types={['string[]']} defaultValue={JSON.stringify(settings.classDeclarations)} />

Object properties:
```js name=classes.js
export const styles = {
    classes: {
        // @MARK target
        btn: 'target'
    }
}
```
Variable declarations:
```js
const classes = {
    // @MARK target
    btn: 'target'
}
```

### `settings.embeddedSyntaxHighlighting`
Control embedded semantic token highlighting mode.
<DocProp defaultValue={JSON.stringify(settings.embeddedSyntaxHighlighting)} types={['"active" | "always" | "off"']} />

`active` highlights the embedded class context at the active editor position, `always` highlights all discovered embedded utility classes, and `off` disables embedded utility highlighting. Master CSS syntax inside CSS documents is always highlighted. Semantic tokens classify Master CSS spans as `class`, `enumMember`, `property`, `variable`, `function`, `number`, `string`, `keyword`, `modifier`, `operator`, or `type`. Components defined in the project plan are emitted as `class` tokens with the `declaration` and `component` modifiers; CSS directives, queries, selectors, pseudo states, units, quoted strings, and important markers use dedicated semantic token modifiers.
