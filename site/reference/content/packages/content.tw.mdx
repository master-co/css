## editorial--master-css-usage \{#copy-editorial--master-css-usage\}


在 Node.js 向引擎與渲染 API 傳入明確 manifest，或在任何環境傳入 `compileRuntimeProgram()` 產生的執行階段程式；瀏覽器只執行程式。重複作業請沿用工作階段，完成後釋放。樣式表撰寫與專案載入請用[編譯器](/reference/packages#css-compiler)；DOM 觀察請用[執行階段](/reference/packages#css-runtime)。

建置整合以 `./client` 宣告的虛擬模組提供交付產物：`virtual:master-css-manifest` 是供 Node 引擎、伺服器渲染器與工具使用的編譯後 `MasterCSSManifest`；`virtual:master-css-program` 是瀏覽器引擎程式，在正式建置中為含雜湊的 `.bin` 資源；`virtual:master-css-emitted-globals` 列出 CSS 入口已輸出的變數與關鍵影格，避免執行階段重複生成。頁面 hydration manifest 是獨立資料，描述單一回應。

建置階段與伺服器生成使用 Rust 語意；瀏覽器引擎執行編譯後程式，在相同定義與 class 下產生相同 CSS。編譯器、伺服器與執行階段版本必須相符：不支援的執行或語言版本會被拒絕。

`executionState(names)` 依請求順序讀取儲存的規則參照，包含重複項，不生成規則；未知或從未確保可用的 class 參照為空。完整規則與 CSS 請用 `snapshot()`。瀏覽器引擎沒有檢查或渲染工作階段。即使轉換沒有 CSS 變更，宿主仍必須同步資源狀態；包裝也必須轉送每個 `MasterCSSEngine` 成員，包含 `executionState`、`registerEmittedGlobals`、`replaceEmittedGlobals`、`refresh`、`dispose` 與 `Symbol.dispose`。

## editorial--master-css-compiler-usage \{#copy-editorial--master-css-compiler-usage\}


API 要求基底 manifest 時，請明確提供。使用結果前先檢查回傳診斷。交付結果是一組資源：每份樣式表與資源都要發布到分配的 URL。解析與交付邊界請見[匯入](/reference/directives/imports)。

**發布檔案編譯結果**

`compileManifestFileSync(file, { baseManifest, delivery })` 讀取檔案圖並回傳資源，不寫入檔案。`delivery` 提供 `entryURL`、`stylesheetURL(file)` 與 `resourceURL(file)`；不同樣式表請分配不同最終 URL。每個回傳 `stylesheets` 項目都須發布到其 `href`，各 `resources` 項目則從 `file` 複製到 `href`。最上層 `css`、`nativeCSS` 與 `generatedCSS` 只描述入口。相對資源 URL 保留原始來源所屬檔案、查詢與片段；只供參照的樣式表不會成為發布資源。缺少資源或樣式表 URL 衝突會在發布前失敗。省略 `delivery` 會回傳單一字串結果，不適用此資源發布契約。

`preserveNativeCSS` 預設為 `true`；明確 `false` 會抑制原始原生 CSS，但在納入的輸出保留已編譯原生 mixin 套用。它不會啟用修剪。樣式表集合透過 `includeNativeCSS`、`includeMasterBaseCSS` 與 `includeGeneratedCSS` 分別選擇原生 CSS、Master 基礎 CSS 與生成 utility。排除原生輸出不會移除生成 utility 使用的定義。檔案政策請見[原生修剪](/reference/directives/pruning)。

`validation: 'report'` 是預設：保留結果並檢查診斷。`validation: 'error'` 在回傳資源前拒絕完整結果中已知無效的 CSS；僅未知能力不會造成失敗。有可用來源對應時，範圍診斷會標示原始樣式表來源。宿主轉換若無法對應某生成片段，不得虛構原始位置。

**為其他轉換器準備原生 CSS**

其他轉換器需要樣式表中未改動的原生部分時，編譯器宿主可啟用 `preserveNativeSource: true`。Master 定義仍會被消耗，原生 `@apply` 規則仍會展開，但無關的註解、空規則、值拼法與規則邊界會保留。預設為 `false`，維持編譯器一般原生 CSS 正規化。

來源保留不可與啟用的原生修剪組合。單純傳入 class 清單不會啟用修剪。`preserveNativeCSS: false` 仍抑制原生輸出。此選項不會阻止宿主後續轉換最佳化結果或重寫來源對應，也不會探索後續轉換新增的 Master 定義或生成全域參照。

**宿主轉換後繼續渲染資源**

若另一份輸出已提供生成主題變數或關鍵影格定義，`compileRenderedStylesheet()` 與 `compileBrowserStylesheet()` 接受選填 `emittedGlobals` 資源計數快照。正計數抑制重複輸出，零不會。新參照仍輸出其遞移資源閉包。回傳快照包含外部情境與此次渲染所需資源，不改變輸入快照。省略選項則維持一般獨立渲染。

此情境防止後續渲染將已處理變數替換回原始 manifest 值，但不會對新生成 CSS 執行宿主外掛。宿主仍負責處理新 CSS 與發布資源，同時保留外掛順序與來源所有權。

| `@master/css/no-invalid-classes` | `error` | 否 | 無效 Master CSS 語法與無效生成 CSS；未比對 class 只在 `disallowUnknownClass` 啟用時回報。 |

## editorial--master-eslint-plugin-css-usage \{#copy-editorial--master-eslint-plugin-css-usage\}


使用[官方預設組態](/reference/packages#eslint-config-css)取得標準規則，或在自己的 flat config 註冊外掛。規則行為請見[程式碼檢查](/guide/code-linting)。

設定位於 `@master/css` 設定鍵下。陣列會取代預設值。

| 設定 | 預設 | 用途 |
| --- | --- | --- |
| `classAttributes` | `['class', 'className']` | 含有 class 字串的標記屬性。 |
| `classFunctions` | `clsx`, `cva`, `ctl`, `cv`, `class`, `classnames`, `classVariant`, `styled`, `classList.add/remove/toggle/replace` | 引數可含 class 字串的被呼叫函式與標記範本；`styled` 也接受 `styled.button` 這類成員形式。 |
| `classDeclarations` | `[]` | 視為 class 宣告的專案變數或物件屬性。 |
| `ignoredKeys` | `['compoundVariants', 'defaultVariants']` | 走訪變體設定物件時略過的物件鍵。 |

`@master/css/no-unapproved-raw-values` 回報有 token 支援的 utility 中使用的原始值。`requireProperties` 將範圍限於所列原生屬性（空或省略時檢查所有有 token 支援的屬性）；`allowProperties` 與 `allowedPatterns` 加入例外，`allowRawValues` 則停用規則。原生自訂屬性參照仍有效。診斷 `data` 指定屬性範圍與標準 token 家族；沒有自動修正。

`@master/css/prefer-component-classes` 回報 class 清單中，超過 `max` 個 class（預設 `3`）透過頂層 `_`、`>`、`+` 或 `~` 組合器替其他元素設定樣式的情況。診斷 `data` 列出 `classNames` 與其 `targets`；沒有自動修正。

## editorial--master-css-runtime-usage \{#copy-editorial--master-css-runtime-usage\}


使用工作階段前先 await `MasterCSSRuntime.start()`，所屬端完成後呼叫 `dispose()`。`withMasterCSSRuntime()` 將啟動與釋放整合到自訂元素的連接回呼，且需要 shadow root。瀏覽器流程請見[渲染模式](/guide/rendering-modes)。

官方整合會注入啟動流程。自訂入口將 `program` 以載入器傳入，例如 `() => import('virtual:master-css-program').then(module => module.default)`，再加上 `emittedGlobals`，然後呼叫 `observe()`。僅執行階段頁面在啟動時載入程式；漸進式頁面若有有效 `hydrationManifest`，會延後引擎直到出現 manifest 外的 class，除非設定 `engine: 'eager'` 或 `enginePrefetch: 'idle'`。`emittedGlobals` 適用使用此 bundle 的每個頁面。執行階段將生成規則與按需關鍵影格插入自己的樣式表，絕不寫入連結樣式表。

`snapshot()` 將 `usageCounts`（已連接的 DOM 使用情況）與 `classRules` 分開；後者也可能包含預先準備、hydration 或保留的規則。`engine` 為 `'deferred'`、`'loading'`、`'ready'` 或 `'failed'`；延後引擎啟動前，class 快照沒有規則項目，`layers` 也為空。`ensureClassRules()` 與 `deleteClassRules()` 不依 DOM 使用情況操作；刪除是同步的，並略過保留機制。引擎尚未就緒時會拋出 `RUNTIME_ENGINE_NOT_READY` 並啟動它，因此請先 await `ready()`。

## editorial--master-css-schema-usage \{#copy-editorial--master-css-schema-usage\}


從擁有型別的專用子路徑匯入。型別宣告描述資料形狀，不驗證任意輸入，也不編譯樣式表指令。在 API 間傳遞 manifest 與診斷時，請保留版本欄位；手動編輯版本不會讓 manifest 相容。

使用 `serializeMasterCSSManifest()` 儲存 manifest。序列化會正規化衍生欄位，不取代引擎驗證，也不保留註解或可編輯的 CSS 格式。未知欄位不是擴充機制：外層封套保留它們，不代表巢狀欄位會被接受或能執行。

## editorial--master-css-server-usage \{#copy-editorial--master-css-server-usage\}


渲染前提供編譯後 manifest。讓 emitted-global 與 hydration 中繼資料和交付用戶端的 CSS 一致，可重複使用工作階段完成後要釋放。完整 HTML 範例請見[渲染模式](/guide/rendering-modes)。

`createServerRenderer()` 跨渲染快取規則：manifest 變更時要重新建立，長時間運作的伺服器則要限制 `maxCachedClasses`。自訂宿主可將頁面可能連結的最終 `stylesheets`，以 `@master/css-compiler/stylesheet` 的 `describeLinkedStylesheet()` 所回傳 `{ href, css, imports }` 形式，搭配供解析使用的 `documentURL` 傳入；樣式表已交付的主題變數與原生關鍵影格不會在 `style#master-css` 重複輸出。渲染會獨立追蹤每個關鍵影格定義，包含不同串接層或條件中的同名定義。
