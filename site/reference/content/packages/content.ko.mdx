## editorial--master-create-css-introduction \{#copy-editorial--master-create-css-introduction\}


기존 프로젝트의 Master CSS 설정을 계획하고 적용합니다. 계획은 적용 전에 의존성 변경, 파일 편집, 명령, 경고를 설명합니다.

## editorial--master-create-css-usage \{#copy-editorial--master-create-css-usage\}


`planMasterCSSSetup()`을 호출해 제안 변경을 검사하세요. `applyMasterCSSSetupPlan()`은 쓰기 전에 기록한 파일 전제 조건을 검사하므로 파일이 바뀌면 새 계획을 만드세요. 설정은 프로젝트 파일을 수정하고 의존성을 설치할 수 있습니다. 대화형 흐름은 [설치](/guide/installation)를 참고하세요.

## editorial--master-css-language-server-introduction \{#copy-editorial--master-css-language-server-introduction\}


Language Server Protocol로 Master CSS 완성, 호버, 색상, 포맷, 시맨틱 토큰을 제공합니다. 라이브러리 진입점은 호스트 관리 수명주기를 지원하고 server 진입점은 프로세스를 시작합니다.

## editorial--master-css-language-server-usage \{#copy-editorial--master-css-language-server-usage\}


호스트에 포함할 때 `MasterCSSLanguageServer`를 만들고 시작한 뒤 종료 시 해제하세요. `/server` 진입점을 불러오면 서버를 즉시 만들고 시작합니다. 편집기 흐름은 [언어 서비스](/guide/language-service)를 참고하세요.

## editorial--master-css-language-server-entries- \{#copy-editorial--master-css-language-server-entries-\}

## editorial--master-css-language-service-introduction \{#copy-editorial--master-css-language-service-introduction\}

## editorial--master-css-language-service-usage \{#copy-editorial--master-css-language-service-usage\}

## editorial--master-css-usage \{#copy-editorial--master-css-usage\}


Node.js의 엔진 및 렌더 API에는 명시적인 manifest를 전달하거나 모든 환경에서 `compileRuntimeProgram()`의 런타임 프로그램을 전달하세요. 브라우저는 프로그램만 실행합니다. 반복 작업에는 세션을 재사용하고 완료 후 해제하세요. 스타일시트 작성과 프로젝트 로딩은 [컴파일러](/reference/packages#css-compiler), DOM 관찰은 [런타임](/reference/packages#css-runtime)을 사용합니다.

빌드 통합은 `./client`에 선언된 가상 모듈로 전달 산출물을 제공합니다. `virtual:master-css-manifest`는 Node 엔진, 서버 렌더러, 도구용 컴파일한 `MasterCSSManifest`입니다. `virtual:master-css-program`은 브라우저 엔진 프로그램이며 프로덕션 빌드에서는 해시가 있는 `.bin` 에셋입니다. `virtual:master-css-emitted-globals`는 CSS 진입점이 이미 출력한 변수와 키프레임을 나열해 런타임 중복 생성을 막습니다. 페이지 하이드레이션 manifest는 응답 하나를 설명하는 별도 데이터입니다.

빌드 시점과 서버 생성은 Rust 의미 체계를 사용합니다. 브라우저 엔진은 컴파일한 프로그램을 실행하며 같은 정의와 클래스에 같은 CSS를 생성합니다. 컴파일러, 서버, 런타임은 서로 맞는 릴리스를 사용하세요. 지원하지 않는 실행 또는 언어 버전은 거부됩니다.

`executionState(names)`는 규칙을 생성하지 않고 중복을 포함한 요청 순서대로 저장된 규칙 참조를 읽습니다. 알 수 없거나 확보하지 않은 클래스의 참조는 비어 있습니다. 전체 규칙과 CSS는 `snapshot()`을 사용하세요. 브라우저 엔진에는 검사나 렌더 세션이 없습니다. CSS 변경 없는 전환에도 호스트는 리소스 상태를 동기화해야 합니다. 래퍼는 `executionState`, `registerEmittedGlobals`, `replaceEmittedGlobals`, `refresh`, `dispose`, `Symbol.dispose`를 포함한 모든 `MasterCSSEngine` 멤버를 전달해야 합니다.

## editorial--master-css-compiler-usage \{#copy-editorial--master-css-compiler-usage\}


API가 기본 manifest를 요구하면 명시적으로 제공하세요. 결과 사용 전에 반환 진단을 검사하세요. 전달 결과는 에셋 집합이므로 모든 스타일시트와 리소스를 지정 URL에 게시해야 합니다. 해석과 전달 경계는 [가져오기](/reference/directives/imports)를 참고하세요.

**파일 컴파일 게시**

`compileManifestFileSync(file, { baseManifest, delivery })`는 파일 그래프를 읽고 쓰기 없이 에셋을 반환합니다. `delivery`는 `entryURL`, `stylesheetURL(file)`, `resourceURL(file)`을 제공합니다. 서로 다른 스타일시트에는 서로 다른 최종 URL을 지정하세요. 모든 `stylesheets` 항목을 `href`에 게시하고 각 `resources` 항목을 `file`에서 `href`로 복사하세요. 최상위 `css`, `nativeCSS`, `generatedCSS`는 진입점만 설명합니다. 상대 리소스 URL은 원래 소스 소유자, 쿼리, 프래그먼트를 유지하며 참조 전용 스타일시트는 게시 에셋이 되지 않습니다. 누락 리소스와 스타일시트 URL 충돌은 게시 전에 실패합니다. `delivery`를 생략하면 이 에셋 게시 규칙 없이 단일 문자열 결과를 반환합니다.

`preserveNativeCSS`의 기본값은 `true`입니다. 명시적 `false`는 원시 네이티브 CSS를 억제하지만 포함된 출력의 컴파일된 네이티브 믹스인 적용은 유지합니다. 가지치기를 활성화하지는 않습니다. 스타일시트 집합은 `includeNativeCSS`, `includeMasterBaseCSS`, `includeGeneratedCSS`로 네이티브 CSS, Master 기본 CSS, 생성 유틸리티를 각각 선택합니다. 네이티브 출력 제외는 생성 유틸리티가 쓰는 정의를 제거하지 않습니다. 파일 정책은 [네이티브 가지치기](/reference/directives/pruning)를 참고하세요.

기본 `validation: 'report'`는 결과를 유지하며 진단을 검사합니다. `validation: 'error'`는 에셋 반환 전에 전체 결과의 알려진 무효 CSS를 거부하며 알 수 없는 기능만으로는 실패하지 않습니다. 사용 가능한 소스 맵이 있으면 범위 진단은 원래 스타일시트 소스를 가리킵니다. 생성 구간을 매핑할 수 없는 호스트 변환은 원래 위치를 만들어 내면 안 됩니다.

**다른 변환기를 위한 네이티브 CSS 준비**

다른 변환기에 스타일시트의 변경하지 않은 네이티브 부분이 필요하면 호스트는 `preserveNativeSource: true`를 활성화할 수 있습니다. Master 정의는 여전히 소비하고 네이티브 `@apply` 규칙도 변환하지만 무관한 주석, 빈 규칙, 값 표기, 규칙 경계는 유지합니다. 기본값 `false`는 컴파일러의 일반 네이티브 CSS 정규화를 유지합니다.

소스 보존은 활성 네이티브 가지치기와 함께 쓸 수 없습니다. 클래스 목록만 전달해도 가지치기가 활성화되지는 않습니다. `preserveNativeCSS: false`는 여전히 네이티브 출력을 억제합니다. 이 옵션은 후속 호스트 변환의 최적화나 소스 맵 재작성을 막지 않으며 뒤의 변환이 도입한 Master 정의나 생성 전역 참조를 탐색하지 않습니다.

**호스트 변환 뒤 리소스 렌더링 계속하기**

다른 출력이 생성 테마 변수나 키프레임 정의를 이미 제공하면 `compileRenderedStylesheet()`와 `compileBrowserStylesheet()`에 선택적 `emittedGlobals` 리소스 수 스냅샷을 전달할 수 있습니다. 양수는 중복 출력을 억제하고 0은 억제하지 않습니다. 새 참조가 의존하는 모든 리소스도 계속 출력합니다. 반환 스냅샷은 입력을 바꾸지 않고 외부 맥락과 이번 렌더링에 필요한 리소스를 포함합니다. 옵션 생략 시 일반 독립 렌더링을 유지합니다.

이 맥락은 후속 렌더링이 이미 처리한 변수를 원래 manifest 값으로 되돌리지 않게 합니다. 새 생성 CSS에 호스트 플러그인을 실행하지는 않습니다. 호스트는 플러그인 순서와 소스 소유권을 유지하며 새 CSS 처리와 리소스 게시를 담당합니다.

## editorial--master-eslint-config-css-usage \{#copy-editorial--master-eslint-config-css-usage\}


ESLint flat config에 프리셋을 추가하세요. 프로젝트별 동작은 [플러그인 설정](/reference/packages#eslint-plugin-css)으로 조정하며 [코드 린트](/guide/code-linting)는 각 규칙을 설명합니다.

| 규칙 | 기본값 | 수정 가능 | 보고 내용 |
| --- | --- | --- | --- |
| `@master/css/sort-classes` | `warn` | 예 | 생성 규칙 순서와 다른 클래스 및 중복. |
| `@master/css/no-invalid-classes` | `error` | 아니요 | 잘못된 Master CSS 구문과 생성 CSS. 일치하지 않는 클래스는 `disallowUnknownClass`일 때만 보고. |
| `@master/css/no-conflicting-classes` | `warn` | 예 | 같은 변형 범위의 전체 및 부분 선언 충돌. 전체 재정의만 수정. |
| `@master/css/prefer-canonical-classes` | `warn` | 예 | 토큰 동일성과 생성 규칙 동작을 유지할 때만 비표준 형식을 보고. |

`@master/css/no-unapproved-raw-values`와 `@master/css/prefer-component-classes`는 프리셋에 없습니다.

## editorial--master-eslint-plugin-css-usage \{#copy-editorial--master-eslint-plugin-css-usage\}


표준 규칙에는 [공식 프리셋](/reference/packages#eslint-config-css)을 쓰거나 자신의 flat config에 플러그인을 등록하세요. 규칙 동작은 [코드 린트](/guide/code-linting)를 참고하세요.

설정은 `@master/css` 설정 키 아래에 있으며 배열은 기본값을 대체합니다.

| 설정 | 기본값 | 용도 |
| --- | --- | --- |
| `classAttributes` | `['class', 'className']` | 클래스 문자열을 포함한 마크업 속성. |
| `classFunctions` | `clsx`, `cn`, `cva`, `ctl`, `cv`, `class`, `classnames`, `classVariant`, `styled`, `classList.add/remove/toggle/replace` | 인수에 클래스 문자열을 포함할 수 있는 호출 대상과 태그 템플릿. `styled`는 `styled.button` 같은 멤버 형식도 허용. |
| `classDeclarations` | `[]` | 클래스 선언으로 취급할 프로젝트 변수나 객체 속성. |
| `ignoredKeys` | `['compoundVariants', 'defaultVariants']` | 변형 설정 객체를 순회할 때 건너뛸 객체 키. |

`@master/css/no-unapproved-raw-values`는 토큰 지원 유틸리티의 원시 값을 보고합니다. `requireProperties`는 나열한 네이티브 속성으로 제한하며 비어 있거나 생략하면 모든 토큰 지원 속성을 검사합니다. `allowProperties`와 `allowedPatterns`는 예외를 추가하고 `allowRawValues`는 규칙을 비활성화합니다. 네이티브 사용자 지정 속성 참조는 유효합니다. 진단 `data`는 속성 범위와 표준 토큰 계열을 명시하며 자동 수정은 없습니다.

`@master/css/prefer-component-classes`는 최상위 `_`, `>`, `+`, `~` 결합자로 다른 요소를 스타일하는 클래스가 `max`개(기본 `3`)를 초과하는 클래스 목록을 보고합니다. 진단 `data`는 `classNames`와 `targets`를 나열하며 자동 수정은 없습니다.

## editorial--master-css-runtime-usage \{#copy-editorial--master-css-runtime-usage\}


세션 사용 전에 `MasterCSSRuntime.start()`를 await하고 소유자가 완료되면 `dispose()`를 호출하세요. `withMasterCSSRuntime()`은 시작과 해제를 사용자 정의 요소 연결 콜백에 통합하며 섀도 루트가 필요합니다. 브라우저 흐름은 [렌더링 모드](/guide/rendering-modes)를 참고하세요.

공식 통합은 시작 코드를 주입합니다. 사용자 정의 진입점은 `program`에 `() => import('virtual:master-css-program').then(module => module.default)` 같은 로더와 `emittedGlobals`를 전달한 뒤 `observe()`를 호출합니다. 런타임 전용 페이지는 시작 시 프로그램을 불러옵니다. 유효한 `hydrationManifest`가 있는 점진적 페이지는 `engine: 'eager'`나 `enginePrefetch: 'idle'`이 없으면 범위 밖 클래스가 나타날 때까지 엔진을 지연합니다. `emittedGlobals`는 번들을 쓰는 모든 페이지에 적용됩니다. 런타임은 생성 규칙과 온디맨드 키프레임을 자체 스타일시트에 삽입하고 연결된 스타일시트에는 쓰지 않습니다.

`snapshot()`은 연결된 DOM 사용인 `usageCounts`와 사전 준비, 하이드레이션, 유지 규칙도 가질 수 있는 `classRules`를 구분합니다. `engine`은 `'deferred'`, `'loading'`, `'ready'`, `'failed'`입니다. 지연 엔진이 시작하기 전 클래스 스냅샷에는 규칙 항목이 없고 `layers`도 비어 있습니다. `ensureClassRules()`와 `deleteClassRules()`는 DOM 사용과 독립적이며 삭제는 동기적이고 유지 정책을 우회합니다. 엔진 준비 전에는 `RUNTIME_ENGINE_NOT_READY`를 던지고 시작하므로 먼저 `ready()`를 await하세요.

## editorial--master-css-schema-usage \{#copy-editorial--master-css-schema-usage\}


타입을 소유한 좁은 하위 경로에서 가져오세요. 타입 선언은 데이터 형태를 설명하며 임의 입력을 검증하거나 스타일시트 지시문을 컴파일하지 않습니다. API 간 manifest와 진단을 전달할 때 버전 필드를 유지하세요. 수동 편집으로 manifest가 호환되지는 않습니다.

`serializeMasterCSSManifest()`로 manifest를 저장합니다. 직렬화는 파생 필드를 정규화하지만 엔진 검증을 대체하거나 주석과 편집 가능한 CSS 서식을 보존하지 않습니다. 알 수 없는 필드는 확장 메커니즘이 아닙니다. 바깥 구조가 이를 유지해도 중첩 필드가 허용되거나 실행 가능해지지는 않습니다.

## editorial--master-css-server-usage \{#copy-editorial--master-css-server-usage\}


렌더링 전에 컴파일한 manifest를 제공하세요. emitted-global과 하이드레이션 메타데이터를 클라이언트에 전달한 CSS와 맞추고 재사용 세션은 사용 후 해제하세요. 전체 HTML 예제는 [렌더링 모드](/guide/rendering-modes)를 참고하세요.

`createServerRenderer()`는 렌더링 간 규칙을 캐시합니다. manifest가 바뀌면 다시 만들고 장기 실행 서버에서는 `maxCachedClasses`를 제한하세요. 사용자 정의 호스트는 페이지가 연결할 수 있는 최종 `stylesheets`를 `@master/css-compiler/stylesheet`의 `describeLinkedStylesheet()`가 반환하는 `{ href, css, imports }`와 이를 해석할 `documentURL`로 전달할 수 있습니다. 해당 스타일시트가 이미 전달하는 테마 변수와 네이티브 키프레임은 `style#master-css`에 반복하지 않습니다. 렌더링은 서로 다른 레이어나 조건의 같은 이름 정의도 포함해 각 키프레임 정의를 독립적으로 추적합니다.
