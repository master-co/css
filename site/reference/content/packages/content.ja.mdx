Node.js のエンジン・描画 API には明示的な manifest を渡すか、全環境で `compileRuntimeProgram()` のランタイムプログラムを渡します。ブラウザーはプログラムだけを実行します。反復作業にはセッションを再利用し、終了後に破棄します。記述と読み込みには[コンパイラー](/reference/packages#css-compiler)、DOM 監視には[ランタイム](/reference/packages#css-runtime)を使います。

ビルド統合は `./client` で宣言する仮想モジュールとして配信成果物を公開します。`virtual:master-css-manifest` は Node エンジン、サーバーレンダラー、ツール用のコンパイル済み `MasterCSSManifest`、`virtual:master-css-program` は本番ビルドでハッシュ付き `.bin` アセットになるブラウザー用プログラム、`virtual:master-css-emitted-globals` は CSS エントリーが出力済みの変数とキーフレームの一覧で、ランタイムの重複生成を防ぎます。ページのハイドレーション manifest は 1 応答を記述する別データです。

ビルド時とサーバーの生成は Rust の意味処理を使い、ブラウザーエンジンはコンパイル済みプログラムから同じ定義とクラスに同じ CSS を生成します。コンパイラー、サーバー、ランタイムは対応するリリースを使ってください。未対応の実行・言語バージョンは拒否します。

`executionState(names)` は規則を生成せず、重複を含め要求順で保存済み規則参照を読みます。未知または未確保のクラスは参照が空です。全規則と CSS には `snapshot()` を使います。ブラウザーエンジンには検査・描画セッションがありません。CSS 変更のない遷移でもホストはリソース状態を同期し、ラッパーは `executionState`、`registerEmittedGlobals`、`replaceEmittedGlobals`、`refresh`、`dispose`、`Symbol.dispose` を含む全 `MasterCSSEngine` メンバーを転送する必要があります。

## editorial--master-css-compiler-usage \{#copy-editorial--master-css-compiler-usage\}


API がベース manifest を要求する場合は明示的に渡します。結果を使う前に診断を確認してください。配信結果はアセット一式で、各スタイルシートとリソースを割り当てた URL に公開します。境界は[インポート](/reference/directives/imports)を参照してください。

**ファイルコンパイルの公開**

`compileManifestFileSync(file, { baseManifest, delivery })` はファイルグラフを読み、書き込みせずアセットを返します。`delivery` は `entryURL`、`stylesheetURL(file)`、`resourceURL(file)` を供給し、別スタイルシートには別の最終 URL を割り当てます。全 `stylesheets` 項目を `href` に公開し、各 `resources` を `file` から `href` にコピーします。最上位の `css`、`nativeCSS`、`generatedCSS` はエントリーだけを記述します。相対リソース URL は元の所有ソース、クエリ、フラグメントを保ち、参照専用 CSS は公開アセットになりません。リソース欠落や URL 衝突は公開前に失敗します。`delivery` の省略は単一文字列の結果となり、この公開契約は適用しません。

`preserveNativeCSS` の既定は `true` です。明示的な `false` は生のネイティブ CSS を抑え、含める出力にはコンパイル済みネイティブミックスイン適用を保持します。プルーニングは有効にしません。スタイルシート集合は `includeNativeCSS`、`includeMasterBaseCSS`、`includeGeneratedCSS` でネイティブ CSS、Master ベース CSS、生成ユーティリティを別々に選びます。ネイティブ出力の除外は、生成側が使う定義を除去しません。方針は[ネイティブのプルーニング](/reference/directives/pruning)を参照してください。

既定の `validation: 'report'` は結果を保持しながら診断を確認します。`validation: 'error'` は全結果の既知の無効 CSS をアセット返却前に拒否し、未知機能だけでは失敗しません。使えるソースマップがあれば範囲診断は元ソースを指します。生成部分を対応付けられないホスト変換は元位置を捏造してはいけません。

**別の変換器用にネイティブ CSS を準備する**

別の変換器が未変更のネイティブ部分を必要とする場合、ホストは `preserveNativeSource: true` を有効にできます。Master 定義は消費し、ネイティブ `@apply` は変換しますが、無関係のコメント、空規則、値の綴り、規則境界を保持します。既定の `false` は通常のネイティブ CSS 正規化を保ちます。

ソース保持と有効なネイティブプルーニングは併用できません。クラスリストだけではプルーニングは有効にならず、`preserveNativeCSS: false` は引き続きネイティブ出力を抑えます。このオプションは後続ホスト変換の最適化やソースマップ書換えを妨げず、後の変換が加える Master 定義や生成グローバル参照を検出しません。

**ホスト変換後のリソース描画を続ける**

別出力が生成テーマ変数やキーフレームを供給済みなら、`compileRenderedStylesheet()` と `compileBrowserStylesheet()` に任意の `emittedGlobals` リソース件数スナップショットを渡せます。正の件数は重複出力を抑え、ゼロは抑えません。新参照は推移的なリソース閉包を引き続き出力します。返すスナップショットは入力を変えず、外部文脈と今回必要なリソースを含みます。省略時は通常の単独描画です。

この文脈は、後の描画が処理済み変数を元の manifest 値に戻すのを防ぎますが、新生成 CSS にホストプラグインは実行しません。ホストはプラグイン順とソース所有権を保ちながら、新 CSS の処理とリソース公開を担います。

## editorial--master-eslint-config-css-usage \{#copy-editorial--master-eslint-config-css-usage\}


ESLint の flat config にプリセットを加えます。プロジェクト固有の動作は[プラグイン設定](/reference/packages#eslint-plugin-css)、各規則は[コード lint](/guide/code-linting)を参照してください。

| 規則 | 既定 | 修正可能 | 報告内容 |
| --- | --- | --- | --- |
| `@master/css/sort-classes` | `warn` | はい | 生成規則の順序と異なるクラス、および重複。 |
| `@master/css/no-invalid-classes` | `error` | いいえ | 無効な Master CSS 構文と生成 CSS。未一致クラスは `disallowUnknownClass` の場合のみ。 |
| `@master/css/no-conflicting-classes` | `warn` | はい | 同じバリアントスコープ内の宣言の完全・部分競合。完全な上書きだけを修正。 |
| `@master/css/prefer-canonical-classes` | `warn` | はい | トークンの同一性と生成規則の動作を保てる場合だけ非正規形を報告。 |

`@master/css/no-unapproved-raw-values` と `@master/css/prefer-component-classes` はプリセットに含みません。

## editorial--master-eslint-plugin-css-usage \{#copy-editorial--master-eslint-plugin-css-usage\}


標準規則には[公式プリセット](/reference/packages#eslint-config-css)を使うか、独自の flat config にプラグインを登録します。規則の動作は[コード lint](/guide/code-linting)を参照してください。

設定は `@master/css` キーの下に置き、配列は既定値を置き換えます。

| 設定 | 既定 | 用途 |
| --- | --- | --- |
| `classAttributes` | `['class', 'className']` | クラス文字列を含むマークアップ属性。 |
| `classFunctions` | `clsx`, `cva`, `ctl`, `cv`, `class`, `classnames`, `classVariant`, `styled`, `classList.add/remove/toggle/replace` | 引数にクラス文字列を含められる呼び出し先とタグ付きテンプレート。`styled` は `styled.button` などのメンバー形式も受け付ける。 |
| `classDeclarations` | `[]` | クラス宣言として扱うプロジェクト変数やオブジェクトプロパティ。 |
| `ignoredKeys` | `['compoundVariants', 'defaultVariants']` | バリアント設定オブジェクトの走査で飛ばすキー。 |

`@master/css/no-unapproved-raw-values` はトークン対応ユーティリティの生の値を報告します。`requireProperties` は列挙したネイティブプロパティに絞り、空または省略なら全トークン対応プロパティを調べます。`allowProperties` と `allowedPatterns` は例外を加え、`allowRawValues` は無効化します。ネイティブカスタムプロパティ参照は有効です。診断の `data` はプロパティのスコープと標準トークンファミリーを示し、自動修正はありません。

`@master/css/prefer-component-classes` は、最上位の `_`、`>`、`+`、`~` 結合子で別要素をスタイルするクラスが `max`（既定 `3`）を超えるクラスリストを報告します。診断の `data` は `classNames` と `targets` を列挙し、自動修正はありません。

## editorial--master-css-runtime-usage \{#copy-editorial--master-css-runtime-usage\}


セッション利用前に `MasterCSSRuntime.start()` を await し、所有者の終了時に `dispose()` を呼びます。`withMasterCSSRuntime()` はカスタム要素の接続コールバックに起動・破棄を統合し、シャドウルートが必要です。ブラウザーの手順は[レンダリングモード](/guide/rendering-modes)を参照してください。

公式統合は起動処理を注入します。独自エントリーは `program` に `() => import('virtual:master-css-program').then(module => module.default)` などのローダーと `emittedGlobals` を渡し、`observe()` を呼びます。ランタイムのみのページは起動時にプログラムを読みます。有効な `hydrationManifest` を持つプログレッシブページは、`engine: 'eager'` または `enginePrefetch: 'idle'` がなければ、その範囲外のクラスが現れるまでエンジンを遅延します。`emittedGlobals` はバンドルを使う全ページに適用します。生成規則とオンデマンドキーフレームは自身のスタイルシートに挿入し、リンク済み CSS には書きません。

`snapshot()` は接続 DOM の使用数 `usageCounts` と、事前準備・ハイドレーション・保持した規則も含み得る `classRules` を分けます。`engine` は `'deferred'`、`'loading'`、`'ready'`、`'failed'` です。遅延エンジンの起動前はクラススナップショットに規則がなく、`layers` も空です。`ensureClassRules()` と `deleteClassRules()` は DOM 使用と独立し、削除は同期で保持機構を迂回します。準備前は `RUNTIME_ENGINE_NOT_READY` を投げて起動するため、先に `ready()` を await してください。

## editorial--master-css-schema-usage \{#copy-editorial--master-css-schema-usage\}


型を所有する狭いサブパスからインポートします。型宣言はデータ形状を記述するもので、任意入力の検証やディレクティブのコンパイルはしません。API 間で manifest や診断を渡す際はバージョンを保ってください。手で変えても互換にはなりません。

manifest の保存には `serializeMasterCSSManifest()` を使います。シリアライズは派生フィールドを正規化しますが、エンジン検証の代わりではなく、コメントや編集可能な CSS 書式は保ちません。未知フィールドは拡張機構ではありません。外側のエンベロープが保持しても、入れ子フィールドの受理や実行を意味しません。

## editorial--master-css-server-usage \{#copy-editorial--master-css-server-usage\}


描画前にコンパイル済み manifest を渡します。emitted-global とハイドレーションのメタデータは配信 CSS に合わせ、再利用セッションは使用後に破棄します。HTML の全例は[レンダリングモード](/guide/rendering-modes)を参照してください。

`createServerRenderer()` は描画間で規則をキャッシュします。manifest の変更時は再作成し、長寿命サーバーでは `maxCachedClasses` を制限します。独自ホストはページがリンクし得る最終 `stylesheets` を、`@master/css-compiler/stylesheet` の `describeLinkedStylesheet()` が返す `{ href, css, imports }` と、解決用の `documentURL` で渡せます。すでに配信するテーマ変数やネイティブキーフレームは `style#master-css` で重複しません。描画は異なるレイヤーや条件の同名定義も含め、各キーフレーム定義を別々に追跡します。
