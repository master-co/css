## editorial--master-css-usage \{#copy-editorial--master-css-usage\}


在 Node.js 向引擎和渲染 API 传入显式 manifest，或在任何环境传入 `compileRuntimeProgram()` 产生的运行时程序；浏览器仅执行程序。重复作业请复用会话，完成后释放。样式表编写与项目加载请用[编译器](/reference/packages#css-compiler)；DOM 观察请用[运行时](/reference/packages#css-runtime)。

构建集成以 `./client` 声明的虚拟模块提供交付产物：`virtual:master-css-manifest` 是供 Node 引擎、服务器渲染器及工具使用的编译后 `MasterCSSManifest`；`virtual:master-css-program` 是浏览器引擎程序，在生产构建中为带哈希的 `.bin` 资源；`virtual:master-css-emitted-globals` 列出 CSS 入口已输出的变量和关键帧，避免运行时重复生成。页面水合 manifest 是独立数据，描述单个响应。

构建时和服务端生成使用 Rust 语义；浏览器引擎执行编译后的程序，在相同定义和类下产生相同 CSS。编译器、服务器与运行时版本须匹配：不支持的执行或语言版本会被拒绝。

`executionState(names)` 按请求顺序读取存储的规则引用，包括重复项，不生成规则；未知或从未确保可用的类引用为空。完整规则与 CSS 请用 `snapshot()`。浏览器引擎没有检查或渲染会话。即使转换没有 CSS 变更，宿主仍须同步资源状态；包装也必须转发每个 `MasterCSSEngine` 成员，包括 `executionState`、`registerEmittedGlobals`、`replaceEmittedGlobals`、`refresh`、`dispose` 和 `Symbol.dispose`。

## editorial--master-css-compiler-usage \{#copy-editorial--master-css-compiler-usage\}


API 要求基础 manifest 时请显式提供。使用结果前先检查返回诊断。交付结果是一组资源：每份样式表和资源均须发布到分配 URL。解析与交付边界见[导入](/reference/directives/imports)。

**发布文件编译结果**

`compileManifestFileSync(file, { baseManifest, delivery })` 读取文件图并返回资源，不写入文件。`delivery` 提供 `entryURL`、`stylesheetURL(file)` 和 `resourceURL(file)`；不同样式表请分配不同最终 URL。每个返回的 `stylesheets` 项均须发布至其 `href`，各 `resources` 项则从 `file` 复制到 `href`。顶层 `css`、`nativeCSS` 和 `generatedCSS` 仅描述入口。相对资源 URL 保留原始源所属文件、查询与片段；仅供引用样式表不成为发布资源。缺少资源或样式表 URL 冲突在发布前失败。省略 `delivery` 返回单字符串结果，不适用此资源发布契约。

`preserveNativeCSS` 默认为 `true`；显式 `false` 抑制原始原生 CSS，但在包含输出中保留已编译原生混入应用。它不启用裁剪。样式表集合通过 `includeNativeCSS`、`includeMasterBaseCSS` 和 `includeGeneratedCSS` 分别选择原生 CSS、Master 基础 CSS 及生成工具类。排除原生输出不移除生成工具类使用的定义。文件策略见[原生裁剪](/reference/directives/pruning)。

`validation: 'report'` 为默认值：保留结果并检查诊断。`validation: 'error'` 在返回资源前拒绝完整结果中已知无效 CSS；仅未知能力不会造成失败。有可用源映射时，范围诊断标出原始样式表源。宿主变换若无法映射某生成片段，不得虚构原始位置。

**为其他转换器准备原生 CSS**

其他转换器需要样式表中未改动原生部分时，编译器宿主可启用 `preserveNativeSource: true`。Master 定义仍被消耗，原生 `@apply` 规则仍会展开，但无关注释、空规则、值拼写与规则边界会保留。默认为 `false`，保持编译器常规原生 CSS 规范化。

源保留不可与已启用原生裁剪组合。仅传入类列表不启用裁剪。`preserveNativeCSS: false` 仍抑制原生输出。该选项不阻止后续宿主变换优化结果或重写源映射，也不发现后续变换新增的 Master 定义或生成全局引用。

**宿主变换后继续渲染资源**

若另一输出已提供生成主题变量或关键帧定义，`compileRenderedStylesheet()` 和 `compileBrowserStylesheet()` 接受可选 `emittedGlobals` 资源计数快照。正计数抑制重复输出，零不会。新引用仍输出其传递资源闭包。返回快照包含外部上下文和此次渲染所需资源，不改变输入快照。省略选项则保持常规独立渲染。

此上下文防止后续渲染将已处理变量替换回原始 manifest 值，但不会对新生成 CSS 运行宿主插件。宿主仍负责处理新 CSS 及发布资源，同时保留插件顺序和源所有权。

## editorial--master-eslint-config-css-usage \{#copy-editorial--master-eslint-config-css-usage\}


将预设配置加入 ESLint flat config。项目特定行为通过[插件设置](/reference/packages#eslint-plugin-css)调整；[代码检查](/guide/code-linting)说明各规则。

| 规则 | 默认值 | 可修复 | 报告内容 |
| --- | --- | --- | --- |
| `@master/css/sort-classes` | `warn` | 是 | 类未按生成规则排序，以及重复类。 |
| `@master/css/no-invalid-classes` | `error` | 否 | 无效 Master CSS 语法及无效生成 CSS；未匹配类仅在 `disallowUnknownClass` 启用时报告。 |
| `@master/css/no-conflicting-classes` | `warn` | 是 | 同变体范围的完整与部分声明冲突；仅修复完整覆盖。 |
| `@master/css/prefer-canonical-classes` | `warn` | 是 | 非标准形式，仅在保留令牌身份及生成规则行为时报告。 |

## editorial--master-eslint-plugin-css-usage \{#copy-editorial--master-eslint-plugin-css-usage\}


使用[官方预设配置](/reference/packages#eslint-config-css)获取标准规则，或在自己的 flat config 注册插件。规则行为见[代码检查](/guide/code-linting)。

设置位于 `@master/css` 设置键下，数组替换默认值。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `classAttributes` | `['class', 'className']` | 包含类字符串的标记属性。 |
| `classFunctions` | `clsx`, `cn`, `cva`, `ctl`, `cv`, `class`, `classnames`, `classVariant`, `styled`, `classList.add/remove/toggle/replace` | 参数可含类字符串的被调用函数与标签模板；`styled` 也接受 `styled.button` 这类成员形式。 |
| `classDeclarations` | `[]` | 视为类声明的项目变量或对象属性。 |
| `ignoredKeys` | `['compoundVariants', 'defaultVariants']` | 遍历变体配置对象时跳过的对象键。 |

`@master/css/no-unapproved-raw-values` 报告有令牌支持的工具类中的原始值。`requireProperties` 将范围限制于所列原生属性（为空或省略时检查全部令牌支持属性）；`allowProperties` 与 `allowedPatterns` 添加例外，`allowRawValues` 则禁用规则。原生自定义属性引用仍有效。诊断 `data` 指定属性范围和标准令牌家族；无自动修复。

`@master/css/prefer-component-classes` 报告类列表中超过 `max` 个类（默认 `3`）通过顶层 `_`、`>`、`+` 或 `~` 组合器为其他元素设置样式的情况。诊断 `data` 列出 `classNames` 及其 `targets`；无自动修复。

## editorial--master-css-runtime-usage \{#copy-editorial--master-css-runtime-usage\}


使用会话前先 await `MasterCSSRuntime.start()`，所属方完成后调用 `dispose()`。`withMasterCSSRuntime()` 将启动与释放集成至自定义元素连接回调，并要求 shadow root。浏览器流程见[渲染模式](/guide/rendering-modes)。

官方集成注入启动流程。自定义入口将 `program` 以加载器传入，例如 `() => import('virtual:master-css-program').then(module => module.default)`，加上 `emittedGlobals` 后调用 `observe()`。仅运行时页面在启动时加载程序；渐进式页面若有有效 `hydrationManifest`，则延后引擎直至出现 manifest 外的类，除非设置 `engine: 'eager'` 或 `enginePrefetch: 'idle'`。`emittedGlobals` 适用于使用此 bundle 的每个页面。运行时将生成规则和按需关键帧插入自身样式表，绝不写入链接样式表。

`snapshot()` 将 `usageCounts`（已连接 DOM 使用情况）与 `classRules` 分开；后者也可能包含预热、水合或保留规则。`engine` 为 `'deferred'`、`'loading'`、`'ready'` 或 `'failed'`；延后引擎启动前，类快照没有规则项，`layers` 也为空。`ensureClassRules()` 和 `deleteClassRules()` 独立于 DOM 使用情况；删除是同步的并绕过保留机制。引擎未就绪时会抛出 `RUNTIME_ENGINE_NOT_READY` 并启动它，因此请先 await `ready()`。

## editorial--master-css-schema-usage \{#copy-editorial--master-css-schema-usage\}


从拥有类型的专用子路径导入。类型声明描述数据形状，不验证任意输入，也不编译样式表指令。API 间传递 manifest 与诊断时请保留版本字段；手动修改版本不会使 manifest 兼容。

使用 `serializeMasterCSSManifest()` 保存 manifest。序列化规范化派生字段，不替代引擎验证，也不保留注释或可编辑 CSS 格式。未知字段不是扩展机制：外层封装保留它们，不代表嵌套字段会被接受或可执行。

## editorial--master-css-server-usage \{#copy-editorial--master-css-server-usage\}


渲染前提供编译后 manifest。让 emitted-global 与水合元数据和交付客户端的 CSS 一致，可复用会话完成后须释放。完整 HTML 示例见[渲染模式](/guide/rendering-modes)。

`createServerRenderer()` 跨渲染缓存规则：manifest 变更时须重新创建，长期运行服务器须限制 `maxCachedClasses`。自定义宿主可将页面可能链接的最终 `stylesheets`，以 `@master/css-compiler/stylesheet` 的 `describeLinkedStylesheet()` 返回的 `{ href, css, imports }` 形式，搭配供解析的 `documentURL` 传入；样式表已交付的主题变量与原生关键帧不会在 `style#master-css` 重复输出。渲染独立追踪每个关键帧定义，包括不同层或条件下的同名定义。
