## editorial-mastercss_lint_project-purpose \{#copy-editorial-mastercss_lint_project-purpose\}

Run native class diagnostics over selected files. In lint payload v5, `coverage.checkedFiles` lists checked inputs, `summary.checkedFiles` counts them, and `summary.filesWithDiagnostics` counts files with diagnostics. `files` contains diagnostic results only. `coverage.status` is `complete` or `no-inputs`; zero diagnostics with no inputs does not verify source. `coverage.description` explains these fields: manifest stylesheet entries are not linted source inputs. Manifest failures remain MCP error results. Use the project’s ESLint command separately for its parser, plugin settings, and team rules.

## editorial-mastercss_lint_project-lifecycle \{#copy-editorial-mastercss_lint_project-lifecycle\}

This operation does not write workspace files.

## editorial-mastercss_lint_content-purpose \{#copy-editorial-mastercss_lint_content-purpose\}

Check an unsaved source buffer with the native class diagnostics and the connected workspace’s manifest. Lint payload v5 reports its virtual path in `coverage.checkedFiles` and `summary.checkedFiles: 1`, even when clean. `summary.filesWithDiagnostics` is zero for a clean buffer, and `files` is then empty. Coverage describes this buffer and the enabled lint rules, not browser behavior or the whole project.

## editorial-mastercss_lint_content-lifecycle \{#copy-editorial-mastercss_lint_content-lifecycle\}

This operation does not write workspace files.

## editorial-mastercss_preview_fixes-purpose \{#copy-editorial-mastercss_preview_fixes-purpose\}

Prepare a reviewable diff for native lint fixes or generated CSS output. This request does not apply its changes.

## editorial-mastercss_preview_fixes-lifecycle \{#copy-editorial-mastercss_preview_fixes-lifecycle\}

Workspace files stay unchanged until `mastercss_apply_preview`. A nonempty preview stores a token in this server process; expiry, restart, or successful application requires a new preview. An unchanged result has no confirmation token.

## editorial-mastercss_preview_directive_format-purpose \{#copy-editorial-mastercss_preview_directive_format-purpose\}

Format directives in a source buffer or create a file-formatting preview. Content mode returns formatted text directly and does not create an apply token.

## editorial-mastercss_preview_directive_format-lifecycle \{#copy-editorial-mastercss_preview_directive_format-lifecycle\}

Content mode does not write files or store a token. In file mode, workspace files stay unchanged until `mastercss_apply_preview`. A nonempty preview stores a token in this server process; expiry, restart, or successful application requires a new preview. An unchanged result has no confirmation token.

## editorial-mastercss_apply_preview-purpose \{#copy-editorial-mastercss_apply_preview-purpose\}

Apply the exact changes from a reviewed preview in the same running server session. This tool writes workspace files.

## editorial-mastercss_apply_preview-lifecycle \{#copy-editorial-mastercss_apply_preview-lifecycle\}

The server validates all original file hashes and writable paths before writing the proposed contents. Successful application consumes the token. File writes are sequential; this is not a transactional multi-file rollback mechanism. Run project checks and inspect the changed UI afterward.

## results-0 \{#copy-results-0\}

Every tool returns a version 3 object with `metadata`, `diagnostics` and a required `result`. Success has `result: { status: 'success', data }`; failure has `result: { status: 'error', error: { code, message } }` and also sets MCP `isError`. JSON text and `structuredContent` contain the same object; validate both branches with the tool's `outputSchema`.

## results-1 \{#copy-results-1\}

`metadata` reports package, language and binding versions, the context actually used, the manifest fingerprint, entries and dependencies; unavailable values are null or empty arrays. Project context is the default: a missing entry or failed compilation is an error, never a silent switch to the preset. Pass `context: 'preset'` explicitly for preset-only queries.

## results-2 \{#copy-results-2\}

Class inspection reports `matchStatus`, `cssSyntaxStatus`, `cssValueStatus` and `browserSupport` separately, and each check record names its version, phase and scope. A CSS grammar error differs from an unknown future capability, `var()` does not establish a computed value, and `browserSupport` stays `not-checked` unless a browser check ran. Known CSS math types are checked without computing lengths or converting units; distinct token definitions stay ambiguous even when their values are equal.

## results-3 \{#copy-results-3\}

Markdown and MDX extraction separates live markup and code from display text and returns original UTF-16 ranges with inclusion or exclusion reasons; the CLI, editor and MCP share the same Rust extraction and matching. CLI report versions are independent of this envelope. In MCP payloads `root` is the configured workspace root; in CLI reports `cwd` is the command root.

## results-4 \{#copy-results-4\}

Project comparison: call `mastercss_scan_project` with `includeSnapshot: true` before and after editing, then pass both `result.data.snapshot` objects to `mastercss_css_compare` as `beforeSnapshot` and `afterSnapshot`; they cannot be mixed with class, content, `filePath` or `context` inputs. The result is `{ version: 3, mode: 'project', comparison }`, where `comparison.version` is 1 and lists changed definitions, known consumers and files, before/after rules, native references, output assets, delivery order and `coverage`. Native consumers are conservative at stylesheet granularity.

## results-5 \{#copy-results-5\}

Design-system inspection: `mastercss_scan_project.designSystem` takes the [design-system options](/reference/tools/cli#design-system-options) object and cannot be combined with `context: 'preset'`. The version 1 report in `result.data.designSystem` lists authored `var()` references with source ranges, selector and at-rule ancestry, importers, token-family collisions, component attribute vocabulary (`components`) and policy diagnostics; add `routeStylesheets` globs for stylesheets imported from JavaScript; read `project.routeStylesheets`, `project.excluded` and `coverage`. An unregistered custom property can still resolve through native CSS and is not automatically an error.

## body-13 \{#copy-body-13\}

A preview records the original file identities and proposed contents in one server process. It does not reserve a file or follow subsequent edits. A nonempty file preview returns `confirmToken` and `expiresAt`; unchanged results and in-memory formatting do not. Apply validates token lifetime, workspace containment and every original file before writing. Successful application consumes the token. Writes are sequential, so this is not a transactional rollback guarantee.
