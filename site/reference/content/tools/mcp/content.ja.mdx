## editorial-mastercss_lint_project-purpose \{#copy-editorial-mastercss_lint_project-purpose\}


選択ファイルにネイティブのクラス診断を実行します。lint ペイロード v5 は `coverage.checkedFiles` に検査入力、`summary.checkedFiles` に件数、`summary.filesWithDiagnostics` に診断のある件数を示します。`files` は診断結果だけです。`coverage.status` は `complete` または `no-inputs` で、入力なしの診断ゼロはソースの検証ではありません。`coverage.description` が説明するように manifest のエントリーは lint したソースではありません。manifest 失敗は MCP エラーのままです。プロジェクトのパーサー、プラグイン設定、チーム規則には別途その ESLint コマンドを使います。

## editorial-mastercss_lint_project-lifecycle \{#copy-editorial-mastercss_lint_project-lifecycle\}


ワークスペースのファイルは書きません。

## editorial-mastercss_lint_content-purpose \{#copy-editorial-mastercss_lint_content-purpose\}


未保存のソースバッファーをネイティブ診断と接続ワークスペースの manifest で調べます。lint ペイロード v5 は問題がなくても `coverage.checkedFiles` に仮想パスを示し、`summary.checkedFiles: 1` を報告します。問題がなければ `summary.filesWithDiagnostics` はゼロ、`files` は空です。対象はこのバッファーと有効な lint 規則であり、ブラウザー動作や全プロジェクトではありません。

## editorial-mastercss_lint_content-lifecycle \{#copy-editorial-mastercss_lint_content-lifecycle\}


ワークスペースのファイルは書きません。

## editorial-mastercss_preview_fixes-purpose \{#copy-editorial-mastercss_preview_fixes-purpose\}

## editorial-mastercss_preview_fixes-lifecycle \{#copy-editorial-mastercss_preview_fixes-lifecycle\}


`mastercss_apply_preview` までファイルは変わりません。空でないプレビューはこのサーバープロセスにトークンを保存し、期限切れ、再起動、適用成功後は再プレビューが必要です。未変更の結果には確認トークンがありません。

## editorial-mastercss_preview_directive_format-purpose \{#copy-editorial-mastercss_preview_directive_format-purpose\}


ソースバッファーのディレクティブを整形するか、ファイル整形のプレビューを作ります。内容モードは整形文字列を直接返し、適用トークンは作りません。

## editorial-mastercss_preview_directive_format-lifecycle \{#copy-editorial-mastercss_preview_directive_format-lifecycle\}


内容モードはファイルもトークンも保存しません。ファイルモードでは `mastercss_apply_preview` までファイルは変わりません。空でないプレビューはサーバープロセスにトークンを保存し、期限切れ、再起動、適用成功後は再プレビューが必要です。未変更の結果には確認トークンがありません。

## editorial-mastercss_apply_preview-purpose \{#copy-editorial-mastercss_apply_preview-purpose\}


同じ稼働中サーバーセッションで、レビュー済みプレビューの変更をそのまま適用します。このツールはワークスペースのファイルを書きます。

## editorial-mastercss_apply_preview-lifecycle \{#copy-editorial-mastercss_apply_preview-lifecycle\}


サーバーは提案内容を書く前に全元ファイルのハッシュと書き込み可能パスを検証します。成功でトークンを消費します。ファイルは逐次書き込みで、複数ファイルのトランザクション型ロールバックではありません。適用後にプロジェクトの検査と変更 UI の確認を行ってください。

## results-0 \{#copy-results-0\}


全ツールは `metadata`、`diagnostics`、必須の `result` を含むバージョン 3 オブジェクトを返します。成功は `result: { status: 'success', data }`、失敗は `result: { status: 'error', error: { code, message } }` で、MCP の `isError` も設定します。JSON テキストと `structuredContent` は同じオブジェクトです。両分岐をツールの `outputSchema` で検証します。

## results-1 \{#copy-results-1\}


`metadata` はパッケージ・言語・バインディングのバージョン、実際の文脈、manifest の指紋、エントリー、依存先を報告し、取得不能値は null または空配列です。既定はプロジェクト文脈で、エントリー欠落やコンパイル失敗はエラーとなり、暗黙にプリセットへ切り替えません。プリセットのみの検索は `context: 'preset'` を明示します。

## results-2 \{#copy-results-2\}


クラス検査は `matchStatus`、`cssSyntaxStatus`、`cssValueStatus`、`browserSupport` を別々に報告し、各記録にバージョン、段階、スコープを示します。CSS 文法エラーと未知の将来機能は別で、`var()` は計算値の確定を意味せず、ブラウザー検査を実行しなければ `browserSupport` は `not-checked` です。既知の CSS 数学型を調べますが長さの計算や単位変換はせず、別々のトークン定義は同値でも曖昧なままです。

## results-3 \{#copy-results-3\}


Markdown と MDX の抽出は有効なマークアップ・コードと表示テキストを分け、元の UTF-16 範囲と包含・除外理由を返します。CLI、エディター、MCP は同じ Rust の抽出と一致処理を共有します。CLI レポートのバージョンはこのエンベロープと独立です。MCP の `root` は設定したワークスペースルート、CLI の `cwd` はコマンドのルートです。

## results-4 \{#copy-results-4\}


プロジェクト比較では編集前後に `includeSnapshot: true` で `mastercss_scan_project` を呼び、両 `result.data.snapshot` を `beforeSnapshot` と `afterSnapshot` として `mastercss_css_compare` に渡します。class、content、`filePath`、`context` 入力とは混在できません。結果は `{ version: 3, mode: 'project', comparison }` で、`comparison.version` は 1。変更定義、既知の参照元とファイル、前後の規則、ネイティブ参照、出力アセット、配信順、`coverage` を列挙します。ネイティブの参照元はスタイルシート単位で保守的に扱います。

## results-5 \{#copy-results-5\}


デザインシステム検査では `mastercss_scan_project.designSystem` に[デザインシステムのオプション](/reference/tools/cli#design-system-options)を渡し、`context: 'preset'` とは併用できません。`result.data.designSystem` のバージョン 1 レポートは、記述した `var()` 参照とソース範囲、セレクターと at-rule の祖先、インポート元、トークンファミリーの衝突、コンポーネント属性語彙（`components`）、方針診断を示します。JavaScript から読み込む CSS は `routeStylesheets` の glob に加え、`project.routeStylesheets`、`project.excluded`、`coverage` を読みます。未登録のカスタムプロパティもネイティブ CSS で解決可能で、自動的なエラーではありません。

## body-13 \{#copy-body-13\}


プレビューは 1 サーバープロセスに元ファイルの同一性と提案内容を記録し、ファイルの予約や後の編集の追跡はしません。空でないファイルプレビューは `confirmToken` と `expiresAt` を返し、未変更結果やメモリー内整形は返しません。適用前に有効期限、ワークスペース内のパス、全元ファイルを検証します。成功するとトークンを消費します。書き込みは逐次で、トランザクション型ロールバックは保証しません。
