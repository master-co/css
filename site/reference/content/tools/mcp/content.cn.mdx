## editorial-mastercss_lint_project-purpose \{#copy-editorial-mastercss_lint_project-purpose\}


对所选文件运行原生类诊断。在 lint 载荷 v5 中，`coverage.checkedFiles` 列出已检查输入，`summary.checkedFiles` 统计数量，`summary.filesWithDiagnostics` 统计有诊断文件。`files` 仅含诊断结果。`coverage.status` 为 `complete` 或 `no-inputs`；无输入时的零诊断不代表源已验证。`coverage.description` 解释这些字段：manifest 样式表入口不是已 lint 源输入。manifest 失败仍为 MCP 错误结果。项目解析器、插件设置与团队规则请另用其 ESLint 命令。

## editorial-mastercss_lint_project-lifecycle \{#copy-editorial-mastercss_lint_project-lifecycle\}


此操作不写入工作区文件。

## editorial-mastercss_lint_content-purpose \{#copy-editorial-mastercss_lint_content-purpose\}


使用原生类诊断及已连接工作区的 manifest 检查未保存源缓冲区。lint 载荷 v5 即使无问题，也会在 `coverage.checkedFiles` 报告虚拟路径，并报告 `summary.checkedFiles: 1`。无问题缓冲区的 `summary.filesWithDiagnostics` 为零，`files` 为空。覆盖范围仅描述此缓冲区与启用的 lint 规则，并非浏览器行为或整个项目。

内容模式不写入文件或保存 token。文件模式中工作区文件在 `mastercss_apply_preview` 前保持不变。非空预览在此服务器进程保存 token；过期、重启或成功应用后须重新预览。无变更结果不含确认 token。

## editorial-mastercss_apply_preview-purpose \{#copy-editorial-mastercss_apply_preview-purpose\}

## results-0 \{#copy-results-0\}


每个工具返回版本 3 对象，包含 `metadata`、`diagnostics` 及必填 `result`。成功为 `result: { status: 'success', data }`；失败为 `result: { status: 'error', error: { code, message } }`，并设置 MCP `isError`。JSON 文本与 `structuredContent` 包含同一对象；请按工具 `outputSchema` 验证两个分支。

## results-1 \{#copy-results-1\}


`metadata` 报告包、语言与绑定版本、实际使用的上下文、manifest 指纹、入口和依赖；无法获取的值为 null 或空数组。默认为项目上下文：缺少入口或编译失败均报错，绝不静默改用预设。仅查询预设时，请显式传入 `context: 'preset'`。

## results-2 \{#copy-results-2\}


类检查分别报告 `matchStatus`、`cssSyntaxStatus`、`cssValueStatus` 和 `browserSupport`，每项记录均标明版本、阶段与范围。CSS 语法错误不同于未知未来能力；`var()` 不代表已确定计算值，未实际运行浏览器检查时 `browserSupport` 保持 `not-checked`。已知 CSS 数学类型会被检查，但不计算长度或转换单位；不同令牌定义即使值相同仍有歧义。

## results-3 \{#copy-results-3\}


Markdown 与 MDX 提取将实际标记、代码与展示文本分开，返回原始 UTF-16 范围及包含或排除原因；CLI、编辑器与 MCP 共用相同 Rust 提取和匹配。CLI 报告版本独立于此封装。MCP 载荷的 `root` 是配置的工作区根目录；CLI 报告的 `cwd` 是命令根目录。

## results-4 \{#copy-results-4\}


项目比较：编辑前后分别以 `includeSnapshot: true` 调用 `mastercss_scan_project`，再将两个 `result.data.snapshot` 对象以 `beforeSnapshot` 和 `afterSnapshot` 传入 `mastercss_css_compare`；不可混用 class、content、`filePath` 或 `context` 输入。结果为 `{ version: 3, mode: 'project', comparison }`，其中 `comparison.version` 为 1，列出变更定义、已知引用方与文件、前后规则、原生引用、输出资源、交付顺序及 `coverage`。原生引用方按样式表粒度保守分析。

## results-5 \{#copy-results-5\}


设计系统检查：`mastercss_scan_project.designSystem` 接受[设计系统选项](/reference/tools/cli#design-system-options)对象，不可搭配 `context: 'preset'`。`result.data.designSystem` 中的版本 1 报告列出原有 `var()` 引用及源范围、选择器与 at-rule 祖先、导入方、令牌家族冲突、组件属性词汇（`components`）及策略诊断；从 JavaScript 导入的样式表请添加 `routeStylesheets` glob，并阅读 `project.routeStylesheets`、`project.excluded` 和 `coverage`。未注册自定义属性仍可能通过原生 CSS 解析，不会自动视为错误。

## body-13 \{#copy-body-13\}


预览在单个服务器进程记录原文件身份与建议内容，不锁定文件，也不追踪后续编辑。非空文件预览返回 `confirmToken` 和 `expiresAt`；无变更结果及内存格式化不返回。应用前验证 token 期限、路径位于工作区内及每个原文件。成功应用消耗 token。写入按序执行，因此不保证事务回滚。
