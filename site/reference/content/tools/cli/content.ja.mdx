## editorial-suggest-notes-0 \{#copy-editorial-suggest-notes-0\}


引用符付きの宣言ブロック 1 つか `--stdin` のどちらか一方を渡します。プロジェクトルートは `--cwd` で選び、既定は現在のディレクトリです。`--` で始まる引数には stdin を使うか、引数の前に `--` を置きます。入力は宣言だけで、セレクターや外側の波括弧を含めないでください。

## editorial-suggest-notes-1 \{#copy-editorial-suggest-notes-1\}


バージョン 1 の JSON エンベロープは `cwd`、`manifest`、`result`、`validation`、`diagnostics` を含みます。`manifest.entries` は検出した Master CSS エントリーの一覧で、なければ既定のプリセットで提案します。検出済みエントリーの読み込み失敗はエラーで、プリセットには切り替えません。プロジェクトのトークンやユーティリティ上書きに頼る前にエントリーを確認してください。

## editorial-suggest-notes-2 \{#copy-editorial-suggest-notes-2\}


`result` はクラス、生成 CSS、`remainingCss`、注記、検証を含むバージョン付き宣言提案レポートです。`preserved` は元ブロック全体を保って正常終了するため、その CSS を残して注記を読んでください。`suggested` は宣言の対応を調べ、カスケードやブラウザー描画は検証しません。クラス別の診断は `className` で特定し、`validation` は一致、CSS 構文、CSS 値、ブラウザー対応を分けます。

## editorial-suggest-notes-3 \{#copy-editorial-suggest-notes-3\}


レポートは常に JSON で stdout に出力します。エラーは stderr にも書き、終了ステータスは 1 です。入力、manifest、実行の失敗は `result: null` を返し、既知の無効な提案 CSS は提案を保ちながらエラーにします。未知の値はエラーではなく、ブラウザー対応は `not-checked` のままです。未知のフラグなど引数解析エラーには通常の CLI ヘルプ診断を使います。

## editorial-generate-notes-0 \{#copy-editorial-generate-notes-0\}


`--output` は CSS エントリー名を指定し、既定は `master.css` です。同じ場所のスタイルシートとリソースも公開してください。順序、条件、URL の所有権を保つため、ローカルインポートやリソースは別ファイルの場合があります。入口のコピーだけでは不完全です。境界は[インポート](/reference/directives/imports)を参照してください。

## editorial-generate-notes-1 \{#copy-editorial-generate-notes-1\}


`--strict` はアセット公開前に既知の CSS 構文・値エラーを拒否します。未知のブラウザー機能は対応確認済みとは扱いません。`--prune-native-css` はプロジェクト所有ファイルを対象にし、パッケージは自身の方針を保ち、`@preserve native` がローカルで優先します。規則とキーフレームの動作は[ネイティブ CSS のプルーニング](/reference/directives/pruning)を参照してください。

## editorial-generate-notes-2 \{#copy-editorial-generate-notes-2\}


`--no-export` は CSS 結果を 1 つ表示し、参照リソースは公開しません。必要なスタイルシートとリソース URL の基準は自身で保ってください。`--verbose 0` は進捗ログを抑えます。監視は Ctrl+C で停止できます。監視が動いていても再ビルドが失敗し、最後の成功出力を保持している場合があります。

## editorial-lint-notes-0 \{#copy-editorial-lint-notes-0\}


Lint レポート v5 は検査済み入力と診断ファイルを分けます。`coverage.checkedFiles` は問題のないファイルや stdin 仮想パスを含む全入力、`summary.checkedFiles` はその件数、`summary.filesWithDiagnostics` は診断のある検査済みファイル数です。`files` 配列は診断結果だけのままなので、空でも未実行とは限りません。

## editorial-lint-notes-1 \{#copy-editorial-lint-notes-1\}


診断ゼロを解釈する前に `coverage.status` を読みます。`complete` は選択入力の検査済み、`no-inputs` は一致する入力なし、`not-run` は manifest 読み込みがソース lint を妨げた状態です。manifest 診断は検査済みソースに数えません。`--fix` の診断数は再検査した内容を表します。問題のない stdin もディスクファイルを作らず 1 入力に数えます。stylish は stderr にカバレッジ概要を含めます。

## editorial-lint-notes-2 \{#copy-editorial-lint-notes-2\}


`coverage.description` は結果を説明し、manifest のスタイルシートエントリーと lint したソース入力を区別します。`manifest.entries` が空でもソース検査なしとは限りません。対象は選択入力と有効な lint 規則だけで、ブラウザー動作やプロジェクト全体の検査は保証しません。`no-inputs` で終了ステータスがゼロでも、ソース検査成功の証拠ではありません。

## editorial-inspect-notes-0 \{#copy-editorial-inspect-notes-0\}


### プロジェクトのスナップショット \{#project-snapshots\}

## editorial-inspect-notes-1 \{#copy-editorial-inspect-notes-1\}


`--snapshot` は解決済みプロジェクトのスナップショットを stdout に書きます。変更前に保存し、`--compare` で現在のプロジェクトと比較します。両モードは同時使用できず、常に JSON を返します。定義と既知の参照元を比較し、ブラウザーのピクセルは比較しません。

## editorial-inspect-notes-2 \{#copy-editorial-inspect-notes-2\}


```sh
master-css inspect --snapshot > before.json
# After the intended source change:
master-css inspect --compare before.json > comparison.json
```

## editorial-inspect-notes-3 \{#copy-editorial-inspect-notes-3\}


### デザインシステムのオプション \{#design-system-options\}

## editorial-inspect-notes-4 \{#copy-editorial-inspect-notes-4\}


`--design-system-options` は JSON ファイルを読み、`--design-system` が必要です。同じオブジェクトを MCP の `mastercss_scan_project` の `designSystem` 入力（プロジェクト文脈のみ）や言語サーバーの `designSystem` 設定にも渡せ、3 者は同じレポートを返します。

## editorial-inspect-notes-5 \{#copy-editorial-inspect-notes-5\}


```json name=design-system.json
{
  "version": 1,
  "metadata": {
    "--color-brand-old": {
      "description": "Previous brand color",
      "deprecated": true,
      "replacement": "--color-brand"
    }
  },
  "rawValuePolicy": {
    "requireProperties": ["color", "background-color"]
  }
}
```

## editorial-inspect-notes-6 \{#copy-editorial-inspect-notes-6\}


| フィールド | 契約 |
| --- | --- |
| `version` | 必須。`1`。 |
| `metadata` | 有効なプロジェクトのトークン名から `description`、`deprecated`、`replacement` への任意のマップ。非推奨警告は記述した CSS の `var()` 参照を対象にし、置換はレビューの提案で自動適用しません。 |
| `rawValuePolicy.requireProperties` | 任意。これらのトークン対応プロパティのネイティブ宣言はトークンを使う必要があります。代替値を含む完全な `var()` 成分は対象外です。方針を省略すると生の値を検査しません。 |

## editorial-inspect-notes-7 \{#copy-editorial-inspect-notes-7\}


未知のフィールドは拒否します。オプションは検査レポートだけに作用し、生成 CSS やブラウザープログラムには影響しません。`components` は `.button[data-variant="primary"]` のように同じ複合セレクター内の属性セレクターから各クラスの属性語彙を列挙します。正確な `values` と単独の `[name]` の有無（`presence`）を含み、`:where()` などの関数型疑似クラス内の属性は集めません。対象はプロジェクトのエントリーとローカル依存先、およびソースパスで指定したスタイルシートです（`project.routeStylesheets` にインポート元なしで記載）。`--design-system` ではソースパスが `.css` に一致する必要があります。パッケージ CSS とルート外のファイルは除外し、`@reference` 辺は配信せず定義文脈を供給し、`browser` は `not-checked` のままです。

## body-28 \{#copy-body-28\}

## body-29 \{#copy-body-29\}


CSS の公開やソースの書き換えなしに、ソース検出、スタイルシートエントリー、不足 CSS を報告します。`--classes` はスキャン結果を検査し、セーフリストには加えません。空の結果を解釈する前に診断とカバレッジを読んでください。
