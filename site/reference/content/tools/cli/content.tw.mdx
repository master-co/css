## editorial-suggest-notes-1 \{#copy-editorial-suggest-notes-1\}


版本 1 JSON 封套包含 `cwd`、`manifest`、`result`、`validation` 與 `diagnostics`。`manifest.entries` 列出找到的 Master CSS 入口；若完全未找到，建議結果會使用預設集。已找到但載入失敗的入口會造成錯誤，絕不改用預設集。依賴專案 token 或 utility 覆寫前，請先檢查入口。

## editorial-suggest-notes-2 \{#copy-editorial-suggest-notes-2\}


`result` 是具版本的宣告建議報告，包含 class、生成 CSS、`remainingCss`、註記與驗證。`preserved` 結果保留整個原始區塊，並成功結束；請保留 CSS 並閱讀註記。`suggested` 結果檢查宣告對應，不檢查階層串接或瀏覽器渲染。class 專屬診斷以 `className` 識別；`validation` 分開呈現比對、CSS 語法、CSS 值與瀏覽器支援。

## editorial-suggest-notes-3 \{#copy-editorial-suggest-notes-3\}


報告一律以 JSON 寫入 stdout。錯誤也寫入 stderr，並以狀態 1 結束。輸入、manifest 或執行失敗會回傳 `result: null`；已知無效的建議 CSS 會產生錯誤，但仍保留提案。未知值不視為錯誤，瀏覽器支援維持 `not-checked`。未知旗標等引數剖析錯誤，使用一般 CLI 說明診斷。

## editorial-generate-notes-0 \{#copy-editorial-generate-notes-0\}


`--output` 指定 CSS 入口名稱（預設 `master.css`）。同層樣式表與資源也須一併發布；為保留順序、條件與 URL 所有權，本地匯入與資源可能維持獨立檔案。只複製入口可能不完整。樣式表邊界請見[匯入](/reference/directives/imports)。

## editorial-generate-notes-1 \{#copy-editorial-generate-notes-1\}


`--strict` 在發布資源前拒絕已知 CSS 語法或值錯誤。未知瀏覽器能力不視為已驗證支援。`--prune-native-css` 讓專案擁有的檔案參與原生修剪；套件檔案維持自身政策，`@preserve native` 在本地優先。[原生 CSS 修剪](/reference/directives/pruning)定義規則與關鍵影格行為。

## editorial-generate-notes-2 \{#copy-editorial-generate-notes-2\}


`--no-export` 列印一份 CSS 結果，不發布其參照資源；須自行保留所需樣式表與資源 URL 的基準。`--verbose 0` 隱藏進度記錄。Ctrl+C 可停止監看模式；監看程序仍運作時，重建仍可能失敗並保留上次成功匯出。

## editorial-lint-notes-0 \{#copy-editorial-lint-notes-0\}


Lint 報告 v5 將已檢查輸入與有診斷的檔案分開。`coverage.checkedFiles` 列出所有傳入 lint 的輸入，包含無問題檔案與 stdin 虛擬路徑。`summary.checkedFiles` 計算這些輸入；`summary.filesWithDiagnostics` 計算有診斷的已檢查檔案。`files` 陣列仍只包含診斷結果；空陣列不表示沒有執行檢查。

## editorial-lint-notes-1 \{#copy-editorial-lint-notes-1\}


解讀零診斷前先讀取 `coverage.status`：`complete` 表示已檢查所選輸入，`no-inputs` 表示沒有符合的來源輸入，`not-run` 表示 manifest 載入阻擋了來源 lint。manifest 診斷不計入已檢查來源檔案。使用 `--fix` 時，診斷數量描述重新檢查後的內容。無問題的 stdin 仍算一個輸入，不會建立磁碟檔案。stylish 輸出會在 stderr 包含涵蓋範圍摘要。

## editorial-lint-notes-2 \{#copy-editorial-lint-notes-2\}


`coverage.description` 說明結果，並區分 manifest 樣式表入口與已 lint 的來源輸入。空 `manifest.entries` 不表示沒有執行來源檢查。涵蓋範圍只適用所選輸入與啟用的 lint 規則，不驗證瀏覽器行為，也不證明整個專案都已檢查。`no-inputs` 搭配零結束狀態，不是來源檢查成功的證據。

## editorial-inspect-notes-1 \{#copy-editorial-inspect-notes-1\}

## editorial-inspect-notes-3 \{#copy-editorial-inspect-notes-3\}


### 設計系統選項 \{#design-system-options\}

## editorial-inspect-notes-4 \{#copy-editorial-inspect-notes-4\}


`--design-system-options` 讀取 JSON 檔案，且必須搭配 `--design-system`。MCP `mastercss_scan_project` 的 `designSystem` 輸入（僅限專案情境），以及語言伺服器的 `designSystem` 設定也接受同一物件；三者回傳相同報告。

## editorial-inspect-notes-5 \{#copy-editorial-inspect-notes-5\}


```json name=design-system.json
{
  "version": 1,
  "metadata": {
    "--color-brand-old": {
      "description": "Previous brand color",
      "deprecated": true,
      "replacement": "--color-brand"
    }
  },
  "rawValuePolicy": {
    "requireProperties": ["color", "background-color"]
  }
}
```

## editorial-inspect-notes-6 \{#copy-editorial-inspect-notes-6\}


| 欄位 | 契約 |
| --- | --- |
| `version` | 必填；`1`。 |
| `metadata` | 選填對應表，將目前專案的 token 名稱對應至 `description`、`deprecated` 與 `replacement`。棄用警告涵蓋撰寫的 CSS `var()` 參照；替換值是檢閱建議，絕不自動套用。 |
| `rawValuePolicy.requireProperties` | 選填。這些有 token 支援的屬性，其原生宣告必須使用 token；完整 `var()` 元件（含備援值）不受限制。省略政策就不檢查原始值。 |

## editorial-inspect-notes-7 \{#copy-editorial-inspect-notes-7\}


不識別的欄位會被拒絕。選項只影響檢查報告，絕不影響生成 CSS 或瀏覽器程式。`components` 從同一複合選擇器中的屬性選擇器，列出各 class 的屬性詞彙，例如 `.button[data-variant="primary"]`：包含精確 `values` 與是否存在裸 `[name]` 選擇器（`presence`）；不收集 `:where()` 這類函式偽類別內的屬性。報告涵蓋專案入口及本地相依檔案，也包含以來源路徑指定的樣式表（列於 `project.routeStylesheets`，沒有匯入端）；使用 `--design-system` 時，來源路徑必須符合 `.css` 檔案。套件 CSS 與專案根目錄外檔案排除；`@reference` 邊提供定義情境但不交付，`browser` 維持 `not-checked`。

## body-27 \{#copy-body-27\}

## body-28 \{#copy-body-28\}

## body-29 \{#copy-body-29\}
