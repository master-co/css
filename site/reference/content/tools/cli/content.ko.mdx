# Reference prose: tools/cli

## editorial-suggest-examples-0-description \{#copy-editorial-suggest-examples-0-description\}


활성 프로젝트 manifest를 사용해 선언에서 클래스를 제안합니다.

## editorial-suggest-examples-1-description \{#copy-editorial-suggest-examples-1-description\}


stdin에서 선언 블록을 읽습니다.

## editorial-suggest-notes-0 \{#copy-editorial-suggest-notes-0\}


따옴표로 감싼 선언 블록 하나 또는 `--stdin` 중 하나만 사용하세요. `--cwd`로 프로젝트 루트를 선택하며 기본값은 현재 디렉터리입니다. `--`로 시작하는 인수는 stdin을 사용하거나 인수 앞에 `--`를 두세요. 입력에는 선언만 포함하고 선택자나 바깥 중괄호는 넣지 마세요.

## editorial-suggest-notes-1 \{#copy-editorial-suggest-notes-1\}


버전 1 JSON 응답은 `cwd`, `manifest`, `result`, `validation`, `diagnostics`를 포함합니다. `manifest.entries`는 발견한 Master CSS 진입점 목록이며 없으면 기본 프리셋으로 제안합니다. 발견한 진입점의 로딩 실패는 오류이며 프리셋으로 대체하지 않습니다. 프로젝트 토큰이나 유틸리티 재정의에 의존하기 전에 진입점을 확인하세요.

## editorial-suggest-notes-2 \{#copy-editorial-suggest-notes-2\}


`result`는 클래스, 생성 CSS, `remainingCss`, 참고 사항, 검증을 포함한 버전이 있는 선언 제안 보고서입니다. `preserved` 결과는 원본 블록 전체를 유지하고 성공으로 종료하므로 CSS를 보존하고 참고 사항을 읽으세요. `suggested`는 선언 대응을 검사하며 캐스케이드나 브라우저 렌더링은 검사하지 않습니다. 클래스별 진단은 `className`으로 식별하며 `validation`은 일치, CSS 구문, CSS 값, 브라우저 지원을 구분합니다.

## editorial-suggest-notes-3 \{#copy-editorial-suggest-notes-3\}


보고서는 항상 JSON으로 stdout에 출력합니다. 오류는 stderr에도 쓰며 상태 1로 종료합니다. 입력, manifest, 실행 실패는 `result: null`을 반환합니다. 제안된 CSS에 알려진 오류가 있으면 제안을 유지하면서 오류를 반환합니다. 알 수 없는 값은 오류가 아니며 브라우저 지원은 `not-checked`로 남습니다. 알 수 없는 플래그 같은 인수 파서 오류는 일반 CLI 도움말 진단을 사용합니다.

## editorial-generate-notes-0 \{#copy-editorial-generate-notes-0\}


`--output`은 CSS 진입점 이름을 지정하며 기본값은 `master.css`입니다. 함께 있는 스타일시트와 리소스 에셋도 게시하세요. 순서, 조건, URL 소유권을 유지하려고 로컬 가져오기와 리소스가 별도 파일로 남을 수 있습니다. 진입점만 복사하면 불완전할 수 있습니다. 경계는 [가져오기](/reference/directives/imports)를 참고하세요.

## editorial-generate-notes-1 \{#copy-editorial-generate-notes-1\}


`--strict`는 에셋 게시 전에 알려진 CSS 구문이나 값 오류를 거부합니다. 알 수 없는 브라우저 기능을 검증된 지원으로 취급하지 않습니다. `--prune-native-css`는 프로젝트 소유 파일을 네이티브 가지치기에 참여시키며 패키지 파일은 자체 정책을 유지하고 `@preserve native`가 로컬에서 우선합니다. 규칙과 키프레임 동작은 [네이티브 CSS 가지치기](/reference/directives/pruning)에 정의되어 있습니다.

## editorial-generate-notes-2 \{#copy-editorial-generate-notes-2\}


`--no-export`는 CSS 결과 하나를 출력하고 참조 리소스를 게시하지 않습니다. 필요한 스타일시트와 리소스 URL 기준을 직접 보존하세요. `--verbose 0`은 진행 로그를 숨깁니다. Ctrl+C로 감시를 중단합니다. 감시자가 실행 중이어도 재빌드가 실패하여 마지막 성공 내보내기를 유지할 수 있습니다.

## editorial-lint-notes-0 \{#copy-editorial-lint-notes-0\}


Lint 보고서 v5는 검사한 입력과 진단 파일을 구분합니다. `coverage.checkedFiles`는 문제가 없는 파일과 stdin 가상 경로를 포함한 모든 입력을 나열합니다. `summary.checkedFiles`는 입력 수이고 `summary.filesWithDiagnostics`는 진단이 있는 검사 파일 수입니다. `files` 배열은 진단 결과만 포함하므로 빈 배열이 검사를 하지 않았다는 뜻은 아닙니다.

## editorial-lint-notes-1 \{#copy-editorial-lint-notes-1\}


진단 0을 해석하기 전에 `coverage.status`를 읽으세요. `complete`는 선택 입력을 검사했다는 뜻이고 `no-inputs`는 일치 소스 입력이 없다는 뜻이며 `not-run`은 manifest 로딩이 소스 lint를 막았다는 뜻입니다. manifest 진단은 검사한 소스 파일에 포함하지 않습니다. `--fix`의 진단 수는 재검사한 내용을 나타냅니다. 문제가 없는 stdin도 디스크 파일을 만들지 않고 입력 하나로 셉니다. stylish 출력은 stderr에 검사 범위 요약을 포함합니다.

## editorial-lint-notes-2 \{#copy-editorial-lint-notes-2\}


`coverage.description`은 결과를 설명하고 manifest 스타일시트 진입점과 lint한 소스 입력을 구분합니다. 빈 `manifest.entries`가 소스 검사를 하지 않았다는 뜻은 아닙니다. 검사 범위는 선택 입력과 활성 lint 규칙에만 적용되며 브라우저 동작이나 전체 프로젝트 검사를 증명하지 않습니다. `no-inputs`의 종료 상태 0은 소스 검사 성공의 증거가 아닙니다.

## editorial-inspect-notes-0 \{#copy-editorial-inspect-notes-0\}


### 프로젝트 스냅샷 \{#project-snapshots\}

## editorial-inspect-notes-1 \{#copy-editorial-inspect-notes-1\}


`--snapshot`은 해석된 프로젝트 스냅샷을 stdout에 씁니다. 변경 전에 저장하고 `--compare`로 현재 프로젝트와 비교하세요. 두 모드는 상호 배타적이며 항상 JSON을 반환합니다. 정의와 알려진 사용처를 비교하고 브라우저 픽셀은 비교하지 않습니다.

## editorial-inspect-notes-2 \{#copy-editorial-inspect-notes-2\}


```sh
master-css inspect --snapshot > before.json
# After the intended source change:
master-css inspect --compare before.json > comparison.json
```

## editorial-inspect-notes-3 \{#copy-editorial-inspect-notes-3\}


### 디자인 시스템 옵션 \{#design-system-options\}

## editorial-inspect-notes-4 \{#copy-editorial-inspect-notes-4\}


`--design-system-options`는 JSON 파일을 읽으며 `--design-system`이 필요합니다. MCP `mastercss_scan_project`의 `designSystem` 입력(프로젝트 맥락만)과 언어 서버의 `designSystem` 설정도 같은 객체를 받으며 세 방식은 같은 보고서를 반환합니다.

## editorial-inspect-notes-5 \{#copy-editorial-inspect-notes-5\}


```json name=design-system.json
{
  "version": 1,
  "metadata": {
    "--color-brand-old": {
      "description": "Previous brand color",
      "deprecated": true,
      "replacement": "--color-brand"
    }
  },
  "rawValuePolicy": {
    "requireProperties": ["color", "background-color"]
  }
}
```

## editorial-inspect-notes-6 \{#copy-editorial-inspect-notes-6\}


| 필드 | 규칙 |
| --- | --- |
| `version` | 필수. `1`. |
| `metadata` | 활성 프로젝트의 토큰 이름을 `description`, `deprecated`, `replacement`에 연결하는 선택적 맵. 사용 중단 경고는 작성한 CSS `var()` 참조를 다룹니다. 교체는 검토 제안이며 자동 적용되지 않습니다. |
| `rawValuePolicy.requireProperties` | 선택 사항. 이 토큰 지원 속성의 네이티브 선언은 토큰을 사용해야 합니다. 대체 값을 포함한 완전한 `var()` 구성요소는 예외입니다. 정책을 생략하면 원시 값을 검사하지 않습니다. |

## editorial-inspect-notes-7 \{#copy-editorial-inspect-notes-7\}


알 수 없는 필드는 거부합니다. 옵션은 검사 보고서에만 영향을 주고 생성 CSS나 브라우저 프로그램에는 영향을 주지 않습니다. `components`는 `.button[data-variant="primary"]`처럼 같은 복합 선택자의 속성 선택자에서 각 클래스의 속성 어휘를 나열합니다. 정확한 `values`와 단독 `[name]` 선택자 존재 여부(`presence`)를 포함하며 `:where()` 같은 함수형 의사 클래스 안의 속성은 수집하지 않습니다. 보고서는 프로젝트 진입점과 로컬 의존성, 소스 경로로 지정한 스타일시트를 다룹니다(`project.routeStylesheets`에 가져오는 주체 없이 나열). `--design-system`에서는 소스 경로가 `.css` 파일과 일치해야 합니다. 패키지 CSS와 프로젝트 루트 밖의 파일은 제외합니다. `@reference` 간선은 전달 없이 정의 맥락을 제공하며 `browser`는 `not-checked`로 남습니다.

[설정 가이드](/guide/installation#cli)로 CLI를 설치한 뒤 프로젝트 루트에서 실행하세요. generate, lint, inspect는 소스 인수 없이 일반 앱 소스를 탐색하며 명시적 경로 인수는 그 선택을 대체합니다. suggest는 CSS 선언 블록을 받습니다.

## body-26 \{#copy-body-26\}


파일을 편집하지 않고 클래스를 제안하고 생성 선언을 검증합니다. 활성 프로젝트 manifest를 사용하며 불확실한 블록은 CSS로 유지합니다. 제안을 적용하기 전에 캐스케이드와 브라우저 동작을 검토하세요.

## body-27 \{#copy-body-27\}


CSS와 관련 스타일시트 리소스를 게시합니다. `--no-export --verbose 0`은 파일 게시 없이 CSS만 출력합니다. `--watch`는 중단할 때까지 실행되며 프로세스가 살아 있어도 재빌드 오류를 확인해야 합니다.

## body-28 \{#copy-body-28\}


기본적으로 소스에 쓰지 않고 클래스 진단을 보고합니다. `--fix`는 지원하는 수정을 적용하고 `--fix-dry-run`은 적용 없이 제안을 반환합니다. stdin 내용은 가상 경로에 쓰지 않습니다.

## body-29 \{#copy-body-29\}


CSS 게시나 소스 재작성 없이 소스 탐색, 스타일시트 진입점, 누락 CSS를 보고합니다. `--classes`는 스캔 결과를 검사하며 해당 클래스를 세이프리스트에 넣지 않습니다. 빈 결과를 해석하기 전에 진단과 검사 범위를 읽으세요.
