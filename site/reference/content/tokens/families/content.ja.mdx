# Reference prose: tokens/families

## intro \{#copy-intro\}


トークンファミリーは、クラスの接頭辞、トークンの名前空間、書き込む CSS プロパティを結び付けます。これらの表は、プリセット値を持たないものも含め、プリセットに登録された全ファミリーを列挙します。

## mapping \{#copy-mapping\}


キーだけではトークンは特定できません。`p-md` では `p-` が `spacing` 名前空間を参照し、`md` が `--spacing-md` を選びます。同じキーでも、別のファミリーでは異なるトークンを選ぶことがあります。

## lookup \{#copy-lookup\}


各行は、接頭辞 → トークン名のパターン → ネイティブプロパティの順に読みます。`*` を登録済みのキーで置き換えます。リンク先の値のページには利用可能なキーがあり、名前空間の列にはそのファミリーが受け付けるトークンが示されています。

## shared \{#copy-shared\}


`font-` には、`--font-family-*`、`--font-size-*`、`--font-weight-*` に対応する別々のファミリーがあります。キーはそのうち 1 つを選べなければなりません。複数の名前空間に同じキーがあると、クラスは曖昧になり CSS を出力しません。

## registration \{#copy-registration\}


トークンは `@theme` に登録します。その外側のネイティブカスタムプロパティはキーを登録せず、新しい名前空間もユーティリティファミリーを自動では作りません。ファミリーを追加する際には、対応する `@utility` パターンを定義します。

## roles \{#copy-roles\}


`--color-text-muted` は、キー `text-muted` として `color` 名前空間に属します。カラーロールはパレットの色と同じファミリーを使い、独立したユーティリティ名前空間ではありません。

## limits \{#copy-limits\}


この索引は、トークンを参照するファミリーを説明します。`w-full` のような固定の綴りは、同じキーのトークンがあっても自身の定義を保ちます。`p(4)` のような値を直接受け取る関数や、`(padding:1rem)` のようなネイティブ宣言は、トークンを検索せずに値を受け付けます。

## title \{#copy-title\}


トークンファミリー

## description \{#copy-description\}


プリセットの全トークンファミリーについて、クラスの接頭辞、トークンの名前空間、ネイティブプロパティを確認できます。
