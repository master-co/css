## Implementation

1. A production pre-plugin uses Vite's public `preprocessCSS` with the configured Sass options, aliases/importers and dependencies. A small PostCSS preparation hook temporarily protects CSS `@import` at-rules from Vite's automatic postcss-import expansion, then restores them before printing. Rust still owns graph analysis, directives and delivery. This does not install PostCSS or implement CSS semantics in TypeScript.
2. Prepared Sass enters a loader-owned `.master-css-sass.css` identity beside the actual source path. This retains Vite's relative URL base for ordinary CSS and avoids applying `additionalData` a second time. A per-build promise cache shares source preparation and is cleared at buildStart. Root and Sass partial dependencies are watched.
3. The async compiler resolution/delivery options accept an absolute root `baseFile`, retaining the graph ID while supplying the owner for relative Node fallback imports, resources and source patterns. Imported source records carry their actual owner too. The no-custom-resolver path also respects `baseFile`; a regression initially proved it incorrectly used the process working directory.
4. Sass CSS Modules reuse the mapping and scoped CSS produced by Vite, with a private JavaScript wrapper importing the prepared CSS and exposing named/default exports. A class named `default` stays in the default mapping without creating a duplicate default export. Raw text/resource requests bypass Sass and stylesheet parsing. CSS request query suffixes, including plain `?inline`, are passed through.
5. Compiler/Vite README and the formal Site directive contract describe the bounded delivery behavior and remaining integration work. No Rust/ABI/runtime, dependency, lockfile, CI/release, or existing fixture/snapshot edits.
