## Changes

- Vite records the original root source alongside each cached preprocessing promise, asks the public `preprocessCSS` API for internal diagnostic maps and included source contents, and reuses the existing Sass dependency/cache lifecycle.
- A private adapter uses Node's built-in `SourceMap` to find the originating segment and resolves its source URL. It refines exact token columns only when the complete generated prefix/span matches original source text. Interpolated or expanded Sass reports the source segment with an explicit note when an exact range cannot be established.
- String `additionalData` maps may omit `sourcesContent`; the cached original root supplies it. A callback without a map can label modified text as the original root; mismatching contents are rejected as evidence of original coordinates. Unmapped generated content retains its preprocessed source/range and an explicit note. Supplied callback maps are covered by an actual-build control. Mapping exceptions retain the compiler diagnostic, and already-adapted error objects are not mapped twice.
- The adapter wraps style-entry/local-compose transforms and final global/inline collection composition. Compiler codes, messages and original causes remain intact; the primary mapped location is exposed through Vite `loc`. No new dependency or public API is added.
- Rust directive parsing blanks consumed reference/entry/extraction statements while preserving byte offsets and line breaks. Graph compilation uses the authored request source before reference removal, including resource relocation and metadata restoration; graph discovery/rendering contracts retain their existing representation. This corrects native/managed diagnostic ranges without moving CSS rules.
- Compiler local stylesheet finalization passes source text to its existing lowering operation. Vite/compiler README and the formal directive contract explain the proven attribution behavior and its limits.
