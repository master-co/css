# Master CSS 首頁圖示

延續「柔和玻璃、淺透視、quiet precision」的定案。依 2026-10-29 的更新，**首頁功能圖示全部使用透明明暗 WebP，包括 lint／MCP 清單小圖**。原 B 方案的小尺寸 SVG 留作構造研究，不再接入首頁。使用者的新指示優先於此基準。

適用於首頁區塊、功能卡片與 lint／MCP 細項。Hero、CTA、品牌標誌及一般操作／狀態圖示不在這套圖示的重設範圍內。

## 先辨識工作

- **新增或精修圖示**：讀 [視覺規範](references/visual-system.md) 與 [製作規範](references/production.md)，實際查看最接近題目的定案圖片，再開始繪製。
- **只調整首頁接入、尺寸或排版**：讀 [接入規範](references/site-integration.md)，重用現有圖示與元件；不因此重新生成資產。
- **只處理密集清單小圖**：先重用對應 WebP，讀接入規範的 48px lint／40px agent 用法。只有原圖在實際尺寸下無法辨識，才精修對應圖像；不要退回 SVG。

定案圖片與檔案索引列在視覺規範中，存放於 `references/approved/`。它們是可攜的實際檔案，不依賴臨時工作目錄。原始 WebP 仍可能帶少量冷色；最終呈現包含既有 `grayscale(1)`，判斷顏色時一起考慮。

## 不可丟失的設計特徵

1. **柔和但清晰**：薄玻璃面、圓潤端點、細灰輪廓、克制的邊緣反光。不要厚重黑線、硬機械感、立體積木或過度發光。
2. **接近 zinc 的中性灰**：明暗兩份材質，透明背景。不要藍色冰玻璃、彩虹折射、金屬倒角或大片投影。
3. **以機制構圖**：例如「一個來源分流三個出口」「既有規則接入新片段」。每個主題有自己的輪廓，不把所有圖示都裝進同一個框，也不照描 Tailwind 的物件造型。
4. **透視與遮擋要成立**：同一組平面共享淺斜方向；游標、連接線、掃描線與面板相遇時，明確處理前後關係，避免穿模與黏線。
5. **先做光學校正，再做尺寸統一**：主要可見形體約占方形畫布最大邊的 78–82%；以整組視覺重量判斷，不用單一輪廓強迫所有圖示等面積。明暗圖共用裁切和位置。
6. **各尺寸統一材質**：384 × 384 透明 WebP 同時供主圖與清單使用。小圖檢查輪廓與核心訊號，不因縮小而改回另一套線稿。

## 接入的定案摘要

- Bento 主圖固定 **7rem／112px**，標題與描述包成左側一組，右側放圖示，兩組間距依卡片可用寬度為 **24／32／48px**。
- 標題直接連到內容；不另外加「See details」「How it works」一行。
- 其他位置有自己的尺寸：區塊標頭 64–80px、編輯器與 rendering 主圖 64px、lint 小圖 48px、密集 agent tool 小圖 40px。不要把 7rem 套到全部位置。
- 定案的 Design system 順序是「明暗／Tokens → 全寬 P3 → 各半寬 Layout／motion 與 Native CSS layers」。只有任務涉及這一區時才套用。

## 工作方式與完成標準

先確認使用者指定的分支、當前 checkout，以及預覽服務實際指向的目錄。以該版本的內容、元件和互動為主；歷史分支只提供資產參考，不整份搬回舊首頁排版。

選最相關的定案圖作材質與透視參考，依題目設計主體；處理一個圖示只做必要變體，不擴張成整套重製。可先完成一款代表作自行校準，無須每一步等待使用者批准。

新主圖必須比較明暗兩種背景、實際顯示尺寸及同組相鄰圖示。重點檢查：交叉線、層數、形體分離、邊緣反光、明暗切換位移、裁切、zinc 色調與縮小後辨識度。清單圖示另看 40／48px。

首頁接入涉及排版時，實際檢查 390／768／1280px、明暗模式；涉及文案換行時包含繁體中文。不要只憑「無水平溢出」判斷排版完成，還要看文字是否過度擠窄、標題基線與視覺重量。

沿用 repository 的檢查要求，修正此次引入的失敗，將既有失敗另列。交付時指出變更的圖示／位置、預覽位置與驗證結果。此 skill 不自行要求 commit、push、發布或新增依賴。
