# Onboarding and progressive disclosure

Help people reach a useful first outcome. An introduction should reduce uncertainty about the task, not make every person tour every feature before beginning.

## Choose the entry

Use a short explanation when the purpose is unfamiliar, a checklist when setup has meaningful independent tasks, and contextual help when information becomes useful during work. A returning person should be able to resume without repeating completed steps.

Offer a route to skip optional instruction and find it again. Do not label required setup as optional or make a tour the only source of essential operating information. A service introduction should explain eligibility, needed information and likely consequences before the start action.

## Reveal at the useful moment

Progressive disclosure reduces visible complexity by deferring secondary detail. It must not conceal a consequential default or applied setting. If advanced options are collapsed, summarize settings that change the outcome.

Prefer help beside the relevant control over a detached sequence of floating hints. A hint must not obscure the target or trap keyboard focus. Do not advance steps automatically while the person is reading or operating a control.

## Keep progress meaningful

Distinguish required, optional, completed and unavailable tasks. Completion should reflect a real result, not merely opening a panel. Save progress when the product supports continuation, and explain when this is only a local demonstration.

If setup fails, preserve entered values and retry the failed step. Skipping a tutorial should not silently discard actual configuration. See [form flows](forms.md) and [empty states](empty.md).

## Acceptance scenario

Start with no data, skip optional help, complete one required step and fail another. Leave and return through the supported continuation path. Confirm completed work is retained, the next action is clear and help remains reachable with keyboard and touch. Test the same flow for a returning person.

The [GOV.UK service-start guidance](https://design-system.service.gov.uk/patterns/start-using-a-service/) is a task-oriented reference; its page styling and public-service assumptions are not defaults for every product.
